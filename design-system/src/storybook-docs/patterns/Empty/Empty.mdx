## Usage

Use Empty when a list, table, card, Panel or page has no records to show, a search or filter returns nothing, a queue is finished, or the content exists but cannot be shown to this person. Show <a target="_top" href="./?path=/docs/patterns-states-loading--docs">Loading</a> instead while content is on its way, and leave one blank field blank.

<DocsTable>
<thead>
<tr><th>Type</th><th>The view is empty because</th><th>Say</th><th>Action</th></tr>
</thead>
<tbody>
<tr><td>First use</td><td>Nothing has been added yet: a new group with no students</td><td>What will appear here and how it gets here</td><td>One Primary, if this person can add something; otherwise none</td></tr>
<tr><td>No matches</td><td>A search or filter matched nothing</td><td>Which search or filters are active</td><td>"Reset filters" as a Default button; it also clears the search</td></tr>
<tr><td>All done</td><td>The person finished everything: every reflection is reviewed</td><td>That they are done, and when more arrives</td><td>None</td></tr>
<tr><td>Can't show</td><td>No access, or the data could not load</td><td>Why, in plain words</td><td>Try again, or who can help; never an action they cannot take</td></tr>
</tbody>
</DocsTable>

## Alternatives

- For content still on its way, follow <a target="_top" href="./?path=/docs/patterns-states-loading--docs">Loading</a>: a skeleton, not an empty state.
- For a save or request that failed while the view still has content, use `SectionMessage`; the Errors pattern says where each failure shows.
- For one blank value in a record, show a dash, not an empty state.

## Best practices

### Show an `EmptyState` in any view that has no records.

<RuleTag kind="review" />

Never a blank area or a bare "No results": a blank reads as broken or still loading.

<DoDontPair
    doExample={<WhatBelongsHere />}
    doCaption="Say what belongs here and give the one action that fills it."
    dontExample={<BareString />}
    dontCaption="A bare string in an empty box: broken, loading or empty, nobody can tell."
/>

### Lay the text out as a left-aligned block.

<RuleTag kind="review" />

The picture above, then the heading, one line and the action, all on one left edge. On a full page the block lines up with the page title; inside a table or a card the block is centered and its text stays left-aligned. The text column never runs wide. <PlannedTag /> `EmptyState` centers its text today.

### Replace the whole table with the empty state.

<RuleTag kind="review" />

No column headers and no footer while the table is empty; the view bar above stays, so the person can change the view, search or reset. A "No matches" state offers "Reset filters". <PlannedTag /> The Table keeps its header row in its `emptyState` slot today.

<DoDontPair
    doExample={<ReplacedTable />}
    doCaption="The whole table replaced; the view bar stays."
    dontExample={<HeaderOverNothing />}
    dontCaption="Column headers and a footer over nothing, with a centered paragraph."
/>

### Give at most one Primary action.

<RuleTag kind="review" />

The second action is Default and never stands alone. When two or more empty states can show on one screen, none of them uses a Primary; their actions are Subtle.

### Offer only an action this person can take.

<RuleTag kind="review" />

If they cannot add anything, show no button. A button that leads to "You don't have permission" is a dead end.

### Write the heading as what belongs here.

<RuleTag kind="review" />

"No students in this group yet". The view is empty, not wrong, so the heading carries no "Sorry", no "Oops" and no code.

### Mark the picture as decorative.

<RuleTag kind="automatic" />

Screen readers skip it and read the heading first; the words carry the meaning. The `EmptyState` hides its picture and icon from assistive technology, and its heading sits one level below the section that holds it.

### Name the active search or filters in a No matches state.

<RuleTag kind="review" />

The person may not remember a filter set last week. "No students match these filters" with "Reset filters" is the way out.

### Use an illustration once and an icon where it repeats.

<RuleTag kind="review" />

An illustration for a full view a person meets once, such as a new tutor's first day; an icon on anything that repeats, such as a card on a home page. Illustrations arrive with the character work <PlannedTag />.

## Content guidelines

<DocsTable>

<tr><th>Do</th><th>Don't</th></tr>

<tr><td>All done: "Every reflection is reviewed. New ones arrive after Friday's sessions."</td><td>"All caught up! 🎉"</td></tr>
<tr><td>Warmer for students, plainer for admins: "Your tutor will add notes after your session." and "No notes for this group."</td><td>One voice for everyone.</td></tr>
</tbody>

## Accessibility

- The heading is one level below the section that holds it, so it joins the page outline.
- The picture is decorative: an empty alt, or `aria-hidden` on an icon.
- When a filter or search empties a list, the result count is announced in a polite live region ("0 students").
- Focus stays where it was. Never move it to the empty state's button.
