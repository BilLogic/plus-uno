## For developers

- **Navigation takes <code>href</code>.** The component forwards <code>href</code> and <code>target</code> to the rendered element, which becomes an anchor. Middle-click and open in a new tab keep working, which a click handler on a button does not allow.
- **Loading is not feedback.** <code>loading</code> paints the label transparent and shows a spinner. For a long wait, keep the label with <code>disabled</code> and say what is happening beside it.
- **<code>style</code> carries two vocabularies.** <code>success</code>, <code>warning</code> and <code>danger</code> say something happened. The five pillar styles are subject colors. A button wearing one is about that subject and not about an outcome.
- **<code>active</code> is a class.** For a selected button in a row of buttons, also pass <code>aria-pressed</code>.
- **Extra props land on the element**, so <code>aria-pressed</code>, <code>aria-expanded</code>, <code>aria-controls</code> and <code>aria-describedby</code> need no wrapper.
- **Other components compose it.** Modal, Card and Jumbotron render a Button from their button props.

## When to use

Use a Button when a click runs an action on this view: save, submit, open a dialog. Going to another page is a link, and picking between options is a [Choice group](?path=/docs/components-forms-and-inputs-choice-group--docs), a [Toggle](?path=/docs/components-forms-and-inputs-toggle--docs) or a [Button group](?path=/docs/components-forms-and-inputs-button-group--docs).

- **Give each view one filled button.** The filled button marks the main action. Draw the actions beside it tonal, outlined or as text, so the main one stands out.
- **Say what the button does.** Label it with a verb and its object, such as Save changes, rather than OK or Submit.
- **Keep icon-only for in-row actions.** A small icon-only button is a 24 square, for actions inside a row such as the × on a sidebar tab or a disclosure chevron. It has no visible label, so give it an accessible name that says what it does, such as "Close Hogwarts · Tue, Sep 9".
- **Keep danger for actions that destroy.** The danger style warns that the action deletes or removes something. Using it for ordinary actions spends the warning.
- **Do not disable a button to explain a rule.** A disabled button does not say why. Where you can, leave it enabled and say what is missing when it is pressed.

</div>

<div className="sb-ds-doc-section">

## Accessibility

- **An icon-only button needs a name.** A string <code>leadingVisual</code> or <code>trailingVisual</code> is hidden from assistive technology, so an icon-only button has no name until you pass <code>aria-label</code> or <code>title</code>. Where touch matters, give it a text label as well.
- **Icon-only targets are small.** An icon-only button is 32×32 at <code>medium</code> and 24×24 at <code>small</code>. Neither reaches the 44×44 touch target, so leave room around it.
- **Loading announces nothing.** <code>loading</code> disables the button and drops its click handler, and the spinner is not announced. If the wait matters to a screen reader user, put the status in a live region beside the button.
- **Disabled leaves the tab order.** A natively disabled button cannot be focused, so any explanation of why it is disabled must sit outside the button, where it can still be reached.
- **A row of buttons is not a selection control.** Nothing announces which one is chosen unless you add <code>aria-pressed</code>.
- **Focus is a ring alone**, 2 wide and drawn 2 off the edge, with no fill under it.

</div>
