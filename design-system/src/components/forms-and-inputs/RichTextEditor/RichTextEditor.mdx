## For developers

- **Sanitize the HTML in and out.** The value is written into the editable region as HTML, and <code>onChange</code> returns whatever the browser produced, including pasted markup. Sanitize before you pass a value in and again before you store it.
- **The editor is built on a deprecated browser API.** Formatting runs through <code>document.execCommand</code>, which works today and whose output differs between browsers: one may wrap a line in a div, another in a paragraph. Do not depend on the shape of the HTML. Store it and render it, or convert it once on save.
- **A name posts the value.** Giving the editor a <code>name</code> renders a hidden input, so the HTML posts with a plain form.
- **The label is a span**, not a label element, because an editable region is not a form control for a label to bind to. The region points at it with <code>aria-labelledby</code>.

## When to use

Use Rich text editor only where the formatting carries meaning: session notes with a list, feedback with emphasis, a description that needs a link.

- **For plain multi-line text**, use [Text area](?path=/docs/components-forms-and-inputs-text-area--docs). It is the smaller, sturdier control.
- **For one line**, use [Text field](?path=/docs/components-forms-and-inputs-text-field--docs).
- **Keep link and image out where a browser prompt will not work.** Those two buttons ask for a URL with the platform's unstyled prompt. Leave them out of the toolbar where that prompt would be suppressed or untranslated.
- **To show formatted content a person cannot edit**, render the sanitized HTML yourself.

</div>

<div className="sb-ds-doc-section">

## Accessibility

- **Label it.** The editing area is announced as a multi-line text box, and the label is what names it. Without a label the area is a named role with no name, and a screen-reader user hears nothing about what it is for.
- **The toolbar buttons are named.** Each has a name from its definition, and bold, italic and underline form a group labeled "Bold, italic, and underline". Their pressed state is not exposed to assistive technology.
- **The placeholder is not a name.** It is drawn from an attribute, so it may not be announced at all.
- **Keep the formatting optional.** Anything that exists only as bold text or a color in the body is invisible to someone hearing the page. Structure content with lists and headings instead.
