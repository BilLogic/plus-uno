## Usage

Use `PageHeader` once per page layout, at the top of the Page template's body,
to carry the page's title and primary action or page-level actions. Pass a
`Breadcrumb` in `breadcrumbs` above the title, page-level controls in `actions`
at the end of the title row, and `Tabs` or a filter bar in `bottomBar` below it.
`disableTitleStyles` lets a custom node such as `InlineEdit` replace the default
heading wrapper.

</div>

<div className="sb-ds-doc-section">

## Alternatives

- For a heading inside a region of the page rather than the page itself, use `Heading`.

</div>

<div className="sb-ds-doc-section">

## Parts

1. **Breadcrumbs.** Optional, above the title.
2. **Title.** The page's `h1` by default, or any node with `disableTitleStyles`.
3. **Actions.** Optional, at the end of the title row.
4. **Bottom bar.** Optional, under the row: tabs, a filter bar or a status line.

## Best practices

### Show the trail on nested pages.

Breadcrumbs tell the person where they are; on a page two levels down they are the way back.

<DoDontPair
    doExample={
        <HeadingContextProvider value={2}>
            <PageHeader breadcrumbs={<Breadcrumb items={trail} label="Breadcrumbs, nested page" />} title="Session notes" />
        </HeadingContextProvider>
    }
    doCaption="Breadcrumbs on a nested page."
    dontExample={
        <HeadingContextProvider value={2}>
            <PageHeader title="Session notes" />
        </HeadingContextProvider>
    }
    dontCaption="Nested page with no way back."
/>

### Name the page in a word or two.

The title shares a row with actions, so it has to stay on one line.

<DoDontPair
    doExample={
        <HeadingContextProvider value={2}>
            <PageHeader title="Sessions" actions={<Button appearance="primary" text="Schedule" />} />
        </HeadingContextProvider>
    }
    doCaption="A short noun."
    dontExample={
        <HeadingContextProvider value={2}>
            <PageHeader title="All of the sessions you have scheduled this semester" actions={<Button appearance="primary" text="Schedule" />} />
        </HeadingContextProvider>
    }
    dontCaption="A title that wraps and pushes actions down."
/>

### Use only the parts the page needs.

Every extra row pushes content down; add a part only when the page uses it.

<DoDontPair
    doExample={
        <HeadingContextProvider value={2}>
            <PageHeader title="Session plans" actions={<Button appearance="primary" text="New plan" />} />
        </HeadingContextProvider>
    }
    doCaption="Title and one action."
    dontExample={
        <HeadingContextProvider value={2}>
            <PageHeader
                breadcrumbs={<Breadcrumb items={[{ text: 'Home', href: '#' }, { text: 'Session plans' }]} label="Breadcrumbs, every part" />}
                title="Session plans"
                actions={<Button appearance="primary" text="New plan" />}
                bottomBar={<Tabs defaultActiveKey="all" spacing="compact"><Tabs.Tab eventKey="all">All</Tabs.Tab><Tabs.Tab eventKey="mine">Mine</Tabs.Tab><Tabs.Tab eventKey="shared">Shared</Tabs.Tab></Tabs>}
            />
        </HeadingContextProvider>
    }
    dontCaption="Breadcrumbs, actions and bottom bar all on."
/>

### Pass the title through `title` or `children`, not both.

Pass the title through `title`, or through `children` when that reads more
naturally in the surrounding code; `children` is only used when `title` is
not given.

```jsx
<PageHeader
    title="Session plans"
    breadcrumbs={<Breadcrumb items={trail} />}
    actions={<Button text="New plan" />}
/>
```

### Pass `titleAs="h2"` when the header sits below another page title.

A page has one `h1`. When a `PageHeader` sits under an existing page heading or
inside a dialog below its `h1` title, pass `titleAs="h2"` so the heading
outline keeps one `h1`.

### Reach for `disableTitleStyles` only when the title is not plain text.

The default renders the title in a `Heading`. Turn styling off only when the
title is a custom element already carrying its own heading semantics.

## Accessibility

- **A real heading.** The title renders as a `Heading` (`h1` by default),
  giving the page one clear entry point for assistive technology navigating by
  heading; see Best practices when a second header needs `titleAs="h2"`.
- **Breadcrumbs keep their own semantics.** `PageHeader` does not wrap
  `breadcrumbs` in extra markup — pass a `Breadcrumb` component, which
  carries its own navigation landmark.
