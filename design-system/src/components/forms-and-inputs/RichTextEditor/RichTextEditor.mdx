## Usage

Use a rich text editor where the formatting is part of the meaning: session notes with a list, feedback with emphasis, a description that needs a link. Where it is not, a text area is the smaller, sturdier control.

`toolbarPreset` is `compact` or `full`; passing `toolbarButtons` selects the buttons by name and implies the full toolbar. `value` and `onChange` are HTML strings. Giving it a `name` also renders a hidden input, so the HTML posts with a plain form.

</div>

## Parts

1. **Label.** Text above the box that names it.
2. **Box.** One edge around the toolbar and the writing area together.
3. **Toolbar.** Flat formatting buttons along the top of the box: block style, bold, italic, underline, lists, link and more. A keyline separates it from the writing area.
4. **Writing area.** The editable region, with a placeholder at the start of its first line while it is empty.

## Best practices

### Use the compact toolbar for short notes.

Fewer tools keep a short field light.

<DoDontPair
    doExample={<RichTextEditor label="Quick note" placeholder="Add a note" toolbarPreset="compact" minHeight={96} />}
    doCaption="The compact toolbar on a short note."
    dontExample={<RichTextEditor label="Quick note" placeholder="Add a note" toolbarPreset="full" minHeight={96} />}
    dontCaption="The full toolbar on a short note."
/>

### Use the full toolbar for long content.

Long-form writing needs the full set of tools.

<DoDontPair
    doExample={<RichTextEditor label="Session summary" placeholder="What did you cover?" toolbarPreset="full" minHeight={96} />}
    doCaption="The full toolbar for a long summary."
    dontExample={<RichTextEditor label="Session summary" placeholder="What did you cover?" toolbarPreset="compact" minHeight={96} />}
    dontCaption="Long-form writing limited to the compact toolbar."
/>

### Use read-only for content people read.

Set `readOnly` on content people need to read: it stays in the tab order at full contrast, so it can be selected and copied. Keep `disabled` for an editor that is unavailable; it steps down and leaves the tab order.

### Use the placeholder for a hint.

<DoDontPair
    doExample={<RichTextEditor label="Session notes" placeholder="What did you cover?" minHeight={96} />}
    doCaption="The placeholder hints at what to write."
    dontExample={<RichTextEditor label="Session notes" placeholder="Session notes" minHeight={96} />}
    dontCaption="The placeholder repeats the label."
/>

### `value` is written to the DOM as HTML.

```jsx
// Incorrect: the value is assigned to the editable region's innerHTML, so
// anything a user can influence is executed as markup.
<RichTextEditor value={note.bodyFromApi} onChange={setBody} />

// Correct: sanitize on the way in, and again on the way out before storing.
<RichTextEditor value={sanitize(note.bodyFromApi)} onChange={(html) => setBody(sanitize(html))} />
```

The same applies to what you receive: `onChange` hands you whatever the browser produced, which is markup from a paste as much as from the toolbar.

### It is built on a deprecated browser API.

Formatting runs through `document.execCommand`, which every engine now documents as deprecated. It works today and its exact output differs between browsers: one may wrap a line in `<div>`, another in `<p>`. Do not depend on the shape of the HTML; store it and render it, or convert it once on save.

### Link and image ask with a browser prompt.

Pressing those buttons opens the platform `prompt()` dialog for a URL. It is unstyled, it is not translatable, and some environments suppress it. Where that matters, leave those two buttons out of `toolbarButtons`.

### Label the editor.

<DoDontPair
    doExample={<RichTextEditor label="Session notes" placeholder="What did you cover?" minHeight={96} />}
    doCaption="A label names the editor on screen and for assistive technology."
    dontExample={<RichTextEditor placeholder="What did you cover?" minHeight={96} />}
    dontCaption="No label, only a placeholder, which disappears as soon as someone types."
/>

## Accessibility

- **The editable region announces itself as a multi-line textbox.** `role="textbox"` with `aria-multiline`, and `aria-readonly` while it is read-only and `aria-disabled` while it is disabled.
- **`label` names it, and is effectively required.** The prop renders a `span` above the editor and the region points at it with `aria-labelledby`. A `label` element cannot be used, because `contentEditable` is not a form control for `htmlFor` to bind to. Without a `label` the region is a named role with no name, which a screen-reader user hears as nothing.
- **The toolbar buttons are named.** Each carries an `aria-label` from its definition, and the bold, italic and underline set is a `role="group"` labeled "Bold, italic, and underline". Their pressed state is tracked internally and is not exposed as `aria-pressed`.
- **The placeholder is CSS.** It is drawn from a `data-placeholder` attribute, so it is not part of the accessible name and may not be announced at all.
- **Keep the formatting optional.** Anything that only exists as bold text or a color in the body is invisible to someone hearing the page. Structure it with lists and headings instead.
