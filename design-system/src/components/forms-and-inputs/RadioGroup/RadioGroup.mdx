## Usage

Use a radio group for one question with mutually exclusive answers, visible all at once: a handful of options someone picks by scanning, not searching. For a long list of options, use Select. For independent choices rather than one answer among several, use a group of Checkbox.

The group owns the legend, the value and the error, so each option stays a plain radio.

</div>

<div className="sb-ds-doc-section">

## Parts

1. **Legend.** The question. It names the group and carries the required marker.
2. **Options.** Radios in a stacked or inline set. Each has a label and an optional description.
3. **Scale ends.** Optional `leadingText` and `trailingText` either side of the options.
4. **Reveal.** Optional content under an option, shown only while that option is chosen.
5. **Error.** One message under the group, tied to it with `aria-describedby`.

## Best practices

### Name the question with a group label.

The `legend` tells people what the options answer. A group with no visible
legend needs its own `aria-label` or `aria-labelledby`; the caller's wins over
the legend.

<DoDontPair
    doExample={<RadioGroup name="do-legend" legend="How often should we send reminders?" options={['Weekly', 'Every two weeks', 'Monthly']} />}
    doCaption="The group has a visible question."
    dontExample={<RadioGroup name="dont-legend" aria-label="How often should we send reminders?" options={['Weekly', 'Every two weeks', 'Monthly']} />}
    dontCaption="Options with no visible question."
/>

### Stack three or more answers.

A stacked list scans faster than a row once options multiply. Keep `inline`
for short labels or a scale.

<DoDontPair
    doExample={<RadioGroup name="do-stack" legend="How often should we send reminders?" options={['Weekly', 'Every two weeks', 'Monthly', 'Never']} />}
    doCaption="A stacked list for several options."
    dontExample={<RadioGroup name="dont-stack" legend="How often should we send reminders?" options={['Weekly', 'Every two weeks', 'Monthly', 'Never']} orientation="inline" />}
    dontCaption="A long row of options."
/>

### Explain an error under the group.

One message under the group says what went wrong and what to do; a bare error
state does not. Don't disable the group to block an answer instead: that hides
why and removes it from the tab order.

<DoDontPair
    doExample={<RadioGroup name="do-error" legend="Did the session happen?" options={['Yes', 'No']} isRequired error="Choose an answer." />}
    doCaption="The error is explained in one message."
    dontExample={<RadioGroup name="dont-error" legend="Did the session happen?" options={['Yes', 'No']} isRequired isInvalid />}
    dontCaption="The error state with no explanation."
/>

### Leave the group unanswered until the person answers.

`value` tells "answered zero" apart from "answered the first option." An unanswered group is `null` or `undefined` and never falls back to the first option. Check for that explicitly before treating the group as answered.

```jsx
<RadioGroup
    legend="How was the session?"
    leadingText="Not at all"
    trailingText="Very"
    options={['1', '2', '3', '4', '5']}
    value={rating}
    onChange={setRating}
/>
```

### Reserve choice tiles for one big question with two to four pictured options.

Use `appearance="tile"` when a step asks one focal question with two to four options and every option carries an `illustration`. Keep ordinary form lists and sets of five or more options in `plain` or `card`.

<DoDontPair
    doExample={
        <RadioGroup
            name="do-rg-tile"
            legend="How would you like to tutor?"
            appearance="tile"
            options={[
                { value: 'one', label: 'One-on-one', description: 'One student per session.', illustration: <Illustration character="relationships" size={48} /> },
                { value: 'group', label: 'Small group', description: 'Two to four students.', illustration: <Illustration character="social-emotional" size={48} /> },
            ]}
        />
    }
    doCaption="Two pictured options for one focal question."
    dontExample={
        <RadioGroup
            name="dont-rg-tile"
            legend="Reminder frequency"
            appearance="tile"
            options={['Daily', 'Weekly', 'Every two weeks', 'Monthly', 'Never']}
        />
    }
    dontCaption="An ordinary five-item list without illustrations drawn as tiles."
/>

### Use `reveal` instead of a separate conditional field.

When choosing one option should show an extra field, such as "Other, please specify", pass that field as the option's `reveal` rather than rendering it outside the group. It stays scoped to the option that triggers it and disappears when another option is chosen.

</div>

## Accessibility

- **One real `radiogroup`, named by the legend.** The outer Fieldset supplies the `<fieldset>`/`<legend>` pair; the inner group repeats the legend's id as its own `aria-labelledby`, so assistive technology announces the question once, not twice.
- **Roving tabindex.** Tab enters and leaves the group as a single stop; arrow keys move the checked state between options, matching native radio button behavior.
- **A caller's own `aria-label` or `aria-labelledby` wins over the legend**, for the rare case where the question is named another way.
- **One error, announced once.** `error` renders a single message tied to the group via `aria-describedby`, rather than repeating it per option.
