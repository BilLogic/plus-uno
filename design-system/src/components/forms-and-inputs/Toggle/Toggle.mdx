## Usage

Use a toggle to let a person turn something on or off instantly, such as making a resource public. If a physical switch would work for the action, a toggle is the right component.

A toggle never waits for a button. For an option that needs a button press to apply, such as a field in a form with a Save button, use a checkbox.

Pick the size by the page. Use 16 where the page has many toggles, such as a settings list. Use 20 to call attention to one setting, such as the single switch in a modal.

</div>

<div className="sb-ds-doc-section">

## Parts

1. **Track.** A pill, 32 by 16 or 40 by 20. Off it is the neutral bold fill; on it is the selected bold fill.
2. **Thumb.** An inverse circle inset 2 from the track. It slides to the end when the toggle is on.
3. **Label.** 14/20 text beside the track in a 24 row. It names the setting and stays the same in both states.
4. **Spinner.** Optional, between the track and the label while a change is saved.

## Best practices

### The label names the setting, in both positions.

<DoDontPair
    doExample={<div><Toggle label="Send reminders" defaultChecked /></div>}
    doCaption="The label names the setting and stays the same whether the toggle is on or off."
    dontExample={<div><Toggle label="Reminders are on" defaultChecked /></div>}
    dontCaption="A label that changes with the state reads as a status, and a screen reader hears it twice."
/>

### The change lands at once.

A toggle changes the setting as the person flips it. If the change needs confirming, saving or reviewing first, use a Checkbox in a form.

### Read-only is not disabled.

`isReadOnly` shows a setting the person may read but not change: the toggle stays in the tab order at full contrast and ignores clicks. `isDisabled` takes it out of the tab order and grays it, for a setting that does not apply right now. Say why next to it.

### Name and id.

`name` is a form key, not an id; two toggles may share a name. `isChecked` controls the value and needs an `onChange`; `defaultChecked` sets the start.

### The role is a switch.

The native input is a checkbox with `role="switch"`, the markup the W3C switch pattern ships. The platform maps the checked state, so no `aria-checked` is written. A `role` prop on the toggle replaces it.

## Content guidelines

<DocsTable>
<thead>
<tr><th>Do</th><th>Don't</th></tr>

<tr><td>Write the label so it reads right in both positions.</td><td>"Enable" or "Disable" in the label, which the position already says.</td></tr>
</tbody>

## Accessibility

- **Label every toggle.** A visible `label` is better. Where the name sits elsewhere in the layout, pass `aria-label` so it still reaches assistive technology.
- **Do not change the label with the state.** The label stays the same whether the toggle is on or off.
- **Explain a disabled toggle.** Put the reason in text beside it, so a person who cannot reach it knows why.
- **Keyboard focus is a 2px ring on `border.focused`, 2px off the track.** Space flips the toggle.
