## Usage

Use a choice grid when the same question is asked of several things at once: rate each of these six statements, tick which of these tools each tutor uses. It is a matrix with one question in the column headers and one subject per row.

It is fully controlled. `values` is `{ rowId: columnId }` in `radio` mode and `{ rowId: { columnId: boolean } }` in `checkbox` mode, and the component holds no state of its own.

</div>

<div className="sb-ds-doc-section">

## Parts

1. **Column headers.** The answer scale. They name every cell in their column.
2. **Row labels.** The subject of each row. They name every cell in their row.
3. **Cells.** A real Radio or Checkbox, centered, with no visible label of its own.
4. **Row-header corner.** Empty on purpose; it carries a visually hidden "Row".

## Best practices

### `onChange` has two shapes, and only one of them is the new state.

```jsx
// radio: the two ids that changed. Merge them yourself.
<ChoiceGrid type="radio" values={v} rows={rows} columns={cols}
            onChange={(rowId, columnId) => setV({ ...v, [rowId]: columnId })} />

// checkbox: the whole new values object, already merged.
<ChoiceGrid type="checkbox" values={v} rows={rows} columns={cols}
            onChange={(next) => setV(next)} />
```

In checkbox mode the merge copies the top level and the row it changes, so the `values` you passed in is left as it was and can be compared against the next one.

### A radio row cannot be unanswered again.

Selecting a column always sets it; there is no path back to "not answered". If that state is meaningful, add a column for it. "Not applicable" as a real option is better than a row the user cannot clear.

### Keep the grid small.

Every cell is a control, so a six-by-five grid is thirty tab stops. Past that, ask the questions one at a time with Radio group.

## Accessibility

- **Every cell is named by its row and its column.** Each input carries `aria-labelledby` pointing at both the row label and the column header, so it is announced as "Punctuality, Agree" rather than as an unnamed radio in a table.
- **Every cell is the real control.** Cells render Checkbox and Radio, so focus, states and read-only behave as they do anywhere else.
- **Radio rows are grouped per row.** Each row's inputs share a `name` built from the grid's id and the row's id, which makes one answer per row and arrow-key movement along it. With no `id` or `name` the grid generates its own base, so two grids on a page never share ids or radio groups.
- **The grid itself has no name.** There is no caption and no `aria-label` on the table. Put the question above it as a heading, and describe the scale in the column headers.
- **The row-header column is empty on purpose.** It carries a visually hidden "Row" so the header row is not a blank cell.
- **On a narrow screen this is a wide table.** Put it in a horizontal scroll area rather than letting the columns crush.
