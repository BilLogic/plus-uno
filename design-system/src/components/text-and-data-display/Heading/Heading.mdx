## When to use

Use `Heading` for every heading in the product — a page title, a section
header, a card title. Never style plain text to look like a heading: a
sighted-only "heading" breaks navigation by heading for anyone using
assistive technology.

</div>

<div className="sb-ds-doc-section">

## Usage notes

### Let the ambient context pick the tag; choose `size` for the look.

Nest content in a `HeadingContextProvider` (or rely on the one a pattern like
`Section` already provides) and `Heading` picks `h1`–`h6` from how deep it
sits, so the document outline stays correct automatically. Reach for `as`
only to break that link deliberately — a styled label that isn't really a
heading, for instance.

```jsx
<Heading size="xlarge">Student progress</Heading>
```

### `size` is required — there is no default.

A heading with no declared size is not a heading. Always pass `size`
explicitly, chosen for the visual weight the spot needs, separate from
whatever tag the context resolves to.

</div>

<div className="sb-ds-doc-section">

## Accessibility

- **The tag is the real heading level**, not a visual effect — a screen
  reader's "jump to heading" list is built from the actual tag, which is why
  nesting through `HeadingContextProvider` matters more than it looks.
- **`as` can break the outline if misused.** Overriding the tag to something
  that isn't `h1`–`h6` (like `div` or `span`) removes it from the heading
  outline entirely — correct for a styled label, wrong for an actual section
  title.
- **Inverse colors are automatic**, not a manual contrast fix: pick
  `color.text.inverse` or `color.text.warning.inverse` to match the ground
  the heading sits on, and the token system handles contrast.

</div>
