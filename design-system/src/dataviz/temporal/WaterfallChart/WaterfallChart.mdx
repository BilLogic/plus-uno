## When to use

Use `WaterfallChart` to explain a change between two totals: enrolled students
at the start of term, plus new sign-ups, minus withdrawals, to the current
count; a tutoring budget, minus each cost, to what remains; a base score, plus
bonuses, minus penalties, to the final score.

The steps must happen in order and add up. For totals without the steps between
them, use `BarChart`. For a continuous running value, use `LineChart` or
`AreaChart`. For a breakdown of one total with no sequence, use `TreemapChart`.

Keep it to about ten steps. Past that the floating bars get thin and the
running total hard to follow.

## Data shape

`categories` names each step. `data` holds one entry per category, in the same
order: a number for a change (negative for a loss), or an object
`{ y, isSum, isIntermediateSum, color }`. A total needs no `y`; the chart
computes it.

```jsx
<WaterfallChart
    yAxisLabel="Enrolled students"
    categories={['Start of term', 'New sign-ups', 'Transfers in', 'Withdrawals', 'Graduated', 'Current']}
    data={[
        { y: 420, color: 'var(--ds-chart-brand)' },
        85,
        12,
        -30,
        -18,
        { isSum: true, color: 'var(--ds-chart-brand)' },
    ]}
/>
```

`height` defaults to 400.

## Color and accessibility

- **Gains and losses are status colors.** A gain takes `--ds-chart-success` and a loss `--ds-chart-danger`. Bars are outlined in `--ds-border-inverse` and connectors take the grid border.
- **Give the start and totals their own color.** They are amounts, not gains or losses. Pass `color` on those points, as the Overview story does with `--ds-chart-brand`; without it they take a status color they do not mean.
- **Labels and direction carry the meaning, not only color.** Every bar shows its value and a loss drops below the previous bar's end. A loss's label carries a minus sign; a gain's carries no plus sign, so direction is the only cue besides color that a step is positive.
- **Screen readers and keyboard.** The chart is a labeled group with a screen-reader summary of its type and axes, per-series and per-point labels, and arrow-key navigation through the data. The chart takes no title of its own, so name it in the Section or Card header around it.
- **Contrast.** Chart colors follow the page's color mode and increased-contrast setting; the tooltip uses the Popup pattern's background and text tokens.

## States

`WaterfallChart` draws what it is given and has no empty, loading or error state of its own. The caller chooses what to mount in its place:

- **Loading:** a `Skeleton` the height of the chart.
- **Empty:** a compact `EmptyState` saying what data belongs here.
- **Error:** a `SectionMessage` with `appearance="danger"` and a way to retry.

```jsx
{isLoading ? <Skeleton shape="rect" height={400} />
    : error ? <SectionMessage appearance="danger" dismissible={false} actions={[{ text: 'Retry', onClick: retry }]}>Enrollment changes could not load.</SectionMessage>
    : data.length === 0 ? <EmptyState size="compact" header="No changes yet" description="Sign-ups and withdrawals appear here as they happen." />
    : <WaterfallChart categories={categories} data={data} yAxisLabel="Enrolled students" />}
```
