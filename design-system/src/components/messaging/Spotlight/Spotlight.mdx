## Usage

Use `Spotlight` to point out one feature the first time someone can use it:
a new button, a changed control, a place to start. It is a single step or a
short, explicit sequence with a `stepCount`, not an ongoing help system.

</div>

<div className="sb-ds-doc-section">

## Alternatives

- For a message that stays in the page until resolved, use `SectionMessage`.
- For a short label on hover or focus over a control, use `Tooltip`.
- For an interactive anchored overlay with arbitrary content, use `Popup`.

</div>

<div className="sb-ds-doc-section">

## Parts

1. **Target.** `SpotlightTarget` wraps the element the spotlight points at and
   shares its anchor with the `Spotlight` through a `SpotlightProvider`.
2. **Headline.** The dialog title, read first.
3. **Dismiss.** The shared `CloseButton` in its `inverse` tone, in the header, the dialog's first focusable element. `dismissible={false}` leaves it out.
4. **Media.** An optional image above the body.
5. **Body.** The `children` text.
6. **Step count.** A short label like "1 of 3".
7. **Actions.** A secondary and a primary `SpotlightAction`, the secondary first. Each takes `onClick`, or `href` to render a link.

## Best practices

### Name the feature in a Spotlight, then say what to do.

A headline names the thing; the body is one sentence.

<DoDontPair
    doExample={<FeatureHeadlineDo />}
    doCaption="Short headline, one-sentence body."
    dontExample={<FeatureHeadlineDont />}
    dontCaption="A greeting and a paragraph."
/>

### Show a Spotlight step count only in a tour.

One step alone has nothing to count.

<DoDontPair
    doExample={<StepCountTourDo />}
    doCaption="Step count in a multi-step tour."
    dontExample={<StepCountTourDont />}
    dontCaption="Step count on a single tip."
/>

### Keep the secondary Spotlight action quieter than the primary.

The primary action leads as the filled action; the secondary is the outlined one.
Either `SpotlightAction` can take `href` to navigate.

<DoDontPair
    doExample={<SecondaryQuieterDo />}
    doCaption="The outlined secondary next to the filled primary."
    dontExample={<SecondaryQuieterDont />}
    dontCaption="Two filled, competing buttons."
/>

### Wrap the target and the spotlight in one `SpotlightProvider`.

`SpotlightTarget` and `Spotlight` share an anchor through context, so both
need to sit inside the same provider. Pass `target` directly only when the
anchor comes from outside that tree.

```jsx
<SpotlightProvider>
    <SpotlightTarget>
        <Button text="Create" />
    </SpotlightTarget>
    <Spotlight headline="Create a new board" onDismiss={() => setSeen(true)}>
        Start a new board from here.
    </Spotlight>
</SpotlightProvider>
```

### Dismiss a Spotlight once, and remember that it was seen.

`isOpen` is yours to control. Store whatever "seen" state applies, such as a
user preference or a session flag, so the same spotlight does not reopen on
every visit.

## Accessibility

- **A dialog, not a tooltip.** The spotlight is a `Popup` with a title and a
  description, read together when it opens.
- **The dismiss control is the first focusable element.** Tab reaches it
  before the body or the actions, so closing never requires finding the
  target again.
- **Escape closes it.** Dismissing with Escape or the close button calls
  `onDismiss`.
