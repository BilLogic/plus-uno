## When to use

Use `PieChart` when the question is "how is this total divided?" and the answer
has two to five parts: sessions per subject this term, students by grade band,
resource types in the library. It works best when one share dominates or when
the split is close to a simple fraction like a half or a quarter.

For parts that need a headline number in the middle, such as a completion
rate, use `DonutChart`. For more than five parts, or when readers need to
compare parts closely, use `BarChart`. For the same split across several
groups, use `StackedBarChart` rather than a row of pies. For parts nested
inside parts, use `SunburstChart`.

## Data shape

`data` is an array of `{ name, y }`, one object per slice. `y` is the raw value;
the chart works out each percentage from the total, so the values do not need
to add up to 100.

```jsx
<PieChart
    data={[
        { name: 'Math', y: 420 },
        { name: 'Reading', y: 310 },
        { name: 'Science', y: 180 },
        { name: 'Other', y: 90 },
    ]}
/>
```

An item may carry its own `color`; leave it out and the chart assigns one.
Slices draw in the order given, so sort `data` from most to least before you
pass it.

</div>

## Color and accessibility

- **Color is assigned by position.** Each slice without a `color` takes the categorical order, slot 1 for the first item, slot 2 for the second, and so on. Even a single slice gets slot 1, not the brand color.
- **Keep it to five slices or fewer.** Slots 7 and 8 exist for overflow only, and thin slices become unreadable. Group the smallest into "Other".
- **Angle carries the value, and angle is hard to compare.** The data labels give each slice its name and percentage, so the chart still reads without hue. Do not turn the labels into the only place a value appears for close shares; use `BarChart` when readers must rank parts that are near each other.
- **No 3D.** Tilting the circle distorts the angles the reader is judging.
- **Screen readers and keyboard.** The chart is a labeled group with a screen-reader summary of its type, per-point labels, and arrow-key navigation through the slices. The chart takes no title of its own, so name it in the Section or Card header around it.
- **Contrast.** Chart colors follow the page's color mode and increased-contrast setting; the tooltip uses the Popup pattern's background and text tokens.

</div>

## States

`PieChart` draws what it is given and has no empty, loading or error state of its own. The caller chooses what to mount in its place:

- **Loading:** a `Skeleton` the height of the chart.
- **Empty:** a compact `EmptyState` saying what data belongs here.
- **Error:** a `SectionMessage` with `appearance="danger"` and a way to retry.

```jsx
{isLoading ? <Skeleton shape="rect" height={400} />
    : error ? <SectionMessage appearance="danger" dismissible={false} actions={[{ text: 'Retry', onClick: retry }]}>Sessions could not load.</SectionMessage>
    : data.length === 0 ? <EmptyState spacing="compact" header="No sessions yet" description="The split appears after a session is logged." />
    : <PieChart data={data} />}
```
