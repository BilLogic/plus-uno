## Usage

Use Navigation when deciding how a person gets from here to there. Name the tier first: the control, the place and the motion follow from it. There is no Topbar in the design and no global search; the Sidebar and the page carry every move.

Least room to most. Pick the lowest step that fits. The picture is on <a target="_top" href="./?path=/docs/templates-overview--docs">Templates</a>.

## Alternatives

- For narrowing a collection rather than switching views, follow <a target="_top" href="./?path=/docs/patterns-finding-things-filtering--docs">Filtering</a>; filters combine, views do not.
- For more pills than fit, fold the extras into "More" <PlannedTag />; keep page tabs to five.
- For a decision that blocks the page, use a <a target="_top" href="./?path=/docs/templates-modal-modal--docs">Modal</a>, not a page.

## Best practices

### Show the breadcrumb only after drilling into a record.

<RuleTag kind="automatic" />

Never on an area page or a focused task. It sits above the title in the page header and shows the record's place: parents only, never history. It never wraps. Folding five or more items into "…" is Planned <PlannedTag />.

<DoDontPair
    doExample={<BreadcrumbOnRecordPage />}
    doCaption="A breadcrumb on the record page, parents only."
    dontExample={<BreadcrumbOnAreaPage />}
    dontCaption="A breadcrumb on an area page: there is nothing to climb out of."
/>

### Keep one tab system per page.

<RuleTag kind="review" />

Page tabs under the title, or pill views in a Section's bar, never both. Under page tabs a Section's views become one Select at the start of its bar. It picks a view, not a filter.

<DoDontPair
    doExample={<OneTabSystem />}
    doCaption="Under page tabs the Section's views are one Select at the start of its bar."
    dontExample={<TwoTabSystems />}
    dontCaption="Page tabs and pill views on one page: two tab systems."
/>

### Make views a fixed set the product defines.

<RuleTag kind="review" />

Two to five views of the same rows, named by short parallel nouns. Nobody adds or edits views. One pill stays even with one view, so nothing moves when a second arrives.

### Swap content in place between views and tabs.

<RuleTag kind="automatic" />

Only the selected indicator glides. Nothing slides between views.

### Open a record at the lowest step that fits.

<RuleTag kind="review" />

Expand the row, then Section detail, then the Details Panel, then a Modal, then its own page. Section detail and the Details Panel both stay: the detail for a queue, the Panel for a table on any other page.

### Give a long task its own focused Frame.

<RuleTag kind="automatic" />

Close at the start of the title row, no Sidebar, no breadcrumb. How the steps, the title row and the bar sit is on <a target="_top" href="./?path=/docs/templates-frame-frame--docs">Frame</a>.

### Name an open item by when and who.

<RuleTag kind="automatic" />

"4:00 PM · Ms. Ortiz", with the school in the Tooltip. Three show, then "Show n more". Removing one is Add and remove; opening one is Go to.

<DoDontPair
    doExample={<OpenItemsPicture />}
    doCaption="Each item names the session by its time and the teacher."
    dontExample={<OpenItemsDont />}
    dontCaption="Each item carries everything, and the time it is found by is cut off."
/>

### Put the collection's add action in its view bar, not the page header.

<RuleTag kind="automatic" />

"Add student" is the Primary at the end of the Students view bar. Page actions sit at the end of the title row and are only about the page.

## Accessibility

- The Sidebar is a navigation landmark; the selected item carries `aria-current="page"`. The selected row is a fill, not color on the icon alone.
- Views and page tabs are a real tab widget: one tab stop, Left and Right move selection, the panel is named by its tab.
- The breadcrumb is a `nav` around an `ol`; the last item is plain text with `aria-current="page"`.
- Leaving a focused task returns focus to the control that opened it <PlannedTag />.
