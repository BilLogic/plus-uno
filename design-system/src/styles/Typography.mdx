<FoundationSection title="Overview">

Noto Serif (weight 500) for headings 32 to 20, Noto Sans for headings 16 to 12, metrics and body text, and a monospace face for code: seven Heading sizes, three Body sizes in regular, medium and bold, and three Metric sizes, each a text style bound to the typography variables. Pick a style by where the text sits on the page, not by how big it should look.

```css
font: var(--heading-medium);
font: var(--body-default);
font: var(--metric-large);
```

Figma holds the text styles Heading/*, Body/*, Metric/* and Code/default, bound to the typography collection (font size, line height, family, weight).

</FoundationSection>

<FoundationSection title="About typography">

Typography is the system of fonts and text styles. It carries communication, reinforces the product's voice and guides how people feel using it. Follow three principles, together with the color and spacing tokens.

<FoundationSubsection title="Optimize for readability">
Help every reader understand easily, regardless of ability. Use Body/large for long reading, such as a lesson or a help article.
</FoundationSubsection>

<FoundationSubsection title="Create visual harmony">
Keep type consistent and cohesive, and use hierarchy and space to simplify complex information.
</FoundationSubsection>

<FoundationSubsection title="Contextualize for different users">
Tutors and students read on laptops and desktops, so check each size on a desktop screen from 768 up.
</FoundationSubsection>

</FoundationSection>

<FoundationSection title="Type scale">

Heading/*, Body/* and Metric/* are the text styles for all new work. Every property of each style is bound to a variable in the typography collection. The tokens are the contract: a later change edits a variable, never a component. Sizes are in rem, where 1rem is 16px, so people can scale text in their browser.

<FoundationSection title="In code">

Component text takes a text style, `font: var(--heading-small)` or `font: var(--body-default)`, and an icon glyph takes an icon size such as `--icon-md`. Never type a font size, family or weight.

A `font` shorthand cannot carry letter spacing, so each tracked heading has a companion token set beside it: `--heading-xxlarge-tracking`, `--heading-xlarge-tracking` and `--heading-large-tracking`.

</FoundationSubsection>

<FoundationSubsection title="Text-style classes">

Markup with no stylesheet of its own takes the text style as a class, one per style, generated beside the type tokens: `.heading-xxlarge` to `.heading-xxsmall`, `.body-large`, `.body-default`, `.body-small`, and `.metric-large` to `.metric-small`. Each sets the `font` shorthand, and the tracked headings their letter spacing too. A component's own stylesheet sets `font: var(--…)` instead.

```jsx
<p className="body-default">Helper text</p>
<h2 className="heading-medium">Section title</h2>
```

</FoundationSubsection>

<FoundationSection title="Using headings">

Headings introduce a new section of content. They are sized to contrast with the content and to make the structure easy to see.

- Use a heading style, not bold text or a change of size. Heading styles carry the structure that assistive technology reads.
- Heading/xxlarge and xlarge are for hero and marketing content. Heading/large is a page title, such as a form title. Heading/medium suits components with room, such as modals. Heading/small and xsmall title small components where space is limited, such as a card or a flag.
- Heading/xxsmall is used sparingly, matched with Body/small, for fine print and group labels.

</FoundationSection>

<FoundationSection title="Labels">

A label uses Body/default/medium (Noto Sans 500). There is no separate button style: use the medium style for button, tab and menu labels and apply it directly, with no variables bound inline. In code it is `font: var(--body-default)` with `font-weight: var(--type-weight-medium)`.

A Sidebar tab is a navigation row, not a tab in a Tab group: its label is Body/default at regular weight, and medium once the tab is selected.

<FoundationSection title="Using body and metric">

- Body/large is the size for long-form content, where a comfortable read matters.
- Body/default is the size in components or wherever space is limited, for detailed or descriptive content.
- Body/small is for secondary content such as fine print or semantic messages. Use it sparingly.
- Weights: every body size comes in three styles, regular, medium and bold. Use Regular for paragraphs, Medium as the default inside components and beside icons (button, tab and menu labels), and Bold for emphasis in body text, sparingly. PLUS bold is 600 (semibold), through the bold weight token.
- In code it stays one size token plus a weight token: `font: var(--body-default); font-weight: var(--type-weight-medium)`.
- Use medium beside an icon, because icon stroke width is designed to align with medium weight text. Do not use heading styles inside components; use body with a heavier weight instead.
- Use Metric when a number is the point, such as a session count or a score. Metric sizes are large, medium and small.
- PLUS has no paragraph-spacing style. Space paragraphs and blocks with the Section and stack tokens (see Spacing).

</FoundationSection>

<FoundationSection title="Code">

Code is code-only. Code/default (12/16) sets code samples, token names and property values in Figma docs. Code is Noto Sans Mono. In code, `var(--code)` sets 0.875em of the parent size in the code font, so a code span follows the text around it.

<FoundationSection title="Usage">

Pick the style by the text's place on the page.

<FoundationSubsection title="Keep xxlarge and xlarge for heroes">

Heading/xxlarge 32 and Heading/xlarge 28 are for heroes, empty states and metric-heavy dashboards only, never for a page title.

</FoundationSubsection>

<FoundationSubsection title="Body/default runs the interface">

Every control label is 14/20, which is what sets the 24, 32 and 40 item heights. Body/large is for reading text such as lessons and help articles; Body/small for meta text, Tag, Status, Count and tooltips.

</FoundationSubsection>

<FoundationSubsection title="Change the token, not the text">

Every style binds the typography variables, so a later change to a size, line height, family or weight edits a variable and no component needs touching. Never type a size, and never detach a style.

</FoundationSubsection>

</FoundationSection>

<FoundationSection title="Truncate and wrap">

Text that may be longer than its box either stops or wraps, and the component decides which. Names and titles stop; text that is the content wraps.

- A title or a name truncates to one line with an ellipsis. Give people the full text on hover or in the detail view.
- A description stops at 3 lines unless the component is set to wrap.
- Set wrap only when the whole text is the content, such as a session note or a help answer. In a table cell, truncate is the default and wrap is chosen per column.
- Never shrink the type to make a long name fit.

<FoundationSection title="Accessibility">

- Heading levels help people using screen readers and other assistive technology navigate a page. Keep one h1 per page and descend one level at a time; the tag sets the structure and the text style sets the look.
- Text color comes from the `color/text/*` tokens, whose pairs clear 4.5:1 on their grounds in all four modes (see Color).
- Sizes are in rem, so text follows the reader's browser setting. A code span is 0.875em of the text around it, so it follows the reader's text size too.

</FoundationSection>
