## Usage

Use `Select` for a list of six or more options, where typing to filter
helps more than scanning — a tutor roster, a list of schools. Up to five
options belong in view as a `RadioGroup` (one pick) or a Checkbox group
(several). Pick the control by the shape of the answer.

### Turn typing off for a short set of choices.

Typing is on because most lists are long enough to need it. A menu that
holds a few choices, applied as you pick, has nothing to search: pass
`isSearchable={false}` so the field stays a plain trigger and Space opens it.

## Parts

1. **Field.** The box that shows the value, or the placeholder, and a chevron.
2. **Label.** Names the field. A required marker follows it.
3. **List.** The options, in a popup under the field. Groups carry a heading.
4. **Caption.** Helper text, or the error that replaces it.

## Best practices

### Keep option labels short and parallel.

Short, parallel labels scan as a list; a sentence in the field gets cut off.

<DoDontPair
    doExample={<div style={{ width: 'var(--width-2000)' }}><Select label="Session length" options={lengths} defaultValue="45" /></div>}
    doCaption="A short label names the value."
    dontExample={<div style={{ width: 'var(--width-2000)' }}><Select label="Session length" options={sentenceLengths} defaultValue="45" /></div>}
    dontCaption="A sentence in the field does not fit."
/>

### Use multi select when answers combine.

Several answers belong in Tags, one per answer, not in one comma-joined value.

<DoDontPair
    doExample={<Select label="Subjects" isMulti options={subjects} defaultValue={['math', 'reading', 'writing']} />}
    doCaption="One Tag per chosen answer."
    dontExample={<Select label="Subjects" options={joinedSubjects} defaultValue="all" />}
    dontCaption="Answers joined into one value."
/>

### Show an error on the field itself.

Mark the field with `isInvalid` so the message reads as an error; the same words as help text in a default field look fine.

<DoDontPair
    doExample={<Select label="Subject" options={subjects} placeholder="Choose a subject" isInvalid errorMessage="Choose a subject." />}
    doCaption="The field shows the error state."
    dontExample={<Select label="Subject" options={subjects} placeholder="Choose a subject" caption="Choose a subject." />}
    dontCaption="The same words as plain help, in a default field."
/>

### Pick the mode by the answer.

`isMulti` shows picks as Tags and checkboxes in the list; `selectAll` and `maxSelections` apply to it only. Typing filters the list unless you pass `isSearchable={false}`, and `isCreatable` adds a "Create" row when nothing matches. `createOption` turns the typed text into the option it creates, or refuses it with null; Time picker uses it to read "1430" as 2:30 PM. `clearable` defaults to on with `isMulti` and off for a required single select.

### Mark a single pick with a check or a radio.

A single Select marks its pick with a check at the end of the row. Pass `marker="radio"` to draw a radio before the label instead, when the list reads as a set of alternatives to choose between, as in a view switch or a filter menu. Several picks always use checkboxes, so `marker` has no effect with `isMulti`. The marker changes color on selection; it does not move.

### Show picks as text when Tags crowd the field.

`displayMode="text"` (with `isMulti`) shows picks as comma-separated text instead of Tags. `isValid` with `successMessage` draws the success edge and message.

### Chain `dependsOn` for fields that filter each other.

Pass the parent's `{ value, label }` as `dependsOn` on the child. The child
disables itself and explains why until the parent has a value, and clears
itself the moment the parent's value changes — no manual wiring needed beyond
passing the parent's current state down.

```jsx
<Select label="School" options={schools} value={school} onChange={setSchool} />
<Select
    label="Teacher"
    options={teachersFor(school)}
    value={teacher}
    onChange={setTeacher}
    dependsOn={{ value: school, label: 'a school' }}
/>
```

### Use `commitOnClose` for a filter bar, not a form field.

A form's multi-select should fire `onChange` on every pick, so other UI can
react immediately. `commitOnClose` is for the opposite case — a filter panel
where firing once, on close, avoids re-querying on every checkbox click.

### Reach for `loadOptions` once a list is genuinely large or server-backed.

`recent` and `suggested` only change the order past 50 static options;
`loadOptions` is for a list too large to ship as a static array at all.

`loadOptions` is `(text, { offset, limit }) => Promise<{ options, total }>`.
The first page loads as the list opens and again whenever the typed text
changes; the next page loads as the list scrolls near its end, 50 at a time,
and an older answer never overwrites a newer one. `isCreatable` works with it.

```jsx
<Select
    label="Student"
    isCreatable
    loadOptions={(text, { offset, limit }) => fetchStudents(text, offset, limit)}
/>
```

While a page is on its way the list shows one "Loading options" row; a Select
never draws skeleton rows. If the request fails the list shows "Couldn't load
options" with a Retry button, and Enter in the field retries too. A later page
that fails keeps the rows already loaded and puts the same message in the
footer. Options fade in one after another, 20 ms apart, the wait capped at
500 ms; reduced motion shows them at once.

</div>

<div className="sb-ds-doc-section">

### Read-only is not disabled.

`isReadOnly` shows a value someone could change but this person cannot right now: it stays in the tab order at full contrast, can be selected and copied, takes the neutral fill, has no hover and says `aria-readonly`. Say why in the caption. `isDisabled` is for a field that does not apply yet, and takes it out of the tab order. Never swap one for the other, and never clip a read-only value. Content nobody can edit is plain text, not a field.

<DoDontPair
    doExample={<div style={{ width: 'var(--width-2000)' }}><Select label="Session length" options={lengths} defaultValue="45" isReadOnly caption="Set by your supervisor." /></div>}
    doCaption="Read-only keeps the value readable, and the caption says why."
    dontExample={<div style={{ width: 'var(--width-2000)' }}><Select label="Session length" options={lengths} defaultValue="45" isDisabled caption="Set by your supervisor." /></div>}
    dontCaption="Disabled fades a value people need to read."
/>

## Accessibility

- **A real combobox.** The field is `role="combobox"` with
  `aria-expanded`/`aria-controls`/`aria-activedescendant` tracking the open
  list and its highlighted row.
- **The label is linked, or named explicitly.** Pass `label` for a visible
  one, or `aria-label`/`aria-labelledby` when there isn't a visible label.
- **Keyboard parity with a native select.** Arrow keys, Enter and Escape
  open, move through and close the list; Backspace removes the last Tag in a
  multi-select with an empty filter; Delete clears the field when
  `clearable`.
- **A waiting dependent field says why.** `dependsOn`'s disabled state pairs
  with a caption ("Choose a school first"), not silence.
