## Usage

Use `Rating` for a five-point satisfaction score given in one gesture, such as end-of-session feedback. Five items is the whole scale; there is no other length. `type` is `comments` (one caption below the row) or `numeric` (1 to 5 above each item); `icon` is `star` or `thumbs-up`.

</div>

<div className="sb-ds-doc-section">

## Alternatives

- For a continuous or wider numeric span, use `Range`.
- For a labeled Likert scale or mutually exclusive options, use `RadioGroup`.
- For the written feedback that accompanies a score, use `TextArea`.

</div>

<div className="sb-ds-doc-section">

## Parts

1. **Label.** Text above the row that names the rating. An optional minority marker (`"(optional)"` or `"(required)"`) follows it in plain text.
2. **Items.** Five 32 circles, each drawing a 16 icon. Items up to the score are filled.
3. **Number.** In the numeric type, 1 to 5 above each item.
4. **Caption.** In the comments type, one line under the row.

## Best practices

### Use stars for quality and thumbs for approval.

Match the icon to the question.

<DoDontPair
    doExample={<Rating label="How was the session?" icon="star" value={0} onChange={() => {}} />}
    doCaption="Stars rate the quality of a session."
    dontExample={<Rating label="How was the session?" icon="thumbs-up" value={0} onChange={() => {}} />}
    dontCaption="Thumbs on a graded five-point scale."
/>

### Start empty for new input.

A pre-filled rating biases the answer.

<DoDontPair
    doExample={<Rating label="How was the session?" value={0} onChange={() => {}} />}
    doCaption="No rating yet, so the person gives their own."
    dontExample={<Rating label="How was the session?" value={4} onChange={() => {}} />}
    dontCaption="Four stars filled before the person has rated."
/>

### Show a recorded rating as plain text.

`Rating` has no read-only state, and `isDisabled` is for a rating that does not apply yet. A rating nobody can change is a result, so write it as text. See [Read-only](?path=/docs/patterns-states-read-only--docs) and [Disabled](?path=/docs/patterns-states-disabled--docs).

<DoDontPair
    doExample={<span>Rated 4 out of 5.</span>}
    doCaption="A recorded rating, written as text."
    dontExample={<Rating label="How was the session?" value={4} isDisabled onChange={() => {}} />}
    dontCaption="Disabled dims a result people need to read."
/>

### Always control it.

```jsx
// Incorrect: the component holds no state. Without an onChange the items are
// clickable and nothing ever changes.
<Rating label="How was the session?" />

// Correct: onChange receives the number, not an event.
<Rating label="How was the session?" value={score} onChange={setScore} />
```

### Set `name` to submit the value with a form.

A hidden input carries the score with its form, so `name` is how a server reads it.

```jsx
<form onSubmit={submit}>
    <Rating name="score" label="Rating" value={score} onChange={setScore} />
</form>
```

### Give it a `label`.

<DoDontPair
    doExample={<Rating label="How was the session?" value={3} onChange={() => {}} />}
    doCaption="A label names the row, so a page with two ratings tells them apart."
    dontExample={<Rating value={3} onChange={() => {}} />}
    dontCaption={'Without a label the row falls back to the generic name "Rating". `commentsLabel` is a caption, not a substitute.'}
/>

## Accessibility

- **It is one value out of five, and says so.** The row is a `radiogroup` and each item is a `radio` carrying `aria-checked` and an `aria-label` of "Rate 1" through "Rate 5". The chosen value is in the accessibility tree, not only in the fill color.
- **One tab stop, arrow keys within it.** Tab reaches the group once, landing on the checked item, or the first when nothing is checked; Left/Right, Up/Down, Home and End move the value. Enter and Space still activate an item directly.
- **Moving the selection is changing it.** An arrow key calls `onChange`, so a keyboard user cannot browse the scale without setting it. That is the usual radio-group behavior.
- **Disabled stays announced.** The items keep their role, label and `aria-checked` and take `aria-disabled`, and drop out of the tab order.
- **The label is a `span`, deliberately.** There is no form control for a `label` element to point at, so the label has an id and the row is named by `aria-labelledby`.
- **`isRequired` sets `aria-required` on the radiogroup.** Pair it with `labelMarker="required"` only when required fields are the minority in the form.
