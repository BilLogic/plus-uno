## Usage

Use `DateTag` for a due or event date beside the thing it belongs to: an
assignment, a session, a report. For a status or a category, use `Tag`
instead; `DateTag`'s outline, icon and three appearances are reserved for
dates.

### Appearance guidance

The app derives `appearance` from the date and a due-soon window it defines.

<DocsTable>
<thead>

<tr><td>Warning</td><td>The date is near, before it turns overdue. Draws a clock. Example: "Due tomorrow".</td></tr>
<tr><td>Danger</td><td>The date has passed. Draws a triangle. Example: "2 days overdue".</td></tr>
</tbody>

## Parts

1. **Icon.** Fixed by the appearance: a calendar for neutral, a clock for warning and a triangle for danger. It is decoration; the date says the rest.
2. **Date.** One short string, set by the app: "Due tomorrow", "Mar 4".
3. **Outline.** A 1 inside border, so the height stays exact. A date tag has no fill.

## Best practices

The app picks the appearance from the date and its due-soon window, never from taste. Write `children` as people say the date: "Due tomorrow", "2 days overdue", not a raw timestamp.

### Reserve danger for overdue dates.

Danger means the date has passed; a far-off date stays neutral.

<DoDontPair
    doExample={<div style={{ display: 'flex', flexWrap: 'wrap', alignItems: 'center', gap: 'var(--inline-md)' }}><span>Overdue</span><DateTag appearance="danger">2 days overdue</DateTag></div>}
    doCaption="Danger when it is overdue."
    dontExample={<div style={{ display: 'flex', flexWrap: 'wrap', alignItems: 'center', gap: 'var(--inline-md)' }}><span>Due in 30 days</span><DateTag appearance="danger">Due in 30 days</DateTag></div>}
    dontCaption="Danger on a date 30 days out."
/>

### Use warning for dates that are close.

Warning tells people the date is near, before it turns overdue.

<DoDontPair
    doExample={<div style={{ display: 'flex', flexWrap: 'wrap', alignItems: 'center', gap: 'var(--inline-md)' }}><span>Due tomorrow</span><DateTag appearance="warning">Due tomorrow</DateTag></div>}
    doCaption="Warning when it is due soon."
    dontExample={<div style={{ display: 'flex', flexWrap: 'wrap', alignItems: 'center', gap: 'var(--inline-md)' }}><span>Due tomorrow</span><DateTag>Due tomorrow</DateTag></div>}
    dontCaption="Neutral hides that it is due soon."
/>

### Show one date tag per row.

A row carries one date; extra tags compete for attention.

<DoDontPair
    doExample={<div style={{ display: 'flex', flexWrap: 'wrap', alignItems: 'center', gap: 'var(--inline-md)' }}><span>Session</span><DateTag>Due Nov 12</DateTag></div>}
    doCaption="One date per row."
    dontExample={<div style={{ display: 'flex', flexWrap: 'wrap', alignItems: 'center', gap: 'var(--inline-md)' }}><span>Session</span><DateTag>Due Nov 12</DateTag><DateTag appearance="warning">Due tomorrow</DateTag><DateTag appearance="danger">2 days overdue</DateTag></div>}
    dontCaption="Several dates in one row."
/>

### Never make a date tag a button.

It renders a `span` with no role and no click handler: `onClick`, `role` and
`tabIndex` are dropped with a console warning in development. The one time it
takes focus is when its text is truncated, so a keyboard user can still reach
the tooltip holding the full date.

## Accessibility

- **Not a control.** No role, no tab stop, no click handler: assistive
  technology reads it as plain text beside whatever it labels.
- **Truncated text stays reachable.** When the label is clipped, the tag
  takes a tab stop and its full text is available as a tooltip on hover or
  focus.
- **The icon is decorative.** It is `aria-hidden`; the appearance's meaning
  lives in the text, not the icon alone.
