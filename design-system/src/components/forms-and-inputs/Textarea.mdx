## When to use

Use `Textarea` when the answer is prose the user writes in their own words —
session notes, a reflection, a reason for canceling. The field is 80 high
at least, and `rows` (default 3) grows it from there. A one-line answer is an
`Input`, which is 32.

</div>

<div className="sb-ds-doc-section">

## Usage notes

- **`validation` and `validationMessage` work as they do on Input.** The
  message sits in the caption, on the left; with `maxLength`, a count sits on
  the right ("55 / 120"), and neither replaces the other.
- **`subtle` keeps the editor open.** A click elsewhere mid-paragraph should not
  publish half a thought, so a subtle textarea saves only through its Save
  button (or Ctrl/⌘+Enter) and stays open when it loses focus. Cancel or Esc
  puts the saved text back. A failed save keeps the field open in `invalid`.
- **`state` is for older call sites and still pictures.** `state="focus"` draws
  focus for documentation; `error`, `success`, `readonly` and `disabled` are
  older names for `validation`, `readOnly` and `disabled`.

### One row, not a short variant.

```jsx
// Incorrect — `variant` is gone; there is one textarea.
<Textarea id="other" label="Other" variant="short" />

// Correct.
<Textarea id="other" label="Other" rows={1} />
```

</div>

## Accessibility

- **The label is associated whether you pass `id` or not.** One id is derived
  once and used for both the label's `htmlFor` and the control; when no `id` is
  given, React's `useId` supplies one. Pass `id` only when something outside the
  component needs to point at the control, and you will get exactly that id back.
- **`showLabel={false}` hides the label without removing it**, as on Input.
- **An error is announced.** With `validation="invalid"`, the control carries
  `aria-invalid`, points at the message with `aria-describedby`, and the message
  renders with `role="alert"`. The count is described too.
- **`required` shows an asterisk and sets `aria-required`.** Explain the
  asterisk once, in the form's legend.
