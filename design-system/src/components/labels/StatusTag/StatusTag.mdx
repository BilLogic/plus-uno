## When to use

Use `StatusTag` for the condition something is in when that condition can change:
completed, needs review, missed, in progress, due tomorrow, overdue. It is the
same component whether the system calculated the state or a person set it.

- **Is it a number?** Count tag.
- **Is it the condition something is in, and can that condition change?** Status tag.
- **Otherwise** (a subject, a person, a category): Tag.

Use `spacing="default"` (20) in rows, lists, tables and sentences, and
`spacing="spacious"` (32) beside a heading.

</div>

## Usage notes

### Let the appearance carry a meaning.

Each appearance means one thing: neutral (not started), success (done), warning
(needs attention), danger (failed or missed), info (in progress) and discovery
(new). A SMART subject keeps its own colors, because it names a subject, not a
condition. There is no color prop; a category with a color is a Tag.

```jsx
// Incorrect — a category borrowing a status color.
<StatusTag appearance="info">Math</StatusTag>

// Correct — a condition that can change.
<StatusTag appearance="info">In progress</StatusTag>
```

### Let the app pick a date's appearance.

A date is neutral when it is not close, warning when it is due soon and danger
when it is overdue. Derive the appearance from the date and the due-soon window,
and write the label as people say it.

```jsx
<StatusTag type="date" appearance="warning">Due tomorrow</StatusTag>
<StatusTag type="date" appearance="danger">2 days overdue</StatusTag>
```

### Nest a count instead of placing one beside it.

```jsx
// Incorrect — two labels that read as unrelated.
<StatusTag appearance="success">Completed</StatusTag> <CountTag value={38} />

// Correct — one label; the number reads as part of it.
<StatusTag appearance="success" trailingMetric={38}>Completed</StatusTag>
```

### Give the metric its own appearance when it means something else.

`trailingMetricAppearance` defaults to the Status tag's own appearance. Set it
only when the number carries a different meaning from the status, such as a
success status with a danger count of failures.

```jsx
<StatusTag appearance="success" trailingMetric={38} trailingMetricAppearance="danger">Completed</StatusTag>
```

A date and the SMART subjects have their own looks and take no metric.

### Edit in the field, not on the label.

A Status tag never opens a menu. Where a status can be changed, the field around
it becomes an inline Dropdown whose options are grouped To do · In progress ·
Complete · Exception · Failed, each group with one appearance (neutral · info ·
success · warning · danger).

## Accessibility

- **Read as its text.** A Status tag is a `span` with no role, so a screen reader
  announces its text and nothing suggests it can be pressed. An `onClick` is
  dropped with a development warning.
- **Not a tab stop, unless truncated.** When the label is clipped, the Status tag
  takes focus so a keyboard user can reach the tooltip holding the full text;
  pointer users get the same tooltip on hover. The full text is always in the
  DOM, so a screen reader hears all of it.
- **Not color alone.** Dates differ in icon as well as color (calendar, clock,
  alert), and a state can add a `leadingVisual` where color alone is not enough.
  Icons are decorative and hidden from assistive technology.
- **An edge on any surface.** The 1px inside border keeps a pale fill visible
  on white and on gray; in forced-colors mode it becomes a real border.
