## When to use

Use `ParetoChart` to find the few causes behind most of a problem: support
tickets by issue type, missed sessions by reason, the topics where students
struggle most. Read across from the 80% mark on the right axis to see how many
causes account for it.

For a ranking with no running total, use `BarChart` or `LollipopChart`. For
shares of one total without an order, use `PieChart` or `TreemapChart`. For
drop-off through ordered stages, use `FunnelChart`.

The running line only means something when the columns run from largest to
smallest. Sort the data before passing it in; the chart keeps the order it is
given.

## Data shape

`categories` is an array of strings. `data` is an array of numbers, one per
category, in the same order, sorted from largest to smallest. The chart
computes the cumulative line itself. `height` defaults to 400.

```jsx
<ParetoChart
    yAxisLabel="Missed sessions"
    categories={['Schedule conflict', 'Tech issue', 'Illness', 'No notice', 'Other']}
    data={[42, 25, 12, 7, 4]}
/>
```

## Color and accessibility

- **Color is fixed.** The columns take categorical slot 1 and the line slot 2. Nothing is assigned per column.
- **Shape tells the series apart, not just hue.** One series is columns, the other a line, each on its own axis, so the chart reads without color.
- **Two axes, two units.** The left axis is a count and the right a percentage. Name the count in `yAxisLabel` so the two are not confused.
- **Screen readers and keyboard.** The chart is a labeled group with a screen-reader summary of its type and axes, per-series and per-point labels, and arrow-key navigation through the data. The legend names the series only as "Values" and "Cumulative", so say what is counted in the surrounding header. The chart takes no title of its own, so name it in the Section or Card header around it.
- **Contrast.** Chart colors follow the page's color mode and increased-contrast setting; the tooltip uses the Popup pattern's background and text tokens.

## States

`ParetoChart` draws what it is given and has no empty, loading or error state of its own. The caller chooses what to mount in its place:

- **Loading:** a `Skeleton` the height of the chart.
- **Empty:** a compact `EmptyState` saying what data belongs here.
- **Error:** a `SectionMessage` with `appearance="danger"` and a way to retry.

```jsx
{isLoading ? <Skeleton shape="rect" height={400} />
    : error ? <SectionMessage appearance="danger" dismissible={false} actions={[{ text: 'Retry', onClick: retry }]}>Missed sessions could not load.</SectionMessage>
    : data.length === 0 ? <EmptyState spacing="compact" header="No missed sessions" description="Reasons appear when a session is marked missed." />
    : <ParetoChart categories={categories} data={data} yAxisLabel="Missed sessions" />}
```

## Related

- For the ranked bars without the cumulative line, use `BarChart`.
- For the cumulative share as parts of one whole, use `TreemapChart` or `PieChart`.
- For a drop-off through ordered stages rather than ranked causes, use `FunnelChart`.
- For columns and a line on any two measures, use `ComboChart`.
