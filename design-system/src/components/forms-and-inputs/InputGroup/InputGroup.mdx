## When to use

Use `InputGroup` for a text field with something inside its box — a unit
after the value, a currency symbol before it, a button that acts on what was
typed. The addons sit in the field's Leading and Trailing slots and share its
one border, so they read as one control.

`leadingVisual` and `trailingVisual` each take one addon or an array of them
(Trailing holds two at most): an element, a string shorthand, or an object like
`{ type: 'button', text: 'Go', onClick }`. Button and dropdown addons are always
the small size, cut to the field's line, so the field keeps its height. The subcomponents —
`InputGroup.Text`, `.Icon`, `.Button`, `.Dropdown`, `.Checkbox`, `.Radio` — are
what those shorthands build, and can be passed directly.

</div>

<div className="sb-ds-doc-section">

## Usage notes

### Label it, and reach for `Input` when the addon is decoration.

```jsx
// The label is associated with the input, and `id` names the input rather than
// the group (#329). `showLabel={false}` clips it without removing the name.
<InputGroup id="amount" label="Amount" leadingVisual="£" />

// For a field whose addon is only an icon or a unit, `Input` is the smaller
// component and has its own leading and trailing visuals.
<Input label="Amount" leadingVisual="fa-solid fa-sterling-sign" value={v} onChange={setV} />
```

Reach for `InputGroup` when the addon is a real control — a button or a dropdown
that `Input` cannot hold.

### An unrecognized string addon becomes text.

```jsx
// Incorrect — "buttons" is not one of the shorthands, so it renders as the
// literal text "buttons" in an addon.
<InputGroup trailingVisual="buttons" />

// Correct — the shorthands are checkbox, radio, icon, plus, button, dropdown.
// Anything else is text, which is what makes the typo silent.
<InputGroup trailingVisual={{ type: 'button', text: 'Search', onClick: run }} />
```

### The string shorthands come with defaults you probably do not want.

`"checkbox"` and `"radio"` render already checked, with no handler and the
generic names "Toggle option" and "Select option". `"button"` is labeled
"Button". Use the object form as soon as the addon does anything.

</div>

## Accessibility

- **The input takes the name.** `label` associates through `htmlFor`, `id`
  lands on the input, and extra props are forwarded there too (#329) — so
  `aria-describedby` reaches the element it describes.
- **Addon controls are named generically.** The checkbox and radio addons
  default to "Toggle option" and "Select option"; pass `aria-label` in the object
  form to say what they actually do.
- **An addon that acts on the field must be a control.** `InputGroup.Button` and
  `InputGroup.Dropdown` are real ones. `InputGroup.Text` and `InputGroup.Icon`
  are decoration — the icon is `aria-hidden`, so an icon that means something
  needs text beside it.
- **`required` shows an asterisk and sets `aria-required`**, and a
  `validationMessage` is announced with `role="alert"`, as on `Input`.
- **Two addons a side is the limit, and it is a limit for a reason.** Four things
  bolted to a field are four things a screen-reader user meets before the field
  itself.

</div>
