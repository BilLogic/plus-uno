## When to use

Use `Select` when someone picks from a known list and the choice is part of a
form's data:

- 5 to 15 options when space is tight, or when there is a good default.
- `mode="multi"` for several values, shown as Tags, with a checkbox on each row.
- `searchable` past about 8 options: typing in the field filters the list.
- `creatable` when the list may grow: "Create *text*" appears when nothing matches.

</div>

<div className="sb-ds-doc-section">

## Usage notes

### `onChange` hands you the value, not an event.

```jsx
// Incorrect — there is no event. `onChange` gets an id in single mode and an
// array of ids in multi mode, so this throws.
<Select options={grades} onChange={(e) => setGrade(e.target.value)} />

// Correct — take the value straight.
<Select options={grades} onChange={(value) => setGrade(value)} />
```

### A filter bar commits when the list closes.

```jsx
// Incorrect — every tick refetches the table while the person is still choosing.
<Select mode="multi" options={subjects} value={filters} onChange={refetch} />

// Correct — one commit, when the list closes.
<Select mode="multi" options={subjects} value={filters} onChange={refetch} commitOnClose />
```

### A sort, or a required pick, has no clear ×.

`clearable` defaults to true in multi mode and to `!required` in single mode. A
sort always has a value, so it passes `clearable={false}`. In Figma the clear is
`_Field Clear` in the `filled?=true` variants.

```jsx
// Incorrect — the × empties the sort, and the list has no order.
<Select aria-label="Sort" options={sorts} value={sort} onChange={setSort} />

// Correct — the sort can change but never empty.
<Select aria-label="Sort" options={sorts} value={sort} onChange={setSort} clearable={false} />
```

### Read-only is not disabled.

```jsx
// Incorrect — disabled takes the field out of the tab order and fades it, so
// a value the person can read but not change looks broken.
<Select options={terms} value={term} disabled />

// Correct — read-only stays focusable, shows the value, and cannot open or clear.
<Select options={terms} value={term} readonly />
```

### A dependent field says what it is waiting for.

```jsx
// Incorrect — an empty, disabled teacher field, and a stale teacher kept when
// the school changes.
<Select options={teachersFor(school)} value={teacher} disabled={!school} />

// Correct — disabled with "Choose a school first" until there is a school, and
// cleared whenever the school changes.
<Select
  label="Teacher"
  options={teachersFor(school)}
  value={teacher}
  onChange={setTeacher}
  dependsOn={{ value: school, label: 'a school' }}
/>
```

### `name` submits through hidden inputs.

```jsx
// A plain form gets the ids: one hidden input per value, named `name`.
<form onSubmit={submit}>
  <Select name="grade" label="Grade" options={grades} required />
</form>
```

`required` sets `aria-required` and the label's asterisk. It does not block a
submit; drive `invalid` and `caption` from your own validation.

</div>

## Accessibility

- **The field is a combobox.** A searchable field is an `<input role="combobox">`;
  a plain one is a `div role="combobox"`. Both carry `aria-expanded`,
  `aria-controls` while open and `aria-activedescendant` on the highlighted row,
  so focus never leaves the field.
- **The list is a listbox.** Each row is a `role="option"` with
  `aria-selected`, in single mode and multi mode alike. Group headings
  (Recent, Suggested) label their `role="group"`.
- **Keys.** Down, Up or Enter opens the list (Space too, on a plain field).
  The arrow keys, Home and End move; Enter picks; Esc closes and leaves the
  value alone; Tab closes. Delete clears the value. In multi mode, Backspace in
  an empty field removes the last value.
- **Naming.** `label` names the field. Without one, pass `aria-label` or
  `aria-labelledby`; both reach the combobox. A field with neither falls back
  to its placeholder.
- **The clear × is not a tab stop.** It is named "Clear *label*", and Delete
  does the same from the keyboard. Without `clearable`, neither the × nor
  Delete empties the field.
- **`invalid`** sets `aria-invalid`, and `caption` becomes an error announced
  with `role="alert"` and described by the field.
- **Tags.** Each Tag's × is named "Remove *value*". Without focus, tags that
  do not fit collapse into "+n", named "+n more tags".

## Related

- For actions rather than a value, use `Dropdown`.
- For fewer than five options that all fit on screen, use `ChoiceGroup`.
- For hierarchical values, use `TreeSelect` or `Cascader`.
- For several values that people mostly type and add, use `TagInput`.
