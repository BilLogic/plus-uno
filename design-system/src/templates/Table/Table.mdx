## Usage

A table sits in a Section and spans it. Its first and last cells sit flush with the section edge. The Section header carries the views, then Search and the "Field: value" filters, and once a filter is applied, the record count. The bulk bar is never in the Section header: while rows are selected, a Dynamic table's head row becomes it, so the header rows stay put. Empty and no results replace the whole table so the Section header stays usable; loading and error states happen inside the table, under its header. Paging stays under the rows, inside the same Section.

### Type guidance

Choose by what people do with the rows. Read the questions in order and stop at the first yes.

<DocsTable>
<thead>
<tr><th>Question</th><th>Type</th></tr>
</thead>
<tbody>
<tr><td>Does any row nest under another? Nesting wins, even when the table is interactive.</td><td>Tree table</td></tr>
<tr><td>Can people act on the table: sort, filter, select, page, expand rows or use row actions?</td><td>Dynamic table</td></tr>
<tr><td>Otherwise, people only read it.</td><td>Static table</td></tr>
</tbody>

Search, filters and actions sit in the Section header: `<Table title="Students" views={...} search={...} filters={[...]} count="340 students" kind="dynamic" tableProps={...} />`. Pass the table as `children` instead of `kind` when you build it yourself.

## Parts

1. **Head row.** Names the columns. Its rule is the bold border.
2. **Rows.** The data you pass as `tbody`. Each draws a thin rule, and there is no zebra striping.
3. **Footer** (optional). The `footer` slot under the rows, aligned to the end: the range, the page-size Select and Pagination. The template draws no default footer: the slot is the contract. On a narrow screen its parts wrap onto lines of their own, and the pager stays at the end. It hides while the empty state shows. A Dynamic or Tree table draws its own footer and empty state, so the template's `footer`, `emptyState` and `empty` are for a Static table.
4. **Empty state.** The `emptyState` slot, which replaces the whole table (head row, caption and footer included) when `empty` is true; with `empty` and no `emptyState`, the table renders normally.

## Accessibility

- Name every column with a head cell. Head cells are labels for a column, so they use Heading/xxs rather than a heading level.
- Mark the sorted column with `aria-sort`, and give every icon-only control a name, such as "Actions for Ava Thompson".
- Mark a selected row with `aria-selected="true"`. That attribute belongs to a row of a table with `role="grid"`.
- Selection is never color alone. The row's checkbox is checked, and the head row says "2 selected".
- A region that scrolls takes keyboard focus, so people can scroll it without a pointer. That covers a region with `maxHeight` and one with a sticky column.
- When empty, the empty state replaces the table with no table roles left behind, and keeps the table's accessible name when one was provided.
- Name the table with its `label`, or `label` on the template for the empty state box, when no caption names it.
