A card is a self-contained box for related content: an image, a title, body copy, a list, links and an action. Reach for it when one item needs its own space beside its peers.

Use this Card component for one item among peers, such as a session, a tutor or a program, when the content fits its props: an image, a title, text, a list, links and one action. ## States

Figma draws one state, default. A card with an <code>onClick</code> gets hover and focus from the browser.

Figma rests the card raised, on the raised surface and shadow, with no outline. In code the Card component rests flat on a 1px outline and lifts to the raised shadow when it is clickable and hovered, or dragged. The card pattern rests raised, as Figma does.

## Rules

- **Turn parts off rather than leaving them empty.** Each part has its own switch. An empty title or link row still takes space.
- **Keep one action per card.** A card with several buttons reads as a form. Put the main action in the button slot and the rest as links.
- **Pick a size, not pixels.** Padding, gap, radius and border come from <code>paddingSize</code>, <code>gapSize</code>, <code>radiusSize</code> and <code>borderSize</code>. Choose a size and set no value.
- **Pad the sides at least as much as the top and bottom.**
- **Do not wrap a card in a link.** Every element inside it, including a button, becomes part of one link target. Give the card an explicit action instead.

</div>

## For developers

<code>header</code> and <code>footer</code> take text, not nodes. Put nodes in the body:

```jsx
<Card header="Live session" footer="Updated 4 minutes ago">
  <Status style="success">Live</Status>
</Card>
```

<code>radiusSize</code> accepts <code>sm</code> and <code>md</code> only.

A clickable card needs a control inside it:

```jsx
<Card
  title="Algebra · Tue 4pm"
  actionButton={{ text: 'Open session', onClick: () => open(session) }}
/>
```

## When to use

Use a card when one item’s content belongs together. It groups an item’s image, title, text and action so it can sit in a grid or list of like items, such as a session summary, a tutor’s stats block or a dashboard tile.

- For rows that share fields, use Table or List group.
- For a page’s one main message, use Jumbotron.
- For collapsible sections, use Accordion.
- For media beside text, use Media object.
- For a box whose content you compose yourself, such as a table or a form with its own header, use the card pattern. See Which Card to use when, below.

Colors follow the toolbar’s Color mode and Contrast switches.

</div>

<div className="sb-ds-doc-section">

## Accessibility

- **The title is a heading.** It is tagged one level below the section the card sits in: an h3 in a section, an h2 straight on a page. A screen-reader user can jump between cards by heading. Leave <code>title</code> unset to keep a card out of the heading outline, and put its text in the body.
- **A clickable card is not a keyboard-reachable card.** <code>onClick</code> adds no role, no tab stop and no key handling. Put the action in a real button or link inside the card.
- **The action button does not trigger the card.** Its handler stops the click, so it never also fires the card’s own <code>onClick</code>.
- **Give every link a destination.** A link with no <code>href</code> goes to <code>#</code>.
- **Describe meaningful images.** A URL <code>image</code> renders with no alternative text. Pass a node you control when the image carries meaning.
- **Text and icons keep their contrast** on the card in every Color mode and Contrast setting.
