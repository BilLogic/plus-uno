## For developers

- **onChange hands you the value, not an event.** It receives an id in single mode and an array of ids in multi mode, so read the argument directly.
- **A filter bar commits when the list closes.** In multi mode, pass <code>commitOnClose</code> so <code>onChange</code> fires once when the list closes, instead of refetching on every tick.
- **A sort or a required pick has no clear.** <code>clearable</code> defaults to true in multi mode and to the opposite of <code>required</code> in single mode. A sort always has a value, so pass <code>clearable=false</code>.
- **Read-only is not disabled.** Read-only stays focusable and shows the value but cannot open or clear. Disabled leaves the tab order and fades the field.
- **A dependent field says what it waits for.** Pass <code>dependsOn</code> with the other field's value and a name. Until that value is set, the field is disabled with "Choose" and the name, and it clears whenever the other field changes.
- **A name submits through hidden inputs**, one per value. <code>required</code> sets the asterisk and marks the field required for assistive technology, but does not block a submit. Drive <code>validation</code> and <code>caption</code> from your own validation.
- **Long lists load as you go.** <code>loadOptions</code> receives the typed text and an offset and limit, and returns a promise of the options and a total.

## When to use

Use Select when someone picks from a known list and the choice is part of a form's data. A Select hides its options until it is opened, so it suits a compact form, and a good default makes the alternatives less prominent.

- **Use it for 5 to 15 options when space is tight.** Under 5 options, show them all with [Choice group](?path=/docs/components-forms-and-inputs-choice-group--docs).
- **Pick several with multi mode**, never with a plain dropdown. Each row has a checkbox, and the picks stay visible as tags in the field, so people can check and remove them without reopening the list.
- **Make long lists searchable.** Past about 8 options, let people type in the field to filter. Above 50, search first and hide Select all. The list stops at 320, about nine rows, so keep it wide and short.
- **Let people add to the list** with creatable, which offers "Create" when nothing matches.
- **For actions rather than values**, use [Dropdown menu](?path=/docs/components-forms-and-inputs-dropdown-menu--docs). A screen reader announces a value list and a menu differently.
- **For several values people mostly type and add**, use [Tag input](?path=/docs/components-forms-and-inputs-tag-input--docs).
- **For a value along a hierarchy**, use [Cascader](?path=/docs/components-forms-and-inputs-cascader--docs) or [Tree select](?path=/docs/components-forms-and-inputs-tree-select--docs).

Select draws no label of its own. Give it a label above and, where it helps, a caption below. The placeholder says what to pick and never replaces the label.

## Accessibility

- **The field is a combobox.** A searchable field is a text input with the combobox role, and a plain one is a div with it. Both announce whether the list is open and which row is highlighted, so focus never leaves the field.
- **The list is a listbox.** Each row is an option that announces whether it is selected, in single and multi mode alike. Group headings, such as Recent and Suggested, label their group.
- **Keys.** Down, Up or Enter opens the list, and Space does too on a plain field. The arrow keys, Home and End move. Enter picks. Esc closes and leaves the value alone. Tab closes. Delete clears the value, and in multi mode Backspace in an empty field removes the last value.
- **Name it.** The label names the field. Without one, pass an <code>aria-label</code> or <code>aria-labelledby</code>. A field with neither falls back to its placeholder.
- **The clear × is not a tab stop.** It is named "Clear" followed by the label, and Delete does the same from the keyboard. Where clearing is off, neither empties the field.
- **Errors are announced.** An invalid field is marked invalid, and its caption becomes an error read out when it appears.
- **Tags are removable by name.** Each tag's × is named "Remove" followed by the value. Without focus, tags that do not fit collapse into "+n", named "+n more tags".
