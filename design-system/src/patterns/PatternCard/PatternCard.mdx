A card is a raised container for one object on a page, such as a student, a session or a metric. It holds an optional image, a header over a body, and an optional footer, and it rests on the raised pair with no border. The pad and the radius follow the card size, and the stack between parts follows use.

The examples on this page follow the toolbar's Color mode switch.

### When to use

Use a card when one object needs its own container on the page. A card holds a heading, some content and, when people can act on it, a footer.

Two pages document a card, and they do different jobs:

- **This pattern** is the shell for a card placed in a region of a page. You fill its slots with your own parts: a header, a body, an image and a footer.
- **The <a target="_top" href="./?path=/docs/components-layout-and-structure-card--docs">Card component</a>** is the ready-made content card, with a title, subtitle, body, list items, links and an action button already built. Use it when those parts already fit what you show.

When something else fits better:

- For a region of the page that holds several things under one heading, use a Section.
- For many objects of the same shape that people compare across columns, use a Table.
- For something that must be decided before the page can continue, use a Modal.

### Anatomy

<DocsCanvasShell attachSourceBelow description={<>Image, header, body and footer, with actions at the end of the header row.</>}>
    <DsCanvasQuiet of={PatternCardStories.Anatomy} />
</DocsCanvasShell>

1. **Image** is an optional slot above everything else. It runs edge to edge, outside the card pad, and the card radius clips its corners.
2. **Header** holds the title, an optional description and an optional actions slot. A custom header replaces all three, for tabs or a toolbar.
3. **Body** is a slot for text, a list or media.
4. **Footer** is an optional slot, left-aligned, for actions that commit a change.

The image sits above a padded frame. The header, the body and the footer sit inside that frame.

### Slots

Pick the slots the object needs. A card with a header over a body is the common case. Turn the header off only when the body carries its own title, such as a metric tile. A card that holds actions that commit a change gets a footer, and its actions start on the left, under the content. Only a modal footer aligns right.

### Building a card

The card owns its pad, its radius and the space between header, body and footer. Build one in four steps.

1. Pick the size by what the card holds. A single stat starts at sm.
2. Choose the header. The default type shows a title and a description, and a custom header hands the header to a slot. Turn the header off when the body carries its own title, as a metric tile does.
3. Fill the body slot. Space only inside the slot content, with the Card stack tokens, and never add spacing to the card itself.
4. Add the footer only for actions that commit. Card actions start at the left, under the content.

### Size

Content picks the size. Choose the smallest card that holds the content without clipping, then let the row decide how many fit. The size sets the pad, the radius and the minimum width. A stack follows use, whatever the size.

- **sm** holds one number or one line. **md** holds a short list or a few lines. **lg** holds a summary with several parts.
- Visible empty space inside the card means size down. A clipped or crowded body means size up.
- Height always hugs the content. There is no fixed height per size, and an optional maximum height caps it, so the card clips what passes the cap.
- Every size has a minimum width. A card narrower than its minimum belongs in a smaller size.

### Cards in a row

### Text

In Figma, the title always truncates to one line with an ellipsis. The <code>text</code> variant sets the description: <code>truncate</code> stops it at three lines with an ellipsis, and <code>wrap</code> has no line limit. Code has no <code>text</code> property and leaves wrapping to CSS. A body that passes the height cap is clipped.

</div>

### Elevation

A card rests on the raised pair, <code>--ds-surface-raised</code> under <code>--ds-shadow-raised</code>, and has no border. The shadow's 1 px ring is the edge. In dark, the raised surface is a lighter gray than the page. A clickable card lifts on hover to <code>--ds-surface-raised-hovered</code> under <code>--ds-shadow-overlay</code>, and settles back onto the raised shadow while pressed. A dragged card takes <code>--ds-surface-overlay</code> with <code>--ds-shadow-overlay</code>.

### Accessibility

- The title is a heading one level below the section the card sits in: an h3 in a section, an h2 straight on a page.
- A card that is clickable as a whole needs a role and a tab stop, and it must answer Enter and Space. When the card has one action, put a Button in the footer instead.
- Mark the card <code>aria-busy</code> while it loads. The skeleton bars are hidden from assistive technology.
- The hover lift is never the only cue that a card is clickable. Pair it with a visible action or a link in the card.
- Text sits on the raised surface in <code>--ds-text</code> and <code>--ds-text-subtle</code>, which meet contrast in every color mode.

### For developers

The card sets the current surface to its raised fill, so a sticky table cell inside it matches the card. The title tag comes from the heading level of the section around the card, so nest the card inside a Section rather than choosing a tag.
