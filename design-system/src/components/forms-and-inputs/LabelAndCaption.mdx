## When to use

These are the two lines that bracket a field: the label above it, and the caption
below. Every field component in this group draws them for you — this page is the
typography they all share, and the rules for what goes in them.

A **label** names the field. It is always present, it is short, and it does not
change. A **caption** is the line under the control that helps, warns or
explains, and it carries a state: `default`, `success`, `danger`, `warning`,
`disabled`.

</div>

<div className="sb-ds-doc-section">

## Best practices

### Say what the field is, not what to do with it.

```jsx
// Incorrect — an instruction where the name should be. It reads badly in a
// screen reader's list of form fields, where the labels appear without context.
<TextField label="Enter your email address" />

// Correct — the instruction is a caption if it is needed at all.
<TextField label="Email address" />
```

### A caption is help; a placeholder is not.

A hint written into `placeholder` disappears the moment the user types, which is
when they need it, and it is low contrast by design. Put help in a caption.

### Standing help is a caption; a state has its own message.

```jsx
// Standing help, with no state.
<TextField label="Phone" caption="Include the area code" />

// A message tied to success, warning or failure.
<TextField label="Phone" isInvalid errorMessage="Enter a 10-digit number." />
<TextField label="Phone" warningMessage="This number looks like a landline." />
<TextField label="Phone" successMessage="Number verified." />
```

### Write the error, not the fact that there is one.

A `danger` caption should say what to do: "Choose a date after today", not
"Invalid date". The state colors the line; the words do the work.

### The asterisk is decoration.

Across these components the required marker is a `span` beside the label with
`aria-label="required"`. None of them sets the `required` attribute or
`aria-required` on the control, so the asterisk is a convention for sighted
users and your own validation is what enforces it.

</div>

## Accessibility

- **The label must be associated, not merely adjacent.** The field components do
  this with `htmlFor` and a shared id. Where you build a field yourself, a label
  that sits above an input and points at nothing names nothing.
- **A label for a set of controls is not a `label`.** For radios or a scale, a
  `label` element would point at one control and clicking it would select that
  one. `RadioGroup` uses a `fieldset` named by its `legend`, and `Rating` a
  `span` with an id and `aria-labelledby` — those are the patterns to copy.
- **Validation messages are attached to their fields.** `TextField`, `TextArea`,
  `FileUpload` and `DateTimePicker` give the message an id and point the
  control at it, and mark an invalid field `aria-invalid`. Your own
  `aria-describedby` is composed with theirs, not replaced by it.
- **Standing help is described, not announced.** A `caption` is attached to the
  control with `aria-describedby`; an error is also announced when it appears.
- **Do not hide the label.** `isLabelHidden` is meant to move pixels, not to
  remove the name; on `TextField` it clips the label and keeps it, which is the
  behavior to expect.
- **State is never color alone.** The caption states carry an icon as well as a
  color, and the words should stand without either.
