## Usage

Use Common actions when a page needs a button and the choice is about the look, the place or the word. The appearance says how much the action matters; the place says what it belongs to; the word says what happens.

<DocsTable>
<thead>
<tr><th>Action</th><th>Appearance</th><th>Place</th><th>Word</th></tr>
</thead>
<tbody>
<tr><td>The main action of an area</td><td>Primary, one per area</td><td>Last in its group (on a page form: first, before Cancel)</td><td>Verb and object: "Add students"</td></tr>
<tr><td>Another action in the area</td><td>Default</td><td>Before the Primary</td><td>Verb and object: "Reschedule session"</td></tr>
<tr><td>Leave without doing anything</td><td>Subtle; Default in a full-bleed footer</td><td>Left of the Primary (on a page form: after it)</td><td>"Cancel"; a link is allowed</td></tr>
<tr><td>Close a layer</td><td>Icon button</td><td>Start of a focused title row; end of a Modal, Panel or Flag header</td><td>Named "Close"</td></tr>
<tr><td>Empty a menu's choices</td><td>Default, full bleed with Apply</td><td>The menu's footer, or the top of a filter side</td><td>"Reset" in a menu; "Reset filters" everywhere else</td></tr>
<tr><td>Empty one field</td><td>Icon button inside the field</td><td>End of the field</td><td>Named "Clear", "Clear search"</td></tr>

## Alternatives

- For a set of choices the person picks between, use `RadioGroup`, not a row of buttons.
- For a menu of actions behind one trigger, use `DropdownMenu` from a More icon button.
- For a main action with variations, use `SplitButton`.
- For moving to another page, use `LinkButton`; a button acts on this page.
- For narrowing rows, follow <a target="_top" href="./?path=/docs/patterns-filtering--docs">Filtering</a>: a filter is not an action.

## Best practices

### Give an area one Primary button.

<RuleTag kind="automatic" />

The Primary is the main call to action or a form's submit. A second main action is Default beside it; a second Primary makes neither read as the next step. The AI appearance follows the same rule, one per region, and only for an action that calls AI.

<DoDontPair
    doExample={<OnePrimary />}
    doCaption="One Primary, with the other action Default beside it."
    dontExample={<TwoPrimaries />}
    dontCaption="Two Primary buttons in one row: neither reads as the next step."
/>

### Left-align buttons under a page form and right-align them in a Modal, a focused task or steps.

<RuleTag kind="automatic" />

On a page the Primary comes first, read in the same direction as the fields. In a layer the Primary is furthest right, where the eye ends. Stacked buttons put the Primary on top. Never top-aligned.

<DoDontPair
    doExample={<PageButtonsLeft />}
    doCaption="Primary first, then Cancel, left-aligned under the fields."
    dontExample={<PageButtonsFarRight />}
    dontCaption="The buttons at the far end of the page, away from the fields, with the Primary last."
/>

### Go full bleed in a Modal footer and keep it 48 high.

<RuleTag kind="automatic" />

Buttons fill the footer, each a fraction of its width with a hairline between, losing their inner corners. One button takes the whole footer. The footer is the same 32 button plus 16 bottom pad a regular footer takes, so nothing inside changes its size. A Panel's editing footer and a card form's footer go full bleed the same way.

<DoDontPair
    doExample={<ModalFooterFullBleed />}
    doCaption="Two buttons filling the footer edge to edge."
    dontExample={<ModalFooterInset />}
    dontCaption="Small buttons inset at the end, with spare footer around them."
/>

### Keep the footer where it is.

<RuleTag kind="automatic" />

Header and footer stay pinned while the body scrolls. A blocked submit, a server message and a sending button change the body or a button, never the footer's size or place. A sending button swaps its label for a spinner in place and keeps its width; only that button disables, and Cancel stays live.

### Keep Close an icon button, separate from Cancel.

<RuleTag kind="automatic" />

Close ends a layer and lives in its header, or at the start of a focused title row. Cancel leaves a form without saving and lives with the form's buttons. Neither stands in for the other; a Modal has both.

### Make Cancel Subtle beside a Primary and Default in a full-bleed footer.

<RuleTag kind="automatic" />

Beside a Primary it is already clear the row is interactive, so Cancel steps back. In a full-bleed footer every cell is a button, so Cancel takes the Default fill to read as one. Cancel may be a link where a button would compete.

### Say Reset in a menu and Reset filters everywhere else.

<RuleTag kind="automatic" />

The words and where they sit: <a target="_top" href="./?path=/docs/patterns-filtering--docs#say-reset-in-a-menu-and-reset-filters-everywhere-else">Filtering › Say Reset in a menu and Reset filters everywhere else</a>.

### Confirm a copy with a Copied tooltip, not a Flag.

<RuleTag kind="automatic" />

The tooltip opens on the Copy button the moment the value is on the clipboard and leaves on its own. Flags stay for events that happened somewhere else.

### Edit one value inline and the whole record from More.

<RuleTag kind="review" />

A value read far more than changed takes `InlineEdit`: a pencil on hover and focus, saved on its own. The record's More menu includes Edit, which opens the form host the <a target="_top" href="./?path=/docs/patterns-forms--docs">Forms</a> pattern picks. Never put inline edits inside a form that has its own Save.

### Name a destructive action by its tier.

<RuleTag kind="review" />

Active: it can be undone, Cancel and a Primary. Active with Danger: a delete, the action in Danger. Danger with the name typed: a delete that cannot be undone, the field caption asks for the name and the Danger button enables once it matches, with no tooltip. Remove, which takes something out of a group it can return to, is Default, not Danger. The Modal that raises the confirm: <a target="_top" href="./?path=/docs/templates-modal-modal--docs">Modal</a>.

### Turn the head row into the bulk bar when rows are selected.

<RuleTag kind="automatic" />

The bar and its words: <a target="_top" href="./?path=/docs/templates-section-section--docs#turn-the-head-row-into-the-bulk-bar-when-rows-are-selected">Section › Turn the head row into the bulk bar when rows are selected</a>.

### Keep a card's main action Subtle in its footer.

<RuleTag kind="review" />

A clickable card has no inner buttons; the whole card is the action. When a card does carry a button, it is Subtle in the footer, and inside tiles it spans the full width when in doubt.

## Accessibility

- A button performs an action and a link navigates; the element gives the role. An icon-only button is an `IconButton` with a `label`: "Close", "Copy", "Edit", "More".
- A sending button sets `aria-busy` and keeps its label in the tree; only that button disables, and Cancel stays live.
- The Danger button in a type-the-name confirm is disabled until the name matches; the field caption carries the reason, never a tooltip.
- The bulk bar's count is a polite live region; the select-all checkbox reports its mixed state. Focus stays on the checkbox that was ticked.
- The focus ring takes `--ds-border-focused` on every appearance.
