## Usage

Use `ChangeTag` beside a number to say how it moved since the last period: in
a card header, a table cell or a chart tooltip. For the number itself, use
plain text; for a count on a tab or button, use `CountTag`; for the shape of
a trend, use `Sparkline`.

### Good direction

`goodDirection` says which way is good for this metric. The tone follows from
it, never from the arrow alone.

<DocsTable>
<thead>
<tr><th>Good direction</th><th>When to use</th></tr>
</thead>
<tbody>
<tr><td>Up</td><td>More is better: sessions held, reflections completed. Up is success, down is danger.</td></tr>
<tr><td>Down</td><td>Less is better: no-shows, absences, missed reflections. Down is success, up is danger.</td></tr>
<tr><td>None</td><td>The change has no value judgment: hours tutored, students assigned. Neutral either way.</td></tr>
</tbody>
</DocsTable>

</div>

## Parts

1. **Arrow.** Up, down or flat, from the sign of `value`. `iconBefore` replaces it. It is decoration; the value and the spoken text say the direction.
2. **Value.** Signed: "+3", "−12%", "+4.5 pts". An em dash when there is nothing to compare.
3. **Chip.** A filled ground in the tone, with a 1 inside border, so the height stays exact.
4. **Comparison.** Optional, such as "vs last week", in subtle text after the chip.

## Best practices

Pass the signed change as a number and let the tag format it. Set `goodDirection` once per metric, not per value.

### Set the tone from the metric, not the arrow.

When less is better, up is bad: say so with `goodDirection="down"`.

<DoDontPair
    doExample={<div style={{ display: 'flex', flexWrap: 'wrap', alignItems: 'center', gap: 'var(--inline-md)' }}><span>No-shows</span><ChangeTag value={2} goodDirection="down" comparison="vs last week" /></div>}
    doCaption="More no-shows reads as danger."
    dontExample={<div style={{ display: 'flex', flexWrap: 'wrap', alignItems: 'center', gap: 'var(--inline-md)' }}><span>No-shows</span><ChangeTag value={2} goodDirection="up" comparison="vs last week" /></div>}
    dontCaption="More no-shows reads as success."
/>

### Keep a change with no value judgment neutral.

Not every change is good or bad. Leave `goodDirection` at `none` for those.

<DoDontPair
    doExample={<div style={{ display: 'flex', flexWrap: 'wrap', alignItems: 'center', gap: 'var(--inline-md)' }}><span>Hours tutored</span><ChangeTag value={6} comparison="vs last week" /></div>}
    doCaption="Neutral: more hours is neither good nor bad."
    dontExample={<div style={{ display: 'flex', flexWrap: 'wrap', alignItems: 'center', gap: 'var(--inline-md)' }}><span>Hours tutored</span><ChangeTag value={6} goodDirection="up" comparison="vs last week" /></div>}
    dontCaption="Success implies a judgment nobody made."
/>

### Never make a change tag a button.

It renders a `span` with no role and no click handler: `onClick`, `role` and
`tabIndex` are dropped with a console warning in development.

</div>

## Content guidelines

<DocsTable>
<thead>
<tr><th>Do</th><th>Don't</th></tr>
</thead>

<tr><td>Use <code>null</code> when there is nothing to compare.</td><td>Show 0 for a missing comparison: 0 means no change.</td></tr>
</tbody>

## Accessibility

- **The change is spoken in words.** A screen reader hears "Up 3 vs last
  week" or "Down 12% vs last month"; the visible chip and comparison are
  `aria-hidden`, so nothing is read twice.
- **Color never carries it alone.** The arrow and the sign say the direction;
  the tone only reinforces it.
- **Not a control.** No role, no tab stop, no click handler.
- **Reduced motion.** The fade and the color change read the motion duration
  tokens, which drop to 0ms when reduced motion is on.
