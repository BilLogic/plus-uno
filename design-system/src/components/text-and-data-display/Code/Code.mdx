## Usage

Use `Code` for a name, command, value or snippet that sits inside a sentence:
a function, a file path, a flag, a token.

The typeface and size come from the `--code-default` text style (`0.875em`, scaling
with the surrounding text).

</div>

<div className="sb-ds-doc-section">

## Alternatives

- For several lines of code or a snippet with line numbers, use `CodeBlock`.

</div>

<div className="sb-ds-doc-section">

## Parts

1. **Element.** A `code` element in the code typeface at `0.875` of the text around it.
2. **Fill.** The neutral ground (`--ds-background-neutral`), with `--radius-md`.
3. **Text.** The code ink (`--ds-text-code-default`); long values wrap inside the span.

## Best practices

### Keep inline code to a short phrase.

A long inline span wraps awkwardly and loses its structure. A block keeps lines and scroll.

<DoDontPair
    doExample={<CodeBlock text={'npm install\nnpm run dev'} label="Start the app" />}
    doCaption="Several lines go in a code block."
    dontExample={<p className="body-default">Run <Code>npm install and then npm run dev to start the app</Code></p>}
    dontCaption="A whole instruction in inline code."
/>

### Do not use Code for emphasis.

`Code` tells readers "this is literal text to type". Use bold or a button label for emphasis.

<DoDontPair
    doExample={<p className="body-default">Press <strong>Continue</strong> to proceed.</p>}
    doCaption="Bold for emphasis, in the reader's words."
    dontExample={<p className="body-default">Press <Code>important</Code> to continue.</p>}
    dontCaption="Inline code on a word that is not code."
/>

### Write Code as the reader would type it.

<DoDontPair
    doExample={<p className="body-default">Call <Code>getSession()</Code> first.</p>}
    doCaption="The exact name, with its brackets."
    dontExample={<p className="body-default">Call <Code>getSession().</Code> first.</p>}
    dontCaption="A trailing period inside the span, which the reader may type."
/>

</div>

## Accessibility

- **Announced as text.** `Code` renders a `code` element; screen readers read it as
  ordinary text, so write the code so it makes sense spoken.
- **Contrast.** The ink on the fill passes in every color mode, because both
  come from the neutral background and code ink tokens.
- **It wraps.** Long values break inside the element, so reflow at narrow widths and
  200% zoom does not scroll the page.
