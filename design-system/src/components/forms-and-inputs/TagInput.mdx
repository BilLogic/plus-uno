## For developers

- **The caller owns the options and stores what is created.** <code>options</code> is required. When a person creates a value, <code>onCreate</code> reports it once with the color it was given. Store both on a new option so the color stays the same everywhere the tag appears.
- **Saving to a server.** Return a promise from <code>onCreate</code> that resolves to the stored id. Until it does, the tag is saving and its value is a temporary id starting "new-". If the promise rejects, the tag is removed, the text goes back in the entry, and the failure is announced.
- **A controlled field needs a handler.** Pass <code>tags</code> with an <code>onChange</code> that receives the new list. With no handler, no tag shows a ×.
- **Tidying is opt-in.** Pass <code>onRename</code>, <code>onDelete</code>, <code>onColorChange</code> and <code>onReorder</code> for each change the screen can store. TagInput only reports the change, and each handler updates your list. A field with none of them shows no "…" and no handle.
- **Delete and rename reach picked tags.** Deleting an option also removes a picked tag made from it, through <code>onChange</code> and <code>onRemove</code>. Rename and a color change update that tag too.
- **Reorder works on the whole list**, so the handles hide while text is typed. <code>onReorder</code> receives two places in <code>options</code>.
- **A tag's color is a Tag color.** The status names the chips once took, such as success and danger, are deprecated aliases and warn in development.
- **Four events report changes:** <code>onAdd</code>, <code>onCreate</code>, <code>onRemove</code> and <code>onChange</code>.

## When to use

Use Tag input when people pick several values and may add new ones, such as the topics a session covered or the languages a tutor teaches. The field holds the picks as tags, with a text entry after them. Focusing it opens the list of options.

- **Show what exists before Create.** List the matches as people type and keep Create last, so they reuse a tag before making a near-duplicate. At a pick limit, hide Create and say why in the caption.
- **Let people tidy options where they pick them.** Each row's "…" opens a menu to rename the option, delete it or change its color, and its grip drags it to a new place. Deleting a picked option also removes its tag. Keep the menu to these three. Anything heavier belongs on a settings page.
- **Keep tags short.** A tag names a category in a word or two. Long tags truncate with a tooltip and push the rest into "+n".
- **Label it like any field.** Give it a visible label. The placeholder invites both actions, "Select or create a tag", and never replaces the label.
- **For one value from a list**, use [Select](?path=/docs/components-forms-and-inputs-select--docs).
- **For several values from a fixed list**, use Select in multi mode.
- **For fewer than 5 options**, use [Choice group](?path=/docs/components-forms-and-inputs-choice-group--docs) with checkboxes.
- **To show tags without editing them**, use [Tag group](?path=/docs/components-labels-tag-group--docs).

## Accessibility

- **The label names the entry.** The text entry is a combobox that points at the list and at the highlighted row, so focus stays in the field while the arrow keys move through the list.
- **The tags are a named list.** The tag group is a list named "Selected:" with the label, and each × is named "Remove" followed by the tag.
- **Changes are announced.** Adding or removing a tag says so, such as "Music added".
- **Invalid is announced.** The message under the field is read when it appears, and the entry is marked invalid and described by it.
- **Read-only and disabled leave nothing to press.** Neither draws a × or opens the list.
- **A row's handle and "…" are real buttons.** They are named "Reorder" and "Options for" followed by the option, and the handle is described by its keys.
- **Reordering is announced.** Picking up, each move, the drop and a cancel each say the row and its position, such as "Design judgment dropped, position 3 of 4".
- **The menu takes focus and gives it back.** Opening it moves focus to the name field. Closing it returns focus to the "…".
