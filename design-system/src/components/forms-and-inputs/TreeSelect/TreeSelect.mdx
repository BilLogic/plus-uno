## Usage

Use `TreeSelect` when options nest in a hierarchy and someone needs to expand branches in place or pick nodes across multiple branches, such as curriculum units and lessons.

</div>

<div className="sb-ds-doc-section">

## Alternatives

- For a single hierarchical path chosen one column per level in sequence, use `Cascader`.
- For a flat list of options with no hierarchy, use `Select`.

</div>

<div className="sb-ds-doc-section">

## Parts

1. **Field.** The box that shows the picks, or the placeholder.
2. **Label.** Names the field. A required marker follows it.
3. **Tree.** Rows that expand to their children. A parent checks its descendants.
4. **Caption.** Helper text, or the error that replaces it.

## Best practices

### Use multi select for several branches.

With `isMulti` each chosen node is named in the field; a single value holds one.

<DoDontPair
    doExample={<TreeSelect label="Topics" isMulti options={topicOptions} value={['triangles', 'linear-equations']} onChange={() => {}} />}
    doCaption="Each chosen node is named in the field."
    dontExample={<TreeSelect label="Topics" options={topicOptions} value="triangles" onChange={() => {}} />}
    dontCaption="A single value cannot hold several nodes."
/>

### Open the tree to show nesting.

The open tree shows how nodes nest before the choice is made. Arrow keys move through visible rows only: a collapsed branch's children are in the data but not on screen, so expand a branch first to reach what is inside it.

### Show the chosen node in the field.

A filled field shows the choice; an empty one cannot confirm it.

<DoDontPair
    doExample={<TreeSelect label="Topic" options={topicOptions} value="triangles" onChange={() => {}} />}
    doCaption="The field names the chosen node."
    dontExample={<TreeSelect label="Topic" options={topicOptions} value="" onChange={() => {}} />}
    dontCaption="An empty field after a choice cannot confirm it."
/>

### Mark a failed pick on the field.

With `isInvalid`, the field draws the danger border and `errorMessage` replaces the caption.

<DoDontPair
    doExample={<TreeSelect label="Topic" options={topicOptions} value="" onChange={() => {}} isInvalid errorMessage="Pick a topic." />}
    doCaption="A failed pick draws the danger border, so the error is seen at the field."
    dontExample={<TreeSelect label="Topic" options={topicOptions} value="" onChange={() => {}} caption="Pick a topic." />}
    dontCaption="A failed pick still draws the normal border, so nothing marks the error."
/>

### Checking a parent is shorthand for checking every descendant.

With `isMulti`, picking a parent node cascades the check to its whole
subtree, and a branch with only some descendants checked shows an
indeterminate mark rather than fully checked or unchecked. `value` always
reflects the actual set of checked nodes, parents included once their
subtree is complete.

```jsx
<TreeSelect
    label="Topics"
    isMulti
    value={topics}
    onChange={setTopics}
    options={[
        { value: 'roosevelt-k8', label: 'Roosevelt K-8', children: [
            { value: 'roosevelt-mon', label: 'Monday 3:30 PM' },
            { value: 'roosevelt-wed', label: 'Wednesday 3:30 PM' },
        ] },
    ]}
/>
```

## Accessibility

- **Keyboard matches what's visible.** Up/Down move between the currently
  expanded rows only, never into a collapsed branch's hidden children.
- **Checked state is explicit, including partial.** A parent with some but
  not all descendants checked is marked indeterminate, not silently rounded
  up or down to a checked or unchecked state.
- **Without a visible label, name the field explicitly** with `aria-label`
  or `aria-labelledby` — `label` is optional, but an accessible name isn't.
