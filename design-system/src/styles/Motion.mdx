export const CURVES = [
    ['out-bold', [0, 0.4, 0, 1]],
    ['inout-bold', [0.4, 0, 0, 1]],
    ['in-practical', [0.6, 0, 0.8, 0.6]],
    ['out-practical', [0.4, 1, 0.6, 1]],
    ['out-expressive', [0.22, 1, 0.36, 1]],
    ['linear', [0, 0, 1, 1]],
];

export const Curve = ({ name, points }) => {
    const [x1, y1, x2, y2] = points;
    const s = 100;
    const path = `M0 ${s} C${x1 * s} ${s - y1 * s}, ${x2 * s} ${s - y2 * s}, ${s} 0`;
    return (
        <figure style={{ margin: 0, display: 'flex', flexDirection: 'column', gap: 'var(--element-stack-sm)' }}>
            <svg viewBox="-8 -8 116 116" role="img" aria-label={`${name}: cubic-bezier(${points.join(', ')})`} style={{ width: '100%', maxWidth: 'var(--image-xl)', minWidth: 'var(--image-lg)', background: 'var(--ds-surface)', borderRadius: 'var(--element-radius-lg)' }}>
                <line x1="0" y1={s} x2={s} y2="0" stroke="var(--ds-border-bold)" strokeDasharray="4 4" />
                <path d={path} fill="none" stroke="var(--ds-chart-brand)" strokeWidth="3" />
            </svg>
            <figcaption style={{ font: 'var(--body-small)', color: 'var(--ds-text-subtle)' }}>
                {name}<br /><code style={{ font: 'var(--code)' }}>{points.join(', ')}</code>
            </figcaption>
        </figure>
    );
};

<FoundationSection title="Overview">

Motion in PLUS builds on the Atlassian system: the same three attributes (duration, easing and property), the same curves and the same four principles, adjusted for a calm tutoring product. Interactions are near-instant, entrances orient people and exits get out of the way. Playful motion is kept for moments that are not part of a task.

Motion is defined by numeric tokens: `Motion/duration-150` for a duration and `Motion/easing-out-practical` for a curve. Bundles that package a duration, an easing and a property exist only for Modal, Blanket, Drawer, Popup, Flag, Tooltip, Tab and Button. Bootstrap's own motion variables are overridden by these tokens, so react-bootstrap keeps its focus and transition lifecycle.

</FoundationSection>

<FoundationSection title="Principles">

Four principles from Atlassian guide every motion, worded for PLUS.

<FoundationSubsection title="Human">
Movement should feel like a supportive teammate nudging, not a machine snapping. Warmth comes from soft landings and restraint, not from extra movement.
</FoundationSubsection>

<FoundationSubsection title="Clarity">
Motion tells a tutor what changed, where it came from and what to do next. Before adding it, ask: if I remove this, does the person lose information or context? If not, remove it.
</FoundationSubsection>

<FoundationSubsection title="Accessible">
Every motion has a reduced-motion form, and nothing is communicated by motion alone.
</FoundationSubsection>

<FoundationSubsection title="Performant">
A tutor in a live session is looking at something else. Frequent things (hover, press, a row, a tab) are near-instant; rare things (finishing a module, a first-run screen) may take a moment. Motion never adds friction.
</FoundationSubsection>

</FoundationSection>

<FoundationSection title="Duration">

Every motion is defined by duration, easing and property. Interactions run 50 to 150 ms; transitions run 150 to 400 ms, and larger elements take longer. Frequent things stay under 150 ms. PLUS changes from Atlassian are marked in the last column.

- Exits are shorter than entrances: a modal, drawer or flag leaves in 150 ms.
- The first-load reveal of the topbar and sidebar plays once per session in 400 ms or less, and never on in-app navigation.
- A tooltip hides 100 ms after the pointer leaves.
- Chart and card intros are capped at 600 ms. Only a character moment may run to 1000 ms.

<FoundationSection title="Easing">

Entering elements ease out, exiting elements ease in, and elements that scale or reposition in place ease in and out. Use the practical curves for everyday interactions and the bold curves for larger movement. Curve names are written `Motion/easing-name`.

<FoundationSection title="Patterns">

Entrances and exits are not symmetrical: entrances orient people, exits confirm a dismissal and clear the way. Open from where an element belongs, use one or two properties per transition, and prefer transform and opacity to width, height and top.

<RefTable
    head={['Pattern', 'Enter', 'Exit', 'Notes']}
    rows={[

        ['Drawer', 'Slide from its edge, 250 ms, out-bold.', 'Slide out, 150 ms, in-practical.', 'A narrow-width sidebar, if one is specified, takes the Drawer tokens.'],
        ['Flag', 'Fade and an 8 px slide toward its anchor edge, 200 ms, out-bold. When a neighbor leaves, the stack moves in 200 ms, inout-bold.', 'Fade, 150 ms, in-practical.', 'Flag travel is 8 px, not half of the flag’s width: a 400-wide flag would sweep 200 px. Announce errors at once.'],

    ]}
/>

- Accordion and Progress animate size (grid rows, width) against the transform-and-opacity rule. They are documented exceptions. A Progress fill carries a label, so scaling it would distort the text.
- Reduce the number of properties in one transition before you shorten its duration.

<FoundationSection title="Do and don't">

<FoundationSubsection title="Keep frequent motion near-instant">

A tutor presses buttons dozens of times in a session, so the response settles color and nothing else.

<DoDont>
<Do caption="Color only, 100 ms, out-practical. The next action is a second away."><Label>Button hover and press · 100 ms</Label></Do>

</DoDont>

</FoundationSubsection>

<FoundationSubsection title="Make exits faster than entrances">

Entrances orient people; exits get out of the way.

<FoundationSection title="Accessibility">

When a person asks for reduced motion, product motion is off and instant, as in Atlassian's guidance. Set it once at the token layer so every component complies without an extra rule.

- Set every duration and stagger token to 0 ms under `prefers-reduced-motion`, and jump to the final state, so nothing is left half-transparent.
- Never flash, oscillate rapidly or sweep large areas of the screen, whether or not reduced motion is on.
- Replace a rotating Spinner with a static icon and the word Loading, so the status still reads. A Skeleton becomes a flat fill with no sweep.
- Charts draw their final state with no intro. Characters show the rest pose.
- Nothing is communicated by motion alone.
- Verify every flow is fully usable with all motion turned off.

</FoundationSection>
