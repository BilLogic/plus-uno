## The three cases

Read-only is one of three ways to show a value without a way to change it. Pick by whether anyone can change it, and who.

## Usage

Use Read-only for a value someone could change but this person cannot right now: a session time the supervisor set, a field locked while a process runs, a record another person is editing. The common PLUS case is permission. Content that is never editable is plain text, not a read-only field.

<DocsTable>
<thead>
<tr><th>Who can change it</th><th>Show it as</th><th>Tab order</th><th>Looks</th></tr>
</thead>
<tbody>
<tr><td>Someone else, or this person later</td><td>Read-only field</td><td>In</td><td>Neutral fill, full contrast, no chevron or calendar, no hover</td></tr>

## Alternatives

- For a value nobody changes here, show plain text in a details Section.
- For a field that waits on another on this screen, follow <a target="_top" href="./?path=/docs/patterns-states-disabled--docs">Disabled</a>.
- For a value this person can change but rarely, use `InlineEdit`.

## Best practices

### Keep a read-only field in the tab order at full contrast.

<RuleTag kind="automatic" />

It can be reached, read, selected and copied. `isReadOnly` sets `aria-readonly` on the controls that carry the role; the text keeps its color and the fill goes neutral. There is no hover change and the cursor is an arrow.

### Drop the interactive cues.

<RuleTag kind="automatic" />

`Select` hides its chevron and `DatePicker` its calendar button. `Checkbox`, `RadioGroup` and `Toggle` keep their state and ignore clicks.

### Say why in the caption.

<RuleTag kind="review" />

"Set by your supervisor." "Locked while the import runs." One caption on a group is enough when every field in it is read-only for the same reason.

<DoDontPair
    doExample={<ReadableWithReason />}
    doCaption='Read-only at full contrast, with "Set by your supervisor" in the caption.'
    dontExample={<FadedNoReason />}
    dontCaption="A faded value with no reason: out of the tab order and hard to read."
/>

### Show a read-only value whole.

<RuleTag kind="review" />

A person who cannot change a value must at least read all of it. A `Select` wraps to show its value; for a `TextArea`, set `rows` so all of it shows. <PlannedTag /> A TextArea that grows to fit its value is Planned.

### Show never-editable content as plain text.

<RuleTag kind="review" />

A field promises an input. A value nobody changes here is a label and a value in a details Section.

<DoDontPair
    doExample={<PlainValue />}
    doCaption="A value nobody changes here is plain text."
    dontExample={<FieldForFixedValue />}
    dontCaption="A field for a value that was never editable: it promises an input."
/>

### Keep read-only and disabled apart.

<RuleTag kind="automatic" />

Disabled is for a prerequisite fixable on this screen and leaves the tab order. Read-only is for content people must read.

</div>

## Accessibility

- `aria-readonly` on every read-only control that carries the role; it is reachable and read by screen readers with its label and caption.
- Text contrast is unchanged from an editable field.
- The value can be selected and copied with the keyboard.
- The caption is tied to the field, so the reason is read with it.
