<Title />
A design token is a named value: a color, a gap, a radius, a size, a text
style. Each one is a Figma variable and a CSS custom property with the same
name, so a designer and a developer pick the same thing. Designs and
components use tokens, never typed values. When a value changes, it changes in
one place, and every component that uses the token follows.

## Two layers

- **Primitives** hold the raw values: the color ramps, the spacing scale.
  They are hidden in Figma, and designs and components never use them.
- **Semantic tokens** point at a primitive and name a job: `--ds-text-subtle`,
  `--card-pad-md`, `--heading-medium`. These are the tokens you use.

A semantic token can have a different value in each mode. Color tokens change
with the color mode, and layout tokens change with the breakpoint, while the
name stays the same.
</div>

## Names

A name reads from the general to the specific. In Figma the parts are joined
with slashes; in CSS, with dashes.

## Using tokens

- **Bind the semantic token, never a primitive or a number.** A typed number
  breaks the moment a token changes.
- **Pick by meaning, not by a matching value.** Two tokens that share a value
  today can part tomorrow.
- **If no token fits, ask for one.** A one-off value becomes a proposed token,
  not a literal.
</div>

<div className="sb-ds-doc-section">
## For developers

The color tokens are generated from the color plan by
`npm run generate:color-tokens`, which writes the CSS and the Figma spec
together. The spacing, size, layout and type tokens are generated from the
Figma variables. Every generated file names its generator in its first line:
change the source and regenerate, never edit the output. `npm run
check:harness` names any generated file that has gone stale.

The older names (`--color-*`, `--size-*`, `--elevation-light-*` and the legacy
type registers) still resolve while components move. The color migration
guide maps each one to its `--ds-*` replacement.
