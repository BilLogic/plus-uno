## The four answers

Pick by what the text is. Wrap when it must be read whole; truncate when the room is fixed and the full text can be reached; fold a list; page a table.

## Usage

Use Overflow when a value may exceed its space. Choose by element so it behaves consistently across pages, with the full text always reachable.

### Fields and inputs

A field answers a value longer than its room with one of four rules, chosen by what the value is. The answer is the same in every component that shares the rule, and each component's Overflow example shows it.

<DocsTable>
<thead>
<tr><th>Rule</th><th>Use it when</th><th>What happens</th><th>Components</th></tr>
</thead>
<tbody>
<tr><td>Grow</td><td>The value is written or read whole: notes, labels, descriptions, a set of tags being edited.</td><td>The box grows by whole lines or rows, with no blank line under the last. Past its maximum height it scrolls inside itself.</td><td>Text area, Rich text editor, Tag input with focus, multiple Select (wrap), and the labels of Fieldset, Checkbox, Radio, Toggle, Choice grid, Setting row, Comment and Filter menu.</td></tr>
<tr><td>Truncate</td><td>The box has one fixed line and the value is a name, a date or a choice.</td><td>One line ending in an ellipsis. The slots keep their places and the box keeps its height.</td><td>Text field, Search field, Select, Popup select, Tree select, Cascader, Date, Time and Date time pickers, Filter button (one value), Dropdown menu items, File item (mid-name), and Button family labels without a Tooltip.</td></tr>
<tr><td>Collapse</td><td>The value is a list the field shows as tags.</td><td>One line with a +n count of what is hidden; focus or a click on +n shows every item.</td><td>Tag input at rest, multiple Select (truncate), Tag group.</td></tr>
<tr><td>Scroll</td><td>The value is a list that must stay on one line and every item must stay reachable.</td><td>One row that scrolls sideways inside the field.</td><td>Multiple Select (no wrap).</td></tr>
</tbody>

## Alternatives

- For a long paragraph, let it wrap; a paragraph is read, not scanned.
- For a trail too long to show, follow Navigation; the Breadcrumb's fold is described there.
- For more views than fit a row of pills, fold the extra pills into "More"; Navigation describes the views.
- For more controls than fit a bar, the extras go into the More icon button, five controls at most.
- For narrowing a long list of rows instead of folding it, follow <a target="_top" href="./?path=/docs/patterns-filtering--docs">Filtering</a>.

## Best practices

### Wrap titles, headers, labels, errors and notifications.

<RuleTag kind="automatic" />

They must be read whole, so they take more lines. Nothing that tells a person what something is, or what went wrong, is ever clipped.

<DoDontPair
    doExample={<WrappedSectionTitleCase />}
    doCode={CODE.WrappedSectionTitle}
    doCaption="A long Section title takes a second line."
    dontExample={<ClippedSectionTitleCase />}
    dontCode={CODE.ClippedSectionTitle}
    dontCaption="A clipped Section title: the one thing that names the content is the one thing cut."
/>

### Truncate cells, tags and names at the end, on one line.

<RuleTag kind="automatic" />

An ellipsis stands for three or more characters. A cell stays one line. Mid-line truncation is only for file names and ids, where the end tells them apart; a file name does it today in the File item, and an id is Planned <PlannedTag />. Truncating from the front is not used.

### Open the full text in a Tooltip only when it is clipped.

<RuleTag kind="automatic" />

The Tooltip opens on hover and on focus, and the clipped element becomes a tab stop only while it is clipped. Never the browser's `title` attribute. An unclipped value has no Tooltip.

<DoDontPair
    doExample={<ClippedCellOpensTextCase />}
    doCode={CODE.ClippedCellOpensText}
    doCaption="A clipped cell opens its full text in a Tooltip."
    dontExample={<ClippedCellNoTextCase />}
    dontCode={CODE.ClippedCellNoText}
    dontCaption="A clipped cell with nothing to open: the rest of the text cannot be read."
/>

### Grow a field by whole rows and stop it at a maximum height.

<RuleTag kind="review" />

A field that grows adds a whole line or a whole tag row and never a blank one: the room under the last row is the room above the first. Past its maximum height, three tag rows for a Tag input, the field scrolls inside itself and the page never moves. No field grows sideways, and none makes its well scroll sideways.

### Reach the full value of a clipped field through focus or a Tooltip.

<RuleTag kind="review" />

A text field the person types in, such as a Text field, a Search field, a Select you type in, or a Date, Time or Date time picker, has no Tooltip, because focus reaches the value: the caret walks to the end and the field scrolls with it. A control that is picked from, such as a Select with `isSearchable` off, a Popup select, a Tree select, a Cascader, a Filter button, a menu item or a file row, opens the full text in a Tooltip on hover and focus, only while it is clipped. Slot elements, the chevron and the clear button keep their places and stay visible at the end.

The one exception is a Button, Link button, Split button or Button group: its label ends in an ellipsis with no Tooltip, so shorten the label. The full label stays in the accessible name.

### Make a bare ellipsis open a menu.

<RuleTag kind="review" />

A "…" that stands for hidden items, such as the breadcrumb middle, is a button that opens them. A "…" at the end of a value is not a control.

### Fold a list behind Show n more and page a table.

<RuleTag kind="review" />

"Show n more" carries the count and "Show less" closes; both are Planned <PlannedTag />. A Tag group folds into +n today. A table pages in its footer instead of growing. No gradients, fades or inner scroll.

<DoDontPair
    doExample={<ShowMoreWithCountCase />}
    doCode={CODE.ShowMoreWithCount}
    doCaption="A button under the list that names how many more it holds, and the list grows in place."
    dontExample={<FadedListCase />}
    dontCode={CODE.FadedList}
    dontCaption="A fade over the list, hiding how much is there."
/>

## Accessibility

- The full text is always in the DOM, so a screen reader hears all of it whether or not it is clipped.
- A clipped element is a tab stop so a keyboard user can reach the Tooltip; an unclipped one is not.
- The +n button of a Tag group names how many tags it holds, "+3 more tags", and opens a menu the arrow keys move through.
- The breadcrumb's "…" button is named "Show hidden levels" <PlannedTag />.
- "Show n more" announces the new count when the list expands <PlannedTag />.
