## Usage

Use `Checkbox` when a person needs to select one or more options from a list of related items, or when a setting needs an explicit confirmation before it applies. Checkboxes let a person choose many options, or none, from a short list they can see whole, and a parent checkbox shows the mixed (`isIndeterminate`) state while some of its children are selected.

</div>

<div className="sb-ds-doc-section">

## Alternatives

- For a question offering a list of checkboxes under a shared legend and error, use `CheckboxGroup`.
- For a setting that takes effect immediately without submitting a form, use `Toggle`.
- For mutually exclusive answers where only one may be chosen, use `RadioGroup` or `Radio`.
- For a long list of multi-select options, use `Select` with `isMulti`.
- For a rows-by-columns matrix of checkboxes, use `ChoiceGrid`.

</div>

<div className="sb-ds-doc-section">

## Parts

1. **Box.** An 18 square with a 2px edge. Selected, it fills with the selected bold fill and draws a check; mixed, it draws a dash.
2. **Label.** 14/20 text beside the box in a 24 row. It names the checkbox. A required marker follows it.
3. **Description.** Optional 12/16 text under the label that describes the choice. It does not name it.

## Best practices

### Reserve choice tiles for one big question with two to four pictured options.

Use `appearance="tile"` when a step asks one focal question with two to four options and every option carries an `illustration`. Keep ordinary form lists and sets of five or more options in `plain` or `card`.

<DoDontPair
    doExample={<div style={{ display: 'flex', flexWrap: 'wrap', gap: 'var(--inline-lg)' }}><Checkbox label="Mastering content" description="Concept fluency." illustration={<Illustration character="mastering-content" size={48} />} appearance="tile" defaultChecked /><Checkbox label="Student advocacy" description="Self-advocacy skills." illustration={<Illustration character="advocacy" size={48} />} appearance="tile" /></div>}
    doCaption="Two pictured tiles with top-end checkboxes for one focal question."
    dontExample={<div style={{ display: 'flex', flexWrap: 'wrap', gap: 'var(--inline-lg)' }}><Checkbox label="Monday" appearance="tile" /><Checkbox label="Tuesday" appearance="tile" /><Checkbox label="Wednesday" appearance="tile" /></div>}
    dontCaption="Plain text options without illustrations drawn as tiles."
/>

### Say what is being agreed to.

The label states the commitment in a full phrase. "Yes" or "OK" hides what the person is accepting.

<DoDontPair
    doExample={<Checkbox label="I agree to the tutor code of conduct" />}
    doCaption="The label names the agreement."
    dontExample={<Checkbox label="Yes" />}
    dontCaption="The label says nothing about what is accepted."
/>

### Keep the label beside the box, in sentence case.

Sentence case reads as a statement. All caps and a trailing period read as a warning.

<DoDontPair
    doExample={<Checkbox label="Email me session reminders" />}
    doCaption="Sentence case, no period."
    dontExample={<Checkbox label="EMAIL ME SESSION REMINDERS." />}
    dontCaption="All caps with a period."
/>

### Keep each label to one line.

A short label sits level with the box. A long one wraps and pushes the box away from its first line.

<DoDontPair
    doExample={<Checkbox label="Remind me by email" />}
    doCaption="One short line."
    dontExample={<Checkbox label="Remind me by email the evening before every session and again an hour before it starts" />}
    dontCaption="A label that wraps into a paragraph."
/>

### Name the choice, not the instruction.

<DoDontPair
    doExample={<Checkbox label="Email me a summary" />}
    doCaption="The label names the choice."
    dontExample={<Checkbox label="Check this box for a summary" />}
    dontCaption="The label tells the person what to do with the box."
/>

### Explain an invalid box; do not disable it.

<DoDontPair
    doExample={<Checkbox label="I accept the terms" isInvalid />}
    doCaption="The invalid box keeps full contrast and stays in the tab order."
    dontExample={<Checkbox label="I accept the terms" isInvalid isDisabled />}
    dontCaption="A disabled box cannot be tabbed to."
/>

### Use read-only for fixed answers and disabled for unavailable ones.

`isReadOnly` shows an answer that cannot be changed: the box stays in the tab order at full contrast with no hover (`aria-readonly`), ignores clicks and Space, and takes the neutral fill when unchecked. `isDisabled` removes it from the tab order and grays it when a prerequisite on the same screen is unmet. Put the reason in `description`, which stays at full contrast, never a tooltip. When it blocks the main action or several boxes, add a warning `SectionMessage` above that says how to turn them on. See [Read-only](?path=/docs/patterns-states-read-only--docs) and [Disabled](?path=/docs/patterns-states-disabled--docs).

### Keep extra detail in `description`.

`description` renders under the label and is wired with `aria-describedby`, so it is read after the name.

### Pick controlled or uncontrolled and stay there.

```jsx
// Incorrect: `isChecked` being defined puts the component in controlled mode,
// which makes `defaultChecked` dead. The two never apply together.
<Checkbox id="terms" label="I accept" isChecked={accepted} defaultChecked />

// Correct: controlled needs a handler; uncontrolled needs neither.
<Checkbox id="terms" label="I accept" isChecked={accepted} onChange={onAccept} />
```

### Treat `isIndeterminate` as display only.

The underlying value is still checked or unchecked. Clicking a mixed box resolves it like any other, so it cannot be used as a third stored value.

## Accessibility

- **Label association.** The component derives an id for the input and label automatically; pass `aria-label` only when there is no visible label.
- **Do not disable a box that must stay reachable.** Use `isInvalid` with a message linked by `aria-describedby`, so a screen reader user hears why the option cannot be chosen. Include an error message for a required or invalid box, for example "Select an option".
- **`isRequired` reaches the input**, so native validation applies. The marker is decoration, hidden from assistive technology.
- **`isIndeterminate` is set on the DOM node** and announced as "mixed".
- **Keyboard.** `Space` toggles the focused checkbox; `Enter` does not. Keyboard focus is a 2px ring on `border.focused`, 2px off the box; pointer focus draws none.
