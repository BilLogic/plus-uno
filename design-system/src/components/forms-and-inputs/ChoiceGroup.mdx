## When to use

Use `ChoiceGroup` for one question whose answers fit on screen — about two to
seven. `type="radio"` (the default) takes one answer, `type="checkbox"` any
number. Past that, or when space is short, use `Select`.

It is also the numbered scale: `orientation="inline"` with `leadingText` and
`trailingText` for the two ends.

</div>

<div className="sb-ds-doc-section">

## Usage notes

### The value is the answer.

A radio group's value is one option value, or `null` while unanswered; a
checkbox group's is an array. `onChange` hands you the next answer, not an
event. Pass `value` to control it or `defaultValue` to let it hold its own.

```jsx
const [subject, setSubject] = useState(null);
<ChoiceGroup legend="Subject" options={subjects} value={subject} onChange={setSubject} />

const [days, setDays] = useState([]);
<ChoiceGroup type="checkbox" legend="Available days" options={weekdays} value={days} onChange={setDays} />
```

### A radio group starts unanswered.

Nothing is chosen until someone chooses. Pre-choosing the first option makes a
real answer of 1 indistinguishable from no answer; pass `defaultValue` only when
the default is itself an answer.

### Options can be strings or objects.

A string is its own value and label. An object takes `value` and `label`, and
optionally `description`, `disabled`, `id` and `reveal` — content shown under the
option while it is chosen, such as the date range for "during a date period".

### "Other" is an answer with a text box.

`other={{ label, placeholder, text, onTextChange }}` adds a last choice (value
`'other'` unless you pass `value`) and a text box beside it. Typing in the box
chooses it. Keep the typed text in your own state.

### `appearance` and `required` belong to the group.

`appearance="card"` draws every choice as a bordered tile. `required` puts the
mark on the legend; for radios it also sets `required` on each radio, and for
checkboxes the group cannot enforce it, so check it on submit. Show the
failure with `error`, once, for the group.

</div>

## Accessibility

- **The legend names the group.** It is a real `fieldset` and `legend`. A radio
  group takes `role="radiogroup"`, which can carry `aria-required` and
  `aria-readonly`; a checkbox group stays a `group`, and each box carries its own
  `aria-readonly`. With no visible question, pass `aria-label`.
- **Scale ends describe the group.** `leadingText` and `trailingText` are joined
  to the group with `aria-describedby`, so they are read once for the question
  rather than attached to the first and last option.
- **One error, announced.** `error` renders with `role="alert"` and the group
  points at it with `aria-describedby`.
- **Descriptions describe, labels name.** Each option's `description` is wired to
  its control with `aria-describedby`.
- **Read-only stays reachable.** `readOnly` keeps every choice in the tab order at
  full contrast and ignores clicks and keys; `disabled` takes them out.
- **Ids never collide.** Without an `id`, the group generates its own base for
  option ids and the radio `name`, so two groups on one page stay independent.

</div>

## Related

- For one independent yes or no, use `Checkbox`; for a setting that applies at once, use `Switch`.
- For the same question asked of several rows, use `ChoiceGrid`.
- For a long list of options, use `Select`.
- For a star rating, use `Rating`.
