A tag group is a set of tags, and the Suggestions offered beside them. It owns
what no single tag can decide: the 8px gap between them, whether a long set
wraps or collapses, which edge it lines up on, and whether it is disabled.

## Usage

Use `TagGroup` wherever more than one `Tag` appears together: the subjects on a
profile, the filters above a table, the recipients on a message. It is the
right wrapper even when the set is short, because what it owns (the spacing,
the wrapping, the alignment and the disabled state) belongs to the set rather
than to any tag in it. Suggestions offered for the field go in the same group;
they always sit at the end of the row, after the tags and `+n`.

A single tag standing alone does not need it.

</div>

## Parts

1. **Tags and suggestions.** The group owns the gaps between them; a tag carries no margin.
2. **Overflow tag.** A <code>+n</code> that opens a menu of the hidden tags, or runs <code>onOverflowClick</code>.
3. **List.** A named <code>list</code> of <code>listitem</code>s; the <code>label</code> is its accessible name.

## Best practices

### Collapse long groups in tight rows.

Collapse keeps one line and puts the rest behind `+n`; wrapping grows the row.

<DoDontPair
    doExample={<div style={{ width: 'var(--size-1500)' }}><TagGroup label="Skills" overflow="collapse"><Tag color="blue">Lincoln Middle</Tag><Tag color="lime">Advocacy</Tag><Tag color="purple">Fractions</Tag><Tag color="magenta">Relationships</Tag><Tag color="teal">Roosevelt K-8</Tag></TagGroup></div>}
    doCaption="Collapse in a tight row."
    dontExample={<div style={{ width: 'var(--size-1500)' }}><TagGroup label="Skills"><Tag color="blue">Lincoln Middle</Tag><Tag color="lime">Advocacy</Tag><Tag color="purple">Fractions</Tag><Tag color="magenta">Relationships</Tag><Tag color="teal">Roosevelt K-8</Tag></TagGroup></div>}
    dontCaption="Wrap pushes the row taller."
/>

`overflow="collapse"` counts what fits by width, so it suits a table cell or a card
header where a second line would break the layout. Give the group a width to
fit into: a group that can grow shows everything. Use `maxVisible` only to show
fewer than fit. The cap never squeezes a tag: `maxVisible={0}` puts every tag
behind `+n`. Only a row too narrow for its first tag squeezes that tag.

`+n` reserves room for the widest label it could show at its number of digits
(`+88` when up to 99 tags are hidden), not for the label it shows now. That is
what keeps the count steady as `+9` becomes `+10`, and it means a row can show
one tag fewer than would squeeze in beside a narrower `+n`.

Suggestions are offers, not values, so they are never hidden: they are not
counted into `+n`, never appear in its menu, and always sit after it. Their
width comes off the row before tags are counted, so a group with suggestions
shows fewer tags, not fewer suggestions.

A Suggestion is recognized by a marker on the component, so pass Suggestions
as direct children of the group. A memoized Suggestion works as is; a wrapper
component of your own must copy the marker
(`MySuggestion.isSuggestion = Suggestion.isSuggestion`), or it is counted as a
tag.

In the menu, a hidden tag keeps what it does. A selectable tag toggles there
(`aria-pressed`), in the selected state when on, and the menu stays open so
the change is seen. A link tag is a link there, to the same address, with a
trailing arrow. A tag still saving is a disabled, busy row that cannot be
pressed.
A read-only or removable tag is a static row that only says its words. Remove is only offered on the row, never from the
menu.

### Align to the surrounding text.

End alignment is for a right-aligned column; elsewhere it drifts from the text. `alignment="end"` belongs in a table column whose other cells are right-aligned. Everywhere else, tags read from the start.

### Disable the whole group when read-only.

A group disables as a unit, the way a disabled field does. Say so once on the group with `isDisabled`, and every Tag and Suggestion in it follows; never disable one tag and leave its neighbors live.

    dontCaption="A read-only group that looks editable."
/>

### Let the group own the gap.

A tag that carries its own margin needs an escape hatch whenever a parent uses
`gap`: an API that exists only to undo a decision made in the wrong place.
`Tag` sets `margin: 0` and `TagGroup` sets `gap`, so there is nothing to undo
and nothing to double up. A row of tags in a hand-built flex container defines
its spacing in two places.

## Accessibility

- **The set is a list, and says so.** Without `role="list"` a screen reader
  reads seven unrelated words in a row; with it the person is told there are
  seven and can move through them as a group.
- **`label` is the group's accessible name.** It is what says these seven tags
  are subjects rather than filters. There is no default, so a group without it
  is an unnamed list.
- **The items are wrapped, not rendered as `li`.** That is what keeps `Tag`
  usable on its own, outside any group, without it carrying list semantics it
  has no right to.
- **Hidden tags leave the list.** A collapsed group's hidden tags are out of
  sight, out of the tab order and out of the list's count until the menu shows
  them.
- **`+n`'s name starts with what it shows**, so a person who says the label
  they see can press it: "+3 more tags", "+1 more tag" for one, and with a
  custom `overflowLabel` the label then the count ("3 more, 3 more tags"). It
  reports whether its menu is open. Enter or Space opens it, Tab reaches each
  hidden tag that does something, and Escape closes it with focus back on
  `+n`. A selectable tag in the menu is a toggle button that reports
  `aria-pressed`, and its checkbox is decorative; a link tag is a real link,
  whose arrow is decorative; a tag still saving is a
  disabled button with `aria-busy`, out of the tab order; a read-only or removable
  tag is a static row, not a control and not in the tab order.
- **Suggestions stay reachable.** They are never behind `+n`, so a keyboard
  user reaches them on the row, after `+n`, without opening the menu.
- **Disabled is announced per tag.** A selectable tag, a Suggestion and `+n`
  are native disabled buttons, announced as disabled ("Selectable, toggle
  button, dimmed" or the reader's equivalent). Every other tag is a plain span,
  which has no disabled state a screen reader announces, so it carries
  visually hidden text and is read as "Science, disabled". Nothing in a
  disabled group takes focus.

## Related

- For one value rather than a set, use `Tag`.
- For a value the system proposes, put a `Suggestion` in the group.
- For a labeled field where the person picks, creates and removes tags, use `TagInput`.
- For a long set that needs paging rather than an overflow count, use `Pagination`.
