## Usage

Use `ProgressIndicator` for a short sequence where position matters more than
the name of each step — a carousel, an onboarding flight, a slide deck. When
each step has its own label people need to see, use `ProgressTracker` instead.

</div>

<div className="sb-ds-doc-section">

## Parts

1. **Dot.** One per step: 8 or 12 across, a circle.
2. **Current dot.** The brand ground (discovery for help, inverse icon for inverted), with <code>aria-current="step"</code>.
3. **Group.** The row, named by <code>label</code>.

## Best practices

### Pass `onSelect` only when jumping ahead makes sense.

Without `onSelect` the dots are decorative and only `aria-current` marks the
active one. With it, every dot becomes a button a person can press to jump
there directly — appropriate for a carousel, not for a linear flow someone
must complete in order.

```jsx
<ProgressIndicator
    values={slides}
    selectedIndex={index}
    onSelect={({ index }) => setIndex(index)}
    ariaControls="carousel-panel"
/>
```

### `values` only supplies a count and, when interactive, each dot's name.

The array's content never renders — only its length becomes the number of
dots, and each entry becomes a dot's accessible name when `onSelect` is set.

## Accessibility

- **A named group.** The row has `role="group"` with a `label` ("Progress" by
  default), so a screen reader announces it as one control.
- **The current step is `aria-current="step"`.** This is the only state a
  non-interactive indicator exposes.
- **Interactive dots are real buttons**, each named from its `values` entry
  and linked to the content it controls with `ariaControls`.
