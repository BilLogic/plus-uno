<Title>Patterns</Title>
A pattern is a page-level shell with its layout rules built in. It sets the fill, radius, padding, elevation and width for one layer of the page, and leaves the content to slots. A page starts from a page template. The surface container holds the Topbar and the sidebar, the Surface pads the content and gives it the 12-column grid, and Sections, Cards and Tables fill it. Modal and Popover sit above the page.

The examples on every pattern page follow the **Color mode** switch in the toolbar, so check each one in light, dark and increased contrast.

### The eight patterns

A slot is a named place in a pattern where you put your own content. Each pattern owns its frame and exposes its slots. In Figma the layout mode (Medium 768, Large 1024 or X-Large 1440) is a variable mode, set once on the page template. In code the tokens follow the viewport width.

### When to use a pattern, and when to use something else

Use a pattern to build a layer of a page: the frame, a region, a container for one object, a table, or a layer above the page. A pattern gives you the layer, never the content inside it.

For a finished piece of UI such as a button, a field or an avatar, use the component. A pattern holds components in its slots, and a component never rebuilds a pattern's frame.

### How a page layers

Each layer has one fill and one elevation. A state such as hover or selected is drawn over the fill, never in place of it.

### Usage

1. **Start a page from its template.** The template frames the page. Section groups content under one heading, Card groups one object's content, Table holds records and Modal interrupts for a step that must happen first.
2. **Swap slots, never restyle the pattern.** Content goes in through slots such as content, body, footer, header, actions, tabs, filters, bulk actions, image, cells, items and side. Leave fill, radius, border, padding and elevation as the pattern sets them, because they come from tokens.
3. **Add content straight into the slot.** Drop content into the slot itself and replace its placeholder. Do not detach the pattern. Inside a surface, Sections group whatever you place, and their spacing comes from the Surface and Section stack tokens, so add padding only where the content itself needs it.
4. **Draw states as overlays.** Hover, pressed and selected take their own token steps: <code>--ds-background-neutral-subtle-hovered</code> and <code>-pressed</code>, then <code>--ds-background-selected</code> and <code>-hovered</code>. Focus is the focus ring in <code>--ds-border-focused</code>, never a fill.
5. **Keep filled versions as local components.** A spec that fills a surface container keeps its own component built from the pattern, so usage traces back to the pattern.
6. **Note every optical nudge.** Spacing tokens set the structure. Where the eye needs a nudge, such as an icon beside text, an all-caps label or a round shape, nudge for optical balance and note it where you make it. Never leave it as an unexplained hard-coded value.

### For developers

Patterns nest by layer, and each layer's tokens belong to it. A Section holds a Card, and the Card holds the object's content. A Table is never wrapped in a Card.

```jsx
import { Frame, Topbar, PatternSection, PatternCard } from '@/patterns';
import { Button, Sidebar } from '@/components';

<Frame
    topbar={<Topbar breadcrumbs={[{ text: 'Home', href: '/' }, { text: 'Team' }]} />}
    sidebar={<Sidebar user="tutor" activeTabId="home" />}
>
    <PatternSection title="Team" actions={<Button text="Add" />}>
        <PatternCard>Content</PatternCard>
    </PatternSection>
</Frame>
```
