## For developers

A row is uncontrolled with a default key, or controlled with a key and a
handler. A controlled row without a handler never moves, and every item needs
an event key or a link, because selection is keyed off one of them.

```jsx
<NavTabs activeKey={tab} onSelect={setTab}>
  <NavTabs.Item eventKey="overview">Overview</NavTabs.Item>
  <NavTabs.Item eventKey="sessions">Sessions</NavTabs.Item>
</NavTabs>
```

In the tabs mode, declare each panel beside its tab so the component owns both
halves of the pointer between them. Only the selected panel renders.

```jsx
<NavTabs mode="tabs" activeKey={tab} onSelect={setTab}>
  <NavTabs.Item eventKey="overview">Overview</NavTabs.Item>
  <NavTabs.Item eventKey="sessions">Sessions</NavTabs.Item>
  <NavTabs.Panel eventKey="overview">{overview}</NavTabs.Panel>
  <NavTabs.Panel eventKey="sessions">{sessions}</NavTabs.Panel>
</NavTabs>
```

The navigation mode is the default because existing screens use the row as
navigation, where links are the right element.

## When to use

Use tabs for views of the same thing. Each tab shows another view of one
subject, such as a student's Overview, Sessions and Progress, or the sections
of an admin page.

- **Moving to a different page or area:** use Sidebar tab or a link, because tabs imply the content stays in place.
- **Switching views with a lighter, filled look:** use Nav pills.
- **Moving between headings of one long page:** use Scrollspy.
- **Filtering a list:** use Select or Choice group. Filters combine, and tabs do not.
- **More tabs than fit the width:** use Select. The row wraps onto a second line rather than scrolling, which hides which row the reader is on.

Two rules keep a row of tabs readable:

- **Use the tabs mode when the tabs swap panels in place.** It gives the row tab semantics, arrow keys and one tab stop. Leave the default navigation mode when each tab is a link to its own URL.
- **Keep labels short and parallel.** One or two words each, in the same form, so the row scans as a set.

</div>

## Accessibility

- **Tab mode.** The row is a tab list. Each tab announces itself as a tab and says whether it is selected, and points at its panel when one is declared.
- **Navigation mode.** The row is a set of links. Every item is a tab stop and activates with Enter, so the row works from the keyboard, but screen readers do not announce a tab set.
- **One tab stop.** In the tabs mode the whole row is a single stop, on the selected tab. Left, Right, Home and End move the selection and the focus together.
- **Disabled tabs.** Arrow keys skip a disabled tab. A disabled tab cannot be focused or pressed, and it drops out of the tab order.
- **A tab with a menu is not a tab.** It has no valid tab semantics inside a tab list, so the arrow keys walk past it. A row that needs an overflow menu uses the navigation mode, or a Select.
- **Name the row.** Pass an accessible name to say what the set of tabs is for, especially when a page carries more than one.
- **Focus** is a 2px ring inside the tab, never a fill, so focus does not read as pressed.
- **Contrast.** The selected state does not rest on color alone: the bar under the tab marks it as well as the ink.
