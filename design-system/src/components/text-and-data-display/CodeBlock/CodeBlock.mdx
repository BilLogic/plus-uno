## Usage

Use `CodeBlock` for code a reader may copy or follow line by line: an example,
a command sequence, a config file. For a name or short phrase inside a
sentence, use `Code`.


The typeface is the `--code` text style at 0.875rem on a 1.25rem line. The
surface is `--ds-background-code-default`, the ink `--ds-text-code-default`, the
gutter `--ds-background-code-gutter` with `--ds-text-code-gutter`, and a
highlighted line `--ds-background-code-highlight`.

</div>

<div className="sb-ds-doc-section">

## Parts

1. **Surface.** The code ground with a hairline edge and a small radius.
2. **Gutter.** Optional line numbers, skipped by screen readers.
3. **Line.** One per line of text; a highlighted line has its own ground.
4. **Region.** The scrolling block, focusable and named when it does not wrap.

## Best practices

### Choose scroll or wrap by what the code means.

```jsx
// Correct: scroll keeps line structure, which matters for shell commands and
// config where a fold could read as a new line.
<CodeBlock text={command} />

// Correct: wrap suits prose-like output inside a narrow column.
<CodeBlock text={log} wrap />
```

### Name each block when there are several on a page.

```jsx
// Incorrect: two regions both named "Code snippet".
<CodeBlock text={install} />
<CodeBlock text={config} />

// Correct: each region says what it holds.
<CodeBlock text={install} label="Install command" />
<CodeBlock text={config} label="Config file" />
```

### Do not rely on a highlight alone.

```jsx
// Incorrect: the fill is the only cue, and the surrounding text never says
// which line to look at.
<CodeBlock text={snippet} highlight="3" />

// Correct: the highlight supports the sentence that points at it.
<p>Line 3 sets the timeout.</p>
<CodeBlock text={snippet} highlight="3" />
```

## Accessibility

- **Keyboard scroll.** A scrolling block is a focusable region with a name, so a
  keyboard user can scroll it with the arrow keys. A wrapping block has nothing
  to scroll and is not a tab stop.
- **Highlights are spoken.** Each highlighted run is bracketed by "Highlight
  start" and "Highlight end" for screen readers, because fill alone says nothing
  to them. Those words are not selectable, so they stay out of a copy.
- **Line numbers are skipped.** The gutter is hidden from assistive technology and
  cannot be selected, so a copy is the code alone.
- **Contrast.** Ink, gutter and highlight come from the code color roles and keep
  their contrast in every color and contrast mode.
