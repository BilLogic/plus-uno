## Usage

Use `ButtonGroup` for a short row of related actions that work on the same object. It spaces the buttons and names the row for assistive technology; it does not join them or track a selection.

</div>

<div className="sb-ds-doc-section">

## Alternatives

- For switching how the same content is shown (Day / Week / Month, Table / Cards), use `SegmentedControl`.
- For a single standalone action, use `Button`.
- For one primary action joined to a menu of variations, use `SplitButton`.
- For mutually exclusive form answers, use `RadioGroup`.
- For large illustrated choices with a title and an illustration, use `ChoiceGrid` (or `RadioGroup` / `CheckboxGroup` in `tile` appearance).

</div>

<div className="sb-ds-doc-section">

## Parts

1. **Container.** Groups its children with `role="group"` and the `label` as its name. It paints nothing of its own.
2. **Buttons.** Button or Icon button children that hug their labels. Each keeps its own appearance, spacing, corners and state.
3. **Gap.** The buttons sit one inline step apart.

## Best practices

### Group related actions only.

A group is one set of actions. Every button in it works on the same object.

<DoDontPair
    doExample={<ButtonGroup label="Draft"><Button text="Edit" /><Button text="Duplicate" /><Button text="Archive" /></ButtonGroup>}
    doCaption="Edit, Duplicate and Archive all act on the same draft."
    dontExample={<ButtonGroup label="Actions"><Button text="Save" /><Button text="Delete" /><Button text="Help" /></ButtonGroup>}
    dontCaption="Save, Delete and Help act on different things."
/>

### Give the group an accessible name.

`ButtonGroup` has no visible title of its own. `label` names the whole group
for assistive technology, such as "Draft actions".

```jsx
<ButtonGroup label="Draft actions">
    <Button text="Edit" onClick={edit} />
    <Button text="Duplicate" onClick={duplicate} />
</ButtonGroup>
```

### Keep every button one size.

Buttons in a group share one spacing so the row keeps one height.

<DoDontPair
    doExample={<ButtonGroup label="Draft"><Button text="Edit" /><Button text="Duplicate" /><Button text="Archive" /></ButtonGroup>}
    doCaption="Every button uses default spacing."
    dontExample={<ButtonGroup label="Draft"><Button text="Edit" /><Button text="Duplicate" spacing="compact" /><Button text="Archive" /></ButtonGroup>}
    dontCaption="A compact button beside default ones makes the row uneven."
/>

### Make the labels parallel.

<DoDontPair
    doExample={<ButtonGroup label="Draft"><Button text="Edit" /><Button text="Duplicate" /><Button text="Archive" /></ButtonGroup>}
    doCaption="Every label is a verb of the same kind."
    dontExample={<ButtonGroup label="Draft"><Button text="Edit" /><Button text="More options" /><Button text="Draft" /></ButtonGroup>}
    dontCaption="A verb, a phrase and a noun in one group."
/>

### Use `SegmentedControl` to switch views, not `ButtonGroup`.

A group runs actions and holds no selection. When one choice stays on and the
view changes at once, such as Day, Week and Month, use `SegmentedControl`.


### Let `ButtonGroup` buttons that do not fit shrink and end their labels in an ellipsis.

The group keeps one row inside its slot. A clipped label has no Tooltip, so keep the labels short enough that the ellipsis is the exception; the full label stays in the accessible name. See [Overflow](?path=/docs/patterns-states-overflow--docs).

## Accessibility

- **A named group.** The row is `role="group"` with `label` as its accessible
  name, so assistive technology announces the buttons as one related set.
- **Each button keeps its own accessible name and state.** `ButtonGroup`
  adds no roles or attributes beyond the group wrapper.

</div>

## Related

- `SegmentedControl`: use to switch how the same content is shown.
- `Button`: use when an action stands alone or sits in a spaced row.
- `SplitButton`: use when one primary action pairs with a chevron menu.
- `ChoiceGrid`: use when offering illustrated choices (or `RadioGroup` / `CheckboxGroup` with `appearance="tile"`).
