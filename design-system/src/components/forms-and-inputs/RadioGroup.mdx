## When to use

Use `RadioGroup` for one question with mutually exclusive answers, visible
all at once — a handful of options someone picks by scanning, not searching.
For a long list of options, use `Select` instead. For independent yes/no
choices rather than one answer among several, use a group of `Checkbox`.

</div>

<div className="sb-ds-doc-section">

## Usage notes

### `value` tells "answered zero" apart from "answered the first option."

There is no implicit default selection — an unanswered group is `null` or
`undefined`, never falls back to the first option. Check for that explicitly
before treating the group as answered.

```jsx
<RadioGroup
    legend="How was the session?"
    leadingText="Not at all"
    trailingText="Very"
    options={['1', '2', '3', '4', '5']}
    value={rating}
    onChange={setRating}
/>
```

### Use `reveal` instead of a separate conditional field.

When choosing one option should show an extra field — "Other, please
specify" — pass that field as the option's `reveal` rather than rendering it
outside the group. It stays scoped to the option that triggers it and
disappears when another option is chosen.

</div>

## Accessibility

- **One real `radiogroup`, named by the legend.** The outer `Fieldset`
  supplies the `<fieldset>`/`<legend>` pair; the inner group repeats the
  legend's id as its own `aria-labelledby`, so assistive technology
  announces the question once, not twice.
- **Roving tabindex.** Tab enters and leaves the group as a single stop;
  arrow keys move the checked state between options, matching native radio
  button behavior.
- **A caller's own `aria-label`/`aria-labelledby` wins over the legend**, for
  the rare case ("Pick one" with no visible legend) where the question is
  named another way.
- **One error, announced once.** `error` renders a single message tied to
  the group via `aria-describedby`, rather than repeating it per option.

</div>
