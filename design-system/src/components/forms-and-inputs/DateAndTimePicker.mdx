## For developers

- **<code>onChange</code> does not hand you an event.** It is called with the date, the time and the moment in UTC, as plain strings, or null for a half that is not yet complete. Store the UTC value and not the date and time, which are only what the viewer saw. Every other field in this group forwards a DOM event, so this is the one place <code>event.target.value</code> is undefined.
- **The time stays null until both hours and minutes are present.** A reader part-way through typing produces a date and a null time, because "09:" is not a time.
- **The hour shown is a 12-hour hour.** <code>timeValue</code> accepts either form: "02:30 PM" is used as given, and "14:30" is split into 02:30 and PM. Midnight and noon both read as 12, and only the period tells them apart.
- **The hour field refuses what the control cannot show.** It takes 0 to 12, not 0 to 23, because an AM/PM control sits beside it. Zero is allowed so a leading zero can be typed on the way to 05.
- **Changing AM/PM reports even without a date.** The change is reported with a null date and is not dropped.
- **Times are stored in UTC and shown in the viewer's zone.** <code>timeZone</code> is the viewer's IANA zone and defaults to the browser's. Pass <code>otherTimeZone</code> and <code>otherPerson</code> when someone else will read the time, and the caption adds theirs. Daylight saving is handled per date, so 4:00 PM in November is an hour later in UTC than in October.
- **The calendar opens 4 below the date field**, left-aligned and flipping above when there is no room. The AM/PM menu opens the same 4 below its button.
- **Extra props go to the wrapper and not to either input.** The wrapper carries the group's role and name, so your <code>aria-describedby</code> lands where it can help. A forwarded <code>aria-invalid</code> therefore marks the group and not the inputs, so use <code>validation</code>, which marks the inputs themselves.

## When to use

Use a Date time picker when the answer is a day and a time, such as when a session starts. Turn <code>showDate</code> off when the day is already known and only the time is asked. For a day alone, use [Date picker](?path=/docs/components-forms-and-inputs-date-picker--docs). For a start from a short list of open slots, a [Select](?path=/docs/components-forms-and-inputs-select--docs) of those slots is quicker. For a length of time, use [Number input](?path=/docs/components-forms-and-inputs-number-input--docs).

- **Name the time zone.** Show the viewer's zone in the caption whenever a time is shown. When the other person in a session is in a different zone, add their time, so neither of you has to convert.
- **Store UTC and show local.** Save the moment in UTC and convert it for each viewer. Never save the time as typed, because the same 4:00 PM is a different moment in another zone.
- **Check it when the field loses focus.** Validate the date and time against the allowed span when focus leaves the field and not on every keystroke, and say what is allowed in the message.

## Accessibility

- **The label names the field and not either input.** The field has two controls, and one label can name only one control, so the label names a group around both. Each input is then named from that plus its section heading, "Session start Date" and "Session start Time", which tells them apart when read out of context.
- **Hiding the label keeps the name.** <code>showLabel</code> set to false clips the label out of sight and keeps it for assistive technology, so the layout does not move.
- **A field with no label has no name.** Then there is no group either, and the inputs are called just "Date" and "Time". Two such pickers on one screen are indistinguishable. Pass a label, and hide it if it should not be seen.
- **A caption you draw above the field cannot be its name.** For one visible "Session time" over a start and an end picker, give each picker its own label with <code>showLabel</code> false. Then point a wrapping group at the caption with <code>aria-labelledby</code>.
- **Never give the same id to two pickers.** Ids are derived once per instance, so leaving <code>id</code> out is safe. Repeating one makes every label on the page land on whichever control the browser reached first.
- **Validation marks both inputs.** The invalid state is set on both inputs, and the message is announced as an alert and describes the group. Required draws an asterisk named "required".
- **The time zone caption is part of the description.** It follows any description you pass, so a reader hears the zone along with the field.
