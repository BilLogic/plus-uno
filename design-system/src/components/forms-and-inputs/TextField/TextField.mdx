## Usage

Use a Text field for single-line text entry: names, emails, search boxes and
numbers. It owns its label, its validation state and its message, which makes it
the right home for an error rather than a Section message at the top of the form.

Use a [Text area](?path=/docs/components-forms-and-inputs-text-area--docs) for several lines, a
Select for a value chosen from a list, and a Date picker for dates.

## Parts

1. **Label.** Names the field. A required marker and an info tooltip sit beside it.
2. **Before.** An icon, a text affix or a Button before the control.
3. **Control.** The native input.
4. **After.** An icon, a text affix, a Button or the number steppers.
5. **Caption.** A message on the left and, with `maxLength`, a count on the right.

## Best practices

### Name the field.

The label says what the field is, not what to do.

<DoDontPair
    doExample={<TextField label="Email address" placeholder="name@example.com" />}
    doCaption="The label names the field."
    dontExample={<TextField label="Enter your email address here" placeholder="name@example.com" />}
    dontCaption="An instruction where the name should be reads badly in a list of fields."
/>

### Put one element on each side, at most.

A leading icon or a trailing action, not both crowding the text.

<DoDontPair
    doExample={<div style={{ maxWidth: 'var(--width-1500)' }}><TextField label="Search tutors" isLabelHidden placeholder="Search tutors" elemBeforeInput={<i className="fa-solid fa-magnifying-glass" aria-hidden="true" />} /></div>}
    doCaption="One element before the text."
    dontExample={<div style={{ maxWidth: 'var(--width-1500)' }}><TextField label="Search tutors" isLabelHidden placeholder="Search tutors" elemBeforeInput={<i className="fa-solid fa-magnifying-glass" aria-hidden="true" />} elemAfterInput={<i className="fa-solid fa-circle-info" aria-hidden="true" />} /></div>}
    dontCaption="Elements on both sides squeeze the value."
/>

### Hint at the answer, not the control.

A placeholder shows what a good answer looks like.

<DoDontPair
    doExample={<TextField label="Email address" placeholder="name@school.edu" />}
    doCaption="Hint shows the format."
    dontExample={<TextField label="Email address" placeholder="Enter email" />}
    dontCaption="Hint describes the control."
/>

### Show an error on the field itself.

The field carries the invalid state.

<DoDontPair
    doExample={<TextField label="Email address" defaultValue="name@school" isInvalid errorMessage="Enter a full email address." />}
    doCaption="The field shows the invalid state."
    dontExample={<TextField label="Email address" defaultValue="name@school" />}
    dontCaption="A default field gives no sign of the problem."
/>

### Say what to do about an error.

<DoDontPair
    doExample={<TextField label="Phone" isInvalid errorMessage="Enter a 10-digit number." />}
    doCaption="Say what to do about the error, in the field's own caption."
    dontExample={<TextField label="Phone" isInvalid errorMessage="Invalid." />}
    dontCaption="A fact that there is an error, with no way forward."
/>

### Keep slots to decoration.

A string is a text affix; an icon is hidden from assistive technology. Anything the reader must know belongs in the label or the message, not in the glyph. Do not nest interactive elements in a slot, other than the Button the field is built for: a control with its own focus is announced apart from the field.

### Let the message follow the state.

`errorMessage` shows with `isInvalid`; `warningMessage` and `successMessage` show on their own; otherwise `caption` shows. `maxLength` adds a count on the right beside any of them. A warning accepts the value: use it when the entry is allowed but worth a second look, and `isInvalid` only when the form cannot go on.

### Set `autoComplete` on every field the browser can fill.

Login email is `email`, the password is `current-password`, and an access code is `one-time-code`.

### Use subtle for editing in place.

`appearance="subtle"` is for record and profile pages, never in a form someone fills from top to bottom. Pass `onSave`.

### Pick the spacing by the row it sits in.

Use `default` in forms and `compact` in toolbars, filter bars and table rows.

### Use `type="number"` for quantities you step.

Such as seats. For an ID, a phone number or a postcode, use `type="text"` with `inputMode`.

## Accessibility

- **The label is associated whether you pass `id` or not.** One id is derived
  once and used for both the label's `htmlFor` and the input.
- **`isLabelHidden` hides the label, it does not remove it.** The label is
  rendered either way and clipped out of sight. A field that has a `label` has an
  accessible name whether or not you show it. If the visible label is rendered
  by the caller instead, point it at the input with `htmlFor`; if there is no
  text anywhere, pass `aria-label`.
- **`isRequired` shows an asterisk and sets `aria-required`.** The asterisk is
  hidden from assistive technology. The form explains it once, in a legend above
  the fields.
- **An error is announced.** The message gets an id, the input points at it with
  `aria-describedby`, and `isInvalid` sets `aria-invalid` and renders the message
  with `role="alert"`. A warning, a success message and standing help are
  described without being announced. Your own `aria-describedby` is kept and the
  message id is appended.
- **Focus is a ring.** 2px in `border.focused`, 2px off the box, with no change of
  fill, so it reads in Light, Dark and More contrast.
- **The number field is a text input**, so the scroll wheel never changes the
  value. The steppers are named for the field they change: "Decrease Seats" and "Increase Seats".
