<Title />

A question with its set of choices under one legend: radios for one answer, checkboxes for any number. Stacked is the default. Inline lays the choices in a row, and with end labels it becomes a scale.

Figma documents this component on two pages. **Multiple choice** covers the group as a whole. **Scale** covers the inline group with end labels, and it has no component of its own. This page covers both: the Multiple choice sections come first, and the Scale sections follow, under their own headings. The Scale page is in [Figma](https://www.figma.com/design/zAecJNRdvJzAUOcjV32tRX/Design-System---BS4-Foundation--Component-LIbrary-?node-id=18314-64686).

Multiple choice:

    <li><strong>Options</strong>: one Radio per point.</li>
    <li><strong>Trailing label</strong>: the high end, set by <code>trailingText</code>.</li>

## For developers

- **The value is the answer.** A radio group's value is one option value, or none while unanswered. A checkbox group's is an array. <code>onChange</code> receives the next answer and not an event. Pass <code>value</code> to control the group, or <code>defaultValue</code> to let it hold its own.
- **A radio group starts unanswered.** Pre-choosing the first option makes a real answer of 1 indistinguishable from no answer. Pass <code>defaultValue</code> only when the default is itself an answer.
- **Options can be strings or objects.** A string is its own value and label. An object takes <code>value</code> and <code>label</code>, and optionally <code>description</code>, <code>disabled</code>, <code>id</code> and <code>reveal</code>, which is content shown under the option while it is chosen.
- **"Other" is an answer with a text box.** <code>other</code> adds a last choice, with the value "other" unless you pass one, and a text box beside it. Typing in the box chooses it. Keep the typed text in your own state.
- **<code>appearance</code> and <code>required</code> belong to the group.** <code>appearance="card"</code> draws every choice as a bordered tile. For radios, <code>required</code> also sets <code>required</code> on each radio. For checkboxes the group cannot enforce it, so check it on submit and show the failure once, with <code>error</code>.

## When to use

Use a Choice group for fewer than five answers a person should see at once. Under five, show them all: radios for one answer and checkboxes for several, so a person compares them at a glance without opening anything. From five to fifteen answers use [Select](?path=/docs/components-forms-and-inputs-select--docs), which saves space. Past fifteen, use a list that shows more of them. When several questions share the same answers, use a [Choice grid](?path=/docs/components-forms-and-inputs-choice-grid--docs) and do not repeat the group.

- **Ask one question per group.** The legend is the question and the options are its answers. A screen reader reads the legend with each option, so the question is never lost.
- **Stack the options unless they form a scale.** A stacked list scans fastest. Use inline only for a short ordered scale, and label its ends with <code>leadingText</code> and <code>trailingText</code>.
- **Use a radio for one answer and a checkbox for several.** If a person may pick more than one, or none, use <code>type="checkbox"</code>. Otherwise use radios, and preselect nothing unless there is a safe default.
- **Offer "Other" only when the list cannot be complete.** <code>other</code> adds a text field for an answer you did not list. If the list is complete, leave it off.

### Scale

- **Keep it short and ordered.** Use five to seven points, lowest on the left. A longer scale reads as noise.
- **Label both ends.** Numbers alone do not say which end is good. Name the low and high ends with the leading and trailing text.
- **Set the scale on this component.** A scale is a Choice group with <code>orientation="inline"</code> and end labels. Figma's older Linear scale and Scale options are deprecated.

## Accessibility

- **The legend names the group.** The group is a real fieldset and legend. A radio group has the role radiogroup, which can carry required and read-only. A checkbox group stays a group, and each box carries its own read-only. With no visible question, pass <code>aria-label</code>.
- **Scale ends describe the group.** <code>leadingText</code> and <code>trailingText</code> are joined to the group, so they are read once for the question and not attached to the first and last option.
- **One error, announced.** <code>error</code> is announced as an alert when it appears, and the group points at it.
- **Descriptions describe and labels name.** Each option's <code>description</code> is wired to its control.
- **Read-only stays reachable.** <code>readOnly</code> keeps every choice in the tab order at full contrast and ignores clicks and keys. <code>disabled</code> takes them out.
- **Ids never collide.** Without an <code>id</code>, the group generates its own base for option ids and the radio name, so two groups on one page stay independent.
