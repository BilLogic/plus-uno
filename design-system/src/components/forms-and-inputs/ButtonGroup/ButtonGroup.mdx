## Usage

Use `ButtonGroup` for a short row of related actions or view toggles that read as one unit.

</div>

<div className="sb-ds-doc-section">

## Alternatives

- For a single standalone action, use `Button`.
- For one primary action joined to a menu of variations, use `SplitButton`.
- For mutually exclusive form answers, use `RadioGroup`.
- For two to four large icon-over-label choices, use `VerticalButton`.

</div>

<div className="sb-ds-doc-section">

## Parts

1. **Container.** Groups its children with `role="group"` and the `label` as its name. It paints nothing of its own.
2. **Buttons.** Button or Icon button children. Each keeps its own appearance, spacing and state.
3. **Seam.** Inner corners are square and neighbors overlap by one edge, so the row reads as one control.

## Best practices

### Group related actions only.

A group reads as one control. Every button in it works on the same object.

<DoDontPair
    doExample={<ButtonGroup label="Calendar view"><Button text="Day" /><Button text="Week" /><Button text="Month" /></ButtonGroup>}
    doCaption="Day, Week and Month all change the same calendar."
    dontExample={<ButtonGroup label="Actions"><Button text="Save" /><Button text="Delete" /><Button text="Help" /></ButtonGroup>}
    dontCaption="Save, Delete and Help act on different things."
/>

### Give the group an accessible name.

`ButtonGroup` has no visible title of its own. `label` names the whole group
for assistive technology, such as "Calendar view".

```jsx
<ButtonGroup label="Calendar view">
    <Button text="Day" isSelected={view === 'day'} onClick={() => setView('day')} />
    <Button text="Week" isSelected={view === 'week'} onClick={() => setView('week')} />
</ButtonGroup>
```

### Keep every button one size.

Buttons in a group share one spacing so the outline stays continuous.

<DoDontPair
    doExample={<ButtonGroup label="Calendar view"><Button text="Day" /><Button text="Week" /><Button text="Month" /></ButtonGroup>}
    doCaption="Every button uses default spacing."
    dontExample={<ButtonGroup label="Calendar view"><Button text="Day" /><Button text="Week" spacing="compact" /><Button text="Month" /></ButtonGroup>}
    dontCaption="A compact button beside default ones breaks the outline."
/>

### Make the labels parallel.

<DoDontPair
    doExample={<ButtonGroup label="Calendar view"><Button text="Day" /><Button text="Week" /><Button text="Month" /></ButtonGroup>}
    doCaption="Every label is a noun of the same kind."
    dontExample={<ButtonGroup label="Calendar view"><Button text="Day" /><Button text="Show all" /><Button text="Choose" /></ButtonGroup>}
    dontCaption="A noun, a phrase and a verb in one group."
/>

### Selection state lives on each `Button`, not on the group.

`ButtonGroup` renders children as given — set `isSelected` on the `Button`
that should read as current, and manage which one that is yourself.

</div>

## Content guidelines

<DocsTable>
<thead>
<tr><th>Do</th><th>Don't</th></tr>
</thead>
<tbody>
<tr><td>Give the group a label that names the choice: "Date range".</td><td>A generic label such as "Buttons" or "Group".</td></tr>
<tr><td>Keep each button label to one or two words in sentence case: "Week", "Month".</td><td>Long or sentence-length labels that make the group wrap.</td></tr>
<tr><td>Make the labels parallel: all nouns or all verbs.</td><td>A mix such as "Week", "Show all" and "Choose".</td></tr>
<tr><td>Order the buttons the way people read the choice, such as smallest to largest.</td><td>An arbitrary order.</td></tr>
</tbody>
</DocsTable>

## Accessibility

- **A named group.** The row is `role="group"` with `label` as its accessible
  name, so assistive technology announces the buttons as one related set.
- **Each button keeps its own accessible name and state.** `ButtonGroup`
  adds no roles or attributes beyond the group wrapper.
