## For developers

- **Pick controlled or uncontrolled and stay there.** Passing <code>checked</code> puts the component in controlled mode, which makes <code>defaultChecked</code> dead. Controlled needs <code>onChange</code>. Uncontrolled needs neither.
- **<code>indeterminate</code> is display only.** It is set on the input as a property, and the underlying value is still checked or unchecked. Clicking an indeterminate box resolves it like any other, so it cannot be a third stored value.
- **A description describes and the label names.** <code>description</code> is read after the name through <code>aria-describedby</code>, so it never becomes part of the name.
- **Read-only is not disabled.** <code>readOnly</code> keeps the box in the tab order at full contrast, announces as read-only, and ignores clicks and Space. <code>disabled</code> takes it out of the tab order and fades it.
- **A checkbox with no visible label needs <code>aria-label</code>.** A row-select checkbox in a table is the usual case. Extra props go to the input.

## When to use

Use a Checkbox for an option that is saved with a form. Checking a box changes nothing until the form is submitted. Each checkbox stands alone: several are several independent yes or no answers, not one answer with parts.

- **For a setting that applies the moment it changes**, use [Toggle](?path=/docs/components-forms-and-inputs-toggle--docs).
- **Keep indeterminate for a parent with mixed children.** A select-all box, or a Tree select parent, shows indeterminate when some but not all of its children are checked. It is never a third answer to a question.
- **Give a group its question.** Several checkboxes answer one question. A [Choice group](?path=/docs/components-forms-and-inputs-choice-group--docs) wraps them in a fieldset with a legend, so the question is read with the options.

</div>

## Accessibility

- **The label is wired for you.** The component derives an id and gives it to the input and the label, so a checkbox with neither an <code>id</code> nor a <code>name</code> still has a label that names it.
- **<code>name</code> is not an id.** It is a form key, it is not unique on the page, and it never stands in for a missing id.
- **A checkbox with no label has no name.** A neighboring span or the column it sits under does not substitute. Where the design has no room for visible text, pass <code>aria-label</code>.
- **Required is forwarded.** The <code>required</code> prop reaches the input as well as drawing the asterisk, so native validation applies. The asterisk itself is named "required".
- **Indeterminate is reported as mixed.** Screen readers announce a partly checked parent as mixed.
- **There is no error state.** A checkbox that fails validation needs its message rendered and linked by you with <code>aria-describedby</code>.
- **Group related checkboxes.** Nothing connects one checkbox to the next, so related ones need a fieldset and legend, or a Choice group.
