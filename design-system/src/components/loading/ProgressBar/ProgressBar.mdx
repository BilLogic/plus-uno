## When to use

Use `ProgressBar` when the proportion done is known and worth showing — an
upload, a course, a multi-step form. If you cannot say how far along it is,
a `Spinner` is the honest control.

`value` is a percent, 0 to 100, ignored when `isIndeterminate`. `appearance`
is `default`, `success` or `inverse`.

</div>

<div className="sb-ds-doc-section">

## Usage notes

### `isIndeterminate` drops `value`.

```jsx
// Incorrect — value is announced even though the duration is unknown.
<ProgressBar value={40} isIndeterminate />

// Correct.
<ProgressBar isIndeterminate ariaLabel="Loading" />
```

### Keep `value` inside its bounds.

The drawn width and the announced `aria-valuenow` clamp together, so a
`value` outside 0–100 never draws a full bar while reporting a number past
its own maximum.

### Name the bar for what it measures.

```jsx
// Incorrect — two bars on a page both announce "Progress".
<ProgressBar value={68} />

// Correct.
<ProgressBar value={68} ariaLabel="68% of goals met" />
```

</div>

<div className="sb-ds-doc-section">

## Accessibility

- **The bar is a real progressbar.** `role="progressbar"` with
  `aria-valuenow`, `aria-valuemin` and `aria-valuemax` when determinate, and
  an `aria-label` that defaults to "Progress".
- **The indeterminate state drops the value attributes rather than faking
  one.** A screen reader hears that work is under way, not a number that
  does not mean anything.
- **Reduced motion is handled.** The indeterminate sweep stops under
  `prefers-reduced-motion: reduce`.
- **Color is not the message.** `appearance` colors the bar; it carries no
  text of its own, so pair it with a caption when the value needs to be read.

</div>

## Related

- For an indeterminate wait with no track at all, use `Spinner`.
- For the outcome when it finishes, use `Flag` or `SectionMessage`.
- For position in a hierarchy rather than progress through a task, use
  `Breadcrumb`.
