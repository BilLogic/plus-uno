## When to use

- **Is it a number?** Count.
- **Is it the condition something is in, and can that condition change?** Status.
- **Otherwise** (a subject, a focus area, a person, a category): Tag.

Who set the value no longer decides. A tag is outlined and a status is filled,
so a reader tells a category from a meaning without reading the words. Until
Status lands, a state is a `BadgeVariants` status.

</div>

<div className="sb-ds-doc-section">

## Usage notes

### Color is a category, not a status.

```jsx
// Incorrect — green reads as "went well" beside anything red.
<Tag color="green">Passed</Tag>

// Correct — pick a color per category and keep it stable, or leave every tag grey.
<Tag color="blue">Biology</Tag>
<Tag color="blue">Chemistry</Tag>
```

### Pick the behavior, not the look.

```jsx
// Read-only, the default: a value on show.
<Tag>Grade 4</Tag>

// Removable: a value the person can take out.
<Tag behavior="removable" onRemove={drop}>Grade 4</Tag>

// Selectable: a filter, with its result count.
<Tag behavior="selectable" isSelected={on} onClick={toggle} count={12}>Science</Tag>

// Link, and a link with a separate ×.
<Tag behavior="link" href="/subjects/algebra">Algebra</Tag>
<Tag behavior="link" href="/subjects/algebra" onRemove={drop}>Algebra</Tag>
```

`count` is for selectable tags only; anywhere else it is ignored with a warning.

### Disable the field, not the tag.

There is no `disabled` prop. A field or group that is disabled says so once,
and every tag inside follows:

```jsx
<TagContext.Provider value={{ isDisabled: true }}>
    <Tag behavior="removable" onRemove={drop}>Grade 4</Tag>
</TagContext.Provider>
```

`useTagContext()` reads the same value from inside a custom tag.

### Let the group own the gaps.

`Tag` sets no margin of its own. A row of tags is a `TagGroup`, which sets
`gap` once for the set.

### Renamed props.

`variant` is now `behavior` (`dismissible` is `removable`), and `orange` is now
`yellow`. The old names still work and warn in development.

</div>

## Accessibility

- **A removable tag is not itself a control.** The × is, and a button inside a
  button is invalid, so the tag is a `span` with one button in it.
- **The × is named from the label.** It announces `Remove Science`;
  `removeLabel` overrides that when the label is not text.
- **Selectable publishes `aria-pressed`**, so the state is not only visible.
  Selected also changes the border to the full hue, so it does not rest on a
  change of lightness alone.
- **A link with a × is two tab stops**, link then ×, and pressing the × never
  follows the link.
- **Saving is announced once.** The spinner is hidden; one status line says
  "Saving". The × stays focusable but does nothing until the save lands.
- **Disabled tags take no focus.** They come from a disabled field, so the
  field is what a keyboard user meets.
- **A clipped label keeps its full text** as a tooltip, set only when the label
  really is clipped.
- **The swatch is decoration** and is hidden from assistive technology.

</div>

## Related

- For a set of tags, use `TagGroup`: it owns the gaps and the overflow.
- For a number on its own, use `Count`.
- For a field where the person types values in and takes them out, use `TagInput`.
- For a state, use `BadgeVariants` until Status lands.
