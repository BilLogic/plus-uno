## When to use

Use `Popup` for a small panel of secondary content anchored to a control: a
definition, a preview or a short list. Its body is text or a short list, never a
form. For a form, use a `Modal`. It holds more than a `Tooltip` and
less than a `Modal`, and unlike a modal it does not take the page.

`trigger` is the element it hangs off, `children` the body, `title` the optional
title. `triggerType` is `click` (the default), `hover`, `focus`, an array of
those, or `manual` for a popup you drive with `show`.

It is the Popup family's Popup: one surface padded 16, with the title in
heading.xsmall over the body, and no arrow. `width` picks the tier, `sm` 320
(the default), `md` 400 or `lg` 480. It opens 4 from its trigger and never
comes nearer than 8 to the screen's edge.

</div>

## Usage notes

### Dismissal is on by default, except when you own the state.

```jsx
// A click away and Escape both close it — `rootClose` defaults to true for
// every trigger but `manual`.
<Popup trigger={<Button appearance="primary" text="Details" />} title="Session 12">…</Popup>

// With `manual` the caller owns `show`, so nothing dismisses it but the caller.
// Pass rootClose explicitly if you want the outside click to reach onToggle.
<Popup trigger={<Button appearance="primary" text="Pinned" />} triggerType="manual" show={open}
       onToggle={setOpen}>…</Popup>
```

### A string trigger is a button.

```jsx
// Fine — a string trigger renders a real <button className="plus-popup-trigger">,
// which carries the role, its own text as the accessible name, and Enter/Space.
<Popup trigger="What is this?">…</Popup>

// Also fine, and what you want when the trigger needs a Button's own styling.
<Popup trigger={<Button appearance="subtle" text="What is this?" />}>…</Popup>

// Incorrect — a `div` is not a control. `aria-expanded` is not added to it,
// because a state on something with no role is invalid ARIA. Pass a control
// instead of decorating a div.
<Popup trigger={<div>What is this?</div>}>…</Popup>
```

### Hover alone leaves out the keyboard.

`triggerType="hover"` has no keyboard equivalent. Use `['hover', 'focus']` at
least, and `click` when the content is more than a sentence — hover content that
must be read is content that has to stay put while it is read.

</div>

## Accessibility

- **The trigger announces the popup.** It carries
  `aria-haspopup="dialog"` and an `aria-expanded` that tracks the open state —
  including while the caller drives `show` themselves. Both are applied only to
  a trigger that can hold them: a `button`, an `a`, a `Button`, anything you
  have already given a `role`, and the button a string trigger becomes. A plain
  `div` gets neither, because a state on something with no role is invalid ARIA.
- **`aria-controls` is not set.** It needs the rendered panel's id,
  `id` is optional here, and an `aria-controls` pointing at an element that does
  not exist yet is worse than none.
- **Focus does not move into it, and does not have to.** A popup is not a
  dialog. But that means anything focusable inside it is reached by continuing to
  Tab, which for a bottom-placed popup comes after the rest of the row.
- **Escape and a click away both close it.** Both come from the same
  `rootClose` binding, which is on for every trigger but `manual`.
- **Do not put required content in one.** Anything the user must read to finish
  the task belongs on the page. A popup is an aside.

</div>
