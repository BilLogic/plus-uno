<Title />

The table primitive is a read-only table for records people read and compare across columns, such as students, sessions, tutors, schools and scores. You pass the column headers and the rows, and it draws a quiet table: a 12px muted header with a stronger rule under it, flat rows with hairline rules between them, and no zebra striping. StaticTable is planned. Today this primitive is the table to use for read-only data.

## Variants

### Frame

Plain is the default on a page: the table spans its section with no outer frame, and its first and last cells are flush with the section edge. Use framed when the table sits beside other content and needs its own edge, such as inside a modal body.

### Row size

Rows are 32, 40 or 48 tall at minimum. Pick by how much each row holds, not by screen width: small for dense admin lists, medium for most tables, large when rows hold avatars or two lines. Two-line cells grow the row.

## States

Rows rest, or are highlighted to mark a new or changed row. Hover, pressed, focus, selected and disabled rows belong to the Dynamic and Tree tables. Highlighted is the warning background across the whole row. Focus is always a 2px focus ring drawn inside the cell or row, so a sticky header or the scroll container never clips it, and it never adds a fill.

## When to use

Use the table when nothing about the table’s data changes on its own: no sorting, filtering, selection, paging, row expansion, row actions or inline edits. A link inside a cell is fine. Rows rest, or are highlighted to mark a new or changed row. The table sits inside a Section and spans it. The Section header above it carries the title and any action that leaves the rows as they are, such as Export, so the table never has a toolbar of its own.

- For a table people sort, filter, select, page or act on, use a Dynamic table. It is planned, and the table pattern is what to build it from today.
- For rows that nest under other rows, use a Tree table, also planned.
- For a list of records with no columns to line up, use List group.
- For one item among many, use Card.

Not sure which type? See the Which table? rule on the <a href="?path=/docs/components-text-and-data-display-static-table--docs">Static table</a> page, and the <a href="?path=/docs/foundations-patterns-table--docs">table pattern</a> for the table in a Section.

Colors follow the toolbar’s Color mode and Contrast switches.

</div>

## Accessibility

- **Every header is a column heading.** The primitive draws each header as a column heading cell, so a screen reader announces it with every cell below.
- **Name a row-select control.** A checkbox in a cell needs its own label, because the column heading does not name it. Label an icon button for its row, such as “More actions for Ava Lee”.
- **Put keyboard actions in a control, not a row.** A row has no button role and no key handling. A row that needs a keyboard action needs a real button or link inside a cell.
- **Show truncated text in full.** A truncated cell shows its full value in a tooltip on hover and focus. Wrap the text people must read in full.
- **Do not mark state with color alone.** A highlighted row needs words or an icon beside it. An error cell carries its icon and a message.
- **Keep contrast.** Text, rules and fills keep their contrast in every Color mode and Contrast setting.
