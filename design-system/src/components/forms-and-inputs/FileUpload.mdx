## For developers

- **One array does two jobs.** <code>acceptedFormats</code> becomes the input's <code>accept</code> filter and, unless you pass your own <code>description</code>, the line of help text under the label.
- **<code>onChange</code> is the input's own change event.** The files are at <code>event.target.files</code>.
- **Render the chosen file yourself.** The button text never changes and the component shows no file name after a pick. Keep the file in your state and pass a list of files as children, or render the name beside the field.
- **Keep <code>label</code> a string.** The label is also written to the input's accessible name, and a node becomes "[object Object]". Put the qualification in <code>description</code>, which is prose.
- **<code>accept</code> is a filter and not a check.** The picker offers the listed types first and every platform lets the person override it. Check the file after it arrives, for type, size and count, and report it through <code>validation</code> and <code>validationMessage</code>.

## When to use

Use a File upload when the form needs a file from the person's device, such as a report, an avatar or a signed form. For a link, use [Text field](?path=/docs/components-forms-and-inputs-text-field--docs). For several short typed values, use [Tag input](?path=/docs/components-forms-and-inputs-tag-input--docs).

- **Write the error, not the fact that there is one.** Check the file after it arrives, for type, size and count, and say what to do next.
- **Put the formats in the description and not the label.** The label is also the input's accessible name, so keep it a short string. Formats and limits are prose and belong on the line under the label.
- **Show the chosen file yourself.** The component shows none after a pick, so render the file name where the person can see it.

</div>

## Accessibility

- **The control is a real file input.** The label points at it, it takes the accepted-types filter and the disabled attribute, and it fires a genuine change event, so all the platform behavior is intact.
- **It is one control with two tab stops.** The input is hidden at zero size and not removed, so the keyboard reaches the invisible input first and the visible button second. Focusing either draws the field's focus border, so the stop is at least visible. Enter on the first opens the picker just as the second does.
- **The description and the message are both attached.** The format rules and the validation message each have an id, and the input points at both, in that order. "PDF, up to 10 MB" is heard before "that file was too large" and not in place of it. An invalid field is also marked invalid.
- **Required marks the label only.** The asterisk is decoration, and the input carries no required attribute.

</div>
