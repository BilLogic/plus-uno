## Usage

Use `ProgressTracker` when each step of a journey has its own name people
need to see and, often, jump back to — a multi-page form, a setup flow, a
reflection with named sections. When position alone is enough and the steps
have no names to show, use `ProgressIndicator` instead.

</div>

<div className="sb-ds-doc-section">

## Parts

1. **Marker.** A dot for unvisited, current and disabled steps; a success check for a visited step.
2. **Label.** One line, truncating with an ellipsis.
3. **Step.** A link, a button or plain text, with <code>aria-current="step"</code> on the current one.
4. **Rule.** A hairline joining horizontal steps.

## Best practices

### An item's status and its action are set separately.

`status` alone decides how a step looks. Give any non-`disabled` item an
`href` or `onClick` to make it reachable; without either, it renders as plain
text even if its status says it can be revisited.

```jsx
<ProgressTracker
    items={[
        { id: 'info', label: 'Session information', status: 'visited', onClick: goTo('info') },
        { id: 'reflection', label: 'Student reflection', status: 'current' },
        { id: 'feedback', label: 'Form feedback', status: 'disabled' },
    ]}
/>
```

### A `disabled` item takes neither a link nor a button, whatever is passed.

This keeps a step someone cannot reach yet from being focusable or clickable,
regardless of what `href` or `onClick` the caller supplies.

## Accessibility

- **A named landmark.** The tracker is a `nav` with `label` as its accessible
  name ("Progress tracker" by default), and its steps are an ordered list.
- **The current step is `aria-current="step"`.** Screen readers announce it
  as the one in progress.
- **Reachable steps are real links or buttons.** Tab reaches any non-`disabled`
  step that carries `href` or `onClick`; `disabled` steps are marked
  `aria-disabled` and are not in the tab order.

</div>
