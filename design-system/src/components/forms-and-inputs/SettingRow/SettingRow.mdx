## Usage

Use `SettingRow` on settings and preference pages where each row adjusts one independent setting or external connection that takes effect immediately. Stack related rows directly under a section heading: adjacent `SettingRow` elements divide with a `1px` border at `--setting-row-pad-y` (`12px`) vertical padding, with no card per row.

</div>

<div className="sb-ds-doc-section">

## Alternatives

- For fields edited and submitted together with a Save button, use stacked form fields inside `Fieldset` (see <a target="_top" href="./?path=/docs/patterns-forms--docs">Forms</a>).
- For an option inside a submitted form, use `Checkbox` rather than `Toggle` or `SettingRow`.
- For one value on a record page read far more often than edited, use `InlineEdit`.

</div>

<div className="sb-ds-doc-section">

## Parts

1. **Label (`label`) and status (`status`).** Strong `--body-default` setting name at the start, with an optional `StatusTag` beside it so the end slot holds only the interactive control.
2. **Description (`description`).** One line of `--body-small` subtle context under the label, or the visible prerequisite/permission reason when disabled or read-only.
3. **Inline error (`error`).** Optional danger error message rendered directly under `description` when a background save fails.
4. **Control (`control` at `end`).** Top-aligned to the label row: a `Toggle` (with no `label` prop), a compact `Select` (`spacing="compact"`), or a compact `Button`.

## Best practices

### Omit Toggle's own label inside SettingRow.

`SettingRow` wires its `label` to `control` through `aria-labelledby`. Passing a second `label` on `Toggle` repeats the text visually and at the end of the row.

<DoDontPair
    doExample={<SettingRow label="Session reminders" description="Send an email before each scheduled session." control={<Toggle defaultChecked />} />}
    doCaption="Row label at the start names the bare Toggle at the end."
    dontExample={<SettingRow label="Session reminders" description="Send an email before each scheduled session." control={<Toggle label="Session reminders" defaultChecked />} />}
    dontCaption="Toggle repeats its own label in the end slot."
/>

### Put connection status beside the label, never in the control slot.

Pass `StatusTag` through `status` so every row's end slot holds only its action control.

<DoDontPair
    doExample={(
        <SettingRow
            label="Google Calendar"
            description="Sync upcoming tutoring sessions to your calendar."
            status={<StatusTag appearance="success">Connected</StatusTag>}
            control={<Button spacing="compact">Disconnect</Button>}
        />
    )}
    doCaption="StatusTag sits beside the label; Disconnect stands alone at the end."
    dontExample={(
        <SettingRow
            label="Google Calendar"
            description="Sync upcoming tutoring sessions to your calendar."
            control={(
                <span style={{ display: 'inline-flex', alignItems: 'center', gap: 'var(--inline-sm)' }}>
                    <StatusTag appearance="success">Connected</StatusTag>
                    <Button spacing="compact">Disconnect</Button>
                </span>
            )}
        />
    )}
    dontCaption="Status crowds the action at the end of the row."
/>

### State the reason in description when a setting is disabled.

When a setting waits on another setting on the same page, explain how to unlock it in `description` rather than hiding it in a tooltip.

<DoDontPair
    doExample={(
        <SettingRow
            label="Reminder lead time"
            description="Turn on session reminders above to choose a lead time."
            isDisabled
            control={<Select spacing="compact" isSearchable={false} options={[{ value: '1h', label: '1 hour before' }]} value="1h" onChange={() => {}} />}
        />
    )}
    doCaption="Description names the prerequisite on the same page."
    dontExample={(
        <SettingRow
            label="Reminder lead time"
            isDisabled
            control={<Select spacing="compact" isSearchable={false} options={[{ value: '1h', label: '1 hour before' }]} value="1h" onChange={() => {}} />}
        />
    )}
    dontCaption="Disabled control gives no clue why it cannot be changed."
/>

## Accessibility

- **Label names the control.** `SettingRow` links its `label` span to `control` via `aria-labelledby`, so a `Toggle` announces `"Session reminders, switch, on"` without needing its own visible label, and `status` text beside the label does not pollute the switch's accessible name.
- **Self-describing action buttons.** When `control` carries visible action text (such as a `Disconnect` `Button`), `SettingRow` combines the button's own id with the row label id in `aria-labelledby` (`"Disconnect Google Calendar"`), keeping multiple connection rows distinct for screen-reader users while satisfying WCAG 2.5.3 Label in Name.
- **Readable descriptions and announced errors.** `description` and `error` link to `control` via `aria-describedby`; `error` renders with `role="alert"` and sets `aria-invalid="true"`.
- **DOM order matches reading order.** Label, status, description, and inline error precede the end control in the DOM so Tab and virtual-cursor order match visual reading order.

## Related

- `Toggle`: use as `control` when a setting turns on or off and applies immediately.
- `Select`: use with `spacing="compact"` as `control` when a setting picks one option from a short list.
- `StatusTag`: pass to `status` to show connection or feature state beside the setting name.
- `Flag`: use in `FlagGroup` to confirm background saves on a settings page.
