## Usage

Use `ScrollBar` when a region has to scroll inside a page that does not — a long
list in a fixed panel, a wide table in a narrow column. It is a wrapper: it caps
the height, turns on overflow, and applies the design system's thin scrollbar so
the region does not draw the platform's default one.

`maxHeight` (default twice the `2000` size, 320 tall) caps a vertical region. `horizontal` switches the
axis, and in that mode `maxHeight` is ignored — the width comes from the
container.

</div>

## Parts

1. **Region.** The wrapper that caps the height and scrolls.
2. **Track.** Transparent, so it never reads as a second edge.
3. **Thumb.** The border-colored bar, darker under the pointer.

## Best practices

Use a scroll region when a part of the page has to scroll inside a page that does not.

### One scrollbar per region.

Two bars side by side suggest two scrolling areas where there is one. Do not nest one region inside another on the same axis.

<DoDontPair
    doExample={<div style={box}><ScrollBar maxHeight={smallCap} aria-label="Notes, one region"><Notes count={12} /></ScrollBar></div>}
    doCaption="A single scrollbar."
    dontExample={<div style={box}><ScrollBar maxHeight={smallCap} aria-label="Notes, outer region"><div style={{ ...box, margin: 'var(--pad-y-lg) var(--pad-x-md)' }}><ScrollBar maxHeight="calc(var(--size-spacing-xlarge-space-2000) * 1.25)" aria-label="Notes, inner region"><Notes count={20} /></ScrollBar></div></ScrollBar></div>}
    dontCaption="A region nested in another: two scrollbars on one region."
/>

### Keep the track thin.

The scrollbar stays at its natural width; stretching it competes with the content. It has no width prop, so leave its styling as shipped.

### Wrap only content that overflows.

A region around content that already fits shows no bar and still adds a tab stop with nothing to scroll.

<DoDontPair
    doExample={<div style={box}><ScrollBar maxHeight={smallCap} aria-label="Notes, long list"><Notes count={12} /></ScrollBar></div>}
    doCaption="A region around a list that overflows."
    dontExample={<div style={box}><ScrollBar maxHeight={smallCap} aria-label="Notes, short list"><Notes count={2} /></ScrollBar></div>}
    dontCaption="A region around two short items."
/>

### It caps the height; it does not fill one.

`maxHeight` is a cap. In a taller container, give the region the height you want it to take, such as `maxHeight="100%"`.

<DoDontPair
    doExample={<div style={{ ...box, height: 'calc(var(--size-spacing-xlarge-space-2000) * 1.5)' }}><ScrollBar maxHeight="100%" aria-label="Notes, filled"><Notes count={16} /></ScrollBar></div>}
    doCaption="The region fills its container and scrolls."
    dontExample={<div style={{ ...box, height: 'calc(var(--size-spacing-xlarge-space-2000) * 1.5)' }}><ScrollBar maxHeight={smallCap} aria-label="Notes, capped"><Notes count={16} /></ScrollBar></div>}
    dontCaption="A smaller cap leaves the space below it empty."
/>

### Name each region.

```jsx
// Incorrect — two scroll regions on a page, both announced as the default
// "Scrollable content".
<ScrollBar><SessionList /></ScrollBar>
<ScrollBar><NoteList /></ScrollBar>

// Correct.
<ScrollBar aria-label="Sessions"><SessionList /></ScrollBar>
<ScrollBar aria-label="Notes"><NoteList /></ScrollBar>
```

### One axis, not both.

`horizontal` chooses which axis is styled and which cap applies. A region that
scrolls both ways is usually a sign the content should be laid out differently —
a table that needs horizontal scroll inside a page that scrolls vertically is
the case this handles, and that is one axis each.

## Accessibility

- **The region is focusable on purpose.** `tabIndex={0}` is what lets a keyboard
  user scroll it with the arrow keys, and it is what satisfies the
  scrollable-region-focusable rule. It is a tab stop, which is the cost of being
  reachable.
- **It has a name, and the default is generic.** `aria-label` defaults to
  "Scrollable content". One per page is tolerable; two are indistinguishable.
- **It is deliberately not a landmark.** No `role="region"` — a role would make
  every scroll area a landmark, and several on one page would collide under the
  unique-landmark rule. The label names the tab stop instead.
- **Do not hide the last row.** A scroll region whose content ends exactly at the
  cap looks finished. Leave the cut visible, or the user will not know to scroll.
