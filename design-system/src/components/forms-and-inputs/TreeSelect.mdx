## For developers

- **Value and onChange match the mode.** <code>value</code> is a single value in single mode and an array with <code>multiple</code>, and <code>onChange</code> matches. Options take strings, or a label or text, a value, children and disabled.
- **Selecting a parent selects its subtree.** In multiple mode, toggling a node toggles every descendant, and a parent shows the dash when only some of its children are selected. The value you receive is the flat list of every selected node, parents included. To keep only leaves, filter the array you are handed.
- **Values must be unique across the whole tree.** Lookup is a depth-first search by value and selection is a flat set, so the same value under two parents is one node.
- **The id lands on the input**, so a label pointing at it names the field.

## When to use

Choose Tree select when a parent or several nodes are valid answers, or when people need the hierarchy in view to choose, such as a subject tree, a folder or an organization.

- **A parent node is a valid answer.** Single mode commits any node, parent or leaf.
- **The answer is a set.** Multiple adds a checkbox to every node, and a partly checked parent shows which branches are partly chosen.
- **People need the hierarchy in view.** The tree shows siblings and depth together, which a column per level hides.
- **Keep the tree short to scan.** Every open branch adds rows to scroll past. Keep parents closed until people open them, and lead with search once the tree passes 50 nodes.
- **Name the parent, not every child.** When every child of a parent is checked, the field shows the parent alone. A partly checked parent shows the dash, so people can see a branch is only partly chosen.
- **For one leaf along a fixed path**, use [Cascader](?path=/docs/components-forms-and-inputs-cascader--docs).
- **For one value from a flat list**, use [Select](?path=/docs/components-forms-and-inputs-select--docs).
- **For several values from a flat list**, use Select in multi mode, or [Tag input](?path=/docs/components-forms-and-inputs-tag-input--docs).
- **For an action rather than a value**, use [Dropdown menu](?path=/docs/components-forms-and-inputs-dropdown-menu--docs).

## Accessibility

- **The roles are announced.** The field is a combobox that says whether the tree is open, the panel is a tree, and every node is a tree item that announces whether it is expanded or selected, its level, and whether it is disabled.
- **The tree walks with the arrow keys.** Down opens it from the field. Up and Down move through the rows that are showing. Right opens a branch and then steps into it. Left closes one and then steps out to its parent. Home and End jump. Enter and Space choose.
- **One tab stop, on the cursor.** Tab leaves the tree rather than walking it. Opening starts on the selected node, with its ancestors expanded for you, or on the first row.
- **Escape closes it and returns focus to the field.** So does choosing, in single mode. In multiple mode choosing leaves the panel open, because people usually choose again.
- **Expanding is not selecting.** The caret expands and collapses without changing the selection, and Right and Left do the same from the keyboard. Clicking or pressing Enter anywhere else on the row selects it, including a parent.
- **A partly checked parent is announced as mixed**, not as unchecked.
- **Name the field.** Point a label at it, or pass an <code>aria-label</code> or <code>aria-labelledby</code>.
