<FoundationSection title="Springs">

A spring has no fixed duration. It is pulled toward its target and settles when it arrives, so it can be interrupted, reversed and handed the speed of a hand at any moment. Linear motion is the one exception: it is for things that follow time or the pointer one to one.

Every demo on this page draws each path from start to landing first, then plays. Use its speed control to watch at ½× or ¼×.

<FoundationSubsection title="How quick and how bouncy">

A spring has two settings: how quick it is (stiffness) and how bouncy it is (damping ratio). At ratio 1 it lands on its target and stays. Below 1 it passes the target and comes back: 0.8 by about 1.5%, 0.6 by about 9.5%. Damping, below, compares them side by side.

Each time is given twice: to 90%, when the motion reads as arrived, and to settled, within 1% of the target.

</FoundationSubsection>

<FoundationSubsection title="Modes and tokens">

Elsewhere in the docs a token drops its `motion.` prefix (`spatial.fast`), and "Expressive `spatial.fast`" means that token in Expressive mode. Every number below is read from the generated spring config, the same table the CSS easings and every demo use.

<SpringTokenTable />

All tokens are mass 1. Figma has no motion tokens; a Figma prototype uses the nearest spring as a proxy.

**Productive** is the mode for everything. **Expressive** is switched on for one container at a time (`data-motion="expressive"`), at two levels, for these moments only:

- **Finish:** every completed reflection. The confirmation Flag lands with one overshoot on Expressive `spatial.fast`.
- **Milestone:** onboarding complete, first session done, a student's goal reached, term start and term end. The one card in the hero entrance is Expressive. A goal shows once per person: the student sees it the moment it happens, the tutor the next time they open that student.

Expressive marks the end of something worth finishing, a few times a week at most. Controls, fields and anything done dozens of times a day stay Productive. Inside an Expressive container, page transitions and data marks stay Productive too, because an overshooting page or bar shows something that isn't true. This is the only list of Expressive moments; other pages point here.

**The shake** is the one other bounce. A blocked submit shakes its container once: a loose spring (stiffness 1187.5, damping 15, mass 1) kicked sideways at 420 px/s. It peaks at 9 px after 40 ms and settles back, and it can be interrupted like every spring. It is one pattern, used by Modal, a field with its own button and InlineEdit, and it is not a token.

<FoundationSubsection title="Exits">

Two questions decide how something leaves.

1. **Can it come back?** If yes (a floating Panel, the Sidebar, a docked Panel), it reverses its entrance one speed faster (`fast` stays `fast`) and settles at the edge, held there.
2. **If it is gone for good, who started it?**
   - **The system** (a Flag timing out): `spatial.exit`. It is aimed 3.8 times past the edge, so it is still speeding up when it crosses and leaves at full speed.
   - **The person, with a click** (a close button, a deleted row): a quick fade on `appearance.fast`, in place. The rows around a deleted row close the gap on `spatial.fast`.
   - **The person, with a flick:** `spatial.exit` starts from the hand's velocity instead of from rest, so it leaves at the speed it was thrown.

An exit is shorter than its entrance and lands without a bounce. A floating layer may shrink 2% as it fades (a Modal to 98%). Every component names an enter and exit pair, and the exit is the entrance one speed faster, so there is no second token set.

<Canvas of={PhysicsStories.Exits} sourceState="none" />

</FoundationSubsection>

<FoundationSubsection title="Loops">

`motion.loop` is a spring with no damping, so it swings as a sine wave, one cycle every 1.2 s, and never settles. Three typing dots are the same loop, each an eighth of a cycle behind the one before. To end a loop softly, turn the damping back on and it settles at rest.

- A loop runs only while work runs (loading, thinking, typing) and stops the moment the work ends.
- A decorative loop stops by 5 s.
- Every loop has a pause.
- In Reduced mode a loop becomes a static label, such as "Thinking".

<Canvas of={PhysicsStories.Loops} sourceState="none" />

</FoundationSubsection>

<FoundationSection title="Velocity">

What a hand moves keeps the hand's speed.

- **Dragging, splitters, swipes and scrubbing run a live spring** that starts from the release velocity, so nothing jumps when the hand lets go.
- **Opening, closing and selecting use the token as CSS.** There is no velocity to carry.
- **Past a limit, it resists, then returns** with the hand's speed. The limit stays visible without a hard stop (Damping at a limit, below).
- **A throw is decided by where it would land,** so a short fast flick dismisses and a long slow drag that lets go does not.
- **The decision shows before release** as an armed state, so the person can still take it back.
- **Gestures stay contained:** a press is not a drag, and the page never scrolls under the hand.

Values for engineers: projected rest = velocity ÷ 1000 × 0.998 ÷ 0.002; resistance follows √overshoot × 4 px and returns on `spatial.fast`; 3 px slop before a drag starts, pointer capture, `touch-action: none`.

<FoundationSection title="Weight">

Pixels weigh nothing, so weight in PLUS is conceptual: how much a thing holds, and how much it costs to undo. It is chosen by token, never by mass (every token is mass 1).

**Size.** Bigger things travel on slower tokens: a control on `fast`, a layer on `default`, a page on `slow` (Speed follows size and distance, above).

**What you carry.** Something dragged follows the pointer on a spring, and how closely it follows says how much it holds. A tag or a name keeps right under the pointer on `spatial.fast`. A whole card, which carries a record, trails a touch on `spatial.default` and settles a beat after the drop. Neither bounces: weight shows as lag, never as wobble. The lag stays small; a carried thing that falls far behind the hand reads as slow, not heavy.

<Canvas of={PhysicsStories.Carry} sourceState="none" />

**What it costs.** A destructive action is heavy in a different way: it gets friction, not slower motion. Deleting or removing something that can't be undone asks for a second, deliberate step (a Modal that names what goes). The animation stays on its normal token; the weight is in the extra step.

</FoundationSection>

<FoundationSection title="Damping">

Damping is how much a motion is held back. In the spring itself, it is how far the motion passes its target.

These four share one stiffness, `spatial.default`'s, and differ only in damping ratio. The line under each is its position over time; the dashed line is the target. Productive motion uses ratio 1 everywhere. Expressive uses 0.8 and, for small things thrown with energy, 0.6. Every token stays at 0.6 or above: below that a spring rings, swinging back and forth before it settles.

<Canvas of={PhysicsStories.Damping} sourceState="none" />

<FoundationSubsection title="Damping at a limit">

Dragged past where it can go, a thing moves less and less instead of stopping dead: the square root of the extra distance, × 4 px. On release it springs back on `spatial.fast` with the hand's speed. The limit is felt before it is seen, and the interface never freezes under the hand.

</FoundationSubsection>

</FoundationSection>

<FoundationSection title="One spring, five ways">

One token, written for each target it ships to. Damping = 2 × ratio × √(stiffness × mass), and response = 2π ÷ √stiffness.

<OneSpringFiveWays />

**Loops in CSS.** CSS can't repeat a generated `linear()` easing, so `motion.loop` ships as its own sine shape running back and forth over half a cycle (600 ms, alternating). It is the spring written the only way CSS can repeat it.

</FoundationSection>

<FoundationSection title="In code">

CSS reads a semantic token as a `linear()` easing plus its settle time. Components read the `--ds-motion-*` semantics only, never a `--motion-spring-*` primitive, and reduced motion is handled once, in the token layer.

```css
transition: transform var(--ds-motion-spatial-default-duration) var(--ds-motion-spatial-default);
```

JS motion (drag, throw, interruption, layout) uses the `motion` package, configured from the same table:

```js
import { animate } from 'motion';
import { SPRINGS } from '@/tokens/ladder/springs.generated.js';

animate(panel, { x: 0 }, SPRINGS['spatial.default'].productive);
```
