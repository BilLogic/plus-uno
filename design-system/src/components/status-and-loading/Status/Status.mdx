## When to use

Use `Status` for the condition something is in when that condition can change:
completed, needs review, missed, in progress, due tomorrow, overdue. It is the
same component whether the system calculated the state or a person set it.

- **Is it a number?** Count.
- **Is it the condition something is in, and can that condition change?** Status.
- **Otherwise** (a subject, a person, a category): Tag.

Use `size="medium"` (20) in rows, lists and sentences, and `size="large"` (32)
beside a heading. Status replaces the BadgeVariants `status` and `date`
variants; their callers move in a later change.

</div>

## Usage notes

### Let the style carry a meaning.

Each style means one thing: neutral (not started), success (done), warning
(needs attention), danger (failed or missed), info (in progress) and discovery
(new). There is no color prop; a category with a color is a Tag.

```jsx
// Incorrect — a category borrowing a status color.
<Status style="info">Math</Status>

// Correct — a condition that can change.
<Status style="info">In progress</Status>
```

### Let the app pick a date's style.

A date is neutral when it is not close, warning when it is due soon and danger
when it is overdue. Derive the style from the date and the due-soon window,
and write the label as people say it.

```jsx
<Status type="date" style="warning">Due tomorrow</Status>
<Status type="date" style="danger">2 days overdue</Status>
```

### Nest a count instead of placing one beside it.

```jsx
// Incorrect — two labels that read as unrelated.
<Status style="success">Completed</Status> <Count value={38} />

// Correct — one label; the number reads as part of it.
<Status style="success" count={38}>Completed</Status>
```

### Edit in the field, not on the label.

A Status never opens a menu. Where a status can be changed, the field around it
becomes an inline Dropdown whose options are grouped To do · In progress ·
Complete · Exception · Failed, each group with one style (neutral · info ·
success · warning · danger).

</div>

## Accessibility

- **Read as its text.** A Status is a `span` with no role, so a screen reader
  announces its text and nothing suggests it can be pressed. An `onClick` is
  dropped with a development warning.
- **Not a tab stop, unless truncated.** When the label is clipped, the Status
  takes focus so a keyboard user can reach the tooltip holding the full text;
  pointer users get the same tooltip on hover. The full text is always in the
  DOM, so a screen reader hears all of it.
- **Not color alone.** Dates differ in icon as well as color (calendar, clock,
  alert), and a state can add a `leadingVisual` where color alone is not enough.
  Icons are decorative and hidden from assistive technology.
- **An edge on any surface.** The 1px inside border keeps a pale fill visible
  on white and on grey; in forced-colors mode it becomes a real border.
