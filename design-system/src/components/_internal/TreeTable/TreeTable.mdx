## What it is

The first column is the tree column. It holds the indent, the 12px toggle and the record name. Only parents have a toggle, and leaf rows keep its space so names stay aligned. A Tree table is never mixed with flat Static or Dynamic table rows in one block.

Colors follow the toolbar’s Color mode and Contrast switches.

## Which table?

Pick the type from what people do with the rows. Rows they only read are a Static table. Rows they sort, filter, select, page or act on are a Dynamic table. Rows that nest under other rows are a Tree table, and nesting wins even when the table is interactive.

The <a href="?path=/docs/foundations-patterns-table--docs">table pattern</a> shows how a table sits in a Section, with its pagination and empty-state slots.

## When to use

Use a Tree table when a row has children. Nesting wins over everything else, even in an interactive table. Keep trees shallow: three levels is the most a Tree table should show. Deeper structures need a different view, such as opening the record on its own page.

- For records people only read, with no nesting, use a Static table.
- For a table people sort, filter, select or page, with no nesting, use a Dynamic table.
- For picking one item from a hierarchy, with no columns, use Tree select.

</div>

<div className="sb-ds-doc-section">

## Accessibility

- **Name each toggle for its row,** such as “Expand Algebra I row”, and say whether the row is expanded.
- **Make the level readable without the indent.** The level is part of the row’s structure, so a screen reader can say how deep a row is.
- **Give the toggle its own focus.** It is a separate control from the row, with its own hover and focus ring.
- **Do not mark selection with color alone.** A selected row shows a checked box as well as the fill.
- **Keep contrast.** Text, rules and fills keep their contrast in every Color mode and Contrast setting.
