## For developers

- **The grid is fully controlled.** It holds no state of its own. In radio mode <code>values</code> maps each row id to a column id. In checkbox mode it maps each row id to an object of column ids and booleans.
- **<code>onChange</code> has two shapes.** In radio mode it receives the row id and the column id that changed, and you merge them. In checkbox mode it receives the whole new values object, already merged. The copy is fresh, so the object you passed in is left as it was.
- **A radio row cannot be unanswered again.** Choosing a column always sets it. If "not answered" is meaningful, add a column for it, such as Not applicable, rather than leaving a row the person cannot clear.
- **Radio rows share a name** built from the grid's id and the row's id, which gives one answer per row and arrow-key movement along it. Without an id the grid generates its own base, so two grids on a page never share ids or groups.

## When to use

Use a Choice grid when every question has the same answers, such as rating each of six statements, or ticking which tools each tutor uses. A grid saves repeating one Choice group per question. If the answers differ from row to row, ask each question on its own.

- **Keep the column headers short.** A header names every control in its column for screen readers. Use one or two words, such as "Never", "Sometimes" and "Often".
- **Choose the type by the answer, not the look.** Use radios when each row takes exactly one answer, and checkboxes when a row may take several, or none.
- **Keep the grid small.** Every cell is a control, so a six-by-five grid is thirty tab stops. Past that, ask the questions one at a time in a [Choice group](?path=/docs/components-forms-and-inputs-choice-group--docs).

</div>

## Accessibility

- **Every cell is named by its row and its column.** Each control points at both the row label and the column header, so it is announced as "Punctuality, Agree" and not as an unnamed radio in a table.
- **Every cell is the real control.** Cells are Checkbox and Radio, so focus, states and read-only behave as they do anywhere else.
- **The grid itself has no name.** There is no caption and no label on the table. Put the question above it as a heading, and describe the scale in the column headers.
- **The row-header corner is hidden text.** The corner cell carries a visually hidden "Row", so the header row has no blank cell.
- **On a narrow screen this is a wide table.** Put it in a horizontal scroll container and not let the columns crush, because a header the person cannot read is a question they cannot answer.
