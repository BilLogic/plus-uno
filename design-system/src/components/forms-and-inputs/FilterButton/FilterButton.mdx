## When to use

Use `FilterButton` for a control that opens a filter's options or toggles a
filter on and off, above a table or a list. For a value already chosen and
removable, show it as a `Tag` instead; `FilterButton` is the trigger, not the
applied result.

</div>

<div className="sb-ds-doc-section">

## Usage notes

### Show the count only once something is applied.

Pass `trailingMetric` when at least one option is selected; leave it out
entirely rather than passing `0` as a placeholder for "none applied" —
`0` renders as a visible count of zero, not an empty state.

```jsx
<FilterButton text="Status" trailingMetric={selected.length || undefined} />
```

### Turn off the chevron only when the button doesn't open a menu.

`hasChevronDown` defaults to `true`. Set it `false` only for a filter that
toggles directly on click, with nothing to open.

</div>

<div className="sb-ds-doc-section">

## Accessibility

- **A real button, unchanged.** `FilterButton` renders a `Button`
  underneath, so focus, activation and disabled/loading states all follow
  `Button`'s own contract.
- **The chevron is decorative.** It signals that a menu opens, but the
  accessible name comes from `text` and, when present, the applied count.

</div>

<div className="sb-ds-doc-section">

## Related

- For the applied value once chosen, use `Tag`.
- For a single action that isn't a filter, use `Button`.
