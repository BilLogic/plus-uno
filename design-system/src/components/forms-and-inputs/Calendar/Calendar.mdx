## When to use

Use `Calendar` directly only when a date grid needs to be visible on the page
without a field or a popup around it — a scheduling view, an embedded picker.
For a single date field, use `DatePicker`; for a date and time together, use
`DateTimePicker`. Both already use this same grid internally.

</div>

<div className="sb-ds-doc-section">

## Usage notes

### `viewDate` and `onViewDateChange` are the component's own navigation state.

`Calendar` holds no state of its own — the caller owns which month shows and
updates it when `onViewDateChange` fires, the same pattern `DatePicker` uses
internally.

```jsx
const [viewDate, setViewDate] = useState(new Date());

<Calendar
    viewDate={viewDate}
    onViewDateChange={setViewDate}
    selected={selectedDate}
    onPick={setSelectedDate}
/>
```

### A fixed grid, not a shrinking one.

Six weeks render every month, including the days of neighboring months that
fill the remaining cells — this keeps the panel's height constant as someone
pages through months, at the cost of occasionally showing a mostly-empty
week.

</div>

<div className="sb-ds-doc-section">

## Accessibility

- **Each day is a real, named button.** The accessible name is the day's
  full date, not just a number, so a screen reader announces an unambiguous
  date on every cell.
- **State is marked, not just styled.** `aria-pressed` marks the picked day
  or a range's ends, `aria-current="date"` marks today, and `data-in-range`
  marks the days between — none of this relies on color alone.
- **Out-of-range and out-of-month days are truly disabled**, not just dimmed:
  they take no focus and fire no `onPick`.

</div>
