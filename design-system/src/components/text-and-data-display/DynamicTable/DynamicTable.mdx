## Usage

Use `DynamicTable` for a table of sessions or records where people act on the
data: sort a column, filter or search the rows, select some for a bulk action,
or split a long result across numbered pages. It holds its own sort and page until the page passes `sortKey` or `page`.

</div>

<div className="sb-ds-doc-section">

## Alternatives

- For a fixed grid people only read or a nested hierarchy, use `Table`.

</div>

<div className="sb-ds-doc-section">

## Parts

1. **Head cell.** A label with an optional type icon; a sortable one holds a button across the whole cell.
2. **Sort arrow.** `12` tall; hidden until hover or focus, kept once sorted.
3. **Row.** Cells in a band, with hover and selected grounds.
4. **Footer.** States the range on a table that pages.
5. **Message row.** The `loading` and `error` states, spanning every column under the head row. `empty` and `no results` replace the whole table with `EmptyState`.
6. **Checkbox column.** With `isSelectable`: as wide as the row is tall, select-all in the head.
7. **Bulk bar.** While rows are selected, the head row itself: select-all in its cell, then the count and `bulkActions` in one cell across the columns. The labels cross-fade in place and the row keeps its height.
8. **Frozen column.** With `isFrozen`: an opaque first column with a stronger divider while scrolled sideways.

## Best practices

### Give a column a sortable key.

A date needs a key that sorts, such as `20261024`, and its readable text as `content`.

<DoDontPair
    doExample={<DynamicTable head={sortHead} rows={keyedRows} label="Sessions" defaultSortKey="date" defaultSortOrder="ascending" />}
    doCaption="A key per cell sorts chronologically rather than alphabetically."
    dontExample={<DynamicTable head={sortHead} rows={plainRows} label="Sessions" defaultSortKey="date" defaultSortOrder="ascending" />}
    dontCaption="No key, so the formatted strings sort alphabetically instead."
/>

### Say what an empty table is for.

`empty` and `no results` replace the whole table (header row, footer and pagination included) with `EmptyState`. Word the message with `emptyView`.

<DoDontPair
    doExample={<DynamicTable head={sortHead} rows={[]} label="Sessions" emptyView="No sessions yet. They appear here once one is booked." />}
    doCaption="A message that says what is missing and what happens next."
    dontExample={<DynamicTable head={sortHead} rows={[]} label="Sessions" emptyView="No data" />}
    dontCaption="No data, with no hint of why."
/>

### Page a long list, and truncate each cell.

The table shows one page and never grows with the list. A cell longer than its column ends in an ellipsis with a Tooltip while it is clipped. See [Overflow](?path=/docs/patterns-states-overflow--docs).

### Page on the server when the list is long.

With `totalRows`, `rows` is the current page only (`rowsPerPage`), and the footer counts against the total.

<DoDontPair
    doExample={<DynamicTable head={sortHead} rows={keyedRows} label="Sessions" rowsPerPage={3} totalRows={8500} />}
    doCaption="One page of rows, counted against the total."
    dontExample={<DynamicTable head={sortHead} rows={keyedRows} label="Sessions" rowsPerPage={3} />}
    dontCaption="The whole list loaded to page on the screen, when it is thousands of rows."
/>

</div>

## Accessibility

- **Sorting is announced.** A sortable header carries `aria-sort` (`none`, `ascending` or `descending`) and holds a real button, so a keyboard reaches it with Tab and a press asks for the next sort.
- **Focus is a ring.** The ring is inset in the cell and focus never changes the fill.
- **The arrow is decorative.** The sort state is in `aria-sort`, so color and the arrow never carry it alone.
- **A disabled row is announced.** It is `aria-disabled` and takes no pointer events.
- **Row selection is named and announced.** Each checkbox is "Select row N" and the head's is "Select all rows", mixed when only some rows are selected; a status says how many are selected, from the first one. The bulk bar's count is not announced a second time.
