<FoundationSection title="Overview">

This page holds the rules every icon follows. The <a href="?path=/docs/components-images-and-icons-icon--docs">Icon</a> component draws one glyph, and its page has the props, examples and playground.

```jsx
<Icon name="calendar-days" size={16} color="subtle" />
```

A component that takes an icon takes its name as a string, such as Button's `iconBefore` and `iconAfter`, and draws it through Icon: `fa-regular fa-<name>`, or `fa-solid` where Font Awesome Free has no regular weight. A node in place of the name renders as given.

```jsx
<Button appearance="primary" text="Add tutor" iconBefore="plus" />
<Button appearance="primary" text="Next" iconAfter="arrow-right" />
```

Sizes bind to the icon size tokens: 12 is `--icon-sm`, 16 is `--icon-md` and 24 is `--icon-lg`. Figma draws the Icon from the Size/Icon variables.

</FoundationSection>

<FoundationSection title="Principles">

<FoundationSubsection title="Use symbols people already recognize">
Pick the glyph most people read the same way: a calendar for dates, a bell for notifications, a gear for settings. A clever metaphor costs the reader a guess.

<Canvas of={IconsStories.OneGlyphOneMeaning} sourceState="none" />
</FoundationSubsection>

<FoundationSubsection title="Keep shapes simple">
Font Awesome glyphs are drawn to read at 12 to 24. Prefer the plainest glyph that says it, and use one glyph for one meaning across the product.
</FoundationSubsection>

<FoundationSubsection title="Pair icons with text labels where possible">
A label says what the icon means and helps people who use a screen reader. Leave an icon alone only for a well-known action in a tight space, and name it in code.

<Canvas of={IconsStories.PairWithLabels} sourceState="none" />
</FoundationSubsection>

<FoundationSubsection title="Use icons intentionally">
Before adding an icon, ask whether a label does the job better. Leave out icons that are not needed.
</FoundationSubsection>

</FoundationSection>

<FoundationSection title="Sizes: 12, 16 and 24">

Icons come in three sizes, bound to the Size/Icon tokens. The box is exactly the size, so an icon never adds height to the line it sits in.

<Banner appearance="announcement">
<strong>Sizes and source</strong><br />
Icons come in 12, 16 and 24. 12 is for chevrons, which are always 12, field validation icons, compact text, small contained elements such as tags, badges and statuses, and secondary actions. PLUS draws icons from Font Awesome Free, so stroke, corner and end-cap rules do not apply.
</Banner>

An icon's box is its font size: `--fa-width: 1em` is set globally, so the glyph fills the square it is sized to.

An icon sits in space the way any box does: give it room with the spacing tokens, not with a larger glyph.

</FoundationSection>

<FoundationSection title="Above 24, use a Tile">

24 is the top of the scale. A bigger or decorative mark, such as a list-item badge, a tool logo or an empty-state picture, goes in a Tile, which sets its size, corner and color in one place.

<Canvas of={IconsStories.LargerMeansTile} sourceState="none" />

</FoundationSection>

<FoundationSection title="Font Awesome Free and color tokens">

Use Font Awesome Free 7.2 only: `fa-solid`, `fa-regular` and `fa-brands`, including brand glyphs such as `fa-brands fa-figma` and `fa-brands fa-github`. Pro families (`fa-light`, `fa-thin`, `fa-sharp`, `fa-duotone`) and Pro-only names are not licensed here and render blank. Check a glyph name against the Free set before you use it; the Free names are generated into `design-system/src/lib/icon-free.generated.js` and `icon-regular.generated.js` (`npm run generate:icon-lists`). A glyph Free does not have is replaced by another glyph that is in the Free set.

Regular is the default weight, and solid is used only where Free has no regular. Where one set of icons needs a glyph Free draws only in solid, that one glyph is solid and the rest stay regular. Use a glyph's current name: an alias such as `calendar-alt` is not in the list and draws solid.

<Canvas of={IconsStories.Families} sourceState="none" />

Color an icon with a color token, never a picked hex. A status icon takes its hue's icon token, such as `--ds-icon-success` or `--ds-icon-danger`; any other icon matches the text beside it.

<Canvas of={IconsStories.Colors} sourceState="none" />

</FoundationSection>

<FoundationSection title="Usage">

<FoundationSubsection title="Pick the mark by what it has to do">
An Icon backs up a label at the size of its text; a Tile frames an icon, logo or picture as a square object; the Logo marks PLUS itself; Image places a picture in content.
</FoundationSubsection>

<FoundationSubsection title="Contribution and adding new icons">
Before a glyph joins the product, check four things. Does a similar icon already exist? Can an existing one serve more than one purpose? Could it be confused with another icon in the same view? Would a label do the job better? A new glyph is proposed through the Intake, and a design lead approves it.
</FoundationSubsection>

</FoundationSection>

<FoundationSection title="Accessibility">

- Icons help, but the label and the code carry the meaning.
- Pair an icon with a text label wherever there is room. Where an icon stands alone for a well-known action in a tight space, name it in code so a screen reader announces it.
- Color icons with color tokens. Icon and text color tokens are built to keep enough contrast against the surface they sit on, which a picked hex does not.
- Keep each glyph to one meaning across the product, so the same icon reads the same way on every screen.
- Decorative icons carry `aria-hidden="true"`.

</FoundationSection>
