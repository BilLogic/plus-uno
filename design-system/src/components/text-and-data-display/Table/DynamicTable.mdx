## Parts

1. **Head cell.** A label with an optional type icon; a sortable one holds a button across the whole cell.
2. **Sort arrow.** 12 tall; hidden until hover or focus, kept once sorted.
3. **Row.** Cells in a band, with hover and selected grounds.
4. **Footer.** States the range on a table that pages.
5. **Message row.** The empty, no results, loading and error states, spanning every column.
6. **Checkbox column.** With `isSelectable`: as wide as the row is tall, select-all in the head.
7. **Bulk bar.** `TableBulkActions`, in the Section header's toolbar while rows are selected.
8. **Frozen column.** With `isFrozen`: an opaque first column with a stronger divider while scrolled sideways.

## Best practices

A dynamic table is one people sort, page or act on. It holds its own sort and page until the page passes `sortKey` or `page`.

### Give a column a sortable key.

A date needs a key that sorts, such as `20261024`, and its readable text as `content`.

<DoDontPair
    doExample={<DynamicTable head={sortHead} rows={keyedRows} label="Sessions" defaultSortKey="date" defaultSortOrder="ascending" />}
    doCaption="A key per cell sorts by date: Oct 9, Oct 24, Nov 2."
    dontExample={<DynamicTable head={sortHead} rows={plainRows} label="Sessions" defaultSortKey="date" defaultSortOrder="ascending" />}
    dontCaption="No key, so the text sorts: Nov 2 lands first."
/>

### Say what an empty table is for.

Every state keeps the head row, so the columns still say what will appear. Word the message with `emptyView`.

<DoDontPair
    doExample={<DynamicTable head={sortHead} rows={[]} label="Sessions" emptyView="No sessions yet. They appear here once one is booked." />}
    doCaption="A message that says what is missing and what happens next."
    dontExample={<DynamicTable head={sortHead} rows={[]} label="Sessions" emptyView="No data" />}
    dontCaption="No data, with no hint of why."
/>

### Page on the server when the list is long.

With `totalRows`, `rows` is the current page only, and the footer counts against the total.

<DoDontPair
    doExample={<DynamicTable head={sortHead} rows={keyedRows} label="Sessions" rowsPerPage={3} totalRows={8500} />}
    doCaption="One page of rows, counted against the 8500 total."
    dontExample={<DynamicTable head={sortHead} rows={keyedRows} label="Sessions" rowsPerPage={3} />}
    dontCaption="The whole list loaded to page on the screen, when it is thousands of rows."
/>

</div>

## Accessibility

- **Sorting is announced.** A sortable header carries `aria-sort` (`none`, `ascending` or `descending`) and holds a real button, so a keyboard reaches it with Tab and a press asks for the next sort.
- **Focus is a ring.** The ring is inset in the cell and is at least 3:1 on the surface; focus never changes the fill.
- **The arrow is decorative.** The sort state is in `aria-sort`, so color and the arrow never carry it alone.
- **A disabled row is announced.** It is `aria-disabled` and takes no pointer events.
- **Row selection is named and announced.** Each checkbox is "Select row N" and the head's is "Select all rows", mixed when only some rows are selected; a status says how many are selected, from the first one.
