## When to use

Use `SidebarTab` for one row of a persistent side navigation — the list down the
left of an admin screen, a section switcher that stays put while the content
changes. One component, one row; the list around it is yours.

`text` is the label and `icon` the Font Awesome name beside it. `leadingVisual`
is on by default and `trailingVisual` off. The row is 32 high and fills the
width it is given: 224 inside the 240 sidebar.

</div>

<div className="sb-ds-doc-section">

## Usage notes

### `state` is a prop, not a behavior.

```jsx
// Incorrect — hover and focus are drawn from the prop, so wiring them to mouse
// and focus events means re-rendering the row on every pointer move, and it
// still will not follow the keyboard.
<SidebarTab text="Sessions" state={isHovered ? 'hover' : 'enabled'}
            onMouseEnter={() => setHovered(true)} />

// Correct — pass only the state you own. `hover` and `focus` exist so the
// design's states can be shown side by side, not to be driven at runtime.
<SidebarTab text="Sessions" state={section === 'sessions' ? 'selected' : 'enabled'}
            onClick={() => go('sessions')} />
```

### It is a row, not a list.

The component renders one row. Wrap the set in a `nav` with an `aria-label`,
and put each row in a list item, so the group has a name and a count. The
Sidebar pattern (`PatternSidebar`) does this for you.

### A link when it has `href`.

Without `href` the row is a `role="button"` and activates through `onClick`.
With `href` it renders an anchor; add `external` for a destination outside the
app, which opens a new tab and tells a screen reader so.

### Slots go in `description`, `elemAfter` and `actionsOnHover`.

`description` is a second line in Body/small, and the row grows past 32 to hold
it. `elemAfter` takes a `Count`, a `Badge` or a `Status` at the end of the row;
it replaces `trailingVisual`, which still draws its placeholder glyph when
`elemAfter` is unset. `actionsOnHover` takes buttons that show on hover and
while the row has focus. They render beside the row, never inside it, so a
button never nests inside the row's button.

</div>

## Accessibility

- **Enter and Space activate it.** Without `href`, the row is a `div` with `role="button"` and
  a key handler for both, so it is operable by keyboard as well as by pointer
  (#320). Space is prevented, so pressing it does not scroll the page.
- **With `href` it is a link.** The row renders an anchor, which Enter follows
  natively. With `external` it opens a new tab, carries `rel="noopener
  noreferrer"`, and its name ends in "(opens in a new tab)".
- **Hover actions are siblings, not children.** `actionsOnHover` renders
  beside the row, so a button never nests inside the row's button or link. The
  actions show while the row has focus, so Tab reaches them next.
- **The selected row says so.** `state="selected"` carries `aria-current="page"`
  as well as the neutral selected fill, the selected text and a 2px leading bar
  in `--ds-border-selected`, so which section you are in is announced, and never
  drawn by fill alone.
- **Focus is a ring outside the row.** A 2px `--ds-border-focused` ring, 2px
  out, so it shows on the frame rather than on the row's fill.
- **Disabled is announced.** `state="disabled"` sets `aria-disabled`, drops the
  click handler and takes the row out of the tab order.
- **The disabled color is the system's.** Text and icon take `--ds-text-disabled`
  and `--ds-icon-disabled`, the one disabled recipe every control shares.
- **The icon is decoration.** It carries the state's color and no text. The
  label is what names the row, so never ship an icon-only row.
