## When to use

Ask who put the value there. If the system produced it and nobody on the screen
can change it, it is a badge: a session's status, an unread count, a due date,
a "New" mark on something just published. If a person picked it, it is a `Tag`.

That test is the whole of the decision, and it is deliberately not "is it
clickable". A read-only tag is still a tag, because the pattern tells the reader
the selection becomes editable again once the surface does. A badge that a
person cannot change is a badge whether or not anything can be pressed.

`BadgeVariants` is the API #276 specifies. The older `Badge` still ships and
still works — see `Badge` for what it keeps and what it is being replaced by.

</div>

<div className="sb-ds-doc-section">

## Usage notes

### Colour is a fixed set, and the set is the point.

`appearance` takes five names and no others. The defect this replaces is a badge
whose colour signalled nothing: with `style="primary"` as the old default a
reader could not tell whether blue meant "information", "the brand colour", or
nothing in particular.

```jsx
// Incorrect — `primary` and `secondary` are brand roles, not states. A reader
// cannot learn anything from the colour, which is the whole job of a status.
<Badge style="primary">Complete</Badge>
<Badge style="secondary">Draft</Badge>

// Correct — a state word on the closed set, so the same state looks the same
// on every screen.
<BadgeVariants variant="status" appearance="positive">Complete</BadgeVariants>
<BadgeVariants variant="status" appearance="neutral">Draft</BadgeVariants>
```

### There is no `size`, and that is deliberate.

Density changes padding and never type. A `size` prop bound to the type scale —
which is what `Badge` still has — lets a badge introduce a size nothing else on
the page shares, so the same status renders differently on different screens and
can disagree with the text beside it.

```jsx
// Incorrect — this is not an API this component has, and the reason it does not
// is that the badge would then be free to disagree with its own row.
<BadgeVariants variant="status" appearance="positive" size="b3">Complete</BadgeVariants>

// Correct — reach for density when the badge needs more presence, not for type.
<BadgeVariants variant="status" appearance="positive" spacing="spacious">Complete</BadgeVariants>
```

### Spacious when the badge is the subject; default when it is metadata.

`spacious` is for a badge beside a heading, in a detail header, in an empty
state — where the badge is what the region is about. `default` is for table
cells, list items and inline prose, where the badge describes a row. The prop
exists on `status` and `date` only; on `counter` it is ignored, because a
prominent count is not a case that arises.

### `custom` is an escape hatch, not a sixth appearance.

It is the only place a non-semantic colour gets in, and a badge that uses it is
saying "this colour means nothing". Reach for it for a curriculum domain or a
brand mark — never to invent a status the closed set does not have.

</div>

## Accessibility

- **The dot carries a name.** A counter with nothing to say renders as a
  circle with no text, which is a coloured shape assistive technology cannot
  describe. It publishes `role="status"` and takes `label`; a badge *with* text
  needs no label, because its text is its meaning and a label would override it.
- **Colour is never the only signal.** Every status badge says its state in
  words. `positive` and `information` sit 74° apart in hue but within four
  points on lightness and saturation, so hue carries all the differentiation —
  and green-versus-teal is the axis that collapses under deuteranopia and
  protanopia. `iconBefore` is there for where that is not enough.
- **A leading glyph is decoration and is hidden.** It repeats what the badge
  already says; announcing it would produce "check, Passed".
- **A truncated status keeps its full text.** `maxWidth` puts the label in
  `title`, because an ellipsis alone deletes the value for anyone not looking at
  the pixels.
- **`custom` derives its foreground.** An escape-hatch colour with inherited
  text failed `color-contrast` on its first run — the same "colour signals
  nothing" defect, arriving through the one door left open — so the foreground
  is computed from the background rather than inherited.
- **Contrast is measured, not asserted here.** The a11y ratchet tracks
  `color-contrast` over every story on this page and may fall but never rise.

## Related

- For a value a person picked rather than one the system produced, use `Tag`.
- For a set of tags, use `TagGroup` — it owns the gaps and the overflow.
- For the older API, still shipping and still supported, use `Badge`.
- For completion or progress rather than a state word, use `Progress`.
- For a message rather than a label, use `Alert` or `Toast`.
- For marking what an agent produced, use `AiLabel`.
