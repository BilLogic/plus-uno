## Usage

Use `Cascader` when a choice is naturally made one level at a time, in
sequence — a region, then a city, then a neighborhood. For a hierarchy where
someone might pick or see several nodes at once rather than one path, use
`TreeSelect` instead. For a flat list, use `Select`.

</div>

<div className="sb-ds-doc-section">

## Parts

1. **Field.** The box that shows the chosen path, joined with separators.
2. **Label.** Names the field. A required marker follows it.
3. **Columns.** One column per level, opening to the right of the last.
4. **Caption.** Helper text, or the error that replaces it.

## Best practices

### The value is the whole path.

`value` is the full path, outermost value first, and `onChange` fires with the path as each column is chosen.

### `value` is the path, not just the final node.

Pass and read the whole array — `['zhejiang', 'hangzhou', 'westlake']` — not
just the last segment, since the intermediate levels are part of the
answer, not scaffolding to discard.

```jsx
<Cascader
    label="Region"
    value={region}
    onChange={setRegion}
    options={[
        { value: 'zhejiang', label: 'Zhejiang', children: [
            { value: 'hangzhou', label: 'Hangzhou', children: [
                { value: 'westlake', label: 'West Lake' },
            ] },
        ] },
    ]}
/>
```

### Reopening a field with a path shows the columns leading to it.

A pre-selected `Cascader` doesn't reopen to a blank first column — it reveals
every column up to the current level, so the person can see and change any
step of the path, not just restart from the top.

## Accessibility

- **The field states the full path**, not just the deepest choice, so its
  accessible value matches what's visibly shown.
- **Without a visible label, name the field explicitly** with `aria-label`
  or `aria-labelledby`.
- **Disabled nodes are skipped, not just dimmed** — they take no focus and
  can't be chosen at any column.
