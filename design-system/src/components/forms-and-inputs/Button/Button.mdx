## Anatomy

<DocsCanvasShell description={<>A button with an icon before and an icon after the label.</>}>
    <Canvas of={ButtonStories.Icons} story={{ inline: true }} layout="padded" sourceState="hidden" />
</DocsCanvasShell>

1. **Container.** The pressable area, 32 high at default spacing and 24 at compact.
2. **Icon before** (optional). A Font Awesome Free glyph at 16, before the label.
3. **Label.** Body/default at the medium weight. It says what the action does.
4. **Icon after** (optional). A Font Awesome Free glyph at 16, after the label.
5. **Spinner** (loading only). Replaces the label and the icons while the button is busy.

Most buttons need no icon. Add one where the glyph has a clear, established meaning, such as `plus` for add.

## Usage

Use a button for an action on the current page: submit a form, mark attendance, close a dialog. For navigation to another page, use Link button.

### One primary action per area.

<DoDontPair
    doExample={<div style={{ display: 'flex', gap: '8px' }}><Button appearance="primary" text="Book session" /><Button appearance="subtle" text="Cancel" /></div>}
    doCaption="One primary button, with the secondary action subtle beside it."
    dontExample={<div style={{ display: 'flex', gap: '8px' }}><Button appearance="primary" text="Book session" /><Button appearance="primary" text="Cancel" /></div>}
    dontCaption="Two primary buttons in one area compete for attention."
/>

### One primary AI action per region.

The AI appearance marks the single main AI action in a region, such as "Generate summary" on a session's notes. Use it only for actions that call AI, never to emphasize an ordinary action, and leave its look as shipped: no custom color, icon or fill. Every other AI action in the region is a default or subtle button with an AI icon.

<DoDontPair
    doExample={<div style={{ display: 'flex', gap: '8px' }}><Button appearance="ai" text="Generate summary" /><Button appearance="subtle" text="Edit notes" /></div>}
    doCaption="One AI button for the region's main AI action, with the other actions subtle."
    dontExample={<div style={{ display: 'flex', gap: '8px' }}><Button appearance="ai" text="Generate summary" /><Button appearance="ai" text="Save notes" /></div>}
    dontCaption="A second AI button competes with the first, and Save notes is not an AI action."
/>

### Pick the spacing for the surrounding space.

Default spacing for most places; compact for tables and tight spaces, such as a row of student sessions.

### Keep a form's submit button pressable.

<DoDontPair
    doExample={<div><Button appearance="primary" text="Save notes" /><p style={{ margin: '8px 0 0' }}>Complete the session notes to continue.</p></div>}
    doCaption="Explain what is missing with validation text under the field."
    dontExample={<Button appearance="primary" text="Save notes" isDisabled />}
    dontCaption="A disabled submit button gives no direction and leaves the tab order."
/>

### Align the primary button with its group.

Right-align buttons in focused tasks and modal dialogs, with the primary on the right. Left-align on single-page forms and full-page tasks with a lot of content, with the primary on the left.

## Content guidelines

<DocsTable>
<thead>
<tr><th>Do</th><th>Don't</th></tr>
</thead>

<tr><td>Use sentence case: "Add student".</td><td>Title case or all capitals: "Add Student", "ADD STUDENT".</td></tr>

<tr><td>Use the same words as the heading and related text in view.</td><td>Different words for the same action within one view.</td></tr>
</tbody>

## Accessibility

- A button performs an action; a link navigates. Use the right element so screen readers announce the right role.
- Avoid `isDisabled`. A disabled button leaves the tab order and receives no events. Use validation and on-screen directions instead, and never attach a tooltip to one.
- A button with no visible label is an Icon button, which requires a `label`.
- Loading blocks interaction and sets `aria-busy`; the label stays in the tree for assistive technology.
- Selected is not color alone: `isSelected` sets `aria-pressed`.
- The focus ring is 2px in `--ds-border-focused`. Never remove it.

## Related

- To act with an icon alone, use Icon button.
- To navigate in the look of text, use Link button.
- For a set of choices the user picks between, use `RadioGroup`.
- For a menu of actions behind one trigger, use `DropdownMenu`.
- To show that work is under way on the page rather than in the control, use `ProgressBar`.
