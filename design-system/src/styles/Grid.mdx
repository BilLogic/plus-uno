<FoundationSection title="Overview">

PLUS is desktop only, from 768 up. The screen grid spans the screen and lives on the Blanket layer: modals and drawers size from it. The content grid sits inside the Page: cards, tables, forms and text blocks align to it, and it is the only grid a page frame carries. A frame changes breakpoint by switching its `spacing / layout` mode, never by hand-editing its grid. The grid decides where containers sit; the spacing tokens decide everything inside them.

<Banner appearance="announcement">
<strong>How the PLUS grid differs from a standard one</strong><br />
PLUS is desktop only, from 768 up: there are no 2 or 6 column tiers and no mobile size. The gutter is 16 at every width. The page margin is 24 at every width. The 1232 maximum counts content only, without margins. Layers over the page sit outside the grid; only the Modal and Drawer take their width from the screen grid.
</Banner>

<Canvas of={GridStories.GridAnatomy} sourceState="none" />

In code, a region lays itself out on the grid rather than reading column widths:

```css
display: grid;
grid-template-columns: repeat(var(--grid-columns), minmax(0, 1fr));
gap: var(--grid-gutter);
```

Figma holds the breakpoint modes in the `spacing / layout` collection: 768, 1024 and 1440. The content grid is on the Page's content frame; the screen grid is on the Blanket only.

</FoundationSection>

<FoundationSection title="Two grids">

Both grids are 12 columns with a 16 gutter.

- **The screen grid** spans the screen inside the screen pad, centered and
  capped at 1232: `clamp(720, screen − 2 × 24, 1232)`, which is 720 · 976 · 1232
  at the three modes. From 1440 the screen pad is 32, but there the grid is
  already at its cap with either pad, so its width depends on the screen alone;
  past a 1280 screen it stops growing and centers. It ignores the sidebar, so a
  modal sits in the same place whether the sidebar is docked or closed. Modals
  and drawers size from it. In Figma it lives on the Blanket layer only, and
  shows and hides with it; code draws no grid at all.
- **The content grid** sits inside the Page, after the sidebar and the
  Page pad take their share. Cards, tables, forms and text blocks align to
  it, and it is the only grid a page frame carries. At X-Large:
  1440 − 240 sidebar − 2 × 24 = 1152. The Frame has no seams, so only a docked Panel takes another share: content = Frame width − Sidebar (240 if docked) − Panel (if docked) − 48, never under 720, which is a 1408 Frame for a 400 Panel beside a docked Sidebar and 1168 with the Sidebar collapsed. A Section with a detail region keeps its 7 + 5 split from 960 of content. At Medium the sidebar is closed, so the Page starts at the window edge and content is 768 − 2 × 24 = 720, exactly its minimum.

These tokens change with the screen, so the table gives the value at each
breakpoint: Medium · Large · X-Large.

<FoundationSection title="Usage">

The grid owns where top-level containers sit; spacing owns everything inside
them.

**Keep the gutter 16 at every width.** Columns flex with the screen; the
gutter never changes.

<Canvas of={GridStories.Gutter} sourceState="none" />

**Span whole columns.** A content container spans whole columns (3, 4, 6 or
12) and can be centered by leaving the same number of columns empty on each
side. Content never bleeds into a gutter or into the Page pad.

<Canvas of={GridStories.SpanWholeColumns} sourceState="none" />

**Size modals from the screen grid.** Pass `6-col`, `8-col` or `10-col`. The width comes
from screen-grid columns, so a modal lines up with the page whenever the
sidebar is closed.

<Canvas of={GridStories.ModalFromScreenGrid} sourceState="none" />

**Cap reading text at 864.** Long-form text uses the reading cap, so lines stay
readable. Structured content, such as dashboards and tables, uses the 1232 cap.

<Canvas of={GridStories.ReadingCap} sourceState="none" />

**Align containers, not their parts.** Only top-level containers align to
columns: cards, tables, forms, images, charts and text blocks. Inside a
container the grid stops and spacing tokens take over, so buttons, icons, tags
and avatars never stretch to columns. Cards have no inner grid.

<Canvas of={GridStories.AlignContainers} sourceState="none" />

**Change breakpoint by mode.** In Figma, use one page frame and switch its
`spacing / layout` mode: the grid, the widths and the sidebar follow together.
Never keep a copy of the page per breakpoint with hand-edited grids. The copies
drift, and the variable bindings stop working.

**Put the screen grid on the Blanket layer only.** In a design file the screen grid is set on the Blanket, so it shows when the Blanket shows and hides with it. A page frame carries only the content grid.

**Design from 768 up.** PLUS has no small-screen tier. Never design below 768,
and never drop to 6 or 2 columns: a four-card row at X-Large is still a
four-card row at Medium, just narrower.

</FoundationSection>

<FoundationSection title="Do and don't">

Align containers to the grid, keep the grid on the page, and build with auto layout.

**Align containers, not small elements.** Cards, tables, forms and text blocks sit on columns. Buttons and icons do not; their size and spacing come from tokens.

<Canvas of={GridStories.AlignContainers} sourceState="none" />

**Keep the grid on the page.** The content grid sits inside the Page. It does not run under the sidebar or the topbar: twelve columns start where the Page starts, after the sidebar.

**Build with auto layout.** The grid guides alignment; auto layout holds the layout together as the breakpoint changes. An auto layout row with a 16 gap keeps cards on the columns when the mode changes; cards dragged into place by hand drift off the columns and do not adapt to the next mode.

</FoundationSection>

<FoundationSection title="Accessibility">

- The grid sets line length, reflow and reading order.
- Cap long-form text at the reading width (`--content-max-width-reading`, 864) so lines stay a readable length on wide screens.
- Content holds a 720 minimum (`--content-min-width`); below it the page scrolls sideways instead of squeezing columns, so text never overlaps or clips when the page is zoomed. PLUS is desktop only, from 768 up.
- Content never sits under the sidebar or the topbar. Below 1024 the sidebar opens over the page and closes on an outside click or Escape, and focus returns to its toggle.
- Keep the order of content in the file the same as its order on the grid, so keyboard focus and screen readers follow the sequence a reader sees.
- Every control is at least 24 tall, and 32 or more outside a table row or an inline toolbar, so it stays an easy target. An icon-only control still needs a name.

</FoundationSection>
