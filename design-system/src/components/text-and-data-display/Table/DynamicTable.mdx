## Usage

Use the Dynamic table where people act on the data: sort a column, filter the
rows, select some for a bulk action, or page through a long result. Use
`StaticTable` instead for a grid people only read.

## Parts

1. **Head cell.** A label with an optional type icon; a sortable one holds a button across the whole cell.
2. **Sort arrow.** 12 tall; hidden until hover or focus, kept once sorted.
3. **Row.** Cells in a band, with hover and selected grounds.
4. **Footer.** States the range on a table that pages.
5. **Message row.** The empty state, spanning every column.

## Best practices

- **Sorting is not built into `Table`.** A sortable column is a `HeadCell` with `isSortable`, `sort` and `onSort`; the consuming page holds the sort state and passes already-ordered `rows`.
- **No single component yet.** Selection with bulk actions, a frozen column and expanding rows are documented in Figma but have no code component of their own. `PatternTable` carries the sticky header and column, paging and the empty state.
- **The footer states the range** — `1–3 of 3` — and sits only on tables that page.

## Accessibility

- **Sorting is announced.** A sortable header carries `aria-sort` (`none`, `ascending` or `descending`) and holds a real button, so a keyboard reaches it with Tab and a press asks for the next sort.
- **Focus is a ring.** The ring is inset in the cell and is at least 3:1 on the surface; focus never changes the fill.
- **The arrow is decorative.** The sort state is in `aria-sort`, so color and the arrow never carry it alone.
- **A disabled row is announced.** It is `aria-disabled` and takes no pointer events.
- **Name a row-select control.** Use a checkbox with its own `aria-label`; the column heading does not name it.
