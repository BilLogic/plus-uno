## Usage

Use `Modal` when the next step has to happen before anything else can: a
destructive confirmation, a short form that would derail the page, a detail view
the person closes and returns from. It is the one messaging component that takes
focus from the page, so it fits when interrupting is the point.

The footer is built in: pass `primaryButton` and `secondaryButton` as objects and
the component renders the `Button` pair, aligned right. Pass `footer` for other
actions, such as a Delete on the left or a single primary. Opening a Modal
closes a floating Sidebar; a docked one stays.

### Width guidance

`width` takes a step of `MODAL_WIDTHS`{` (${MODAL_WIDTHS.join(' · ')})`}: that
many columns of the screen grid plus the modal pad.

## Alternatives

- For a message the person only reads, use `SectionMessage` in the page or `Flag` at the screen corner.
- For a task that takes more than a screen or has sections, use `PageLayout` with `frame="focused"`.
- For a task that keeps the page in view, use `PatternDrawer`: a row's details, filters, a short edit.
- For a small aside anchored to a control, use `Popup`.
- For a list of actions or a value to pick, use `DropdownMenu` or `Select`.

## Parts

1. **Blanket.** Dims the page and holds focus inside.
2. **Header.** Title, optional description, header actions and the close button.
3. **Body.** Text or any content; scrolls when it overflows.
4. **Footer.** Appears only when a button or `footer` is given: a secondary and a primary.
5. **Dividers.** Optional rules under the header and over the footer.

The tokens each part draws are read from `Modal.scss` and listed under Tokens
touched in the Agent view tab.

## Best practices

### Size the Modal to its content with a step of `MODAL_WIDTHS`.

A short confirmation takes `6-col`, a short form `8-col`, a table or an editor
`10-col`. A step grows with the screen; a fixed number keeps one size on every
screen.

<DoDontPair
    doExample={<div style={scaledScreen}><Modal show renderAs="inline" width="6-col" title="Remove this session?" body="The student is told it was canceled." secondaryButton={{ text: 'Cancel' }} primaryButton={{ text: 'Remove' }} onClose={() => {}} /></div>}
    doCaption="The narrowest step for a short question."
    dontExample={<div style={scaledScreen}><Modal show renderAs="inline" width="10-col" title="Remove this session?" body="The student is told it was canceled." secondaryButton={{ text: 'Cancel' }} primaryButton={{ text: 'Remove' }} onClose={() => {}} /></div>}
    dontCaption="The widest step around one sentence."
/>

### Keep Close on a Modal unless the person has to answer it.

An informational Modal keeps its close button; `showCloseButton={false}` is for
a decision that has to be answered from the footer.

<DoDontPair
    doExample={<div style={narrowScreen}><Modal show renderAs="inline" title="Session details" description="Monday, 4:00 PM" body="Algebra with Jordan, 45 minutes." primaryButton={{ text: 'Done' }} onClose={() => {}} /></div>}
    doCaption="Close stays on an informational dialog."
    dontExample={<div style={narrowScreen}><Modal show renderAs="inline" showCloseButton={false} title="Session details" description="Monday, 4:00 PM" body="Algebra with Jordan, 45 minutes." primaryButton={{ text: 'Done' }} onClose={() => {}} /></div>}
    dontCaption="No way out of an informational dialog."
/>

### Add `dividers` when the Modal body scrolls.

The rules mark where the header and footer stay put while the body scrolls; a
short body reads cleaner without them.

<DoDontPair
    doExample={<div style={shortCap}><Modal show renderAs="inline" dividers title="Session notes" body={longBody} primaryButton={{ text: 'Done' }} onClose={() => {}} /></div>}
    doCaption="Dividers around a scrolling body."
    dontExample={<div style={shortCap}><Modal show renderAs="inline" dividers title="Session notes" body="One short note." primaryButton={{ text: 'Done' }} onClose={() => {}} /></div>}
    dontCaption="Dividers around a short body."
/>

### Give the Modal footer a button.

`showBottomButtons` defaults to true, and the footer renders only when
`primaryButton`, `secondaryButton` or `footer` is given; describe the actions as
objects and the component renders the Button pair.

### Show a follow-up decision in the same Modal, or stack its confirm as a second Modal.

The confirm view swaps the same Modal's title, body and footer, and Back returns
to the form with what was typed. A confirm raised as a second Modal stacks over
the first: at most `MAX_STACKED_OVERLAYS`{` (${MAX_STACKED_OVERLAYS})`} overlays
stack, a `PatternDrawer` counted among them, and one more stays closed and calls
its `onClose`.

```jsx
<Modal
  title={confirming ? 'Discard changes?' : 'Session settings'}
  show={open}
  onClose={close}
  secondaryButton={confirming ? { text: 'Back', onClick: () => setConfirming(false) } : { text: 'Cancel', onClick: close }}
  primaryButton={confirming ? { text: 'Discard changes', appearance: 'danger', onClick: discard } : { text: 'Save', onClick: save }}
>
  {confirming ? 'Your edits to this session are not saved.' : settingsForm}
</Modal>
```

## Accessibility

- **Escape and a press on the Blanket close the Modal by default.** `keyboard`
  and `backdrop` both default to `true`. Turning either off leaves the close
  button as the exit, so keep that button. The header, and its close button, is
  left out only when the Modal has no `title`, no `description`, no
  `headerActions` and `showBottomButtons` is false.
- **The close button is labeled `Close modal`**, hard-coded. Its icon is
  `aria-hidden`. `showCloseButton={false}` removes it; keep Escape or a footer
  action as a way out.
- **The title is the dialog's h1 and its accessible name**, through
  `aria-labelledby`: the dialog reads as its own page. The `description`
  describes it, through `aria-describedby`. A Modal with no title takes
  `ariaLabel`.
- **A body that scrolls is focusable.** Once the content runs past the cap, the
  body gets `tabIndex={0}` so a keyboard user can scroll it.
- **Loading is announced as busy.** `loading` sets `aria-busy` on the body while
  the skeleton bars stand in for it.
- **Opening traps focus inside the dialog and closing returns it to the
  trigger.** Tab cycles within the dialog; a view change (the confirm view
  swapping in) moves focus into the dialog again.
- **Turn off the Blanket click for an inline confirmation of a destructive
  action.** Set `backdrop="static"` (or `false`) while the confirmation shows,
  so a stray click outside cannot destroy something by accident; Close, Escape
  or the footer's Back still work.
- **Focus order is Close, then the content, then the secondary action, then
  the primary action.**
- **`renderAs="inline"` is for docs previews only.** It draws the panel with no
  Blanket, no focus trap and no Escape, so a live dialog keeps the default
  `renderAs="modal"`.
