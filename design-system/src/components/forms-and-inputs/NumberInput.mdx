## When to use

Use `NumberInput` for a quantity the user adjusts as much as types — a session
count, a duration, a score out of a known total. The stepper is the point: if
nobody will ever press it, a plain `Input` is the simpler field.

It works controlled or uncontrolled. Pass `value` and `onChange` to control it;
leave `value` off and it keeps its own. The stepper buttons call `onChange` with
a synthetic event carrying `{ name, value, type: 'number' }`, and `onIncrement`
and `onDecrement` with the new number.

</div>

<div className="sb-ds-doc-section">

## Usage notes

### Typed values clamp when the field loses focus.

`min` and `max` bind the steppers at once and a typed value on blur: "1" on the
way to "12" is left alone while it is typed, and "12" becomes "10" when the field
loses focus, with `onChange` called. The steppers turn off at the bounds.

### Empty is not 0.

An empty field stays empty and `onChange` reports `''`; 0 is a value of its own.
Stepping from empty starts at 0 and clamps, so an empty field with `min={5}`
steps to `5`. Give a field with a floor a starting value anyway — a field that
shows nothing and means five is one the user has to press to understand.

### The scroll wheel never changes the value.

The control is a text input with `inputMode="decimal"`, so scrolling the page
over a focused field does not nudge the number, and phones show a number pad.

</div>

## Accessibility

- **`showLabel={false}` hides the label; it does not remove the name.** The
  label is rendered and clipped to nothing, the same treatment `Input` gives it
  — see the `showLabel` section in the `Input` docs for why a name cannot be
  taken away. Prefer a visible label regardless: a field whose name only exists
  in the accessibility tree is a field sighted users have to guess at.
- **The steppers are named for the field.** `Decrease {label}` and
  `Increase {label}`, minus before plus, so a form with three number fields
  does not read out three identical "Increase" buttons. They take the real `disabled`
  attribute at the bounds. Read-only hides them.
- **`required` shows an asterisk and sets `aria-required`.** Explain the
  asterisk once, in the form's legend.
- **The validation message is attached to the input.** It carries an id, the
  field points at it with `aria-describedby`, an invalid field carries
  `aria-invalid`, and the message renders with `role="alert"` — so the error is
  heard when it appears and again with the name.
- **Forwarded props reach the input.** `aria-describedby`, `aria-invalid` and
  anything else you pass lands on the field itself, and your `aria-describedby`
  is composed with the message's rather than replaced by it.
- **The value is text to assistive technology.** There is no spinbutton role,
  so the label and the unit carry the meaning.

</div>
