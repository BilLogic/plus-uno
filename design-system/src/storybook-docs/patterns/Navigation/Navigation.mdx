## Usage

Choose the navigation tier first; it sets the control, placement and motion. Navigation belongs in the Sidebar and page. There is no global search.

## Alternatives

- For narrowing a collection rather than switching views, follow <a target="_top" href="./?path=/docs/patterns-filtering--docs">Filtering</a>; filters combine, views do not.
- For more pills than fit, fold the extras into "More" <PlannedTag />; keep page tabs to five.
- For a decision that blocks the page, use a <a target="_top" href="./?path=/docs/templates-modal--docs">Modal</a>, not a page.

## Best practices

### Show the breadcrumb only after drilling into a record.

<RuleTag kind="automatic" />

Never on an area page or a multi-step task. It sits above the title in the page header and shows the record's place: parents only, never history. It never wraps. Folding five or more items into "…" is Planned <PlannedTag />.

<DoDontPair
    doExample={<BreadcrumbCase record />}
    doCode={CODE.BreadcrumbOnRecordPage}
    doCaption="A breadcrumb on the record page, parents only."
    dontExample={<BreadcrumbCase record={false} />}
    dontCode={CODE.BreadcrumbOnAreaPage}
    dontCaption="A breadcrumb on an area page: there is nothing to climb out of."
/>

### Keep one tab system per page.

<RuleTag kind="automatic" />

Either page tabs under the title, or pill views in a Section's bar, never both. Under page tabs a Section's views become one labeled PopupSelect at the start of its bar. It picks a view, not a filter.

<DoDontPair
    doExample={<OneTabSystem />}
    doCaption="Under page tabs the Section's views are one labeled PopupSelect at the start of its bar."
    dontExample={<TwoTabSystems />}
    dontCaption="Page tabs and pill views on the same page: two tab systems."
/>

### Make views a fixed set the product defines.

<RuleTag kind="review" />

Two to five views of the same rows, named by short parallel nouns. Nobody adds or edits views. One pill stays even with one view, so nothing moves when a second arrives.

### Swap content in place between views and tabs.

<RuleTag kind="automatic" />

Only the selected indicator glides. Nothing slides between views.

### Open a record at the lowest step that fits.

<RuleTag kind="review" />

Expand the row, then Section detail, then the Details Panel, then a Modal, then its own page. Section detail and the Details Panel both stay: Section detail expands in place (see <a target="_top" href="./?path=/docs/templates-section--docs">Section</a>), and the Details Panel docks beside the list on a queue page or opens from a table.

### Give a long task its steps in the inner sidebar.

<RuleTag kind="automatic" />

The steps replace the Sidebar's rows and Back returns to them; no breadcrumb. How the steps, the page and the footer sit is on <a target="_top" href="./?path=/docs/templates-frame--docs">Frame</a>.

### Name an open item by when and who.

<RuleTag kind="automatic" />

"4:00 PM · Ms. Ortiz", with the school in the Tooltip. Three show, then "Show n more". Removing one is Add and remove; opening one is Go to.

<DoDontPair
    doExample={<OpenItemsPicture />}
    doCaption="Each item names the session by its time and the teacher."
    dontExample={<OpenItemsDont />}
    dontCaption="Each item carries everything, and the time it is found by is cut off."
/>

### Put the collection's add action in its Section's title row, not the page header.

<RuleTag kind="automatic" />

"Add student" is the Primary at the end of the Students Section's title row. Page actions sit at the end of the page header and are only about the page.

## Accessibility

- The Sidebar is a navigation landmark; the selected item carries `aria-current="page"`. The selected row is a fill, not color on the icon alone.
- Views and page tabs are a real tab widget: one tab stop, Left and Right move selection, the panel is named by its tab.
- The breadcrumb is a `nav` around an `ol`; the last item is plain text with `aria-current="page"`.
- Leaving a multi-step task returns focus to the control that opened it <PlannedTag />.
