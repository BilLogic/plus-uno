## When to use

Use `Skeleton` while content loads, so the space it will fill is already on
screen and the layout does not jump when it arrives.

- **One label loading on its own** (a Status calculated after the row appears, a
  tag list fetched separately): the matching preset.
- **A whole table or card loading:** plain text bars and shapes, composed to the
  real content's dimensions.
- **A thumbnail, avatar or header:** a rectangle or circle with its own size.

</div>

<div className="sb-ds-doc-section">

## Usage notes

The loading rules, as Do and Don't.

### Do: use a label preset when one label loads after its row is on screen.

```jsx
<span>Unit 3 review {status ? <Status style="success">{status}</Status> : <Skeleton preset="status" />}</span>
```

### Do: use plain text bars inside a loading table or card.

The container owns the skeleton. Labels become the same text bars as the rest,
so a loading table does not fill with dozens of label shapes.

```jsx
// Incorrect — label shapes inside a loading container.
<tr><td><Skeleton shape="text" /></td><td><Skeleton preset="status" /></td><td><Skeleton preset="tag-group" /></td></tr>

// Correct — text bars throughout.
<tr><td><Skeleton shape="text" /></td><td><Skeleton shape="text" width={64} /></td><td><Skeleton shape="text" width={64} /></td></tr>
```

### Don't: skeleton a Count on a button, tab or nav item.

Show nothing until the number arrives; `Count` already renders nothing without
a value.

```jsx
// Incorrect
<button type="button">Messages <Skeleton preset="count" /></button>

// Correct
<button type="button">Messages <Count value={unread} /></button>
```

### Don't: skeleton a Count alone inside a Status or Tag.

Skeleton the host instead: one `preset="status"` for the whole Status.

### Don't: skeleton a toast, modal, menu or spinner.

They appear when they have something to say. A Tag saving a change keeps its
own spinner (`isLoading`), so saving and loading look different.

</div>

## Accessibility

- **Every skeleton is hidden from assistive tech.** It renders `aria-hidden="true"`
  with no role, never takes focus and ignores the pointer, so a screen reader
  does not read a list of empty items and a placeholder cannot be clicked.
- **The loading region carries the busy state.** Set `aria-busy="true"` once on
  the container that is loading, and remove it when the content arrives. The
  component does not set it, because it cannot see the region.
- **Pair the busy state with a live label.** `aria-busy` alone is not announced
  by every screen reader. Render a visually hidden `role="status"` element
  **beside** the busy region, not inside it: content inside a busy region may
  be held back until it is no longer busy. Mount the status **empty** and set
  its text after mount ("Loading students…"), because text a status already
  holds when it mounts is not announced. Keep it mounted, and when the content
  arrives, set its text again ("Students loaded").

```jsx
const [message, setMessage] = useState('');
useEffect(() => {
  setMessage(loading ? 'Loading students…' : 'Students loaded');
}, [loading]);

<div role="status" className="visually-hidden">{message}</div>
<section aria-labelledby="students" aria-busy={loading || undefined}>
  <h3 id="students">Students</h3>
  {loading ? <Skeleton shape="text" lines={3} /> : renderStudents(students)}
</section>
```
- **Reduced motion.** Under `prefers-reduced-motion: reduce` the shimmer stops
  and the fill is flat.
- **Contrast in any theme.** The fill is `surface-container` and the shimmer
  moves toward `surface-container-lowest`, both theme tokens.
