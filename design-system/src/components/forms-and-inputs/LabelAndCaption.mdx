## Usage

These are the two lines that bracket a field: the label above it, and the caption
below. Every field component in this group draws them for you — this page is the
typography they all share, and the rules for what goes in them.

A **label** names the field. It is always present, it is short, and it does not
change. A **caption** is the line under the control that helps, warns or
explains, and it carries a state: `default`, `success`, `danger`, `warning`.

## Parts

1. **Label.** The field's name, tied to its control.
2. **Required marker** (optional). An asterisk after the label.
3. **Info button** (optional). An icon beside the label that opens a tooltip, outside the label so its name never joins the field's.
4. **Caption message** (optional). Help, or a status message with its icon.
5. **Character count** (optional). On the right of the caption line, beside the message.

## Best practices

### Say what the field is, not what to do with it.

An instruction reads badly in a screen reader's list of form fields, where the labels appear without context. The instruction is a caption if it is needed at all.

<DoDontPair
    doExample={<TextField label="Email address" />}
    doCaption="The label names the field."
    dontExample={<TextField label="Enter your email address" />}
    dontCaption="An instruction where the name should be."
/>

### Mark the optional fields, not the required ones.

Most fields are required. Mark the exceptions with "(optional)" so the common case stays clean.

<DoDontPair
    doExample={<div style={{ display: 'flex', flexDirection: 'column', gap: 'var(--stack-md)' }}><TextField label="Student name" defaultValue="Maya Johnson" /><TextField label="Grade" defaultValue="Grade 8" /><TextField label="Notes (optional)" placeholder="Anything we should know?" /></div>}
    doCaption="Only the exception is marked."
    dontExample={<div style={{ display: 'flex', flexDirection: 'column', gap: 'var(--stack-md)' }}><TextField label="Student name" defaultValue="Maya Johnson" isRequired /><TextField label="Grade" defaultValue="Grade 8" isRequired /><TextField label="Notes" placeholder="Anything we should know?" isRequired /></div>}
    dontCaption="Every field wears a star."
/>

### Write the error, not the fact that there is one.

A danger caption should say what to do. The state colors the line; the words do the work.

<DoDontPair
    doExample={<TextField label="Session date" defaultValue="Oct 2" isInvalid errorMessage="Choose a date after today." />}
    doCaption="The error says what to do."
    dontExample={<TextField label="Session date" defaultValue="Oct 2" isInvalid errorMessage="Invalid date." />}
    dontCaption="The error only says something is wrong."
/>

### Title the form for what it does.

The first line says what the form is for. A generic title makes people read the fields to find out.

<DoDontPair
    doExample={<div style={{ display: 'flex', flexDirection: 'column', gap: 'var(--stack-md)' }}><p style={{ margin: 0, font: 'var(--heading-small)' }}>Book a session</p><TextField label="Student name" defaultValue="Maya Johnson" /></div>}
    doCaption="The title names the task."
    dontExample={<div style={{ display: 'flex', flexDirection: 'column', gap: 'var(--stack-md)' }}><p style={{ margin: 0, font: 'var(--heading-small)' }}>Form</p><TextField label="Student name" defaultValue="Maya Johnson" /></div>}
    dontCaption="A generic title."
/>

### Name the submit action.

The button says what happens next. "Submit" leaves people unsure what they are sending.

<DoDontPair
    doExample={<div style={{ display: 'flex', flexDirection: 'column', alignItems: 'flex-start', gap: 'var(--stack-md)' }}><TextField label="Student name" defaultValue="Maya Johnson" /><Button appearance="primary" text="Book session" /></div>}
    doCaption="A verb and a noun."
    dontExample={<div style={{ display: 'flex', flexDirection: 'column', alignItems: 'flex-start', gap: 'var(--stack-md)' }}><TextField label="Student name" defaultValue="Maya Johnson" /><Button appearance="primary" text="Submit" /></div>}
    dontCaption={'A bare "Submit".'}
/>

### A caption is help; a placeholder is not.

A hint written into `placeholder` disappears the moment the user types, which is
when they need it, and it is low contrast by design. Put help in a caption.

### Standing help is a caption; a state has its own message.

```jsx
// Standing help, with no state.
<TextField label="Phone" caption="Include the area code" />

// A message tied to success, warning or failure.
<TextField label="Phone" isInvalid errorMessage="Enter a 10-digit number." />
<TextField label="Phone" warningMessage="This number looks like a landline." />
<TextField label="Phone" successMessage="Number verified." />
```

## Accessibility

- **The label must be associated, not merely adjacent.** The field components do
  this with `htmlFor` and a shared id. Where you build a field yourself, a label
  that sits above an input and points at nothing names nothing.
- **A label for a set of controls is not a `label`.** For radios or a scale, a
  `label` element would point at one control and clicking it would select that
  one. `RadioGroup` uses a `fieldset` named by its `legend`, and `Rating` a
  `span` with an id and `aria-labelledby` — those are the patterns to copy.
- **Validation messages are attached to their fields.** `TextField`, `TextArea`,
  `FileUpload` and `DateTimePicker` give the message an id and point the
  control at it, and mark an invalid field `aria-invalid`. Your own
  `aria-describedby` is composed with theirs, not replaced by it.
- **The asterisk is hidden from screen readers.** It is `aria-hidden`; a
  field's `isRequired` sets `aria-required` on the control, and your own
  validation is what enforces it.
- **Standing help is described, not announced.** A `caption` is attached to the
  control with `aria-describedby`; an error is also announced when it appears.
- **Do not hide the label.** `isLabelHidden` is meant to move pixels, not to
  remove the name; on `TextField` it clips the label and keeps it, which is the
  behavior to expect.
- **State is never color alone.** The caption states carry an icon as well as a
  color, and the words should stand without either.
