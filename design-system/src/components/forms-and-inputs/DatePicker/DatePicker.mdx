## When to use

Use `DatePicker` for a calendar date — a session date, a deadline, a birthday
within a bounded range — or, with `range`, a first and a last day. The field
takes a typed `MM/DD/YYYY` as well as a click in the calendar.

`value` and `onChange` speak ISO `YYYY-MM-DD`. The closed field displays
`MM/DD/YYYY`, and the two formats are not the same string — do not read what is
on screen as the value. `minDate` and `maxDate` accept either an ISO string or a
`Date`, and disable everything outside them.

</div>

<div className="sb-ds-doc-section">

## Usage notes

### The value is ISO. Anything else parses to empty.

```jsx
// Incorrect — parsing splits on "-" and requires three parts, so a slashed
// date returns null and the field silently shows the placeholder.
<DatePicker value="08/29/2026" onChange={setDate} />

// Correct.
<DatePicker value="2026-08-29" onChange={setDate} />
```

### A range is one picker, not two.

```jsx
// value and onChange speak [start, end]; either end may be null while picking.
<DatePicker range value={[start, end]} onChange={([s, e]) => setSpan([s, e])} />
```

The first click sets the first day and the second the last; a click before the
first day starts again. Typed, a range is two dates joined by a dash.

### Typed dates are checked when the person is done.

The field is checked on Enter or when focus leaves it. A real day inside
`minDate`…`maxDate` is picked and `onChange` fires. Anything else stays as typed,
the field is drawn invalid, and `onChange` is not called, so the last good value
is still yours.

### The calendar opens 4px below the field.

The popup sits `--size-element-gap-xs` below the field, its left edge on the
field's, and at least as wide. With no room below it opens above, the same gap
away. `calendarAlign` moves it to the center or the right; near the right edge
of the viewport it right-aligns on its own. This is the rule every field popup
shares with `Select`.

### It gives you a date, not a time.

`onChange` hands back the ISO day and nothing else. For a moment in time, use
`DateAndTimePicker`, which pairs the two fields and names them as one group.

### Label it the ordinary way.

```jsx
// The id lands on the input, so a label pointing at it works — unlike the other
// menu-backed fields in this group.
<label htmlFor="starts">Session date</label>
<DatePicker id="starts" value={date} onChange={setDate} />
```

### Bounds disable days; they do not clamp a value.

A `value` outside `minDate`/`maxDate` that you pass in is still displayed. The
bounds stop the user picking or typing another one, so validate the incoming
value yourself.

</div>

## Accessibility

- **The trigger is wired correctly.** `role="combobox"` with
  `aria-haspopup="dialog"`, `aria-expanded`, and `aria-controls` pointing at the
  calendar. Down opens it from the keyboard, Escape closes it, and Enter checks
  what was typed.
- **The days are real buttons.** Each is a `button` with a genuine `disabled`
  attribute outside the bounds, so they are reachable by Tab and announced as
  unavailable rather than doing nothing.
- **A day announces its whole date.** Each button is named with the weekday,
  day, month and year in the reader's locale, carries `aria-pressed` when it is
  the chosen day, and `aria-current="date"` when it is today (#331). The header's
  month and year are no longer the only context.
- **Adjacent-month days are dimmed, not unreadable.** They measure 7.66:1
  against the calendar surface — still lighter than the current month's 13.98:1,
  and above the 4.5:1 that 14px text needs.
- **There is no arrow-key movement inside the calendar.** Tab steps through the
  days one at a time; up to 31 tab stops to reach the end of a month. Typing the
  date is the faster path, and the field accepts it.
- **A rejected date is announced.** The input carries `aria-invalid` when what
  was typed is not a day it can take.
- **In a range, the ends and the span are marked.** Both ends carry
  `aria-pressed`; the days between are drawn as in range.
- **`readOnly` and `disabled` both stop the calendar opening.** `disabled` takes
  the input out of the tab order; `readOnly` leaves it focusable and inert,
  which is the right difference between "not for you" and "not now".
