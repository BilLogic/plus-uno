## Usage

Use `Tabs` for the tab bar that switches between sibling views of the same
subject — a student's Overview / Sessions / Progress, or the sections of an
admin page. Compose it from `Tabs.Tab` children, and declare a `Tabs.Panel`
alongside each one when the tab's content should be owned by the component
rather than rendered separately.

It can be uncontrolled (`defaultActiveKey`) or controlled (`activeKey` plus
`onSelect`). `alignment` covers left, center, right and `justified`, which
stretches the tabs to fill the bar. `appearance` is `default` (an underline) or
`pill` (a filled, rounded selected tab); `spacing` is `default` (32px) or
`compact` (24px).

</div>

## Parts

1. **Tab strip.** A `tablist` of buttons, aligned left, center, right or justified.
2. **Tab.** A button whose label names a view, on one line; the selected one is marked by an underline on the strip's baseline (`default`) or a filled pill (`pill`), whose strip has no baseline.
3. **Baseline.** The hairline under an underline strip that the selected bar sits on.
4. **Panel.** The content one tab controls, shown below the strip.

## Best practices

### A controlled bar needs `onSelect`, or it will never move.

```jsx
// Incorrect — activeKey pins the bar and nothing updates it.
<Tabs activeKey="overview">
  <Tabs.Tab eventKey="overview">Overview</Tabs.Tab>
  <Tabs.Tab eventKey="sessions">Sessions</Tabs.Tab>
</Tabs>

// Correct.
<Tabs activeKey={tab} onSelect={setTab}>
  <Tabs.Tab eventKey="overview">Overview</Tabs.Tab>
  <Tabs.Tab eventKey="sessions">Sessions</Tabs.Tab>
</Tabs>
```

### Every `Tabs.Tab` needs an `eventKey` — selection is keyed off it.

```jsx
// Incorrect — with no eventKey, there is no key to compare against activeKey,
// so the tab never shows as selected and onSelect fires with nothing useful.
<Tabs activeKey={tab} onSelect={setTab}>
  <Tabs.Tab>Overview</Tabs.Tab>
</Tabs>

// Correct.
<Tabs activeKey={tab} onSelect={setTab}>
  <Tabs.Tab eventKey="overview">Overview</Tabs.Tab>
</Tabs>
```

### Keep the labels short and parallel.

Each label is one or two words naming a view of the same subject: Overview, Sessions, Progress. Parallel wording lets people scan the strip without reading it.

<DoDontPair
    doExample={<Tabs defaultActiveKey="0"><Tabs.Tab eventKey="0">Overview</Tabs.Tab><Tabs.Tab eventKey="1">Sessions</Tabs.Tab><Tabs.Tab eventKey="2">Progress</Tabs.Tab></Tabs>}
    doCaption="Short nouns for views of the same subject."
    dontExample={<Tabs defaultActiveKey="0"><Tabs.Tab eventKey="0">View the overview</Tabs.Tab><Tabs.Tab eventKey="1">Sessions list</Tabs.Tab><Tabs.Tab eventKey="2">Show progress</Tabs.Tab></Tabs>}
    dontCaption="Mixed verbs and phrases that do not scan."

### Choose the appearance by weight, not taste.

The underline suits a strip that sits above page content. The pill suits a strip inside a card or toolbar, where a filled selected tab reads as a control.

### Keep labels the same across visits.

A label names a view. A count or status in it changes the name and breaks the parallel wording.

    doExample={<Tabs defaultActiveKey="0"><Tabs.Tab eventKey="0">Overview</Tabs.Tab><Tabs.Tab eventKey="1">Sessions</Tabs.Tab><Tabs.Tab eventKey="2">Progress</Tabs.Tab></Tabs>}

## Accessibility

- **A real tab widget, always.** `role="tablist"` on the strip, `role="tab"`
  and `aria-selected` on each tab, `aria-controls` pointing at the panel when
  one is declared, and roving tabindex: one stop for the whole strip, with
  Left, Right, Home and End moving selection and focus together. Tabs are real
  `<button>` elements, so activating one pushes no history entry and moves no
  scroll position.
- **A disabled tab stays reachable by the arrow keys**, so its existence is
  discoverable, but is never selected — `isDisabled` keeps it out of
  `activeKey` contention without removing it from the strip's keyboard path.
- **`aria-controls` is omitted rather than dangled.** A `Tabs.Tab` with no
  matching `Tabs.Panel` gets no pointer at all — an id that is not in the
  document sends assistive technology to nothing, which is worse than pointing
  nowhere.

## Related

- For navigating to a different page, use the Top bar pattern or `Breadcrumb` — tabs imply the content stays in place.
- For more tabs than fit the width, use `Select` — the strip is `flex-wrap:
  wrap`, so the overflow becomes a second row of tabs rather than a scroll or
  an overflow menu, and the row the reader is on stops being obvious.
- For filtering a list rather than switching between views, use `Select` or `RadioGroup` — filters combine, tabs do not.
