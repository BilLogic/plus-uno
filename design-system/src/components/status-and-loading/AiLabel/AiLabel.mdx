## When to use

Use `AiLabel` wherever a person is looking at something the agent had a hand in:
a suggested question, a drafted summary, a recommended lesson. It answers two
questions at once — where did this come from, and how much should I trust it —
and both belong on the content rather than in a paragraph elsewhere on the page.

It is a **first stab at #269, not a settled component.** The colour is
deliberately unresolved: `--plus-ai-accent` is one local custom property behind a
neutral token, so when the brand decision is made it lands on a single
declaration.

</div>

## Usage notes

### The axis is authorship, not technology.

`origin` separates the agent's own output from a person's work it helped with,
and both from output a person has since checked. A reader needs those three
apart far more than they need to know a model was involved somewhere.

```jsx
// Incorrect — "AI was here" is not information a reader can act on.
<AiLabel text="AI-powered" />

// Correct — say who authored it, and the default words follow.
<AiLabel origin="generated" />
<AiLabel origin="reviewed" text="AI draft, checked by Ms Okafor" />
```

### A low-confidence mark has to say what to do.

`confidence="low"` changes the treatment and the accessible name. It also
carries a note, and the default note is an instruction rather than a label —
a caution with no instruction is the thing this is meant to prevent.

```jsx
// Incorrect — the reader is told to worry and not told what about.
<AiLabel origin="generated" confidence="low" note="Low confidence" />

// Correct — the note says what is wrong and what to do.
<AiLabel origin="generated" confidence="low" note="Two citations could not be verified" />
```

### The mark is not a control.

`onExplain` renders one real button inside it. Nesting one interactive element
inside another is invalid per ARIA — the same rule `Tag` and `Badge` both
record. To make a whole row pressable, put a `Button` around the content and
this inside it.

</div>

## Accessibility

- **The name says what the mark means, not what it is.** The surface this
  replaces is labelled `AI-powered feature`, which tells a screen-reader user
  the category of the thing and nothing about the content it is attached to.
- **The confidence is in the accessible name.** Somebody who cannot see the
  caution treatment is otherwise told the same thing whether or not the system
  trusts its own output.
- **`role="note"`** makes the mark one thing rather than a loose icon beside
  loose words, so it is announced as a phrase.
- **The glyph is decorative and hidden.** It repeats what the words already say;
  announcing it would give "wand, Generated by PLUS AI" and no extra
  information — the same rule `Tag`'s `swatchBefore` follows.
- **The explain button says what it does.** `How was this made?` is an action,
  not a category. Compare `title="AI recommended"`, which is not a reliable
  accessible name in any screen reader.
- **Low confidence uses the warning *container* pair, never the warning
  ground.** Measured: `--color-warning` with a white label is 3.70:1 — the only
  one of the 65 button combinations below AA (#312) — while
  `--color-warning-container` with `--color-on-warning-container` is 13.27:1. A
  new component must not be built on the one pair known to fail.

</div>

## Related

- For a value a person chose rather than one the agent produced, use `Tag`.
- For system-generated data with no trust question attached, use `Badge`.
- For a message about the whole page rather than a mark on one thing, use `Alert`.
- For work still in progress, use `Spinner` or `Progress`.
