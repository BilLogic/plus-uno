## Usage

Use Radio when the options need custom presentation, such as options listed in a table. For a plain list of options, use RadioGroup, which owns the group label, the value and the error.

Make one option the default: the safest and lowest-risk one. If a person may decline all options, add a "None" option; if the list cannot be complete, add "Other".

</div>

<div className="sb-ds-doc-section">

## Parts

1. **Radio.** A 12 circle. Selected, it fills with the selected bold fill and draws an inverse dot; unselected, it is an empty circle.
2. **Label.** 14/20 text beside the radio in a 24 row. It names the option. A required marker follows it.
3. **Description.** Optional 12/16 text under the label that describes the option. It does not name it.

## Best practices

### Reserve choice tiles for one big question with two to four pictured options.

Use `appearance="tile"` when a step asks one focal question with two to four options and every option carries an `illustration`. Keep ordinary form lists and sets of five or more options in `plain` or `card`.

<DoDontPair
    doExample={<div style={{ display: 'flex', flexWrap: 'wrap', gap: 'var(--inline-lg)' }}><Radio name="do-tile-r" label="One-on-one" value="a" description="One student." illustration={<Illustration character="relationships" size={48} />} appearance="tile" defaultChecked /><Radio name="do-tile-r" label="Small group" value="b" description="Two to four students." illustration={<Illustration character="social-emotional" size={48} />} appearance="tile" /></div>}
    doCaption="Two pictured tiles for one focal question."
    dontExample={<div style={{ display: 'flex', flexWrap: 'wrap', gap: 'var(--inline-lg)' }}><Radio name="dont-tile-r" label="Daily" value="a" appearance="tile" /><Radio name="dont-tile-r" label="Weekly" value="b" appearance="tile" /><Radio name="dont-tile-r" label="Monthly" value="c" appearance="tile" /></div>}
    dontCaption="Plain text options without illustrations drawn as tiles."
/>

### Show one answer selected at a time.

A radio group holds exactly one answer. Never show two selected.

<DoDontPair
    doExample={<div style={{ display: 'flex', flexDirection: 'column', gap: 'var(--stack-md)' }}><Radio name="do-one" label="Email" value="a" defaultChecked /><Radio name="do-one" label="Text message" value="b" /><Radio name="do-one" label="No reminders" value="c" /></div>}
    doCaption="One radio selected in the group."
    dontExample={<div style={{ display: 'flex', flexDirection: 'column', gap: 'var(--stack-md)' }}><Radio name="dont-one-a" label="Email" value="a" defaultChecked /><Radio name="dont-one-b" label="Text message" value="b" defaultChecked /><Radio name="dont-one-c" label="No reminders" value="c" /></div>}
    dontCaption="Two radios selected at once."
/>

### Never preselect a high-risk answer.

Leave consequential choices, such as ones about privacy or payment, for the
person to make on purpose. When an option starts selected, make it the safe
one.

<DoDontPair
    doExample={<div style={{ display: 'flex', flexDirection: 'column', gap: 'var(--stack-md)' }}><Radio name="do-risk" label="Keep my history" value="a" defaultChecked /><Radio name="do-risk" label="Delete my history" value="b" /></div>}
    doCaption="The safe option, Keep my history, starts selected."
    dontExample={<div style={{ display: 'flex', flexDirection: 'column', gap: 'var(--stack-md)' }}><Radio name="dont-risk" label="Keep my history" value="a" /><Radio name="dont-risk" label="Delete my history" value="b" defaultChecked /></div>}
    dontCaption="The high-risk option, Delete my history, starts selected."
/>

### Keep labels short and parallel.

Short labels scan as a list; long ones wrap and blur the choices.

<DoDontPair
    doExample={<div style={{ display: 'flex', flexDirection: 'column', gap: 'var(--stack-md)' }}><Radio name="do-short" label="Daily" value="a" /><Radio name="do-short" label="Weekly" value="b" /><Radio name="do-short" label="Monthly" value="c" /></div>}
    doCaption="Short, parallel labels."
    dontExample={<div style={{ display: 'flex', flexDirection: 'column', gap: 'var(--stack-md)' }}><Radio name="dont-short" label="Every day, before my first session starts" value="a" /><Radio name="dont-short" label="Once a week, on the day I choose in settings" value="b" /><Radio name="dont-short" label="Monthly" value="c" /></div>}
    dontCaption="Long labels that wrap, beside a one-word one."
/>

### Order options by likelihood or risk.

<DoDontPair
    doExample={<div style={{ display: 'flex', flexDirection: 'column', gap: 'var(--stack-md)' }}><Radio name="do-order" label="In person" value="a" /><Radio name="do-order" label="Online" value="b" /><Radio name="do-order" label="Either" value="c" /></div>}
    doCaption="Order options from most to least likely, or from least to most risk."
    dontExample={<div style={{ display: 'flex', flexDirection: 'column', gap: 'var(--stack-md)' }}><Radio name="dont-order" label="Either" value="a" /><Radio name="dont-order" label="In person" value="b" /><Radio name="dont-order" label="Online" value="c" /></div>}
    dontCaption="Alphabetical order cannot be localized and says nothing about which option fits most people."
/>

### A lone Radio is not a group.

Radios that share a `name` are one group; each option gets its own id. ARIA allows `aria-readonly` on a radiogroup and not on a radio, so a read-only question belongs in RadioGroup, which announces it.

### Avoid long lists and overlapping ranges.

For a long list, use Select. Do not write numeric options that overlap ("0-20", "20-40") or skip a number.

### A description describes; the label names.

`description` renders under the label and is read after the name.

## Content guidelines

<DocsTable>
<thead>
<tr><th>Do</th><th>Don't</th></tr>
</thead>
<tbody>
<tr><td>Write each label as the option: "In person".</td><td>A sentence or an instruction: "Choose this if you meet in person."</td></tr>

<tr><td>Add "None" when a person may decline every option, "Other" when the list cannot be complete.</td><td>Force an answer that does not fit.</td></tr>
<tr><td>Say what to do in an error: "Select an option".</td><td>"Required" or "Invalid".</td></tr>
</tbody>

## Accessibility

- **Each option has its own id.** The component derives one per instance, so labels never resolve to the first radio of the group.
- **A radio with no `label` has no accessible name.** Pass `aria-label` where the design has no room for visible text.
- **Include an error message for a required or invalid group**, for example "Select an option".
- **Disable an option only for something the person can fix on the same screen.** Put the reason in the option's `description`, at full contrast, and never in a tooltip. A disabled option leaves the tab order. For a choice that must stay reachable, keep it enabled and use validation, so a screen reader user hears why it cannot be chosen.
- **Keyboard focus is a 2px ring on `border.focused`, 2px off the radio.** Arrow keys move between the radios of a group.
