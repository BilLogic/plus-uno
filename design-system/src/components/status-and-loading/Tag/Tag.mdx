## When to use

Use `Tag` for a value a person chose: the subjects on a tutor's profile, the
filters someone applied to a table, the recipients they added to a message. The
test is authorship — who put the value there — and not whether the control can
be clicked.

That test is what survives the edge case. A `read-only` tag is still a tag,
because the pattern tells the reader the selection becomes editable again once
the surface does. `Badge` is what to reach for when the system produced the
value and nobody can change it: a session's status, an unread count.

</div>

<div className="sb-ds-doc-section">

## Usage notes

### Colour is a category, not a status.

`color` takes plain names, and that is deliberate. There is no `success` and no
`danger`, because a green tag would be read as "this went well" the moment one
appears next to a red one.

```jsx
// Incorrect — the colour is doing the work the label should do, and it is
// doing it wrongly: `green` here means "Biology", not "passed".
<Tag color="green">Biology</Tag>
<Tag color="orange">Chemistry</Tag>

// Correct — pick a colour per category and keep it stable across the app, or
// leave every tag `grey` and let the words carry the meaning.
<Tag color="blue">Biology</Tag>
<Tag color="blue">Chemistry</Tag>
```

### `onRemove` belongs to `dismissible`, and nothing else.

The gate is behaviour, not a type. `propTypes` will accept the function on any
variant; the component renders the remove button on one.

```jsx
// Incorrect — no X renders, and the value stays put. The tag is read-only
// because that is what `variant` says, whatever handler is attached.
<Tag variant="read-only" onRemove={drop}>Grade 4</Tag>

// Correct — the variant is the API.
<Tag variant="dismissible" onRemove={drop}>Grade 4</Tag>
```

### Let the group own the gaps.

`Tag` sets no margin of its own. A row of tags is a `TagGroup`, which sets
`gap` once for the set; spacing a row by hand means every future change to the
rhythm has to find each place it was done.

</div>

## Accessibility

- **A dismissible tag is not itself a control.** Its remove button is, and a
  button inside a button is invalid per ARIA. So the tag renders as a `span`
  and exactly one control exists inside it.
- **The remove button is named from the label.** It announces `Remove Science`,
  not `Remove` — `removeLabel` overrides that string when the label is not
  text. This is the defect `Badge` still carries: its dismiss control is
  hard-coded to one word, so a row of them exposes identical names.
- **`selectable` publishes `aria-pressed`; `operational` does not.** A toggle
  reports its state, and a control that acts once has no state to report.
  Saying `aria-pressed="false"` on the latter tells a screen-reader user to
  track something that never changes.
- **A truncated label keeps its full text.** `maxWidth` puts the label in
  `title`, because a CSS ellipsis alone deletes the value for anyone not
  looking at the pixels.
- **`swatchBefore` is decoration and is hidden.** It repeats what the tag
  already says in words; announcing it would produce "square, Series A".
- **A loading tag exposes no control.** `isLoading` stands the tag down so a
  second press cannot queue a second action against a value that is already
  changing.

</div>

## Related

- For a set of tags, use `TagGroup` — it owns the gaps and the overflow.
- For a field where the person types values in and takes them out, use `TagInput`.
- For system-generated data nobody can change, use `Badge`.
- For choosing from a fixed list rather than showing what was chosen, use `Select` or `Checkbox`.
