<Title />
A template is the whole page every screen starts from: the sidebar and the page that holds the page's content, under its breadcrumb. It sets the screen width, the grid and the content width once, and everything inside moves with it. The default frame is for pages people move among. The focused frame is for one task, with no sidebar.

A template is also the container the app is dropped into, so it is the one level that carries the browser window around the Frame. The **Browser** switch in the toolbar draws Chrome, Safari or Edge around these examples; the sidebar and page keep the same width and left edge. What the Frame does inside the window, from the Sidebar docking to the Panel and overlays at each width, is on <a href="?path=/docs/templates-frame-frame--docs">Frame</a>.

The examples on this page follow the toolbar's Color mode and Contrast switches. Each is drawn at a real screen width, so the layout mode is the one named.

## Usage

Start every page from a template. Pick the frame by the kind of work the page holds.

<DocsTable>
<thead>
<tr><th>Frame</th><th>When to use</th></tr>
</thead>
<tbody>
<tr><td>Default</td><td>The person moves among pages: browse, compare, come back. It keeps the sidebar and the breadcrumb.</td></tr>
<tr><td>Focused</td><td>One task that takes more than a screen or a few minutes, which the person finishes or leaves. Writing a session note, setting up a session and reviewing an import are focused tasks.</td></tr>
</tbody>
</DocsTable>

A confirmation, a rename or a few fields that keep the page behind them in view belong in a Modal; a form that scrolls for long or has sections is a focused page. The details of a row or a set of filters open in a Panel over the template.

The mode is the screen: Medium is 768 to 1023, Large 1024 to 1439 and X-Large 1440 and wider. Sections, Cards and Tables inherit it and never carry one of their own. The frame rules (no top bar, no seams, the content cap, the Sidebar and the Panel) are on <a href="?path=/docs/templates-frame-frame--docs">Frame</a>.

### Build a real page

A page is built from the top down out of patterns. A Sessions page is built on Page, holding a page header, a row of metric cards and a table under a header with tabs.

1. **Frame.** The sidebar and the content box around the page.
2. **Section header, level page.** The page title, description and page-level actions. One per page.
3. **Card, size sm.** Metric tiles. A card shows one piece of information, with the header turned off when the body carries its own title.
4. **Section header, tabs type.** The tabs are the header's bottom row. They replace a separate tab group above the table.
5. **Table.** A plain table directly under the header, with no card around it and no toolbar of its own.

### For developers

A template is a composition, not a component of its own. The default frame is `Frame` with the PLUS `Sidebar` (`@/components`, which fills the Sidebar pattern from the role's config) in `sidebar` and a `Breadcrumb` in `header`; the page's `h1` is its page-level Section header. The focused frame is `Frame` with no `sidebar`, `width="reading"`, the task's name as the `h1` in `header`, and `onBack` and `onClose`, which draw Back and Close; its actions are a group at the foot of the content. There is no mode prop in code: the layout tokens switch on the viewport width, so the screen picks the mode. Figma's `drawer?` toggle is a `PatternDrawer` beside the Frame, whose open state the page holds. `surfaceDirect` puts the children straight in the page with no content grid, for a full-width page such as chat.

### The patterns

A pattern is a page-level shell with its layout rules built in. It sets the fill, radius, padding, elevation and width for one layer of the page, and leaves the content to slots. A page starts from a template. Frame holds the sidebar beside the Page, Page pads the content and gives it the 12-column grid, and Sections, Cards and Tables fill it. Overlays and Popups sit above the page.

In Figma the layout mode (Medium 768, Large 1024 or X-Large 1440) is a variable mode, set once on the template. In code the tokens follow the viewport width.

### A pattern or a component

Use a pattern to build a layer of a page: the frame, a region, a container for one object, a table, or a layer above the page. A pattern gives you the layer, never the content inside it. For a finished piece of UI such as a button, a field or an avatar, use the component. A pattern holds components in its slots, and a component never rebuilds a pattern's frame.

### How a page layers

Each layer has one fill and one elevation. A state such as hover or selected is drawn over the fill, never in place of it.

## Parts

The default frame has three parts.

1. **Frame.** The sidebar beside the page, on the sunken fill.
2. **Header.** The page's first row, 32 high on the sidebar logo row's center line: the breadcrumb. While the sidebar is closed the toggle leads it. Help Center and the account sit in the sidebar's account row.
3. **Content.** A slot in the page. It holds a page-level Section header, whose title is the page's `h1`, and the Sections.

The focused frame has three parts, all in the Frame with no sidebar.

1. **Header row.** 32 high. Back, an icon button with `arrow-left`, leads; the title, the page's one visible `h1` at Heading/xsmall on one line that truncates, follows; Close, an icon button with `xmark`, ends the row. Each button is drawn only with its handler.
2. **Content.** The Page's `main` at reading width: Sections capped at 864, centered and never under 720. It scrolls on its own.
3. **Actions** (optional). A group inside the Page, held at its foot while it scrolls, end-aligned in the content column, 8 apart, the primary action last. A task with nothing to submit has none.

The page carries the content grid, 12 columns with a 16 gutter. The screen grid lives on Blanket only, and the modal guide belongs to Modal.

### States

A template has no interactive states of its own. Every Sidebar, Panel and overlay state is on <a href="?path=/docs/templates-frame-frame--docs">Frame</a>.

## Best practices

### Start from the template and fill its slots.

A slot is a region left open for real content. The pattern owns the layout, the spacing and the size, and the slot holds what the feature needs.

<DoDontPair
    doExample={<FillSlotsDo />}
    doCaption="Start from the template and fill its slots."
    dontExample={<FillSlotsDont />}
    dontCaption="Rebuild the page chrome by hand."
/>

### Keep the slot wrapper.

Replace the placeholder inside a slot, not the slot. If a layout is duplicated to handle a variation, that layout needs a slot. Slots live in Card (header, body, footer), Modal (body, footer), Section (content, side, actions, tabs) and the templates (the page). A table is never a slot shell.

<DoDontPair
    doExample={<SlotsDo />}
    doCaption="Keep the card attached. The content goes in the body slot, and the card’s own stack sets the spacing."
    dontExample={<SlotsDont />}
    dontCaption="A card rebuilt by hand with 24 of extra space added to the chrome drifts from the pattern and misses later fixes."
/>

### Pick the mode, never a width between modes.

In Figma, pick Medium, Large or X-Large on the template instance, and never resize it to a width between modes. In code the screen picks the mode, so set nothing.

### Use the focused frame for a single task.

<DoDontPair
    doExample={<FocusedHeaderDo />}
    doCaption="Use the focused frame for a single task: Back, Close and its name, and nothing else competing."
    dontExample={<FocusedHeaderDont />}
    dontCaption="Keep the sidebar on a one-task page, and its toggle and breadcrumb invite the person away."
/>

If Back and Close would go to the same place, keep Close only.

### End-align the actions, one primary, last.

<DoDontPair
    doExample={<FocusedActionsDo />}
    doCaption="End-align the actions at the foot, one primary, last."
    dontExample={<FocusedActionsDont />}
    dontCaption="Several primary actions, start-aligned: the person cannot tell which one finishes the task."
/>

### Let the content pick the size.

Choose the smallest step of a sized pattern (Card, Modal, Panel) that holds the content without clipping. Never pick a size to make the content look a certain way.

### No card in a card, no modal over a modal.

A Card never holds a Card: group related cards in a Section instead. A Modal never opens a second Modal: a follow-up decision swaps the same Modal's content for an inline confirmation.

### Draw states as overlays.

Hover, pressed and selected take their own token steps: <code>--ds-background-neutral-subtle-hovered</code> and <code>-pressed</code>, then <code>--ds-background-selected</code> and <code>-hovered</code>. Focus is the focus ring in <code>--ds-border-focused</code>, never a fill.

### Keep filled versions as local components.

A spec that fills Frame keeps its own component built from the pattern, so usage traces back to the pattern.

### Note every optical nudge.

Spacing tokens set the structure. Where the eye needs a nudge, such as an icon beside text, an all-caps label or a round shape, nudge for optical balance and note it where you make it. Never leave it as an unexplained hard-coded value.

## Accessibility

- **Landmarks.** The sidebar's `nav` is the navigation and the page is the one `main`. The focused actions are a group named Page actions.
- **One page title.** The page has one `h1`. In the default frame it is the page-level Section header's title, and the breadcrumb shows the place. In the focused frame it is the visible title in the Page header row.
- **Focus order.** In the focused frame it is Back, Close, the content, then the actions. In the default frame the sidebar toggle comes first, then the page.
- **Names.** Back and Close are icon buttons named Back and Close (Frame's `backLabel` and `closeLabel`), and Close keeps its name when the title truncates.
- **Sidebar, Panel and overlays.** Their keyboard and focus rules are on Frame and on each overlay's page.
- **Color.** The frame, the page and the title use color roles, so they hold their contrast in Light, Dark and increased contrast.
