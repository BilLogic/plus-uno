The table pattern is how a table sits on a page. A Section holds the table, and the Section header carries the title and the toolbar. The table spans the section under it, plain, with no card around it and no padding of its own. The shell takes your head and rows, and adds a pagination slot and an empty-state slot.

Static table, Dynamic table and Tree table are planned components, and they have no exports in code yet.

The examples on this page follow the toolbar's Color mode switch.

### Which table?

Pick the type from what people do with the rows. Ask the questions in order, and stop at the first yes.

1. **Does any row nest under another?** Use a Tree table. Nesting wins over everything else, even when the table is interactive.
2. **Can people act on the table?** Sorting, filtering, selecting, paging, expanding rows and row actions all count. If they can, use a Dynamic table.
3. **Otherwise,** use a Static table. People only read it.

One kind of table per block: a Static, Dynamic or Tree table, never mixed in one Section.

### Anatomy

<DocsCanvasShell attachSourceBelow description={<>A Section header with a title, then the head row, the rows and the pager.</>}>
    <DsCanvasQuiet of={PatternTableStories.Overview} />
</DocsCanvasShell>

1. **Section header** holds the title and, in the toolbar type, search, filters, the count and actions.
2. **Head row** names the columns. Its rule is the bold border.
3. **Rows** are the data. Each draws a thin rule, and there is no zebra striping.
4. **Pagination** is a slot under the rows, aligned to the end.
5. **Message row** replaces the rows when the table is empty. It sits under the head row and spans every column.

</div>

<div className="sb-ds-doc-section">

### Composition

- A table sits in a Section and spans it. The default frame is plain: no outer frame, no card around it, and no padding of its own. Its first and last cells sit flush with the section edge.
- The Section header carries the toolbar and the tabs. Search, filters, the record count and the bulk bar use the toolbar type, and saved views use the tabs type.
- The table has no toolbar of its own. Nothing sits between the Section header and the head row.
- Empty, no results, loading and error states happen inside the table, under its header, so the Section header stays usable.
- Paging stays under the rows, inside the same Section.

### Row states

Row states are layered over each cell's fill, never swapped for it. A hovered row takes the neutral subtle hovered step and a pressed row the pressed step. A selected row takes the selected color across the whole row, with no stripe on its leading edge. The checkbox a selectable row carries is the cue that does not rest on color.

### Sticky header and column

<code>stickyHeader</code> pins the head row and <code>stickyColumn</code> the first column. Only a bounded region scrolls vertically, so pair <code>stickyHeader</code> with <code>maxHeight</code>. A sticky edge takes the overflow shadow only once content is scrolled under it.

<DocsCanvasShell description={<>Scroll the table: the header and the first column take the overflow shadow once content passes under them.</>}>

</DocsCanvasShell>

### Empty state

With <code>empty</code>, the head row stays and the empty-state slot takes the body as one message row spanning every column, so the columns still say what will appear and the Section header stays usable. The message row takes no hover state, and the pager hides with the rows. The message shows only when <code>emptyState</code> is also set.

#### Static table: a weekly session summary

People read the days and compare them. Nothing is sorted, selected or paged, and the total sits in the summary row.

### Accessibility

- Name every column with a head cell. Head cells are labels for a column, so they use Heading/xxsmall rather than a heading level.
- Mark the sorted column with <code>aria-sort</code>, and give every icon-only control a name, such as "Actions for Ava Thompson".
- Mark a selected row with <code>aria-selected="true"</code>. That attribute belongs to a row of a table with <code>role="grid"</code>.
- Selection is never color alone. The row's checkbox is checked, and the toolbar says "2 selected".
- A region that scrolls takes keyboard focus, so people can scroll it without a pointer. That covers a region with <code>maxHeight</code> and one with a sticky column.
- The empty message is a row of the table, so assistive technology reads it with the columns it replaces.

</div>

### For developers

The <code>toolbar</code> slot is deprecated. It still renders above the table, with a one-time warning in development. Put search, filters and actions in the Section header instead: <code>{'<PatternSection toolbar={<PatternSection.Toolbar />}>'}</code>.
