## Usage

Use `Breadcrumb` when a page sits inside a hierarchy the user needs to see and
climb — a student inside a cohort inside a program, a lesson inside a unit. It
answers two questions at once: where am I, and what is one level up. When the
hierarchy is one level deep, a single "Back to X" `Link` says the same thing
with less furniture.

It takes a single `items` array of parents, ordered root first. Each item is
`{ text, href, onClick }` and renders as a link. The current record is not an
item: the `PageHeader` title names it.

</div>

<div className="sb-ds-doc-section">

## Alternatives

- For progress through a sequence of steps, use `ProgressTracker`.
- For moving between sibling views of the same subject, use `Tabs`.
- For a persistent hierarchy the user browses rather than retraces, use `Sidebar`.

## Parts

1. **Landmark and list.** A `nav` named by `label` around an ordered list, one item per level, root first.
2. **Parent link.** Every item, in the link color; an `onClick` intercepts it for a router.
3. **Separator.** A slash drawn between items; `separator` swaps the character.

## Best practices

### List parents only.

```jsx
// Incorrect — the last item is the current record. The page title already
// names it, so the trail repeats it.
<Breadcrumb items={[
    { text: 'Cohorts', href: '/cohorts' },
    { text: 'Autumn 2026' },
]} />

// Correct — every item is a parent the person can climb to.
<Breadcrumb items={[
    { text: 'Cohorts', href: '/cohorts' },
]} />
```

### Pass `href` alongside `onClick` on ancestor items.

```jsx
// Incorrect — with no href the item is rendered active, which means it is an
// li rather than a link. The click handler still fires for a mouse, and is
// unreachable by keyboard.
<Breadcrumb items={[
    { text: 'Cohorts', onClick: goToCohorts },
    { text: 'Autumn 2026', href: '/cohorts/a26' },
]} />

// Correct — the href makes it a real, focusable link; onClick intercepts it
// for the router. The component calls preventDefault for you.
<Breadcrumb items={[
    { text: 'Cohorts', href: '/cohorts', onClick: goToCohorts },
    { text: 'Autumn 2026', href: '/cohorts/a26' },
]} />
```

### Pass a string to `separator`, not a node.

Despite the `node` prop type, the value is written into the breadcrumb's
divider custom property, and a custom property holds text. A string is quoted
for you and works; a React element is stringified by CSS and disappears. Pass
`'/'`, `'›'`, `'—'`.

<DoDontPair
    doExample={<Breadcrumb separator="›" items={[{ text: 'Cohorts', href: '#' }, { text: 'Autumn 2026', href: '#' }]} />}
    doCaption="A string separator is quoted for you."
    dontExample={<Breadcrumb separator={<span>›</span>} items={[{ text: 'Cohorts', href: '#' }, { text: 'Autumn 2026', href: '#' }]} />}
    dontCaption="A React element is stringified by CSS and disappears."
/>

### Show the whole path, root first.

A trail that starts mid-hierarchy leaves people unsure where they are. List every parent from the top down to the page's own parent, and let a level too long end in an ellipsis rather than dropping it.

<DoDontPair
    doExample={<Breadcrumb items={[{ text: 'Cohorts', href: '#' }, { text: 'Autumn 2026', href: '#' }, { text: 'Lincoln Middle School', href: '#' }]} />}
    doCaption="Every parent from the root down."
    dontExample={<Breadcrumb items={[{ text: 'Autumn 2026', href: '#' }, { text: 'Lincoln Middle School', href: '#' }]} />}
    dontCaption="The trail starts mid-hierarchy, so the top is missing."
/>

### Keep the trail on one line and truncate each level.

A level longer than its room ends in an ellipsis with its full text in a Tooltip while clipped; the trail never wraps. Five or more levels fold the middle into a "…" button named "Show hidden levels", which opens the hidden levels as links, in order; the root and the last two stay. See [Overflow](?path=/docs/patterns-states-overflow--docs).

### Use it for position, not for history.

A breadcrumb shows where a page sits in the hierarchy, never the pages the person happened to visit. The trail for a page is the same whichever way they arrived.

### Name each level literally.

Use the page's own title, not a direction or a pointer.

<DoDontPair
    doExample={<Breadcrumb items={[{ text: 'Cohorts', href: '#' }, { text: 'Autumn 2026', href: '#' }]} />}
    doCaption="Short, literal names that match the page titles."
    dontExample={<Breadcrumb items={[{ text: 'Back', href: '#' }, { text: 'here', href: '#' }]} />}
    dontCaption="Names that mean nothing out of context."
/>

## Accessibility

- **The landmark is handled.** It renders a `nav` around an `ol`, one link per
  parent. The current record is the page's heading, not a crumb, so no item
  carries `aria-current`.
- **Every breadcrumb is named "breadcrumb" unless you say otherwise.** Pass
  `label` to name the landmark when more than one breadcrumb appears on a page.
- **Keep `text` short and literal.** It is the whole accessible name of the
  link. "Autumn 2026" navigates; "here" does not.
- **The separator is generated content.** It is a `::before` on each item after
  the first, not text in the list; the `ol` structure is what states the
  nesting.
- **`id` lands on the last item.** Not on the `nav`. If you need to point an
  `aria-describedby` or a test at the trail as a whole, use `className`.
