## When to use

Use `Pagination` when a list is split into numbered pages and the user needs to
move between them or jump to a known one — admin tables of sessions, students,
tutors. It is fully controlled: `currentPage` and `totalPages` are required, and
every click calls `onPageChange` with the target page. It holds no state.

The window of numbers is computed for you. `max` (default 5) centers the
window on the current page, and first and last pages are pinned with an ellipsis
whenever the window does not reach them.

</div>

## Usage notes

### It is controlled, so it needs both the page and the handler.

```jsx
// Incorrect — nothing happens on click. The component never tracks a page of
// its own, and without onPageChange each click is preventDefault and stop.
<Pagination currentPage={1} totalPages={12} />

// Correct.
<Pagination currentPage={page} totalPages={12} onPageChange={setPage} />
```

</div>

## Accessibility

- **The structure is right.** A `nav` labeled by `label` (default "Page
  navigation") wraps a `ul` of `li`s, and the current page carries
  `aria-current="page"`.
- **Every page has a name.** Each page button is labeled "Page 3", "Page 4", so
  a screen reader never reads a bare number. Naming the `nav` says which list
  the pages belong to.
- **Parts are buttons.** `Pagination.Page` and `Pagination.Navigator` are
  `button` elements: Tab reaches each, Enter and Space activate it, and none
  follows a link.
- **A disabled Navigator stays reachable.** At the first or last page the
  Previous or Next control keeps its tab stop and carries `aria-disabled="true"`;
  activating it does nothing. It is announced as unavailable rather than
  disappearing, which keeps the row from reflowing.
- **The ellipsis is hidden.** It is `aria-hidden`: the pinned first and last
  pages beside it carry the meaning.
- **Pages are not destinations.** If page numbers should be linkable or
  shareable, render your own anchors with real URLs.
- **Focus is a ring inside the segment** (`--focus-ring-width`), and the current page keeps an
  outline in forced-colors mode.

### Text mode is the one that labels its arrows.

```jsx
// Incorrect — in the default `icon` navigator, previousLabel and nextLabel are used only
// as the arrows' accessible names, so these strings are never visible.
<Pagination currentPage={page} totalPages={9} onPageChange={setPage}
            previousLabel="Back a page" nextLabel="On a page" />

// Correct — navigator="text" renders the words; otherwise leave the defaults, which
// already label the arrows "Previous" and "Next".
<Pagination currentPage={page} totalPages={9} onPageChange={setPage} navigator="text" />
```

### Name the navigation when there is more than one on the page.

```jsx
// Incorrect — two paginated tables produce two landmarks both called
// "Page navigation", the component's default.
<Pagination currentPage={p1} totalPages={4} onPageChange={setP1} />
<Pagination currentPage={p2} totalPages={7} onPageChange={setP2} />

// Correct.
<Pagination label="Sessions pages" currentPage={p1} totalPages={4} onPageChange={setP1} />
<Pagination label="Students pages" currentPage={p2} totalPages={7} onPageChange={setP2} />
```

## Related

- For a continuously loading feed, use infinite scroll rather than pages.
- For a step-by-step flow, use `ProgressBar` with your own step control.
- For a long table, pair pagination with sorting and filtering; on its own it makes a specific row hard to find.
