## Usage

Use a calendar directly only when a date grid needs to be visible on the page without a field or a popup around it: a scheduling view, an embedded picker. For a single date field, use Date picker; for a date and time together, use Date time picker. Both already use this same grid.

</div>

<div className="sb-ds-doc-section">

## Parts

1. **Header.** The month and year in full, with Previous month and Next month buttons.
2. **Weekday row.** Seven short day names.
3. **Day cells.** Forty-two buttons in six weeks. Days of neighboring months fill the spare cells.

## Best practices

### Name the month in full, with the year.

The header says which month the grid shows, such as "October 2026". The calendar writes it this way itself; numbers alone make people count.

### Dim unavailable days, do not hide them.

A dimmed day tells people why a slot is missing; a day that looks pickable but is not wastes a tap. Set `minDate` and `maxDate` to the span that can be chosen.

<DoDontPair
    doExample={<Calendar viewDate={new Date(2026, 9, 1)} onViewDateChange={() => {}} minDate="2026-10-12" maxDate="2026-10-25" onPick={() => {}} />}
    doCaption="Days outside the span that can be chosen are dimmed and disabled."
    dontExample={<Calendar viewDate={new Date(2026, 9, 1)} onViewDateChange={() => {}} onPick={() => {}} />}
    dontCaption="Every day looks pickable, and the limit is found only after an error."
/>

### Show the selected date as one filled day.

In single mode one day carries the selected fill. A second fill reads as a range.

<DoDontPair
    doExample={<Calendar viewDate={new Date(2026, 9, 1)} onViewDateChange={() => {}} selected="2026-10-14" onPick={() => {}} />}
    doCaption="One picked day carries the fill."
    dontExample={<Calendar viewDate={new Date(2026, 9, 1)} onViewDateChange={() => {}} rangeStart="2026-10-07" rangeEnd="2026-10-09" onPick={() => {}} />}
    dontCaption="Two filled ends for a single answer read as a range."
/>

### Say which dates can be chosen.

Put the limit in text near the calendar, so people do not find it by trying disabled days.

<DoDontPair
    doExample={<div><p style={{ margin: '0 0 var(--stack-sm)' }}>Pick a day between October 12 and 25.</p><Calendar viewDate={new Date(2026, 9, 1)} onViewDateChange={() => {}} minDate="2026-10-12" maxDate="2026-10-25" onPick={() => {}} /></div>}
    doCaption="A line above the grid states the span."
    dontExample={<div><Calendar viewDate={new Date(2026, 9, 1)} onViewDateChange={() => {}} minDate="2026-10-12" maxDate="2026-10-25" onPick={() => {}} /></div>}
    dontCaption="No text: the limit shows only as dimmed days."
/>

### Let the caller own the month on show.

`Calendar` holds no state of its own. The caller owns `viewDate` and updates it when `onViewDateChange` fires, the same pattern Date picker uses internally.

```jsx
const [viewDate, setViewDate] = useState(new Date());

<Calendar
    viewDate={viewDate}
    onViewDateChange={setViewDate}
    selected={selectedDate}
    onPick={setSelectedDate}
/>
```

### Keep the grid at six weeks.

Six weeks render every month, including the days of neighboring months that fill the remaining cells. This keeps the panel's height constant as someone pages through months, at the cost of occasionally showing a mostly empty week.

## Accessibility

- **Each day is a real, named button.** The accessible name is the day's full date, not just a number, so a screen reader announces an unambiguous date on every cell.
- **State is marked, not just styled.** `aria-pressed` marks the picked day or a range's ends, `aria-current="date"` marks today, and `data-in-range` marks the days between. None of this relies on color alone.
- **Out-of-range and out-of-month days are truly disabled**, not just dimmed: they take no focus and fire no `onPick`.
- **The month buttons are named** "Previous month" and "Next month".
