## For developers

- **The message renders only with a validation state.** <code>validationMessage</code> shows when <code>validation</code> is not "none". Set the message alone and nothing shows, which suits a field that should carry its message only once it has failed.
- **The caption holds a message and a count.** <code>caption</code> is standing help, and a validation message takes its place while <code>validation</code> is set. <code>maxLength</code> adds a count on the right beside either.
- **Describedby is composed.** Your own <code>aria-describedby</code> is kept and the message id is appended, so standing help and a new error are both read, in that order.
- **Extra props land on the input**, so <code>autoComplete</code>, <code>pattern</code>, <code>inputMode</code> and any <code>aria-*</code> attribute reach the control rather than its box.
- **Type changes the keyboard.** <code>type="email"</code> and <code>type="tel"</code> change the mobile keyboard as well as the validation. Set them even where the server validates.
- **subtle is for editing in place**, on record and profile pages, and not in a form someone fills from top to bottom. Pass <code>onSave</code>. It is called on blur or Enter, Esc cancels, and while it runs the trailing slot shows "saving…". Throw or reject and the field stays open and invalid, keeping what was typed, with your error as the caption.
- **The id is derived** when you do not pass one. Pass <code>id</code> when something outside the component needs to point at the input. The name is a form key and is never used as an id.
- **Name the field when the design shows no label:** pass a label and <code>showLabel=false</code>, not only a placeholder.

## When to use

Use Text field for one line of text: names, emails and short answers. It owns its label, its validation state and its message, which makes it the right home for an error rather than an alert at the top of the form.

- **Say how to fix it in the message.** An invalid field colors the border, and the message says what to do, such as "Enter an email like name@school.edu".
- **Show search with the field's magnifier.** Put the magnifier on the leading side and leave the trailing side empty. Keep the placeholder to what is searched, such as "Search tutors".
- **Use Text field, not the field box.** The field box behind every text-like input is an internal part. Place Text field, Text area, Number input or Select, and reach for the field box only when building a new input.
- **For an answer that may run past a line**, use [Text area](?path=/docs/components-forms-and-inputs-text-area--docs).
- **For a number**, use [Number input](?path=/docs/components-forms-and-inputs-number-input--docs).
- **For an addon that acts on the value**, use [Input group](?path=/docs/components-forms-and-inputs-input-group--docs).
- **For a choice from a list**, use [Select](?path=/docs/components-forms-and-inputs-select--docs).

## Accessibility

- **The label is associated with the field.** Clicking it focuses the field, and a screen reader announces it with the field.
- **Hiding the label keeps the name.** <code>showLabel=false</code> clips the label out of sight and keeps it for assistive technology. Use it where the design has no room to show it.
- **A field with no label has no name.** If the visible label is drawn by something else, such as a column header or a label above the field, point it at the input. If there is no text anywhere, pass an <code>aria-label</code>. A placeholder is not a name, because it disappears as soon as someone types.
- **Required is marked once.** An asterisk shows beside the label, and the field is announced as required. The form explains the asterisk once, in a legend above the fields. Fields carry no "(required)" or "(optional)" text.
- **The info tooltip is outside the label**, so its name is never part of the field's name.
- **Validation is announced.** An invalid field is marked invalid, points at its message, and the message is read out when it appears. A success message describes the field without claiming an error.
- **A visual is decoration.** Leading and trailing icons are hidden from assistive technology. Anything the reader must know, such as that this is a search field, belongs in the label or the message.
- **Set autofill on every field the browser can fill.** Login email is "email", the password is "current-password", and an access code is "one-time-code".
