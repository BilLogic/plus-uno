<FoundationSection title="Overview">

Borders mark a boundary, separate neighbors and show state. The width token sets how heavy the line is and the color token says what it means, so always choose them as a pair.

```css
border-width: var(--border-width-default);
border-width: var(--border-width-selected);
border-width: var(--border-width-focused);
```

Figma holds `Border/default`, `Border/selected` and `Border/focused` in `spacing / semantics`, paired with `color/border/*` in `color / semantics`.

<Callout title="Border rules">
A card has no border: its edge comes from <a href="?path=/docs/foundations-visual-elevation-overview--docs" style={{ color: 'var(--ds-link)', textDecoration: 'underline' }}>Elevation</a>. A divider is a border, not a component.
</Callout>

</FoundationSection>

<FoundationSection title="Width tokens">

<FoundationSection title="Focus ring">

The focus ring shows keyboard users where they are. It is a ring, never a fill: a filled field looks selected or disabled.

Do: The field keeps its fill and gains the ring.

Don't: A filled field reads as selected and hides what is typed.

<FoundationSection title="Selected states">

A selected option, active tab or chosen tile takes `Border/selected` (2 px) in `color/border/selected` on every side, paired with a second cue such as a check or a fill. State and emphasis use the whole shape, never a colored stripe on one edge.

</FoundationSection>

<FoundationSection title="Dividers">

- Space comes first. Add a 1 px line (`Border/default` in `color/border/default`) only when spacing alone does not separate two groups.
- A horizontal rule spans the content width of its container. A vertical rule sits between controls and takes their height.
- A heavier or colored line is a state, not a divider.

<Canvas of={BorderStories.Dividers} />

</FoundationSection>

<FoundationSubsection title="Give the sidebar one edge and the topbar none">

The sidebar ends in a 1 px divider in `color/border/default`. The topbar has no border.

Do: One hairline on the sidebar edge.

Don't: A line under the topbar adds a second edge the Frame does not use.

<Canvas of={BorderStories.SidebarEdges} />

</FoundationSubsection>

<FoundationSection title="Do and don't">

<FoundationSubsection title="Show selection with the whole outline">

A selected row takes the 2 px selected border on every side, in `color/border/selected`.

Do: The 2 px outline wraps the whole row.

Don't: A colored stripe on one edge marks nothing the system recognizes. Use the full outline, a fill or an icon.

<Canvas of={BorderStories.WholeSelectionOutline} />

</FoundationSubsection>

<FoundationSubsection title="Use the selected width only for selection">

`Border/default` is the width for everything that is not a state.

Do: Resting rows and cards keep Border/default.

Don't: The 2 px width on a resting row reads as selected, so users cannot tell what is chosen.

<Canvas of={BorderStories.SelectedWidthOnlyForSelection} />

</FoundationSubsection>

</FoundationSection>

<FoundationSection title="Accessibility">

- A border that is the only cue for a control's edge clears 3:1 against its surround (WCAG 1.4.11). Use `color/border/input` for fields.
- The focus ring is the one signal for keyboard focus and clears 3:1 against what it sits on.
- Selection never rests on color alone: the 2 px width is the second cue beside `color/border/selected`.
- A subtle accent background needs an accent border to reach 3:1 against the surface.

</FoundationSection>
