## Usage

Use `ProgressIndicator` for a short sequence where position matters more than
the name of each step — a carousel, an onboarding flight, a slide deck. When
each step has its own label people need to see, use `ProgressTracker` instead.

</div>

<div className="sb-ds-doc-section">

## Parts

1. **Dot.** One per step: 8 or 12 across, a circle.
2. **Current dot.** The brand ground (discovery for help, inverse icon for inverted), with <code>aria-current="step"</code>.
3. **Group.** The row, named by <code>label</code>.

## Best practices

### Pass `onSelect` only when jumping ahead makes sense.

Without `onSelect` the dots are decorative and only `aria-current` marks the active one. With it, every dot becomes a button a person can press to jump there directly. That suits a carousel, not a linear flow someone must complete in order.

<DoDontPair
    doExample={<ProgressIndicator values={['Slide 1', 'Slide 2', 'Slide 3', 'Slide 4']} selectedIndex={1} onSelect={() => {}} label="Carousel slides" />}
    doCaption="Interactive dots on a carousel, where any slide can be opened."
    dontExample={<ProgressIndicator values={['Step 1', 'Step 2', 'Step 3', 'Step 4']} selectedIndex={1} onSelect={() => {}} label="Checkout steps" />}
    dontCaption="Interactive dots on a flow that must be finished in order."
/>

```jsx
<ProgressIndicator
    values={slides}
    selectedIndex={index}
    onSelect={({ index }) => setIndex(index)}
    ariaControls="carousel-panel"
/>
```

### Keep the number of dots small.

A row of dots reads at a glance. Past about seven, position stops being readable.

<DoDontPair
    doExample={<ProgressIndicator values={['a', 'b', 'c', 'd', 'e']} selectedIndex={2} />}
    doCaption="A handful of dots, so the current one is easy to find."
    dontExample={<ProgressIndicator values={Array.from({ length: 24 }, (_, i) => String(i))} selectedIndex={11} size={8} spacing="compact" />}
    dontCaption="Two dozen dots, where the current one is lost in the row."
/>

### Match the appearance to the surface.

`inverted` is for a dark surface; on a light one use `default`, `primary` or `help`.

<DoDontPair
    doExample={<div style={{ display: 'inline-flex', padding: 'var(--pad-y-lg) var(--pad-x-md)', borderRadius: 'var(--radius-md)', backgroundColor: 'var(--ds-background-neutral-bold)' }}><ProgressIndicator values={['a', 'b', 'c', 'd']} selectedIndex={1} appearance="inverted" /></div>}
    doCaption="Inverted dots on a dark ground."
    dontExample={<ProgressIndicator values={['a', 'b', 'c', 'd']} selectedIndex={1} appearance="inverted" />}
    dontCaption="Inverted dots on a light surface, where they vanish."
/>

### `values` supplies a count and each dot's name.

The array's content never renders. Its length becomes the number of dots, and when `onSelect` is set each entry becomes a dot's accessible name.

</div>

## Accessibility

- **A named group.** The row has `role="group"` with a `label` ("Progress" by
  default), so a screen reader announces it as one control.
- **The current step is `aria-current="step"`.** This is the only state a
  non-interactive indicator exposes.
- **Interactive dots are real buttons**, each named from its `values` entry
  and linked to the content it controls with `ariaControls`.
