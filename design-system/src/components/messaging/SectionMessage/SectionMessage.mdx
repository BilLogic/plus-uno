## Usage

Use `SectionMessage` for a message that belongs to the page and stays there
until it is resolved or dismissed: why a session cannot be booked, a notice
that a report is out of date, a confirmation that survives a scroll. It takes
children, so the message can carry a link or emphasis, and up to two `actions`
after the body.

A section message always says something about state, so it has six styles and
no others. Each style sets the ground to its role's background token and a
default leading icon in the style's icon color. There is no border or side
stripe: the fill and the icon carry the style.

## Parts

1. **Leading icon.** The appearance glyph on the first line, decorative.
2. **Title.** An optional heading; set <code>headingLevel</code> to fit the outline.
3. **Description.** What the person needs to act. A link in it keeps the text color and is underlined.
4. **Actions.** Link buttons, separated by a divider.
5. **Dismiss.** The shared CloseButton, centered on the first line.

## Best practices

### Match the appearance to the meaning.

Warning for a caution; danger only when something failed.

<DoDontPair
    doExample={<SectionMessage appearance="warning">This term's schedule is provisional.</SectionMessage>}
    doCaption="Warning for a provisional schedule."
    dontExample={<SectionMessage appearance="danger">This term's schedule is provisional.</SectionMessage>}
    dontCaption="Danger for a caution."
/>

### Add a title only when the body needs a heading.

A short body speaks for itself.

<DoDontPair
    doExample={<SectionMessage appearance="info">Tutors confirm times by Friday.</SectionMessage>}
    doCaption="A short body, no title."
    dontExample={<SectionMessage appearance="info" title="Tutors confirm times by Friday">Tutors confirm times by Friday.</SectionMessage>}
    dontCaption="A title that repeats the body."
/>

### Dismiss only what is optional.

A blocking message stays until the problem is fixed. `dismissible` is on by
default, so turn it off when the message must stay.

<DoDontPair
    doExample={<SectionMessage appearance="danger" dismissible={false}>Sign-in didn't complete. Try again.</SectionMessage>}
    doCaption="A blocking error cannot be dismissed."
    dontExample={<SectionMessage appearance="danger">Sign-in didn't complete. Try again.</SectionMessage>}
    dontCaption="A blocking error that can be dismissed."
/>

### Replace the icon through icon, not the children.

A Font Awesome Free solid name or a node replaces the default; `false` removes
it. An icon in the children adds a second one, in the text.

<DoDontPair
    doExample={<SectionMessage appearance="success" icon="trophy">Goal reached.</SectionMessage>}
    doCaption="icon replaces the default icon."
    dontExample={<SectionMessage appearance="success"><i className="fa-solid fa-trophy" aria-hidden="true" /> Goal reached.</SectionMessage>}
    dontCaption="An icon in the children, beside the default one."
/>

### Put field errors on the field.

An error about one input belongs to that input's own error state, such as
`TextField`'s `isInvalid` and `errorMessage`, not in a section message above it.

A rejected submit is the exception that proves the rule: a danger section
message at the top of the form says what was refused, and each field named
still shows its own error.

### Dismissal is one-way.

The component keeps its own dismissed state, and `show` is not a prop. To bring
a message back when it genuinely changes, remount it with a new `key`.

## Accessibility

- **It announces assertively.** The message renders `role="alert"`, which
  implies `aria-live="assertive"`, so a screen reader interrupts to read it.
  That is right for something that just went wrong and wrong for ambient
  information; for the latter, prefer plain text on the page.
- **A message rendered on mount may not be announced at all.** Live regions
  announce changes. If the message is present in the first paint, treat it as
  ordinary content and make sure the surrounding page still reads correctly.
- **`title` renders as a real heading**, at `headingLevel` (default `h2`). It
  joins the page's outline, so pick the level that fits where it sits.
- **The dismiss button is labeled `Dismiss message`**, hard-coded. It is the
  shared `CloseButton`: a fixed 24×24 target whose × is `aria-hidden`.
- **Say the meaning in the words.** The leading icon is `aria-hidden` and there
  is no text prefix, so `appearance="danger"` on its own does not say "error"
  to a screen reader. The icon differs in shape per style, so danger and
  warning do not rely on color alone to look different.
- **Links keep the text color.** A link in the body is told from the text by
  its underline alone.
