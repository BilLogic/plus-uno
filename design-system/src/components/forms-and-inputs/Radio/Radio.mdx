## Usage

Use `Radio` directly only when options need custom layout, such as radio cells inside a table.

Make one option the default: the safest and lowest-risk one. If a person may decline all options, add a "None" option; if the list cannot be complete, add "Other".

</div>

<div className="sb-ds-doc-section">

## Alternatives

- For a standard radio question with a shared legend and error, use `RadioGroup`.
- For a question where several options may be chosen, use `CheckboxGroup` or `Checkbox`.
- For a list of six or more options, use `Select`.
- For a setting that turns on or off immediately, use `Toggle`.

</div>

<div className="sb-ds-doc-section">

## Parts

1. **Radio.** A 12 circle in `plain` and `card` appearances; visually hidden in `soft` and `tile` while keeping native radio semantics, keyboard navigation, and form submission.
2. **Label.** 14/20 text beside the radio in a 24 row. It names the option. An optional minority marker (`"(optional)"` or `"(required)"`) follows a standalone radio's label in plain text.
3. **Description.** Optional 12/16 text under the label that describes the option. It does not name it.
4. **Appearances.** `plain` draws the circle and label inline; `card` wraps them in a bordered surface row; `soft` draws a `--ds-background-neutral` row without a radio dot (selected row shows `--ds-background-selected`, a 1px `--ds-border-selected` edge, and a trailing `fa-solid fa-check` icon) for the majority selection type in a choice flow while the minority selection type keeps its visible control; `tile` draws a 224px pictured card.

## Best practices

### Reserve choice tiles for one big question with two to four pictured options.

Use `appearance="tile"` when a step asks one focal question with two to four options and every option carries an `illustration`. Keep ordinary form lists and sets of five or more options in `plain` or `card`.

<DoDontPair
    doExample={<FigureRow gap="lg"><Radio name="do-tile-r" label="One-on-one" value="a" description="One student." illustration={<Illustration character="relationships" size={48} />} appearance="tile" defaultChecked /><Radio name="do-tile-r" label="Small group" value="b" description="Two to four students." illustration={<Illustration character="social-emotional" size={48} />} appearance="tile" /></FigureRow>}
    doCaption="Two pictured tiles for one focal question."
    dontExample={<FigureRow gap="lg"><Radio name="dont-tile-r" label="Daily" value="a" appearance="tile" /><Radio name="dont-tile-r" label="Weekly" value="b" appearance="tile" /><Radio name="dont-tile-r" label="Monthly" value="c" appearance="tile" /></FigureRow>}
    dontCaption="Plain text options without illustrations drawn as tiles."
/>

### Show one answer selected at a time.

A radio group holds exactly one answer. Never show two selected.

<DoDontPair
    doExample={<FigureStack><Radio name="do-one" label="Email" value="a" defaultChecked /><Radio name="do-one" label="Text message" value="b" /><Radio name="do-one" label="No reminders" value="c" /></FigureStack>}
    doCaption="One radio selected in the group."
    dontExample={<FigureStack><Radio name="dont-one-a" label="Email" value="a" defaultChecked /><Radio name="dont-one-b" label="Text message" value="b" defaultChecked /><Radio name="dont-one-c" label="No reminders" value="c" /></FigureStack>}
    dontCaption="Two radios selected at once."
/>

### Never preselect a high-risk answer.

Leave consequential choices, such as ones about privacy or payment, for the
person to make on purpose. When an option starts selected, make it the safe
one.

<DoDontPair
    doExample={<FigureStack><Radio name="do-risk" label="Keep my history" value="a" defaultChecked /><Radio name="do-risk" label="Delete my history" value="b" /></FigureStack>}
    doCaption="The safe option, Keep my history, starts selected."
    dontExample={<FigureStack><Radio name="dont-risk" label="Keep my history" value="a" /><Radio name="dont-risk" label="Delete my history" value="b" defaultChecked /></FigureStack>}
    dontCaption="The high-risk option, Delete my history, starts selected."
/>

### Keep labels short and parallel.

Short labels scan as a list; long ones wrap and blur the choices.

<DoDontPair
    doExample={<FigureStack><Radio name="do-short" label="Daily" value="a" /><Radio name="do-short" label="Weekly" value="b" /><Radio name="do-short" label="Monthly" value="c" /></FigureStack>}
    doCaption="Short, parallel labels."
    dontExample={<FigureStack><Radio name="dont-short" label="Every day, before my first session starts" value="a" /><Radio name="dont-short" label="Once a week, on the day I choose in settings" value="b" /><Radio name="dont-short" label="Monthly" value="c" /></FigureStack>}
    dontCaption="Long labels that wrap, beside a one-word one."
/>

### Order options by likelihood or risk.

<DoDontPair
    doExample={<FigureStack><Radio name="do-order" label="In person" value="a" /><Radio name="do-order" label="Online" value="b" /><Radio name="do-order" label="Either" value="c" /></FigureStack>}
    doCaption="Order options from most to least likely, or from least to most risk."
    dontExample={<FigureStack><Radio name="dont-order" label="Either" value="a" /><Radio name="dont-order" label="In person" value="b" /><Radio name="dont-order" label="Online" value="c" /></FigureStack>}
    dontCaption="Alphabetical order cannot be localized and says nothing about which option fits most people."
/>

### A lone Radio is not a group.

Radios that share a `name` are one group; each option gets its own id. ARIA allows `aria-readonly` on a radiogroup and not on a radio, so a read-only question belongs in RadioGroup, which announces it.

### Avoid long lists and overlapping ranges.

For six or more options, use `Select`. Do not write numeric options that overlap (`0–20`, `20–40`) or skip a number.

### Keep extra detail in `description`.

`description` renders under the label and is read after the name.

### Let a `Radio` label longer than its line wrap.

The circle keeps its size at the top of the row, and the label is never clipped. See [Overflow](?path=/docs/patterns-states-overflow--docs).

## Accessibility

- **Unique ids.** Each instance derives its own id so labels never resolve to the first radio of the group; pass `aria-label` only when there is no visible label.
- **Required or invalid group.** Include an error message, for example "Select an option".
- **Disabled options.** Disable an option only for something the person can fix on the same screen, and put the reason in `description` at full contrast, never a tooltip; a disabled option leaves the tab order. For a choice that must stay reachable, keep it enabled and use validation, so a screen reader user hears why it cannot be chosen. See [Disabled](?path=/docs/patterns-states-disabled--docs).
- **Keyboard.** Arrow keys move between radios that share a `name`. Focus is a 2px ring on `--ds-border-focused`, 2px off the radio.

## Related

- `RadioGroup`: use when asking a complete radio question with a legend, value and error.
- `CheckboxGroup`: use when any number of options may be chosen.
- `Select`: use when choosing one option from a list of six or more.
- `Toggle`: use when flipping a single setting on or off immediately.
