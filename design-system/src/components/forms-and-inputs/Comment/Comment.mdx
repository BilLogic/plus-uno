## When to use

Use `Comment` for one entry in a threaded discussion — a note on a session, a
reply in a review thread. For a single-field text entry with no author or
thread context, use `TextArea` instead.

</div>

<div className="sb-ds-doc-section">

## Usage notes

### Nest replies through `nestedReplies`, not by composing comments yourself.

Passing replies through `nestedReplies` opens a `HeadingContextProvider` at
`headingLevel`, so any `Heading` inside the reply tree nests one level deeper
automatically — composing `Comment`s directly without this prop skips that
step.

```jsx
<Comment
    author="Jane Park"
    time="2h ago"
    content="Looks good to me."
    nestedReplies={<Comment author="Sam Lee" time="1h ago" content="Agreed." />}
/>
```

### Swap `actions` for `savingText` with `isSaving`, don't hide them yourself.

Set `isSaving` rather than conditionally rendering `actions` — it keeps the
saving state in one prop instead of two places making the same decision.

</div>

<div className="sb-ds-doc-section">

## Accessibility

- **A real article.** Each comment is an `<article>`, giving assistive
  technology a landmark per entry in the thread.
- **Replies nest their headings correctly.** Because `nestedReplies` opens
  its own `HeadingContextProvider`, a reply thread's headings read in the
  right outline order rather than all landing at the same level.
- **Restricted visibility is stated, not just implied.** `restrictedTo`
  renders as visible text in the header, so who can see the comment isn't
  communicated by color or icon alone.

</div>
