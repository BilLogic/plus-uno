## Usage

Use `PromptStarters` to offer a few things a person could ask an AI feature,
before they've typed anything: an empty chat, a fresh reflection, a blank
prompt field. Once a conversation is underway, use `Suggestion` directly for
a single follow-up prompt instead of a full row of starters.

</div>

<div className="sb-ds-doc-section">

## Parts

1. **Group.** A wrapping row with <code>role="group"</code>, named by the required <code>label</code>.
2. **Starter.** A prompt <code>Suggestion</code> per entry in <code>starters</code>: the sparkle wand, the short <code>label</code> on the chip, and the longer <code>text</code> it stands for.

## Best practices

### Keep the label short, and put the prompt in `text`.

A chip sits in a row, so its `label` is a few words that read as a request;
the full prompt it stands for goes in `text`.

<DoDontPair
    doExample={<PromptStarters label="Suggested prompts" starters={[{ id: 'summarize', label: 'Summarize this session', text: 'Summarize Maya\'s last two sessions and suggest what to practice next.' }]} onSelect={() => {}} />}
    doCaption="A short label for a longer prompt."
    dontExample={<PromptStarters label="Suggested prompts" starters={[{ id: 'summarize', label: 'Summarize Maya\'s last two sessions and suggest what to practice next', text: 'Summarize Maya\'s last two sessions and suggest what to practice next.' }]} onSelect={() => {}} />}
    dontCaption="The whole prompt as the label."
/>

### Offer a few.

Three to five starters fit a row and can be read at a glance.

<DoDontPair
    doExample={<PromptStarters label="Suggested prompts" starters={[{ id: 'summarize', label: 'Summarize this session', text: 'Summarize this session for the family.' }, { id: 'plan', label: 'Plan next steps', text: 'What should we cover next session?' }, { id: 'explain', label: 'Explain this concept', text: 'Explain this in simpler terms.' }]} onSelect={() => {}} />}
    doCaption="A few starters to choose from."
    dontExample={<PromptStarters label="Suggested prompts" starters={[{ id: 'summarize', label: 'Summarize this session', text: 'Summarize this session for the family.' }, { id: 'plan', label: 'Plan next steps', text: 'What should we cover next session?' }, { id: 'explain', label: 'Explain this concept', text: 'Explain this in simpler terms.' }, { id: 'practice', label: 'Suggest practice', text: 'Suggest what to practice next.' }, { id: 'family', label: 'Draft a family note', text: 'Draft a note to the family.' }, { id: 'compare', label: 'Compare sessions', text: 'Compare the last two sessions.' }, { id: 'goals', label: 'Review goals', text: 'Review the student goals.' }, { id: 'quiz', label: 'Make a quiz', text: 'Make a short quiz on this topic.' }]} onSelect={() => {}} />}
    dontCaption="So many starters the row becomes a wall."
/>

### Write each label as a request.

The label says what the person is asking for, starting with a verb.

<DoDontPair
    doExample={<PromptStarters label="Suggested prompts" starters={[{ id: 'plan', label: 'Plan next steps', text: 'What should we cover next session?' }, { id: 'explain', label: 'Explain this concept', text: 'Explain this in simpler terms.' }]} onSelect={() => {}} />}
    doCaption="Labels that read as requests."
    dontExample={<PromptStarters label="Suggested prompts" starters={[{ id: 'plan', label: 'Next steps', text: 'What should we cover next session?' }, { id: 'explain', label: 'Concepts', text: 'Explain this in simpler terms.' }]} onSelect={() => {}} />}
    dontCaption="Topic names that don't say what will be asked."
/>

### Let `onSelect` decide what happens.

The component never sends on its own. The common pattern is putting the
starter's `text` into a `PromptInput` so a person can read and edit it before
sending, not sending it immediately on their behalf.

### Pass an empty list rather than a guard.

Don't guard the component with your own conditional: passing an empty
`starters` array already renders nothing, with no empty group left behind.

## Accessibility

- **A named group.** The row is `role="group"` with `label` as its accessible
  name, required so assistive technology announces the set together.
- **Each chip is `Suggestion`'s own control.** Keyboard reach, focus and the
  accept action all follow `Suggestion`'s accessibility contract.
