## Usage

Use `DatePicker` for a single date or a date range typed or chosen from a calendar: a session date, a billing period. For a time alone, use Time picker; for a date and a time together, use Date time picker.

</div>

## Parts

1. **Field.** A 40 box (32 at compact) on the input fill, with the date as text.
2. **Calendar icon.** Opens the calendar. Decoration for assistive technology; the input is the control.
3. **Calendar.** A month grid in a popup 4px below the field, flipped above when there is no room. A picked day is the selected fill; days between a range's ends are the neutral selection.

## Best practices

### Typing is checked on Enter or on leaving the field.

A real day inside `minDate` to `maxDate` is picked; anything else is kept exactly as typed and marked invalid, and `onChange` is not called until the text reads as a real date.

```jsx
<DatePicker
    value={date}
    onChange={setDate}
    minDate="2026-01-01"
    maxDate="2026-12-31"
/>
```

### A range is two clicks, not a drag.

The first click sets the first day, the second sets the last day, and `onChange` receives `[start, end]`. A click before the first day starts the range again rather than erroring.

### Name the field.

There is no `label` prop. Pass `aria-label` or `aria-labelledby`; both go straight to the input.

### Show the date format as a hint.

The field says how to type the date before anyone types it. Without a hint people guess the order. The placeholder is MM/DD/YYYY unless you replace it, so leave it.

<DoDontPair
    doExample={<DatePicker aria-label="Session date" />}
    doCaption="The format is shown."
    dontExample={<DatePicker aria-label="Session date" placeholder="Select date" />}
    dontCaption="No format given."
/>

### Show dates in one format everywhere.

Use the same order and separators in the field, the calendar and any message. Mixed formats read as different dates.

<DoDontPair
    doExample={<div style={stack}><DatePicker aria-label="Session date" value="2026-10-21" /><span>Your session is on 10/21/2026.</span></div>}
    doCaption="One format throughout."
    dontExample={<div style={stack}><DatePicker aria-label="Session date" value="2026-10-21" /><span>Your session is on 21 Oct 2026.</span></div>}
    dontCaption="A second format appears in the message."
/>

### Use one range field, not two dates.

A range picks start and end in one field and one calendar. Two separate fields split one decision in two.

<DoDontPair
    doExample={<div style={stack}><DatePicker aria-label="Billing period" range value={['2026-10-05', '2026-10-23']} /></div>}
    doCaption="One range field."
    dontExample={<div style={stack}><DatePicker aria-label="Billing period start" value="2026-10-05" /><DatePicker aria-label="Billing period end" value="2026-10-23" /></div>}
    dontCaption="Two separate fields."
/>

</div>

<div className="sb-ds-doc-section">

### Read-only is not disabled.

`isReadOnly` shows a value someone could change but this person cannot right now: it stays in the tab order at full contrast, can be selected and copied, takes the neutral fill, has no hover and says `aria-readonly`. Say why in the caption. `isDisabled` is for a field that does not apply yet, and takes it out of the tab order. Never swap one for the other, and never clip a read-only value. Content nobody can edit is plain text, not a field.

<DoDontPair
    doExample={<DatePicker aria-label="Session date" value="2026-10-25" isReadOnly />}
    doCaption="Read-only keeps the value readable, and the caption says why."
    dontExample={<DatePicker aria-label="Session date" value="2026-10-25" isDisabled />}
    dontCaption="Disabled fades a value people need to read."
/>

## Accessibility

- **The input is the named control.** `aria-label`, `aria-labelledby` and `aria-describedby` are read straight off the props and land on the text input a screen reader focuses.
- **The popup is a labeled dialog.** It opens as `role="dialog"` with an `aria-label` of "Choose a date" or "Choose dates", not a bare list.
- **`aria-expanded` and `aria-haspopup` track the calendar's open state** on the input itself, which is `role="combobox"`.
- **An invalid typed date keeps the typed text** rather than silently reverting, so the person can see and correct what they entered.
- **Invalid is not color alone:** the input sets `aria-invalid`.
