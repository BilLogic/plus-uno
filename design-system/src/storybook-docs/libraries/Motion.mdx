<FoundationSection title="What it is for">

PLUS motion is springs in three families (spatial, appearance and linear) plus a loop, written once in the token ladder as `--ds-motion-*` semantics. A component names a spatial or appearance token and its duration and adds nothing else. Under reduced motion every spatial token becomes a fade, so a component needs no branch of its own. The values and when to use each are on <DocsLink id="foundations-expression-motion-physics">Physics</DocsLink>.

</FoundationSection>

<FoundationSection title="What wraps it">

Components that appear and disappear, such as <DocsLink id="components-overlays-and-layering-popup">Popup</DocsLink> and <DocsLink id="components-messaging-modal-dialog">Modal</DocsLink>, transition on the `data-starting-style` and `data-ending-style` attributes that <DocsLink id="libraries-base-ui">Base UI</DocsLink> sets, using the tokens. The `motion` package drives the Storybook illustrations and one component, <DocsLink id="components-messaging-flag">Flag</DocsLink>, whose entrance and exit need an interruptible JavaScript spring; drag uses Pragmatic drag and drop. No other component imports a JavaScript animation library. Which token each component takes is on <DocsLink id="foundations-expression-motion-library">Motion · Library</DocsLink>.

</FoundationSection>

<FoundationSection title="What not to do">

- Do not write a literal `ms` value or `cubic-bezier()` in a component. Read the `--ds-motion-*` tokens.
- Do not add an animation library for a transition CSS can do.
- Do not animate more than one or two properties, and prefer transform and opacity to size and position.
- Do not make motion the only signal. Each motion has a reduced-motion form that still shows what changed.

</FoundationSection>
