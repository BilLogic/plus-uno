## Usage

Use `EmptyState` when a view, panel, card or table has no content yet, in place
of a blank area or a bare "No results". It carries a picture, a header, one line
and one primary action.

Use `EmptyState` too when content cannot be shown. A view, panel or table that
fails to load shows the failure in the same slot, with a filled **Try again**.
A view the person may not open says so plainly and names who can help. A
rejected form submit is not one of these: a danger `SectionMessage` at the top
of the form summarizes it. A failure in the background is a `Flag`.

## Parts

1. **Picture.** An <code>image</code> slot or a Font Awesome Free <code>icon</code>. Decorative and hidden from assistive technology.
2. **Header.** A heading one level below the section that holds it.
3. **Description.** One line on what goes here and what to do.
4. **Actions.** One primary Button and an optional secondary one.

## Best practices

### Use default spacing for a whole view.

Compact spacing is for a table body or a card.

<DoDontPair
    doExample={<EmptyState icon="user-group" header="No students yet" description="Add a student to start scheduling sessions." primaryAction={<Button text="Add student" appearance="primary" />} />}
    doCaption="Default spacing fills a view or panel."
    dontExample={<EmptyState spacing="compact" icon="user-group" header="No students yet" description="Add a student to start scheduling sessions." primaryAction={<Button text="Add student" appearance="primary" />} />}
    dontCaption="Compact spacing leaves a full view cramped."
/>

### Lead with one filled action.

The second action is outlined and never stands alone.

<DoDontPair
    doExample={<EmptyState icon="calendar-plus" header="No sessions this week" description="Book a session to fill this view." primaryAction={<Button text="Book a session" appearance="primary" />} />}
    doCaption="A filled action leads."
    dontExample={<EmptyState icon="calendar-plus" header="No sessions this week" description="Book a session to fill this view." primaryAction={<Button text="Book a session" />} />}
    dontCaption="An outlined action with nothing to lead."
/>

### Invite with the next step.

Say what goes here and what to do, in a warm voice. Never apologize.

<DoDontPair
    doExample={<EmptyState icon="user-group" header="No students yet" description="Add a student to start scheduling." primaryAction={<Button text="Add student" appearance="primary" />} secondaryAction={<Button text="Import a list" />} />}
    doCaption="What goes here and what to do."
    dontExample={<EmptyState icon="user-group" header="No data" description="Nothing to show." />}
    dontCaption="A cold label with no way forward."
/>

### Show a load failure in the slot, with Try again.

State what failed and offer the retry. Never leave the view blank or send the
person to a message above it.

<DoDontPair
    doExample={<EmptyState icon="circle-exclamation" header="Couldn't load sessions" description="Check your connection and try again." primaryAction={<Button text="Try again" appearance="primary" />} />}
    doCaption="What failed, with Try again."
    dontExample={<EmptyState icon="calendar-plus" header="No sessions this week" description="Book a session to fill this view." primaryAction={<Button text="Book a session" appearance="primary" />} />}
    dontCaption="An empty-view invitation when the load failed."
/>

### Fill a Table with it, not around it.

The Table's `emptyState` takes the body; an EmptyState never sits under a Table. <PlannedTag /> The <a target="_top" href="./?path=/docs/patterns-states-empty--docs">Empty pattern</a> replaces the whole table, header row and footer included; today the Table keeps its header row.

<DoDontPair
    doExample={<Table headers={['Student', 'Grade']} rows={[]} emptyState={<EmptyState spacing="compact" icon="user-group" header="No students yet" description="Add a student to see them here." />} />}
    doCaption="An EmptyState in the Table's emptyState."
    dontExample={<div style={{ display: 'flex', flexDirection: 'column', gap: 'var(--stack-md)' }}><Table headers={['Student', 'Grade']} rows={[]} /><EmptyState spacing="compact" icon="user-group" header="No students yet" description="Add a student to see them here." /></div>}
    dontCaption="An EmptyState under a Table with an empty body."
/>

## Content guidelines

<DocsTable>
<thead>
<tr><th>Do</th><th>Don't</th></tr>
</thead>
<tbody>
<tr><td>Keep the header short and specific to what is missing.</td><td>Apologize or blame: "Oops, nothing here."</td></tr>
<tr><td>Use the description for context that helps someone decide what to do.</td><td>Repeat the header in the description.</td></tr>
<tr><td>Make the primary action name the next step: "Add student".</td><td>Use a generic label such as "Continue".</td></tr>
<tr><td>Add a secondary action only for a real alternative, such as importing.</td><td>Add a second action just to fill space.</td></tr>
<tr><td>For a failure, say what happened in plain words and offer Try again.</td><td>Show an error code or "Something went wrong" with no next step.</td></tr>
<tr><td>For no access, give the reason and who can help.</td><td>Offer an action the person is not allowed to take.</td></tr>
</tbody>
</DocsTable>

## Accessibility

- **A real heading.** The header is one level below the section that holds the
  EmptyState, so it joins the page outline.
- **Decorative picture.** The image and icon are hidden from screen readers; the
  words carry the meaning.
- **Contrast.** Header and description use the text roles, which pass in every
  color mode.
- **Reflow.** The text wraps inside a column no wider than
  `--section-min-width-main`.
