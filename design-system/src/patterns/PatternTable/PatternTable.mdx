The table pattern is how a table sits on a page. A Section holds the table, and the Section header carries the title and the toolbar. The table spans the section under it, plain, with no card around it and no padding of its own. The shell takes your head and rows, and adds a pagination slot and an empty-state slot.

`StaticTable`, `DynamicTable` and `TreeTable` are the components for the three table types.

The examples on this page follow the toolbar's Color mode switch.

## Usage

A table sits in a Section and spans it. Its first and last cells sit flush with the section edge. The Section header carries the toolbar and the tabs: search, filters, the record count and the bulk bar use the toolbar type, and saved views use the tabs type. Empty, no results, loading and error states happen inside the table, under its header, so the Section header stays usable. Paging stays under the rows, inside the same Section.

### Type guidance

Pick the type from what people do with the rows. Ask the questions in order, and stop at the first yes.

<DocsTable>
<thead>
<tr><th>Question</th><th>Type</th></tr>
</thead>
<tbody>
<tr><td>Does any row nest under another? Nesting wins, even when the table is interactive.</td><td>Tree table</td></tr>
<tr><td>Can people act on the table: sort, filter, select, page, expand rows or use row actions?</td><td>Dynamic table</td></tr>
<tr><td>Otherwise, people only read it.</td><td>Static table</td></tr>
</tbody>
</DocsTable>

Search, filters and actions sit in the Section header: `<PatternSection toolbar={<PatternSection.Toolbar />}>`.

## Parts

1. **Section header.** Not part of the table: the title and, in the toolbar type, search, filters, the count and actions.
2. **Head row.** Names the columns. Its rule is the bold border.
3. **Rows.** The data you pass as `tbody`. Each draws a thin rule, and there is no zebra striping.
4. **Pagination** (optional). A slot under the rows, aligned to the end. It hides while the empty state shows.
5. **Message row.** The `emptyState` slot, which replaces the rows when `empty` is true. It sits under the head row and spans every column.

### States

Row states are layered over each cell's fill, never swapped for it.

## Best practices

### Put a plain table in a Section.

<DoDontPair
    doExample={<PlainTable />}
    doCaption="The table spans the Section under its header: no frame, no card, no padding of its own."
    dontExample={<FramedTable />}
    dontCaption="The table sits inside its own frame with padding. It stops lining up with the Section and the Section header."
/>

### Put nothing between the header and the head row.

<DoDontPair
    doExample={<PlainTable />}
    doCaption="Search, filters and the record count live in the Section header toolbar. The head row follows directly."
    dontExample={<SecondToolbar />}
    dontCaption="A second toolbar sits between the Section header and the head row. The table has no toolbar of its own."
/>

### One table per block.

Never mix a Static, Dynamic or Tree table in one Section either.

<DoDontPair
    doExample={<PlainTable />}
    doCaption="One table per Section, with its own header, so people always know which rows a toolbar acts on."
    dontExample={<TwoTables />}
    dontCaption="Two tables share one Section and one header. The toolbar no longer says which table it acts on."
/>

### Use a Dynamic table for rows people act on.

<DoDontPair
    doExample={<DynamicRoster />}
    doCaption="A roster people act on as a Dynamic table: sortable heads, checkboxes, a pager, and bulk actions in the Section header."
    dontExample={<RosterAsStatic />}
    dontCaption="A roster people act on as a Static table. With no sort, selection or paging, 340 students become one long scroll."
/>

### Use a Tree table for a hierarchy.

## Accessibility

- Name every column with a head cell. Head cells are labels for a column, so they use Heading/xxsmall rather than a heading level.
- Mark the sorted column with `aria-sort`, and give every icon-only control a name, such as "Actions for Ava Thompson".
- Mark a selected row with `aria-selected="true"`. That attribute belongs to a row of a table with `role="grid"`.
- Selection is never color alone. The row's checkbox is checked, and the toolbar says "2 selected".
- A region that scrolls takes keyboard focus, so people can scroll it without a pointer. That covers a region with `maxHeight` and one with a sticky column.
- The empty message is a row of the table, so assistive technology reads it with the columns it replaces.
- Name the table through `tableProps`, such as `aria-label`, when no caption names it.
