## When to use

Use `TagInput` when a field's value is a set of short labels: the topics a
session covered, or the subjects a tutor teaches. The tags are `Tag`s in a
`TagGroup`, so a picked value looks like every other category in the product.
The field shows and removes tags; it has no text entry of its own.

</div>

<div className="sb-ds-doc-section">

## Usage notes

### A controlled field needs a handler to offer a ×.

```jsx
// Incorrect — controlled with no handler, so no tag can be removed and none shows a ×.
<TagInput label="Topics" tags={topics} />

// Correct — onChange receives the new list. onRemove, which receives the index
// and the tag, offers the × as well.
<TagInput label="Topics" tags={topics} onChange={setTopics} />
```

### A tag's color is a Tag color.

```jsx
// Incorrect — the status names are deprecated aliases and warn in development.
<TagInput label="Subjects" defaultTags={[{ value: 'math', text: 'Math', color: 'success' }]} />

// Correct — a tag is a category, so it takes a Tag color.
<TagInput label="Subjects" defaultTags={[{ value: 'math', text: 'Math', color: 'green' }]} />
```

</div>

<div className="sb-ds-doc-section">

## Accessibility

- **The label names a group.** TagInput renders tags, not an input, so its
  label is a `span` that names the tag container through `aria-labelledby`,
  and the container takes `role="group"`. With no `label` the container has
  no role and no name, so give every TagInput a label.
- **Each × names its tag.** The remove button is named `Remove <tag>`, so a
  row of them is not a row of identical controls.
- **Disabled leaves nothing to press.** TagInput draws no ×, and `TagGroup`
  disables every tag.

</div>

## Related

- For one value rather than a set, use `Tag`.
- For the set without a field around it, use `TagGroup`.
- For picking several values from a known list, use `SelectMultiple`.
