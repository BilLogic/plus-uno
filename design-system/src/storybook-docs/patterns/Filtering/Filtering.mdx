### Below 960, the filter side

The side hides and the Filter icon returns with its count. Pressing it gives the filters the Section's whole width, and "Show results" goes back. The Section owns this behavior: <a target="_top" href="./?path=/docs/templates-section-section--docs#width-behavior">Section › Width behavior</a>.

### Widths

A one-list menu is auto: at least the trigger, 160 to 320, truncating with a tooltip. Side by side takes 3-col; stacked takes 3-col and never goes past 4-col. The widths are the <a target="_top" href="./?path=/docs/templates-popup-popup--docs">Popup</a> template's.

## Usage

Use Filtering when a person narrows a collection by its attributes. Filters live at the end of the view bar, in the bar's order: a format switch if any, Search, then the filters, then More and the Primary. Views at the start are not filters: a view is one of a fixed set, and filters combine.

## Best practices

### Use one tier per bar.

<RuleTag kind="automatic" />

Quick filters and a filter menu never share a bar: some filters outside and some inside read as two systems. When a Section outgrows tier 1, all of its filters move into the menu. Where the filters sit in the bar, and the bar's order: <a target="_top" href="./?path=/docs/templates-section-section--docs#order-the-end-of-the-bar-format-switch-search-filters-more-primary">Section › Order the end of the bar</a>.

<DoDontPair
    doExample={<OneTier />}
    doCaption="One tier: three quick filters, all in the bar."
    dontExample={<TwoTiers />}
    dontCaption="Two quick filters plus a Filter icon: two systems in one bar."
/>

### Keep the filters at the end of the bar.

<RuleTag kind="automatic" />

The start of the bar is for views. The filters come after Search and before More and the Primary, so a person finds them in one place on every Section.

<DoDontPair
    doExample={<FiltersAtEnd />}
    doCaption="Views at the start; Search, then the filters, at the end."
    dontExample={<FiltersAmongViews />}
    dontCaption="The filters squeezed in beside the views."
/>

### Show what is on through the control that holds it.

<RuleTag kind="automatic" />

A FilterButton's count, the Filter icon's count on the selected fill, or a count beside each category in a side. No separate count tag, and no row of tags under the bar.

<DoDontPair
    doExample={<CountOnIcon />}
    doCaption="The count on the Filter icon, on the selected fill."
    dontExample={<TagRow />}
    dontCaption="A row of tags under the bar, repeating what is on."
/>

### Apply one list as you pick and several categories on Apply.

<RuleTag kind="automatic" />

A one-list menu is a <a target="_top" href="./?path=/docs/components-forms-and-inputs-popup-select--docs">Popup select</a>: radios for one choice, not searchable for a short list. Checkboxes for several choices in one list are Planned on it <PlannedTag />. A multi-category menu is a <a target="_top" href="./?path=/docs/components-forms-and-inputs-filter-menu--docs">Filter menu</a> that holds values until Apply; Apply closes it and updates the content once, and Reset clears the choices without applying. Where a menu opens and how wide it is: <a target="_top" href="./?path=/docs/templates-popup-popup--docs">Popup</a>.

### Say Reset in a menu and Reset filters everywhere else.

<RuleTag kind="automatic" />

"Reset filters" at the top of a side clears them all, and the "No matches" state offers it too; both clear the search. "Apply filters" appears only for batch filtering in a side.

### Hide the filter side below 960 and fold quick filters below 768.

<RuleTag kind="automatic" />

Below 960 the side hides and the Filter icon returns with its count; pressing it gives the filters the Section's whole width, with "Show results" to go back: <a target="_top" href="./?path=/docs/templates-section-section--docs#drop-the-filter-icon-while-a-filter-side-shows">Section › Drop the Filter icon while a filter side shows</a>. Below 768 quick filters become a stacked menu.

## Accessibility

- The Filter icon's name is "Filters"; with a count it reads "Filters, 2 applied". Apply returns focus to it, so its new name is read.
- A FilterButton's name is its text plus its count. Its list is a listbox the arrow keys move through; Escape closes it and returns focus to the button.
- The result count is a polite live region: it is read as the rows narrow.
- Reset and Apply are the last tab stops in a menu.
- A filter side is a region named "Filters", and each category is a group named by its legend.
