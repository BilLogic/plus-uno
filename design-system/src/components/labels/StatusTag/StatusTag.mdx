## Usage

Use `StatusTag` for the condition something is in when that condition can change:
completed, needs review, missed, in progress. It is the same component whether
the system calculated the state or a person set it.

- **Is it a number?** Count tag.
- **Is it a due or event date?** Date tag.
- **Is it the condition something is in, and can that condition change?** Status tag.
- **Otherwise** (a subject, a person, a category): Tag.

Use `spacing="default"` (20) in rows, lists, tables and sentences, and
`spacing="spacious"` (32) beside a heading.

## Parts

1. **Icon before.** Optional: a Font Awesome Free icon by name, or a node.
2. **Label.** The condition, in a word or two. Past <code>maxWidth</code> it ends in an ellipsis and the full text is a tooltip.
3. **Trailing metric.** Optional: a compact Count tag nested inside, with its own appearance when it means something else.
4. **Fill.** The appearance's tinted ground with its words and an edge one step darker.

## Best practices

### Match the appearance to the meaning.

Color carries the verdict, so success never labels a problem. Each appearance
means one thing (see the guidance above). There is no color prop; a category
with a color is a Tag.

<DoDontPair
    doExample={<StatusTag appearance="success">Complete</StatusTag>}
    doCaption="Success for a finished thing."
    dontExample={<StatusTag appearance="danger">Complete</StatusTag>}
    dontCaption="Danger on a finished thing."
/>

### Keep labels to one or two words.

A status is read at a glance; a sentence belongs in the row text.

<DoDontPair
    doExample={<StatusTag appearance="success">On track</StatusTag>}
    doCaption="On track."
    dontExample={<StatusTag appearance="success">Student is on track for the next session</StatusTag>}
    dontCaption="A sentence in the tag."
/>

### Show one status per object.

Two statuses on one object force people to decide which is true.

<DoDontPair
    doExample={<div style={{ display: 'flex', flexWrap: 'wrap', alignItems: 'center', gap: 'var(--inline-md)' }}><span>Session 12</span><StatusTag appearance="success">Complete</StatusTag></div>}
    doCaption="One status per row."
    dontExample={<div style={{ display: 'flex', flexWrap: 'wrap', alignItems: 'center', gap: 'var(--inline-md)' }}><span>Session 12</span><StatusTag appearance="success">Complete</StatusTag><StatusTag appearance="warning">Needs review</StatusTag></div>}
    dontCaption="Two competing statuses."
/>

### Nest a count instead of placing one beside it.

<DoDontPair
    doExample={<StatusTag appearance="success" trailingMetric={38}>Completed</StatusTag>}
    doCaption="One label; the number reads as part of it."
    dontExample={<div style={{ display: 'flex', flexWrap: 'wrap', alignItems: 'center', gap: 'var(--inline-md)' }}><StatusTag appearance="success">Completed</StatusTag><CountTag value={38} /></div>}
    dontCaption="Two labels that read as unrelated."
/>

### Give the metric its own appearance when it means something else.

`trailingMetricAppearance` defaults to the Status tag's own appearance. Set it
only when the number carries a different meaning from the status, such as a
success status with a danger count of failures.

### Edit in the field, not on the label.

A Status tag never opens a menu. Where a status can be changed, the field around
it becomes an inline Dropdown whose options are grouped To do · In progress ·
Complete · Exception · Failed, each group with one appearance (neutral · info ·
success · warning · danger).

## Accessibility

- **Read as its text.** A Status tag is a `span` with no role, so a screen reader
  announces its text and nothing suggests it can be pressed. An `onClick` is
  dropped with a development warning.
- **Not a tab stop, unless truncated.** When the label is clipped, the Status tag
  takes focus so a keyboard user can reach the tooltip holding the full text;
  pointer users get the same tooltip on hover. The full text is always in the
  DOM, so a screen reader hears all of it.
- **Not color alone.** A state can add a `iconBefore` where color alone is
  not enough. Icons are decorative and hidden from assistive technology.
- **An edge on any surface.** The 1px inside border keeps a pale fill visible
  on white and on gray; in forced-colors mode it becomes a real border.
