## Usage

Use `Flag` to confirm something that has already happened and needs no reply —
saved, sent, copied. It appears over the page, times out, and takes nothing with
it when it goes.

`show` and `onDismiss` are yours; the component holds no state. `appearance` is
`normal`, `information`, `warning`, `error` or `success`; `title` is required and
the description is optional. `actions` adds link buttons, and `bold` expands the
flag to its appearance's bold fill. `delay` is the timeout in milliseconds and
`autohide` turns it off. `FlagGroup` positions a stack of them.

</div>

## Parts

1. **Icon.** The appearance glyph, decorative.
2. **Title.** What happened, in a few words.
3. **Timestamp.** Optional, subtle, after the title.
4. **Description.** At most one line.
5. **Actions.** Link buttons under the description.
6. **Expand toggle.** Only on a bold flag, which starts collapsed to its title.
7. **Dismiss.** The shared CloseButton.

## Best practices

### Nothing important goes only in a flag.

```jsx
// Incorrect — five seconds, then gone, and it took the only copy of the error
// with it. An error the user must act on is not a flag.
<Flag appearance="error" title="Upload failed" show={failed} onDismiss={dismiss}>
    The file was larger than 10 MB.
</Flag>

// Correct — a failure that needs a decision stays on the page.
<SectionMessage appearance="danger" title="Upload failed">The file was larger than 10 MB.</SectionMessage>
```

### Turn off `autohide` for anything the user might need to re-read.

```jsx
// delay is ignored when autohide is false, and setting delay={0} also disables
// the timer — the flag then waits for its close button.
<Flag title="Report ready" show={ready} onDismiss={dismiss} autohide={false}>
    Your export is on the downloads page.
</Flag>
```

### Keep `dismissible` on.

It is on by default and is the only way to close a flag that is not timing out.
Turning it off with `autohide={false}` leaves a flag that never goes away.

## Accessibility

- **Only warning and error interrupt.** Those two appearances are `role="alert"`
  with `aria-live="assertive"`. Every other appearance is `role="status"` with
  `aria-live="polite"`, so a success flag waits for the screen reader to finish
  what it is saying. Every appearance is `aria-atomic`, so the flag is read as one
  message.
- **An eight-second timeout is a timing limit.** Normal, information and success flags
  close after 8 seconds; warning and error stay until they are dismissed, because
  they ask for something to be done. Content that disappears on its own has to
  be dismissible or extendable to satisfy WCAG's timing rule. The close button
  is what does that here, which is why it is on by default.
- **Announcement needs the region to already exist.** A flag mounted at the same
  moment as its container may not be announced at all. Render `FlagGroup`
  with the page and put flags into it.
- **The dismiss button is named "Dismiss flag".** It is the shared `CloseButton` in its
  default tone on the flag's surface, with an `aria-hidden` ×. The × and its
  focus ring are at least 3:1 on that surface.
- **The appearance icon is decorative.** It is `aria-hidden`, so the title beside it
  carries the meaning; the color and icon should never carry it alone.
- **Every flag is one surface.** The appearance shows in the 16 icon's color
  alone; the flag is `--ds-surface-overlay` with `--ds-shadow-overlay`, the
  title `--ds-text` and the message `--ds-text-subtle` on every appearance, so no
  appearance needs a contrast exception.
