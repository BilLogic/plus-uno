## Usage

Use `FileItem` inside `FileUpload`'s `children` slot to represent every chosen file or folder, or standalone to display attachments on session notes, comments, and messages. Every row stays locked to `--file-item-height` (`56px`) across `queued`, `uploading`, `done`, and `error` so a list never shifts height as uploads progress.

</div>

<div className="sb-ds-doc-section">

## Alternatives

- For choosing or dropping files from a device, use `FileUpload`.
- For overall progress across a checklist or page section rather than a row's lead slot, use `ProgressBar`.
- For a compact inline token representing a person or category rather than an attachment, use `Tag`.

</div>

<div className="sb-ds-doc-section">

## Parts

1. **Lead (`start`).** A `--image-xs` (`20px`) slot: a `subtlest` clock when `queued`, a `ProgressRing` when `uploading`, a danger icon on `error`, a folder icon when `kind="folder"` is `done`, or the matching file-type icon when `kind="file"` is `done`.
2. **Name (`label`).** Single-line name that truncates before the extension so `.mp4` or `.pdf` remains readable, wrapped in a `Tooltip` with the full name. Opens via `Link` when `href` is set on a `done` item.
3. **Meta (`description`).** Single-line secondary status: `Waiting` when `queued`, `Uploading · <n>%` when `uploading`, `meta` (or `Uploaded`) when `done`, and the `error` message in danger text on `error`.
4. **Actions (`end`).** Omitted when `isReadOnly` or `isDisabled`. Draws a compact subtle X `IconButton` for `cancel` and `remove`, or a trash `IconButton` that confirms via `Popup` for `delete`. On `error`, a compact subtle `Retry` `Button` precedes the X control.

## Best practices

### Match the removal mode to whether the file is already saved.

Use `removal="cancel"` while uploading and `removal="remove"` in an unsaved form so an accidental click is reversible, and reserve `removal="delete"` for saved attachments where removing deletes stored data.

<DoDontPair
    doExample={<FileItem name="signed_consent.pdf" status="done" fileType="pdf" meta="Added Nov 12" removal="delete" />}
    doCaption="Saved attachment uses trash and asks to confirm before deleting."
    dontExample={<FileItem name="signed_consent.pdf" status="done" fileType="pdf" meta="Added Nov 12" removal="remove" />}
    dontCaption="Saved attachment removed immediately with an X and no confirmation."
/>

### State both the cause and the fix on upload errors.

Write `error` as one sentence naming why the upload failed and what the person can do next alongside `Retry`.

<DoDontPair
    doExample={<FileItem name="zoom_0.mp4" status="error" error="That recording is over 500 MB. Trim or compress it and retry." />}
    doCaption="Names the limit and the next step beside Retry."
    dontExample={<FileItem name="zoom_0.mp4" status="error" error="Upload failed" />}
    dontCaption="Leaves the user guessing why Retry will or will not work."
/>

### Represent a chosen folder as one folder row with its file count.

Keep the file list scannable by collapsing a dropped or picked folder into one `kind="folder"` row that reports its item count in `meta`.

<DoDontPair
    doExample={<FileItem name="Week 4 recordings" kind="folder" status="done" meta="6 files · 142 MB" />}
    doCaption="One folder row with its file count in meta."
    dontExample={<FileItem name="Week 4 recordings" kind="folder" status="done" />}
    dontCaption="Folder row hides how many files were included."
/>

## Accessibility

- **Full file name stays accessible.** Visually truncated names expose a single unbroken accessible text node for screen readers and Links, and reveal the full name in a `Tooltip` on hover or focus.
- **Determinate upload progress.** While `status="uploading"`, `ProgressRing` announces `role="progressbar"` with `aria-label="Uploading <name>"` and `aria-valuenow`.
- **Named per-file actions.** Cancel, Remove, and Delete `IconButton` controls include the file name in their accessible label (`"Remove zoom_0.mp4"`, `"Delete signed_consent.pdf"`) so screen-reader users can distinguish rows in a batch.
- **Keyboard-accessible delete confirmation.** `removal="delete"` opens a Base UI `Popup` dialog that traps Escape and outside clicks to cancel cleanly and returns focus to the trigger.
