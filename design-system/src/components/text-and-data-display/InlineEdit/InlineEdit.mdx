## Usage

Use `InlineEdit` for a value that is read far more often than it is changed and
that can be saved on its own: a title, a name or a short note on a record or a
profile page.

Use `TextField` inside a form, where a Save button submits every field together. An
inline edit saves when it is confirmed and has no say in the form's submit, so
placing one in a form leaves two ways to save. Use a subtle `TextField` where
leaving the field should save with no buttons at all.

</div>

<div className="sb-ds-doc-section">

## Parts

1. **Label** (optional). Shown above both views.
2. **Read view.** The value as plain text on the field's own box. The whole view is one button.
3. **Edit view.** The field it opens into: a `TextField` in `InlineEditableTextfield`, or any edit view passed to `InlineEdit`.
4. **Actions.** The confirm and cancel icon buttons, on an overlay under the field. `hideActionButtons` leaves them off.

## Best practices

### Keep the read view plain text.

The whole read view is one button. A link or a button inside it cannot be
reached or pressed, so put those beside it.

<DoDontPair
    doExample={<InlineEditableTextfield label="Name" defaultValue="Ada Lovelace" />}
    doCaption="Plain text in the read view."
    dontExample={<InlineEdit label="Name" defaultValue="Ada Lovelace" readView={() => <a href="#profile">Ada Lovelace</a>} editView={({ id, value, onChange }) => <input id={id} value={value} onChange={onChange} />} />}
    dontCaption="A link inside the read view, which cannot be reached or pressed."
/>

### Confirm on Enter and on leaving.

Both save; Escape cancels. The inline edit saves itself, so it needs no Save button of its own.

<DoDontPair
    doExample={<InlineEditableTextfield label="Session title" defaultValue="Fractions" />}
    doCaption="Enter or leaving the field saves the title."
    dontExample={<div style={{ display: 'flex', alignItems: 'flex-end', gap: 'var(--inline-md)' }}><InlineEditableTextfield label="Session title" defaultValue="Fractions" /><Button text="Save" /></div>}
    dontCaption="A separate Save step beside an inline edit."
/>

### Use compact in dense lists.

Compact draws both views 32 high, to sit in a table cell or a dense row.

<DoDontPair
    doExample={<div><div style={{ borderBottom: 'var(--border-default) solid var(--ds-border)' }}><InlineEditableTextfield defaultValue="Ada Lovelace" compact /></div><div style={{ borderBottom: 'var(--border-default) solid var(--ds-border)' }}><InlineEditableTextfield defaultValue="Grace Hopper" compact /></div><div style={{ borderBottom: 'var(--border-default) solid var(--ds-border)' }}><InlineEditableTextfield defaultValue="Katherine Johnson" compact /></div></div>}
    doCaption="Compact rows in a dense list."
    dontExample={<div><div style={{ borderBottom: 'var(--border-default) solid var(--ds-border)' }}><InlineEditableTextfield defaultValue="Ada Lovelace" /></div><div style={{ borderBottom: 'var(--border-default) solid var(--ds-border)' }}><InlineEditableTextfield defaultValue="Grace Hopper" /></div><div style={{ borderBottom: 'var(--border-default) solid var(--ds-border)' }}><InlineEditableTextfield defaultValue="Katherine Johnson" /></div></div>}
    dontCaption="The default height spreads a dense list out."
/>

### Let the parent hold the value.

`defaultValue` is what the edit view starts with each time it opens. Update it
in `onConfirm`, or the next edit starts from the old value.

### Say why a value was refused.

Return the reason from `validate`, in the words a tutor would use. A refused
value leaves the editor open, so the person can fix it without retyping.

### Leave the editor open for long text.

Set `keepEditViewOpenOnBlur` where a stray click would publish an unfinished
thought, and keep the buttons so there is a clear way out.

## Accessibility

- **The read view is a button.** It is named by the label and the text ("Display
  name Ada Lovelace") and described as "Edit" (`editLabel`).
- **Focus follows the editor.** Opening it puts the caret in the field. Enter,
  the check or Escape returns focus to the read view. Leaving the field
  confirms and leaves focus where the person sent it.
- **Enter confirms and Escape cancels.** In a multi-line edit view, Enter adds a
  line and Cmd or Ctrl and Enter confirms.
- **Refusals are announced.** The message is in the field's caption with
  `role="alert"`, and the field is `aria-invalid`.
- **The buttons are named.** The check and the cross are icon-only, named by
  `confirmLabel` and `cancelLabel`.
