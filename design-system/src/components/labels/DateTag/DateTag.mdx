## When to use

Use `DateTag` for a due or event date beside the thing it belongs to — an
assignment, a session, a report. For a status or a category, use `Tag`
instead; `DateTag`'s outline, icon and three appearances are reserved for
dates.

</div>

<div className="sb-ds-doc-section">

## Usage notes

### The app picks the appearance, never taste.

Derive `appearance` from the date and a due-soon window the app defines —
`neutral` while there's time, `warning` as it nears, `danger` once it has
passed. Write `children` as people say the date: "Due tomorrow," "2 days
overdue," not a raw timestamp.

```jsx
<DateTag appearance="warning">Due in 2 days</DateTag>
```

### A date tag is never a button.

It renders a `span` with no role and no click handler — `onClick`, `role` and
`tabIndex` are dropped with a console warning in development. The one time it
takes focus is when its text is truncated, so a keyboard user can still reach
the tooltip holding the full date.

</div>

<div className="sb-ds-doc-section">

## Accessibility

- **Not a control.** No role, no tab stop, no click handler — assistive
  technology reads it as plain text beside whatever it labels.
- **Truncated text stays reachable.** When the label is clipped, the tag
  takes a tab stop and its full text is available as a tooltip on hover or
  focus.
- **The icon is decorative.** It is `aria-hidden`; the appearance's meaning
  lives in the text, not the icon alone.

</div>
