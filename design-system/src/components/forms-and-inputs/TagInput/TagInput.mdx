## Usage

Use `TagInput` when a field's value is a set of short labels the person picks
from a list and may add to: the topics a session covered, or the languages a
tutor teaches. It behaves like Notion's multi-select. The field holds the
picked values as `Tag`s in a `TagGroup`, with a text entry after them, and
focusing it opens the list of options under it.

- For one value from a list, use `Select`.
- For several values from a fixed list nobody adds to, use `Select` with `isMulti`.
- For fewer than 5 options, use a Checkbox group (`Fieldset` + `Checkbox`).

</div>

## Parts

1. **Field.** The box holding the tags and the text entry.
2. **Tags.** The picked values, each removable unless the field is read-only or disabled.
3. **Entry.** The text entry after the tags. Typing filters the list.
4. **List.** The options under the field, with a "Create" row when nothing matches.
5. **Caption.** Helper text, or the error that replaces it.

## Best practices

### Label every tag input.

A visible label says what the tags are; tags alone do not.

<DoDontPair
    doExample={<TagInput label="Topics" options={topics} defaultTags={['Fractions']} />}
    doCaption="A label names what is being tagged."
    dontExample={<TagInput options={topics} defaultTags={['Fractions']} />}
    dontCaption="Tags with no label leave the field unnamed."
/>

### Show an error on the field itself.

The field carries the error state.

<DoDontPair
    doExample={<TagInput label="Topics" options={topics} isInvalid errorMessage="Pick at least one topic" />}
    doCaption="The field shows the error state."
    dontExample={<TagInput label="Topics" options={topics} />}
    dontCaption="A default field gives no sign of the problem."
/>

### Disable instead of hiding.

A disabled field tells people the option exists but is unavailable.

<DoDontPair
    doExample={<TagInput label="Topics" options={topics} defaultTags={['Fractions']} disabled />}
    doCaption="Visible but disabled."
    dontExample={<TagInput label="Topics" options={topics} defaultTags={['Fractions']} />}
    dontCaption="An enabled field that cannot take tags."
/>

### The caller owns the options, and stores what is created.

`options` is required. When the person creates a value, `onCreate` reports it
once, with the color it was given. Store both on a new option, so the color
stays the same everywhere the tag appears.

```jsx
// Incorrect — the created value is never stored, so its color is lost on the next render.
<TagInput label="Topics" options={topics} />

// Correct — the new value joins the options with its color.
<TagInput
    label="Topics"
    options={topics}
    onCreate={({ value, color }) => setTopics((list) => [...list, { value, label: value, color }])}
/>
```

### A value saved to a server holds a temporary id until it is confirmed.

Return a promise from `onCreate` that resolves to the stored id. Until it
does, the tag is saving and its `value` is a temporary id starting `new-`. If
it rejects, the tag is removed, the text goes back in the entry, and the
failure is announced.

```jsx
<TagInput
    label="Topics"
    options={topics}
    onCreate={({ value, color }) => api.createTopic({ name: value, color }).then((topic) => topic.id)}
/>
```

### A controlled field needs a handler to offer a ×.

```jsx
// Incorrect — controlled with no handler, so no tag can be removed and none shows a ×.
<TagInput label="Topics" options={topics} tags={picked} />

// Correct — onChange receives the new list.
<TagInput label="Topics" options={topics} tags={picked} onChange={setPicked} />
```

### Let people tidy options where they pick them.

Pass a handler for each change the screen can store. The caller owns the
options, so each handler updates the list. TagInput only reports the change.
A field with none of them works as before, with no "…" and no handle.

```jsx
<TagInput
    label="Topics"
    options={topics}
    onRename={(value, name) => setTopics((list) => list.map((t) => (t.value === value ? { ...t, label: name } : t)))}
    onDelete={(value) => setTopics((list) => list.filter((t) => t.value !== value))}
    onColorChange={(value, color) => setTopics((list) => list.map((t) => (t.value === value ? { ...t, color } : t)))}
    onReorder={(from, to) => setTopics((list) => {
        const next = [...list];
        next.splice(to, 0, ...next.splice(from, 1));
        return next;
    })}
/>
```

- **Delete** also removes a picked tag made from that option, through
  `onChange` and `onRemove`. Rename and a color change update that tag too.
- **Reorder** works on the whole list, so the handles hide while text is
  typed. `onReorder(fromIndex, toIndex)` gives places in `options`.

### A tag's color is a Tag color.

A tag is a category, so it takes a Tag color. Any other name draws gray and
warns in development.

## Accessibility

- **The label names the entry.** The text entry is a `combobox` that points at
  the list with `aria-controls` and at the highlighted row with
  `aria-activedescendant`, so focus stays in the field while the arrow keys
  move through the list.
- **The tags are a named list.** `TagGroup` is a list named "Selected:" and the
  label, and each × is named `Remove <tag>`.
- **Changes are announced.** Adding or removing a tag says so in a live
  region, such as "Music added".
- **Invalid is announced.** The message under the field has `role="alert"`,
  and the entry has `aria-invalid` and is described by it.
- **Read-only and disabled leave nothing to press.** Neither draws a × or opens
  the list.
- **A row's handle and "…" are real buttons.** They sit beside the listbox,
  laid over the highlighted row, because an option's content is presentational
  and a button inside one would be lost to a screen reader. They are named `Reorder <option>` and
  `Options for <option>`, and the handle is described by its keys.
- **Reordering is announced.** Picking up, each move, the drop and a cancel
  each say the row and its position, such as "Design judgment dropped,
  position 3 of 4".
- **The menu takes focus and gives it back.** Opening it moves focus to the
  name field. Closing it returns focus to the "…".
