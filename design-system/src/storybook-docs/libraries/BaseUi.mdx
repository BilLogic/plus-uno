<FoundationSection title="What it is for">

`@base-ui/react` supplies behavior and no look. It gives a component its open and closed state, focus handling, keyboard interaction and ARIA roles. PLUS supplies the look with SCSS on `--ds-*` tokens, targeting Base UI's `data-*` state attributes. The version is pinned in `package.json`.

</FoundationSection>

<FoundationSection title="What wraps it">

Each interactive component wraps its own Base UI part, among them <DocsLink id="components-overlays-and-layering-popup">Popup</DocsLink>, <DocsLink id="components-overlays-and-layering-tooltip">Tooltip</DocsLink>, <DocsLink id="components-messaging-modal-dialog">Modal dialog</DocsLink>, <DocsLink id="components-navigation-tabs">Tabs</DocsLink>, Checkbox, Radio, Toggle, Range and Accordion. Use the PLUS component. Its props are the API; Base UI's are not.

</FoundationSection>

<FoundationSection title="What not to do">

- Do not import `@base-ui/react` in product code. If a screen needs behavior no component offers, propose the component.
- Do not style a Base UI part with literal values. Style on tokens and the named state tokens.
- Do not hand-write open and closed state, focus trapping or arrow-key handling for a new interactive control. Build it on a Base UI part.
- Do not patch Base UI's behavior. If a part cannot do what the component needs, the wrapper is the wrong shape.
- Do not install another behavior or UI framework beside it.

</FoundationSection>
