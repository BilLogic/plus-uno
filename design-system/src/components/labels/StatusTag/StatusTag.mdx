## Usage

Use `StatusTag` for the condition something is in when that condition can change:
completed, needs review, missed, in progress. It is the same component whether
the system calculated the state or a person set it.

Give it a `menu` where a person changes the status in place: attendance,
engagement or a workflow status in a row. The tag becomes the trigger of a
`DropdownMenu` and the rows are `ButtonItem`s, the current one `isSelected`.
Leave `menu` off where nobody changes the status there.

Use `spacing="default"` (`20`) in rows, lists, tables and sentences, and
`spacing="spacious"` (`32`) beside a heading.

## Alternatives

- For a status that nobody changes in that place, leave `menu` off: the tag stays a label.
- For a status inside a form that a Save button submits, use `Select`.
- For a menu that only reads, with nothing to pick, use `Popup`.
- For a number on its own, use `CountTag`.
- For a due or event date, use `DateTag`.
- For a change over time such as "+3 vs last week", use `ChangeTag`.
- For a category or subject or person, use `Tag` or `CompetencyTag`.

## Parts

1. **Icon before.** Optional: a Font Awesome Free icon by name.
2. **Label.** The condition, in a word or two. Past `maxWidth` it ends in an ellipsis and the full text is a tooltip.
3. **Trailing metric.** Optional: a 16 `CountTag` nested inside, with its own appearance when it means something else.
4. **Fill.** The appearance's tinted ground with its words and an inset edge one step darker.
5. **Chevron.** With a `menu` only: `angle-down`, and `angle-up` while the menu is open.

## Best practices

### Match the appearance to the meaning.

Color carries the verdict, so success never labels a problem. Each appearance
means one thing (see the guidance above). There is no color prop; a category
with a color is a `Tag`.

<DoDontPair
    doExample={<StatusTag appearance="success">Complete</StatusTag>}
    doCaption="Success for a finished thing."
    dontExample={<StatusTag appearance="danger">Complete</StatusTag>}
    dontCaption="Danger on a finished thing."
/>

### Keep labels to one or two words.

A status is read at a glance; a sentence belongs in the row text.

<DoDontPair
    doExample={<StatusTag appearance="success">On track</StatusTag>}
    doCaption="On track."
    dontExample={<StatusTag appearance="success">Student is on track for the next session</StatusTag>}
    dontCaption="A sentence in the tag."
/>

### Let a label longer than `maxWidth` end in an ellipsis with a Tooltip.

The Tooltip is on only while the label is clipped. See [Overflow](?path=/docs/patterns-states-overflow--docs).

### Show one status per object.

Two statuses on one object force people to decide which is true.

<DoDontPair
    doExample={<FigureRow><span>Session 12</span><StatusTag appearance="success">Complete</StatusTag></FigureRow>}
    doCaption="One status per row."
    dontExample={<FigureRow><span>Session 12</span><StatusTag appearance="success">Complete</StatusTag><StatusTag appearance="warning">Needs review</StatusTag></FigureRow>}
    dontCaption="Two competing statuses."
/>

### Nest a count instead of placing one beside it.

<DoDontPair
    doExample={<StatusTag appearance="success" trailingMetric={38}>Completed</StatusTag>}
    doCaption="One label; the number reads as part of it."
    dontExample={<FigureRow><StatusTag appearance="success">Completed</StatusTag><CountTag value={38} /></FigureRow>}
    dontCaption="Two labels that read as unrelated."
/>

### Give the metric its own appearance when it means something else.

`trailingMetricAppearance` defaults to the Status tag's own appearance. Set it
only when the number carries a different meaning from the status, such as a
success status with a danger count of failures.

### Add a menu where the status changes in place.

A row full of `Select` fields is heavy for a value a person mostly reads and
sometimes flips. Give the tag a `menu` there. Elsewhere, leave it a label.

<DoDontPair
    doExample={<FigureRow><span>Hermione Granger</span><StatusTag appearance="success" menu={<><ButtonItem isSelected>Present</ButtonItem><ButtonItem>Late</ButtonItem></>} aria-label="Attendance, Hermione Granger: Present">Present</StatusTag></FigureRow>}
    doCaption="A menu where the status is flipped in the row."
    dontExample={<FigureRow><span>Session summary</span><StatusTag appearance="success" menu={<ButtonItem>Read-only note</ButtonItem>} aria-label="Summary: Complete">Complete</StatusTag></FigureRow>}
    dontCaption="A menu that only reads is a Popup."
/>

### List the other statuses, each one a row.

Each row is a `ButtonItem` with the same wording as the tag it stands for, and
the current one is `isSelected`. Picking one closes the menu.

### Name the tag by field, record and status.

<DoDontPair
    doExample={<StatusTag appearance="warning" menu={<ButtonItem isSelected>Late</ButtonItem>} aria-label="Attendance, Hermione Granger: Late">Late</StatusTag>}
    doCaption="A name with the field, the record and the status."
    dontExample={<StatusTag appearance="warning" menu={<ButtonItem isSelected>Late</ButtonItem>} aria-label="Late">Late</StatusTag>}
    dontCaption="A name that does not say which field or record."
/>

### Use spacious beside buttons.

Use `spacing="spacious"` so the heights line up with the buttons around the
tag, and `default` in table rows and lists.

## Accessibility

- **Read as its text.** Without a `menu`, a Status tag is a `span` with no role, so a screen reader
  announces its text and nothing suggests it can be pressed. An `onClick` is
  dropped with a development warning.
- **A button with a menu.** With a `menu` it is a `button` with `aria-haspopup="menu"`
  and `aria-expanded`. Its name is the `aria-label`, "field, record: status", so
  a truncated label stays readable through the name and the menu.
- **Keyboard.** Enter, Space and ArrowDown open the menu, arrows move through the
  rows, and Escape closes it and returns focus to the tag.
- **Not a tab stop, unless truncated.** When the label is clipped, the Status tag
  takes focus so a keyboard user can reach the tooltip holding the full text;
  pointer users get the same tooltip on hover. The full text is always in the
  DOM, so a screen reader hears all of it.
- **Not color alone.** A state can add `iconBefore` where color alone is
  not enough. Icons are decorative and hidden from assistive technology.
- **An edge on any surface.** The inset border keeps a pale fill visible
  on white and on gray; in forced-colors mode it becomes a real border.
