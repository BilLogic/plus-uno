## Usage

Use `VisuallyHidden` when the words a screen reader needs are not words a
sighted person needs: the name of an icon-only button, the title of a table
column that holds only checkboxes, the count in a status message, a table
caption the layout already explains.

It renders the `.visually-hidden` class on a `span`, which is one pixel
square, clipped, out of the flow and kept in the accessibility tree. Existing
markup that writes `className="visually-hidden"` is the same thing and can move
to the component as it is touched.

</div>

## Best practices

Use hidden text to give assistive technology the words the layout already gives a sighted reader. In the examples below, the line under each control spells out what a screen reader announces.

### Name icon-only controls.

A control with no visible words still needs a name a screen reader can say.

<DoDontPair
    doExample={<div><Button iconBefore="xmark"><VisuallyHidden>Close dialog</VisuallyHidden></Button><Heard>Close dialog, button</Heard></div>}
    doCaption="Hidden text names the icon."
    dontExample={<div><Button iconBefore="xmark" /><Heard>button</Heard></div>}
    dontCaption="An icon-only control left unnamed."
/>

### Add context the layout implies.

Sighted readers see the heading above a link; others need the words.

<DoDontPair
    doExample={<div><Link href="#">Read more<VisuallyHidden> about the spring schedule</VisuallyHidden></Link><Heard>Read more about the spring schedule, link</Heard></div>}
    doCaption="Hidden words complete the link."
    dontExample={<div><Link href="#">Read more</Link><Heard>Read more, link</Heard></div>}
    dontCaption="“Read more” repeated with no object."
/>

### Do not repeat what is visible.

Hidden text that duplicates visible text is read twice.

<DoDontPair
    doExample={<div><Button appearance="primary" text="Search" /><Heard>Search, button</Heard></div>}
    doCaption="The visible label speaks for itself."
    dontExample={<div><Button appearance="primary">Search<VisuallyHidden> Search</VisuallyHidden></Button><Heard>Search Search, button</Heard></div>}
    dontCaption="The label echoed in hidden text."
/>

### Hide with this, not with `display: none`.

`display: none` and the `hidden` attribute remove the text from the
accessibility tree too, so nothing is announced.

```jsx
// Incorrect: nothing is announced.
<span style={{ display: 'none' }}>Delete session</span>

// Correct: drawn nowhere, still read.
<VisuallyHidden>Delete session</VisuallyHidden>
```

### Do not hide what a sighted person also needs.

An instruction that is invisible to people who can see is one they cannot
find. Say it to everyone, and let the field point at it.

```jsx
<p id="pw-help">Passwords must be at least 12 characters.</p>
<input aria-describedby="pw-help" />
```

### Keep it out of the focus order.

A hidden link or button can still be focused, and a keyboard user lands on
something they cannot see. Hide text, not controls; a skip link needs to
appear on focus.

## Accessibility

- **Announced, not drawn.** The text stays in the accessibility tree, so it is
  part of the name, description or content of whatever contains it. This is the
  difference from `display: none`, `visibility: hidden` and `aria-hidden`, which
  remove it.
- **Pair with `aria-hidden` on the visual.** An icon beside hidden text should be
  `aria-hidden="true"`, so the control is announced once, by its text.
- **Live regions.** `role="status"` makes a polite announcement when its text
  changes. Render the region before the text changes, since a region that
  appears already filled is often not announced.
- **No contrast or size to meet.** Nothing is painted, so there is no color
  requirement. The text should still be written for the ear: complete words, in
  the page's language.
