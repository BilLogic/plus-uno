## Anatomy

<ol>

    <li><strong>Menu</strong>: the list of rows that opens under the trigger.</li>
    <li><strong>Item</strong>: one action per row, set by <code>items</code>.</li>

Each item takes <code>text</code>, an optional second line in <code>description</code>, <code>disabled</code>, <code>selected</code>, <code>header</code>, <code>divider</code>, <code>leadingIcon</code>, <code>trailingIcon</code>, <code>counter</code>, <code>onClick</code> and <code>keepOpen</code>. A link takes <code>href</code>. An on and off row takes <code>isToggle</code>, a plain text row takes <code>isStatic</code>, and a row still working takes <code>isBusy</code>.

The rows are the shared option row. Its states, default, hover, pressed, dragging, selected and disabled, are documented with the option list on the Select page, and hover is also the keyboard-highlighted row.

## For developers

- **Controlled mode needs both halves.** <code>isOpen</code> without <code>onToggle</code> freezes the menu, because nothing ever sets it back to closed. Pass both, or pass neither and let the component own its state.
- **It stores no selection.** The trigger keeps its own text. <code>selected</code> is a display flag per row that you keep in sync by hand, which is why a value the person picks belongs in a Select.
- **It places itself.** The menu flips up when there is no room below, right-aligns when a left-aligned menu would run off the edge, never comes nearer than 8 to the screen's edge, and remeasures on scroll and resize.
- **The menu is the Popover family's menu.** Rows are 32, or 24 with the small size, inset 4, in a menu 160 to 320 wide that stops at 320 tall and scrolls. A description adds a second line and the row grows to hold it.
- **The label half of a split button carries no handler.** It takes no prop for one. For a real main action, place a Button beside a Dropdown that holds the extra options.
- **Rows can be links and toggles.** An item with <code>href</code> is a real link, and <code>linkComponent</code> swaps in a router's. An item with <code>isToggle</code> publishes <code>selected</code> as pressed, and <code>keepOpen</code> leaves the menu open after it.

## When to use

Use a Dropdown menu for a menu of actions, and not a picker. It stores no selection and its trigger keeps its own text. A value the person picks belongs in a [Select](?path=/docs/components-forms-and-inputs-select--docs).

- **Split only when the main action is the common one.** The left half runs the main action and the caret opens the alternatives.
- **Name an icon-only trigger.** When <code>buttonText</code> is an icon, pass <code>ariaLabel</code>. Otherwise the button has no name.
- **Pass both halves when you control it.** <code>isOpen</code> needs <code>onToggle</code>. Or pass neither.

</div>

## Accessibility

- **The trigger is well formed.** It is a real button that announces a popup and a live expanded state. A split button also gets a name built from <code>buttonText</code> and the word "options", which is why the caret half shows no text.
- **The menu is not an ARIA menu.** The container is a plain element and each item is a button, or a link for an item with <code>href</code>. There is no menu role and no arrow-key navigation. Items are reached by tabbing, which works but does not match the menu pattern a screen reader user expects.
- **Escape closes it and returns focus to the trigger.** That is the caret button on either side of a split button, or the control inside a custom trigger. A custom trigger with nothing focusable in it returns focus to whatever had it when the menu opened, if that is still on the page. A click outside also closes it.
- **Escape stops at the dropdown.** The first Escape closes the menu and the next one reaches an enclosing Modal, so the Modal stays open.
- **A custom trigger brings its own keyboard access.** The node you pass is wrapped in an element that is not itself focusable. Pass a control, such as a Button, for Enter and Space to open the menu.
- **Links and toggles say what they are.** A link item is announced as a link and can open in a new tab. A toggle item reports <code>selected</code> as pressed. The multi-select checkbox is decoration, since pressed already says whether it is on.
- **A selected row is shown by color.** Color is all that marks it, so a row that switches on and off should also be a toggle item, which says so to assistive technology.
- **A static row is not a control.** It is not focusable, and pressing it leaves the menu open. A busy row, which is disabled, reports that it is busy.
- **Icons are decorative, mostly.** The multi-select checkbox, the leading icon and the trailing icon are hidden from assistive technology. The submenu caret is not, so an icon font glyph there can leak into the item's announced name. Keep the item's meaning in its text.
