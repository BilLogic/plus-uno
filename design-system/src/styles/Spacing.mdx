<FoundationSection title="Overview">

Spacing tokens name a job, not a size. Pick the pattern you are in (Page, Section, Card, Modal, Popup, Table or Element inside a component), then the relationship (pad inside a box, stack between rows, inline between things side by side), then the size. Primitives hold the raw numbers and stay hidden: designers and code bind the semantic token, never a primitive and never a typed number.

```css
padding: var(--card-pad-default);
gap: var(--card-stack-md);
```

Figma holds them in `spacing / foundations` (Element, Border, Size), `spacing / patterns` (Frame, Section, Card, Table, Blanket, Modal, Popup, Tile), `spacing / layout` (Page, Grid, Content, Screen) and the hidden `spacing / primitives`.

</FoundationSection>

<FoundationSection title="Principles">

Five principles decide which tier a gap takes. Similar things share one gap,
a new group gets a bigger one, tiers grow from the component to the page,
headings and actions get room, and a modal breathes before its footer.

**1 · Similarity: the same kind of thing takes the same gap**

Items of equal weight, such as the fields of one form group, sit close
together with one stack.

<Canvas of={SpacingStories.Similarity} sourceState="none" />

**2 · Differentiation: a new group gets a bigger gap**

When the content changes kind, from a suggestion to the form controls, step
up a tier so the change reads at a glance.

<Canvas of={SpacingStories.Differentiation} sourceState="none" />

**3 · Rhythm: tiers, never one value**

Gaps grow with the box: Element and Card 4 · 8 · 12 inside a component,
Section and Modal 8 · 16 · 24 inside a region, Surface 16 · 24 · 40 between
regions.

<Canvas of={SpacingStories.Rhythm} sourceState="none" />

**4 · Hierarchy: headings and primary actions get room**

The heading and the main action read first because they have space around
them. Give them the larger stack of their tier, and never add space by hand.

<Canvas of={SpacingStories.Hierarchy} sourceState="none" />

**5 · White space: let a modal breathe before its footer**

Pad the modal on every side, and leave the largest gap of its tier between the
content and the footer buttons.

<Canvas of={SpacingStories.WhiteSpace} sourceState="none" />

</FoundationSection>

<FoundationSection title="Tokens">

Every spacing, size and radius value comes from one ladder of four tiers, most general to most specific: **primitives**, **semantics**, **patterns**, **components**. A token is used bare, by its tier name, and a typed px value never appears. The plan is `scripts/lib/tokens/plan.mjs`; the generated output in `design-system/src/tokens/ladder/` is never hand-edited. Old names map to new ones in `architecture/token-tiers-name-map.md`.

- **Primitives** are the raw scale, named rem × 100: `--space-100` is 16,
  `--space-050` is 8. They are hidden in Figma, and nothing binds them.
- **Every other tier** points at a primitive and names a job, as
  `Collection/property-variant` in Figma, and the same words joined by dashes
  in code: `Section/pad-x-default` is `--section-pad-x-default`. A collection with a
  single property skips the variant (`--table-stack`).

Name the relationship first, then pick the token. If you cannot name the
context a value belongs to, step back to the box that holds it.

<FoundationSubsection title="Fallback rule">

Read the most specific tier that holds the value you need:

1. A component token, if the component has one (`--button-radius-default`).
2. Otherwise the pattern token of the pattern you are inside (`--card-pad-compact`).
3. Otherwise a semantics step (`--pad-x-md`, `--stack-sm`).

A value belongs to a pattern or component when it would change if that pattern or component changed; a step nothing specific owns is semantics. When no tier holds the value, name the gap and add a row to `scripts/lib/tokens/plan.mjs` (then `npm run generate:design-tokens`) rather than read a primitive. Adding a step is a design call.

```css
/* Component radius, semantics pad, pattern pad and stack */
.my-button { border-radius: var(--button-radius-default); padding: var(--pad-y-md) var(--pad-x-md); }
.my-card   { padding: var(--card-pad-default); gap: var(--card-stack-md); }
.my-row    { display: flex; gap: var(--inline-md); }
```

</FoundationSubsection>

<FoundationSubsection title="Private wiring">

A component that resolves a tier token into its own rules does it through a private custom property named `--_<component>-<role>`, set once on the component root and read by that component's rules:

```scss
.plus-tag {
  --_tag-pad-x: var(--pad-x-xs);
  --_tag-gap: var(--inline-sm);

  padding: 0 var(--_tag-pad-x);
  gap: var(--_tag-gap);

  &--spacious { --_tag-pad-x: var(--pad-x-sm); }
}
```

The leading underscore marks the property as the component's own: no other file reads it and no tier declares it. A variant or density changes the one `--_` line, and the rules below it stay put. The value on the right is always a tier token, chosen by the fallback rule. `npm run check:no-primitive-reads` holds components and patterns to that: the count of numbered-primitive reads can fall and never rise.

</FoundationSubsection>

</FoundationSection>

<FoundationSection title="Three kinds of box">

Every box on a page is one of three kinds, and the kind decides its padding.

- An **Item** has a minimum height, and its pad-x is larger than its pad-y.
- A **Container** has a background and one pad on every side, and its height
  hugs its content.
- A **Wrapper** has no fill and no pad. It only arranges its children with a
  gap or a grid.

</FoundationSection>

<FoundationSection title="Padding">

An Item pads by its height, a Container pads by its size, and a Wrapper has no
pad.

**Items: height first**

The label stays 14/20 at every size, so pad-y is (height − 20) ÷ 2: 2 at 24
and 6 at 32. Pad-x is always the larger: 8 at 24 and 12 at 32. Buttons and tabs come in

in 40, or 32 compact, with pad-y 10 at 40. Buttons round 6 (4 compact); every

<FoundationSection title="Usage">

How to build a feature that spaces like the rest of PLUS.

**Group first, then assign tokens.** Grouping is the first step to hierarchy.
Before you pick a token, group the content from the inside out; each step out
is one tier up. In a modal form:

1. Pair a control with what it changes, such as a field and its "Repeats
   weekly" toggle: `--stack-md` (8).
2. Gather related fields: `--modal-stack-md` (16) between them.
3. Separate unrelated groups: `--modal-stack-lg` (24).
4. Separate the header from the body, and the body from the footer:
   `--modal-stack-lg` (24).
5. Set the actions side by side: `--modal-inline-sm` (8).

**Pick by context, not by number.** A Card token inside a card, a Section
token inside a section, Element tokens inside a component. Never borrow a
token because its number happens to match. When the card's tokens change, the
borrowed one does not follow.

**Never hand-space.** If a gap still looks wrong with the right tokens, step
to the next tier of the same group, such as `--section-stack-md` to
`--section-stack-lg`. If no tier fits, raise it as a token or pattern question
rather than adding space by hand.

<Canvas of={SpacingStories.NeverHandSpace} sourceState="none" />

**Bind the semantic token, never a primitive or a number.** Primitives are
hidden so nothing binds them, and a typed number breaks the moment a token
changes. A one-off value takes the nearest semantic token of its context, or
becomes a proposed token.

**Build features from patterns and slots.** Start from the pattern (Section,
Card, Modal, Popup) and keep it attached; never detach it. The pattern owns
the pad, the stacks and the size, and you add content only inside its slots.
If you copy a layout to get a variation, it needs a slot, not a new variant.

**No card inside a card.** A card groups one thing. Tiers inside it are
stacks and dividers in the card body, not more cards.

<Canvas of={SpacingStories.NoCardInCard} sourceState="none" />

**Let the content pick the size.** Visible empty space means a smaller size;
overflow or clipping means a larger one. Cards hug their content, with an
optional maximum height that scrolls the body. Modals hug or fill. Tables,
sections and tab groups grow to fit.

</FoundationSection>

<FoundationSection title="Space never speaks alone">

A gap tells the eye there is a boundary, but it cannot say what the boundary is. Pair it with a heading, a label or a divider.

- Group first, then space: related fields sit close and each group takes a bigger gap than the one inside it.
- Pick one stack tier for the context and keep it across the container. All three metric cards on Home take the same stack.
- An optical nudge is allowed where the eye needs it, such as an icon beside an all-caps label. Note it on the layer; never leave a silent hard-code. Keep the nudge on a scale unit.

**Name the groups the space separates.** The create-session form has student fields, then schedule fields.

<FoundationSection title="Accessibility">

- Spacing groups content, so keep the grouping consistent.
- Related items sit closer together (a tighter stack) than unrelated ones (a looser stack), so a reader can tell what belongs together without reading every label.
- Spacing never carries meaning alone. If a gap separates two groups, a heading, label or divider says so as well.
- Pick one stack tier for the context, then keep to it across the container, so the rhythm reads the same on every screen.
- Keep the focus ring's room. The ring is drawn 2 outside a control, so a control never sits flush against a clipping edge, and Element and Card tokens leave room for it.
- The same groups need structure for everyone: a heading for each section, and a fieldset or a group label for related fields.
