## Usage

Use `CodeBlock` for code a reader may copy or follow line by line: an example,
a command sequence, a config file. For a name or short phrase inside a
sentence, use `Code`.


The typeface is the `--code` text style at 0.875rem on a 1.25rem line. The
surface is `--ds-background-code-default`, the ink `--ds-text-code-default`, the
gutter `--ds-background-code-gutter` with `--ds-text-code-gutter`, and a
highlighted line `--ds-background-code-highlight`.

</div>

<div className="sb-ds-doc-section">

## Parts

1. **Surface.** The code ground with a hairline edge and a small radius.
2. **Gutter.** Optional line numbers, skipped by screen readers.
3. **Line.** One per line of text; a highlighted line has its own ground.
4. **Region.** The scrolling block, focusable and named when it does not wrap.

## Best practices

Choose scroll or wrap by what the code means, name each block, and let the text carry what a highlight points at.

### Scroll commands, wrap prose.

Scroll keeps line structure, which matters for shell commands and config, where a fold could read as a new line. Wrap suits prose-like output in a narrow column.

<DoDontPair
    doExample={<div style={{ width: 240 }}><CodeBlock text="npm run build -- --mode production --verbose" label="Build command" /></div>}
    doCaption="A command scrolls, so one line stays one line."
    dontExample={<div style={{ width: 240 }}><CodeBlock text="npm run build -- --mode production --verbose" wrap /></div>}
    dontCaption="A command folded onto a second line reads like two commands."
/>

### Name each block when there are several on a page.

<DoDontPair
    doExample={<div style={{ width: 320 }}><CodeBlock text="npm install" label="Install command" /></div>}
    doCaption="Each region says what it holds: Install command, Config file."
    dontExample={<div style={{ width: 320 }}><CodeBlock text="npm install" /></div>}
    dontCaption="Every block named Code snippet."
/>

### Do not rely on a highlight alone.

<DoDontPair
    doExample={<div style={{ width: 320 }}><p className="plus-body-1" style={{ margin: '0 0 var(--stack-sm)' }}>Line 2 sets the retries.</p><CodeBlock text={'const timeout = 30;\nconst retries = 3;'} highlight="2" /></div>}
    doCaption="The sentence says which line to read, and the highlight supports it."
    dontExample={<div style={{ width: 320 }}><CodeBlock text={'const timeout = 30;\nconst retries = 3;'} highlight="2" /></div>}
    dontCaption="The fill is the only cue."
/>

### Keep the numbers for code you discuss.

<DoDontPair
    doExample={<div style={{ width: 320 }}><CodeBlock text="npm run dev" showLineNumbers={false} /></div>}
    doCaption="A one-line command with no gutter."
    dontExample={<div style={{ width: 320 }}><CodeBlock text="npm run dev" /></div>}
    dontCaption="A line number beside a single command."
/>

## Accessibility

- **Keyboard scroll.** A scrolling block is a focusable region with a name, so a
  keyboard user can scroll it with the arrow keys. A wrapping block has nothing
  to scroll and is not a tab stop.
- **Highlights are spoken.** Each highlighted run is bracketed by "Highlight
  start" and "Highlight end" for screen readers, because fill alone says nothing
  to them. Those words are not selectable, so they stay out of a copy.
- **Line numbers are skipped.** The gutter is hidden from assistive technology and
  cannot be selected, so a copy is the code alone.
- **Contrast.** Ink, gutter and highlight come from the code color roles and keep
  their contrast in every color and contrast mode.
