## For developers

- **Never leave the control indeterminate**, and never set the checked state by hand with <code>aria-checked</code>. The native checked property carries the state, and the mixed value is not valid for the switch role.
- **A switch acts now.** Persist on change, for example from <code>onChange</code> with the new checked value, or use a checkbox.
- **Controlled means controlled.** Pass <code>checked</code> with an <code>onChange</code> that updates it, or the input never moves. Use <code>defaultChecked</code> to leave the state with the browser.
- **The id is derived** from <code>id</code>, then <code>name</code>, then a generated one.
- **inputProps** reaches the input for attributes the component does not name, such as <code>aria-describedby</code> and <code>data-*</code>. The <code>type</code> key is removed before they are spread, and a <code>role</code> you pass wins over the default.

## When to use

Use Toggle for a setting that is turned on or off, where the change lands immediately and no Save button sits between the flick and the effect: notification preferences, showing archived sessions, a feature switch in an admin panel. The code component is called Switch.

- **A switch acts now. If the change waits for a Save or Submit button**, use [Checkbox](?path=/docs/components-forms-and-inputs-checkbox--docs) instead.
- **Name the thing that is on.** Label it "Session reminders", not "Turn on session reminders". The track already says whether it is on.
- **Show settings the viewer cannot change as read-only.** Read-only keeps the value legible. Disabled says the control is unavailable right now and fades it.
- **For one option from a set**, use [Radio](?path=/docs/components-forms-and-inputs-radio--docs), or [Choice group](?path=/docs/components-forms-and-inputs-choice-group--docs) for the group.
- **For a value along a span**, use [Range](?path=/docs/components-forms-and-inputs-range--docs).
- **For accepting terms**, use Checkbox. The decision is submitted, not applied on the spot.

</div>

## Accessibility

- **A toggle needs a label.** Nothing else says what it governs. Without a label the control has no name, and a screen reader announces only "switch, on".
- **It is announced as a switch.** Screen readers say "on" and "off" rather than "checked" and "not checked". Underneath it is a real checkbox, so keyboard behavior, the checked state and the value in a form are the browser's. Assistive technology that does not know the switch role falls back to the checkbox it is.
- **The label is part of the hit area.** The default track is 25 by 12, and neither size reaches the 44 by 44 target that the [Accessibility](?path=/docs/foundations-accessibility--docs) page asks for. The label's click area is the practical reason never to drop it.
- **Read-only is announced.** A read-only toggle stays focusable at full contrast, is announced as read-only, and ignores clicks and Space. Use disabled for a setting that does not apply right now.
- **The label is always associated** with the control, so a label never ends up orphaned.
