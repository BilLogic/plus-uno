## Footer actions

`Dialog` renders its bottom bar with <DocsLink id="components-forms-and-inputs-button-footer-actions">FooterActions</DocsLink>: pass `primaryButton` and `secondaryButton` for a `50/50` pair (`secondaryButton` draws in the left half when `primaryButton` is also given, defaulting to "Discard" in the soft neutral fill), `primaryButton` alone for the right half, or `footer` with `<FooterActions>` for three actions or a leading action (a `danger` side action or a link, never "Not now"). Because the header close button dismisses the dialog, Dialog footers name real outcomes rather than Cancel. See <DocsLink id="components-forms-and-inputs-button-footer-actions">Footer actions</DocsLink> for the full placement rules, do and don't pairs, and the hug-or-fill surface map.

## Usage

Use `Dialog` as the panel inside the <DocsLink id="templates-modal">Modal</DocsLink> template, or when a docs illustration or mockup draws the dialog panel inline with no Blanket and no modal behavior. For a working overlay over the page (Blanket, portal, focus trap, Escape and scroll lock), use the `Modal` template from `@/templates`.

The footer runs on `FooterActions`: pass `primaryButton` and `secondaryButton`
as objects for a `50/50` pair (or `primaryButton` alone for the right half), or
pass `footer` with `<FooterActions>` for three actions or a leading action
(a `danger` side action or a link).

### Width guidance

`width` takes a step of `DIALOG_WIDTHS`{` (${DIALOG_WIDTHS.join(' · ')})`}: that
many columns of the screen grid plus the dialog pad.

`Dialog` draws `--ds-surface-material-overlay` and a `--ds-border-material` edge with `--dialog-shadow` (`--ds-shadow-blocking`) in every width. A `Select` list opened inside it keeps `--ds-shadow-overlay`.

The width grows with the screen, never shrinks, and ignores the Sidebar. The
height hugs its content up to the cap (`--dialog-max-height`);
`height="fill"` sits at that cap.

## Alternatives

- For a blocking overlay over the page with Blanket, focus trap, Escape and scroll lock, use `Modal` (`@/templates`).
- For a message the person only reads, use `SectionMessage` in the page or `Flag` at the screen corner.
- For a task that keeps the page in view, use `Panel`, floating: a row's details, filters, a short edit.
- For a small aside anchored to a control, use `Popup`.
- For a list of actions or a value to pick, use `DropdownMenu` or `Select`.

## Parts

1. **Header.** Title, optional description, header actions and the close button, or a custom `header` and optional `tabs`.
2. **Body.** Text, tabs panel, or any content; scrolls when it overflows.
3. **Footer.** Appears only when a button or `footer` is given: `FooterActions` divides the width inside container padding into four equal tracks.
4. **Dividers.** Optional rules under the header and over the footer.

The tokens each part draws are read from `Dialog.scss` and listed under Tokens
touched in the Harness tab.

## Best practices

### Size the Dialog to its content with a step of `DIALOG_WIDTHS`.

A short confirmation takes `6-col`, a short form `8-col`, a table or an editor
`10-col`. A step grows with the screen; a fixed number keeps one size on every
screen.

Do: The narrowest step for a short question.

Don't: The widest step around one sentence.

<Canvas of={DialogStories.SizeToContent} />

### Keep Close on a Dialog unless the person has to answer it.

An informational `Dialog` keeps its close button; `showCloseButton={false}` is
for a decision that has to be answered from the footer.

<DoDontPair
    doExample={<FigureScreen><Dialog title="Session details" description="Monday, 4:00 PM" body="Lincoln Middle with Jordan, 45 minutes." primaryButton={{ text: 'Done' }} onClose={() => {}} /></FigureScreen>}
    doCaption="Close stays on an informational dialog."
    dontExample={<FigureScreen><Dialog showCloseButton={false} title="Session details" description="Monday, 4:00 PM" body="Lincoln Middle with Jordan, 45 minutes." primaryButton={{ text: 'Done' }} onClose={() => {}} /></FigureScreen>}
    dontCaption="No way out of an informational dialog."
/>

### Add `dividers` when the Dialog body scrolls.

The rules mark where the header and footer stay put while the body scrolls; a
short body reads cleaner without them.

<DoDontPair
    doExample={<FigureScreen short><Dialog dividers title="Session notes" body={longBody} primaryButton={{ text: 'Done' }} onClose={() => {}} /></FigureScreen>}
    doCaption="Dividers around a scrolling body."
    dontExample={<FigureScreen short><Dialog dividers title="Session notes" body="One short note." primaryButton={{ text: 'Done' }} onClose={() => {}} /></FigureScreen>}
    dontCaption="Dividers around a short body."
/>

### Give the Dialog footer a button.

`showBottomButtons` defaults to true, and the footer renders only when
`primaryButton`, `secondaryButton` or `footer` is given; describe the actions as
objects and the component renders the `FooterActions` pair.

Do: Pass `primaryButton` or `footer` when the dialog asks for a decision.

Don't: Leave a confirm dialog with no footer action.

### Use `Modal` from `@/templates` when a task needs a Blanket and focus trap.

`Dialog` draws the panel inline; `Modal` places it on a Blanket with Base UI
focus management, Escape dismissal and scroll lock.

Do: Use `Modal` for live overlay confirmations and short forms.

Don't: Render a bare `Dialog` over page content on your own.

## Accessibility

- **The close button is labeled `Close`**, hard-coded. Its icon is
  `aria-hidden`. `showCloseButton={false}` removes it.
- **The title is the dialog's h1 and its accessible name**, through
  `aria-labelledby`: the panel reads as its own page. The `description`
  describes it, through `aria-describedby`. A `Dialog` with no title takes
  `ariaLabel`.
- **A body that scrolls is focusable.** Once the content runs past the cap, the
  body gets `tabIndex={0}` so a keyboard user can scroll it.
- **Loading is announced as busy.** `loading` sets `aria-busy` on the body while
  the skeleton bars stand in for it.
- **`Dialog` has no Blanket, focus trap or Escape handling.** Use
  <DocsLink id="templates-modal">Modal</DocsLink> for live blocking dialogs over
  the page.
