## Usage

Use `DatePicker` for a single date or a date range typed or chosen from a popup calendar, such as a session date or a billing period.

</div>

<div className="sb-ds-doc-section">

## Alternatives

- For a time of day with no date, use `TimePicker`.
- For a combined date and time answer, use `DateTimePicker`.
- For an always-visible month grid on the page, use `Calendar`.

</div>

<div className="sb-ds-doc-section">

## Parts

1. **Field.** A 40 box (32 at compact) on the input fill, with the date as text.
2. **Clear button.** A subtle `IconButton` (`xmark` at `--icon-sm`) before the calendar icon when a date, range or typed text is in a live field (not read-only or disabled).
3. **Calendar icon.** Opens the calendar. Decoration for assistive technology; the input is the control.
4. **Calendar.** A month grid of 24px day cells (`--calendar-day-sm`) in a popup `--stack-sm` below the field, flipped above when there is no room. A picked day or range end is a filled square; days between form a continuous band that rounds where a week starts or ends.
5. **Presets and footer.** With `presets`, a 160px (`--width-1000`) column of 32px radio rows (`All time`, `Today`, `Last 7 days`, `Last 30 days`) sits beside the calendar with arrow-key navigation and `Enter`/`Space` selection, and presets outside `minDate`–`maxDate` are disabled. Compact `Clear` and `Apply` buttons sit below: `Clear` commits `[null, null]` immediately while `Apply` stays disabled until an in-bounds complete range (or `All time` over a non-empty filter) is ready. Otherwise, a compact subtle "Clear" `Button` sits at the end of the popup footer while a value or typed text is in the field.

## Best practices

### Typing is checked on Enter or on leaving the field.

A real day inside `minDate` to `maxDate` is picked; anything else is kept exactly as typed and marked invalid, and `onChange` is not called until the text reads as a real date.

```jsx
<DatePicker
    value={date}
    onChange={setDate}
    minDate="2026-01-01"
    maxDate="2026-12-31"
/>
```

### A range is two clicks, not a drag.

The first click sets the first day, the second sets the last day, and `onChange` receives `[start, end]`. A click before the first day starts the range again rather than erroring.

### Name the field.

`label` does not name a plain field: it is the filter trigger's text and turns `DatePicker` into the filter popup. Name a plain field with `aria-label` or `aria-labelledby` (both go straight to the input), or a visible label tied to its `id` with `htmlFor`.

### Show the date format as a hint.

The field says how to type the date before anyone types it. Without a hint people guess the order. The placeholder is MM/DD/YYYY unless you replace it, so leave it.

<DoDontPair
    doExample={<DatePicker aria-label="Session date" />}
    doCaption="The format is shown."
    dontExample={<DatePicker aria-label="Session date" placeholder="Select date" />}
    dontCaption="No format given."
/>

### Show dates in one format everywhere.

Use the same order and separators in the field, the calendar and any message. Mixed formats read as different dates.

<DoDontPair
    doExample={<FigureStack gap="sm" align="start"><DatePicker aria-label="Session date" value="2026-10-21" /><span>Your session is on 10/21/2026.</span></FigureStack>}
    doCaption="One format throughout."
    dontExample={<FigureStack gap="sm" align="start"><DatePicker aria-label="Session date" value="2026-10-21" /><span>Your session is on 21 Oct 2026.</span></FigureStack>}
    dontCaption="A second format appears in the message."
/>

### Use one range field, not two dates.

A range picks start and end in one field and one calendar. Two separate fields split one decision in two.

<DoDontPair
    doExample={<FigureStack gap="sm" align="start"><DatePicker aria-label="Billing period" range value={['2026-10-05', '2026-10-23']} /></FigureStack>}
    doCaption="One range field."
    dontExample={<FigureStack gap="sm" align="start"><DatePicker aria-label="Billing period start" value="2026-10-05" /><DatePicker aria-label="Billing period end" value="2026-10-23" /></FigureStack>}
    dontCaption="Two separate fields."
/>

### Use read-only for fixed dates and disabled for unavailable ones.

`isReadOnly` keeps the date focusable, selectable and at full contrast (`aria-readonly`); `isDisabled` removes the field from the tab order when it does not apply yet. Never swap one for the other, and never clip a read-only value; content nobody can edit is plain text, not a field. See [Read-only](?path=/docs/patterns-states-read-only--docs) and [Disabled](?path=/docs/patterns-states-disabled--docs).

<DoDontPair
    doExample={<DatePicker aria-label="Session date" value="2026-10-25" isReadOnly />}
    doCaption="Read-only keeps the value readable, and the caption says why."
    dontExample={<DatePicker aria-label="Session date" value="2026-10-25" isDisabled />}
    dontCaption="Disabled fades a value people need to read."
/>

### Let a `DatePicker` value wider than its field end in an ellipsis.

The field is typed in, so it has no Tooltip: focus reaches the whole value. It keeps its height and stays inside its slot; give it room for the whole date. See [Overflow](?path=/docs/patterns-states-overflow--docs).

## Accessibility

- **The input is the named control.** `aria-label`, `aria-labelledby` and `aria-describedby` are forwarded to the text input (`role="combobox"`), which tracks the popup with `aria-expanded` and `aria-haspopup`.
- **Name a plain field with `aria-label` or a tied label.** `label` is the filter trigger's text, not the plain field's name: it turns `DatePicker` into the filter popup. Give a plain field `aria-label`, or a visible label tied to its `id` with `htmlFor`.
- **The calendar moves like a date grid.** One day is in the tab order; the arrow keys move by day and week, Home and End go to the start and end of the week, and Page Up and Page Down change month (with Shift, year). `Enter` picks the focused day.
- **The popup is a labeled dialog.** It opens as `role="dialog"` with `aria-label` "Choose a date" or "Choose dates".
- **Clearing by keyboard and screen reader.** When a live field holds a value or typed text, the field's plain ✕ `IconButton` (`xmark` at `--icon-sm`) is named `"Clear <noun>"` in lowercase (such as `"Clear start date"`, `"Clear date"` or `"Clear dates"`) and sets `tabIndex={-1}` so `Tab` moves past the field in one stop, while the popup footer's subtle "Clear" `Button` stays in the tab order. Keyboard users clear the text and press `Enter`, or `Tab` through the open calendar dialog to the footer "Clear" button; pointer and screen-reader users can activate either button. Both empty the field, call `onChange` with `''` (or `[null, null]` with `range`) when a pick was set, and return focus to the input.
- **Invalid input stays editable.** An invalid typed date keeps the typed text and sets `aria-invalid` so the person can correct it.
