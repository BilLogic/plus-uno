## Usage

Use `SectionMessage` for a message that belongs to the page and stays there
until it is resolved or dismissed — a banner explaining why a session cannot
be booked, a notice that a report is out of date, a confirmation that
survives a scroll. It takes children, so the message can carry a link or
emphasis, and up to two `actions` after the body.

Six styles: `primary`, `secondary`, `success`, `danger`, `warning`, `info`. That
list is shorter than `Button`'s — there is no `tertiary`, no `light` or `dark`,
and there are no SMART domain colors, because a section message is always
saying something about state.

Each style sets the ground to its role's named background token
(`--ds-background-success` for success, and so on) and a default leading
icon, drawn in the style's Icon color on the first line of text. There is no
border or side stripe — the style is carried by the fill and the icon, not an
edge. The title, the body and any link in it are `--ds-text` in
every style. Every style has 4px corners.

| Style | Default icon |
|---|---|
| `primary` | `circle-info` |
| `secondary` | `circle-info` |
| `success` | `circle-check` |
| `danger` | `circle-exclamation` |
| `warning` | `triangle-exclamation` |
| `info` | `circle-info` |

## Parts

1. **Leading icon.** The appearance glyph, 20 on the first line, decorative.
2. **Title.** An optional heading; set <code>headingLevel</code> to fit the outline.
3. **Description.** What the person needs to act.
4. **Actions.** Link buttons, separated by a divider.
5. **Dismiss.** The shared CloseButton, centered on the first line.

## Best practices

### Field errors go on the field.

```jsx
// Incorrect — the error is a hundred pixels away from the input it is about,
// and nothing connects the two.
<SectionMessage appearance="danger">Email address is not valid.</SectionMessage>
<TextField id="email" label="Email" value={email} onChange={onEmail} />

// Correct — the field owns its own error state and message.
<TextField
  id="email"
  label="Email"
  value={email}
  onChange={onEmail}
  isInvalid
  errorMessage="Enter an email address in the form name@example.com."
  aria-invalid={true}
/>
```

### `dismissible` is on by default.

```jsx
// Incorrect — this renders a close button the author never asked for, and the
// message the page depends on can be dismissed away.
<SectionMessage appearance="warning">This term's schedule is provisional.</SectionMessage>

// Correct — say so explicitly when the message must stay.
<SectionMessage appearance="warning" dismissible={false}>This term's schedule is provisional.</SectionMessage>
```

### Replace the icon through `leadingVisual`, not the children.

```jsx
// Incorrect — the style's default icon still renders, so this message has two,
// and the one in the children sits in the text instead of on the first line.
<SectionMessage appearance="success"><i className="fa-solid fa-trophy" /> Goal reached.</SectionMessage>

// Correct — a Font Awesome solid name (or a node) replaces the default.
<SectionMessage appearance="success" leadingVisual="trophy">Goal reached.</SectionMessage>

// Correct — `false` removes it, for a short one-line message such as the
// sign-in messages on the Login page.
<SectionMessage appearance="warning" leadingVisual={false}>Sign-in didn't complete. Please try again.</SectionMessage>
```

### Dismissal is one-way.

```jsx
// Incorrect — `show` is not a declared prop, and the component checks its own
// dismissed state and returns null before any passed-through prop is read.
// Once the user closes this message, nothing you own brings it back.
<SectionMessage appearance="info" show={hasNews}>Three new sessions this week.</SectionMessage>

// Correct — remount it with a key when the message genuinely changes.
{hasNews && <SectionMessage key={newsId} appearance="info">Three new sessions this week.</SectionMessage>}
```

## Accessibility

- **It announces assertively.** The underlying message renders `role="alert"`,
  which implies `aria-live="assertive"` — a screen reader interrupts to read it.
  That is right for something that just went wrong and wrong for ambient
  information; for the latter, prefer plain text on the page.
- **A message rendered on mount may not be announced at all.** Live regions
  announce *changes*. If the message is present in the first paint, treat it as
  ordinary content and make sure the surrounding page still reads correctly.
- **`title` renders as a real heading**, at `headingLevel` (default `h2`). It
  joins the page's outline, so pick the level that fits where it sits.
- **The dismiss button is labeled `Dismiss message`**, hard-coded. It is the
  shared `CloseButton`: a fixed 24×24 target whose × is `aria-hidden`, centered
  on the title line when there is a title and on the first body line otherwise.
- **The leading icon is decorative.** It is `aria-hidden`, whether it is the
  default or one you pass: the message's role and its text already say what it
  is. The icon differs in shape per style, so danger and warning do not rely
  on color alone to look different, but a screen reader hears neither the
  icon nor the style.
- **Links keep the text color.** A link in the body inherits `--ds-text` and
  stays underlined, so it is told from the text by its underline alone.
- **So say it in the children.** There is no text prefix, so
  `appearance="danger"` on its own does not say "error" to a screen reader.
