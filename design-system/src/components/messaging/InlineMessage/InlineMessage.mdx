## Usage

Use `InlineMessage` for a note that explains or qualifies something right
beside it — why a field is required, what a score means — without taking up
space until someone asks. It is built on `Popup`, so placement, dismissal and
focus return are shared with every other popup in the system.

For a message that belongs to a whole page or section and should always be
visible, use `Banner` or `SectionMessage` instead. `InlineMessage` is for
detail that most people will never need to open.

## Best practices

### `label` is the only visible text before the popup opens.

The trigger is an icon button with no text of its own, so `label` carries its
accessible name and its tooltip. Write it as the question the popup answers,
not as "info" or "more."

### Pick the appearance for what the note says, not for decoration.

`info` is the default for a neutral explanation. Use `warning`, `danger` or
`success` only when the note itself is cautionary, blocking or confirming
something — the icon is a second cue, not a style choice.

```jsx
<InlineMessage label="Why this field is required" title="Required for billing">
    Your institution uses this to route invoices.
</InlineMessage>
```

## Accessibility

- **The trigger is a real button.** It is reached with Tab and opens with
  Enter or Space, same as any `IconButton`.
- **`label` is required.** It is the trigger's only accessible name; a vague
  label like "info" tells a screen reader nothing about what the popup holds.
- **Focus and dismissal follow `Popup`.** Opening moves focus into the popup;
  Escape or a click outside closes it and returns focus to the trigger.
