## When to use

Use `PromptInput` as the one place a person writes to PLUS AI — a chat panel,
a feature that drafts from a free-text ask. For a plain multi-line field with
no AI behavior (no send-on-Enter, no loading state), use `TextArea` instead.

</div>

<div className="sb-ds-doc-section">

## Usage notes

### `onSubmit` always receives trimmed-nonempty text.

`canSend` already guards against an empty, disabled or loading field, and
against a mid-composition Enter — `onSubmit` only fires when there is real
text to act on.

```jsx
<PromptInput
    label="Message to PLUS AI"
    placeholder="Ask anything about this session…"
    isLoading={isGenerating}
    onSubmit={sendMessage}
    onStop={cancelGeneration}
/>
```

### Pair `isLoading` with `onStop`, not a disabled field.

Disabling the field while a reply generates would also disable Stop, which
must stay reachable. `isLoading` swaps the send button for Stop instead of
locking the whole control.

</div>

<div className="sb-ds-doc-section">

## Accessibility

- **`label` is required** and is the field's only accessible name — there is
  no visible label by default.
- **Send and Stop are both labeled buttons**, each with its own
  `aria-label`, not just an icon.
- **Enter-to-send follows the platform convention for composed text**:
  Shift+Enter inserts a line break, and an in-progress IME composition never
  triggers a send.

</div>
