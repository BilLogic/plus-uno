## Usage

Use `Spotlight` to call out one feature the first time someone can use it:
a new button, a changed control, a place to start. It is a single step or a
short, explicit sequence with a `stepCount`, not an ongoing help system.

For a message that stays on the page until resolved, use `SectionMessage` or
`Banner` instead. For a short note tied to one field or value, use
`InlineMessage`.

</div>

<div className="sb-ds-doc-section">

## Parts

1. **Target.** `SpotlightTarget` wraps the element the callout points at and
   shares its anchor with the `Spotlight` through a `SpotlightProvider`.
2. **Headline.** The dialog title, read first.
3. **Dismiss.** The shared `CloseButton` in its `inverse` tone, in the header, the dialog's first focusable element. `dismissible={false}` leaves it out.
4. **Media.** An optional image above the body.
5. **Body.** The `children` text.
6. **Step count.** A short label like "1 of 3".
7. **Actions.** A secondary and a primary <code>SpotlightAction</code>, the secondary first. Each takes `onClick`, or `href` to render a link.

## Best practices

### Name the feature, then say what to do.

A headline names the thing; the body is one sentence.

<DoDontPair
    doExample={<StaticSpotlight headline="Find sessions here" stepCount="1 of 3" secondaryAction={skip} primaryAction={gotIt}>Open the calendar to see this week.</StaticSpotlight>}
    doCaption="Short headline, one-sentence body."
    dontExample={<StaticSpotlight headline="Welcome!" stepCount="1 of 3" secondaryAction={skip} primaryAction={gotIt}>Click here to learn about the new calendar view and everything else we changed this term.</StaticSpotlight>}
    dontCaption="A greeting and a paragraph."
/>

### Show a step count only in a tour.

One step alone has nothing to count.

<DoDontPair
    doExample={<StaticSpotlight headline="Find sessions here" stepCount="1 of 3" secondaryAction={skip} primaryAction={gotIt}>Open the calendar to see this week.</StaticSpotlight>}
    doCaption="1 of 3 in a three-step tour."
    dontExample={<StaticSpotlight headline="Find sessions here" stepCount="1 of 1" secondaryAction={skip} primaryAction={gotIt}>Open the calendar to see this week.</StaticSpotlight>}
    dontCaption="1 of 1 on a single tip."
/>

### Make the secondary action a link.

The primary action leads; the second one stays quiet. A `SpotlightAction` with
`href` renders as a link.

<DoDontPair
    doExample={<StaticSpotlight headline="Find sessions here" stepCount="1 of 3" secondaryAction={linkAction} primaryAction={gotIt}>Open the calendar to see this week.</StaticSpotlight>}
    doCaption="Secondary action as a link."
    dontExample={<StaticSpotlight headline="Find sessions here" stepCount="1 of 3" secondaryAction={<SpotlightAction appearance="primary">Learn more</SpotlightAction>} primaryAction={gotIt}>Open the calendar to see this week.</StaticSpotlight>}
    dontCaption="Two competing buttons."
/>

### Wrap the target and the callout in one SpotlightProvider.

`SpotlightTarget` and `Spotlight` share an anchor through context, so both
need to sit inside the same provider. Pass `target` directly only when the
anchor comes from outside that tree.

```jsx
<SpotlightProvider>
    <SpotlightTarget>
        <Button text="Create" />
    </SpotlightTarget>
    <Spotlight headline="Create a new board" onDismiss={() => setSeen(true)}>
        Start a new board from here.
    </Spotlight>
</SpotlightProvider>
```

### Dismiss it once, and remember that it was seen.

`isOpen` is yours to control. Store whatever "seen" state applies, such as a
user preference or a session flag, so the same spotlight does not reopen on
every visit.

## Accessibility

- **A dialog, not a tooltip.** The callout is a Popup with a title and a
  description, read together when it opens.
- **The dismiss control is the first focusable element.** Tab reaches it
  before the body or the actions, so closing never requires finding the
  target again.
- **Escape closes it.** Dismissing with Escape or the close button calls
  `onDismiss`.
