## Usage

Use a Tree table for records that nest — a curriculum of units and lessons, a
folder of sessions. For a flat list, use the Static or Dynamic table instead.

## Parts

1. **Head cell.** A label, as in the other tables.
2. **Chevron.** 12 tall in a 24 hit area, leading a parent's title cell; a spinner while children load.
3. **Indent.** One `--table-indent` step per level, up to three levels.
4. **Count.** An optional count beside a parent's name.
5. **Message row.** Under an open parent that is loading or has nothing in it.

## Best practices

- **Data nests the same shape.** `items` is one `{ id, cells, children, hasChildren, count }` per row, and `children` holds more of the same. Every level keeps every column.
- **Depth is space.** Each level indents one `--table-indent` step; a leaf keeps an empty toggle box so names at one level line up.
- **Load children late.** Give a parent `hasChildren` and no `children`, and `loadChildren(item)` returns them, or a promise of them, the first time it opens.
- **Keep the row press for rows without controls.** `shouldExpandOnClick` never fires from a button or link inside the row, but a row that carries controls reads better with the chevron alone.
- **Keyboard follows the treegrid pattern.** The table is one tab stop. Every row carries `aria-level`, `aria-posinset` and `aria-setsize`, and a parent `aria-expanded`.

## Accessibility

- **A treegrid.** Each row carries `aria-level`, `aria-posinset` and `aria-setsize`, and a parent `aria-expanded`, so depth and state are announced.
- **One tab stop.** Arrow keys move, open and close rows; Home and End jump to the ends; Enter toggles.
- **The chevron is a pointer target only.** It is `aria-hidden`; the keyboard route is the arrow keys on the row.
- **Loading is busy.** A parent whose children are loading is `aria-busy`.
