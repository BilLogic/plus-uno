## When to use

Use `DatePicker` for a single date or a date range typed or chosen from a
calendar — a session date, a billing period. For a time alone, use
`TimePicker`; for a date and a time together, use `DateTimePicker`.

</div>

<div className="sb-ds-doc-section">

## Usage notes

### Typing is checked on Enter or on leaving the field.

A real day inside `minDate`–`maxDate` is picked; anything else is kept exactly
as typed and marked invalid, and `onChange` is not called until the text
reads as a real date.

```jsx
<DatePicker
    value={date}
    onChange={setDate}
    minDate="2026-01-01"
    maxDate="2026-12-31"
/>
```

### A range is two clicks, not a drag.

The first click sets the first day, the second sets the last day, and
`onChange` receives `[start, end]`. A click before the already-set first day
starts the range again rather than erroring.

### There is no `label` prop.

Name the field with `aria-label` or `aria-labelledby` — props the component
forwards straight to the input, same as `aria-describedby` and `data-*`.

</div>

<div className="sb-ds-doc-section">

## Accessibility

- **The input is the named control.** `aria-label`, `aria-labelledby` and
  `aria-describedby` are read straight off the props and land on the text
  input a screen reader focuses.
- **The popup is a labeled dialog.** It opens as `role="dialog"` with an
  `aria-label` of "Choose a date" or "Choose dates", not a bare list.
- **`aria-expanded` and `aria-haspopup` track the calendar's open state** on
  the input itself, which is `role="combobox"`.
- **An invalid typed date keeps the typed text** rather than silently
  reverting, so the person can see and correct what they entered.

</div>
