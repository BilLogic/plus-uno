An addon is an element, a string shorthand, or an object such as <code>type: 'button'</code> with its <code>text</code> and <code>onClick</code>. The shorthands are checkbox, radio, icon, plus, button and dropdown. Any other string is shown as text. The types are checkbox, radio, icon, plus, text, button and dropdown.

Figma sets the addon with a <code>type</code> variant: checkbox, radio, icon, text, button or dropdown. The variant only decides which addon is placed by default. Swap the leading slot, or replace the trailing slot's content, for anything else. Figma also draws a second addon on a side as the Trailing slot's content. Code takes it as the second entry of a list.

The field is 32 high. <code>small</code> and <code>large</code> are deprecated: they draw like <code>medium</code> and warn in development. Hover exists only in code, from the browser.

## For developers

- **Label it, and use a Text field when the addon is decoration.** <code>label</code> is associated with the input, and <code>id</code> names the input and not the group. <code>showLabel</code> set to false clips the label without removing the name. For an addon that is only an icon or a unit, a Text field is the smaller component.
- **An unrecognized string addon becomes text.** A typo such as "buttons" renders as the literal text "buttons" in an addon, with no warning. Use one of the shorthands, or the object form.
- **The string shorthands come with defaults.** The checkbox and radio shorthands render already checked, with no handler and the generic names "Toggle option" and "Select option". The button shorthand is labeled "Button". Use the object form as soon as the addon does anything.
- **Subcomponents build the shorthands.** <code>InputGroup.Text</code>, <code>.Icon</code>, <code>.Button</code>, <code>.Dropdown</code>, <code>.Checkbox</code> and <code>.Radio</code> can be passed directly.
- **Extra props land on the input**, so <code>aria-describedby</code> reaches the element it describes.

## When to use

Use an Input group when the addon is a real control. A button or a dropdown that acts on what was typed belongs here. When the addon is only an icon, use a [Text field](?path=/docs/components-forms-and-inputs-text-field--docs), which has its own leading and trailing visuals.

- **Put a currency before the value and a unit after it.** A text addon is decoration and does not act on the field: "$" before, "kg" after.
- **Name every control addon.** A checkbox, radio or button addon needs its own accessible name. The defaults "Toggle option", "Select option" and "Button" say nothing.
- **Use two addons a side at most.** Each addon is one more thing a screen reader user meets before the field.

</div>

<div className="sb-ds-doc-section">

## Accessibility

- **The input takes the name.** The label is associated with the input, the id lands on the input, and extra props are forwarded there too.
- **Addon controls are named generically.** The checkbox and radio addons default to "Toggle option" and "Select option". Pass <code>aria-label</code> in the object form to say what they do.
- **An addon that acts on the field must be a control.** The button and dropdown addons are real ones. The text and icon addons are decoration, and the icon is hidden from assistive technology, so an icon that means something needs text beside it.
- **Required shows an asterisk** and marks the input required, and a validation message is announced as an alert, as on Text field.
- **Two addons a side is the limit.** Four things attached to a field are four things a screen reader user meets before the field itself.

</div>
