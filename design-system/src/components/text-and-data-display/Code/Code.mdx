## Usage

Use `Code` for a name, command, value or snippet that sits inside a sentence:
a function, a file path, a flag, a token.


The typeface and size are the `--code` text style (0.875em, so the chip scales
with the text around it). The fill is `--ds-background-neutral` and the ink is
`--ds-text-code-default`.

</div>

<div className="sb-ds-doc-section">

## Parts

1. **Chip.** A <code>code</code> element in the code typeface at 0.875 of the text around it.
2. **Fill.** The neutral ground, with a small radius.
3. **Text.** The code ink; long values wrap inside the chip.

## Best practices

Use `Code` for a name, value or flag inside a sentence. For several lines, use `CodeBlock`.

### Keep the chip to a short phrase.

A long chip wraps awkwardly and loses its structure. A block keeps lines and scroll.

<DoDontPair
    doExample={<CodeBlock text={'npm install\nnpm run dev'} label="Start the app" />}
    doCaption="Several lines go in a code block."
    dontExample={<p className="plus-body-1" style={{ margin: 0 }}>Run <Code>npm install and then npm run dev to start the app</Code></p>}
    dontCaption="A whole instruction in a chip."
/>

### Do not use it for emphasis.

The chip tells readers "this is literal text to type". Use bold or a button label for emphasis.

<DoDontPair
    doExample={<p className="plus-body-1" style={{ margin: 0 }}>Press <strong>Continue</strong> to proceed.</p>}
    doCaption="Bold for emphasis, in the reader's words."
    dontExample={<p className="plus-body-1" style={{ margin: 0 }}>Press <Code>important</Code> to continue.</p>}
    dontCaption="A chip on a word that is not code."
/>

### Write it as the reader would type it.

<DoDontPair
    doExample={<p className="plus-body-1" style={{ margin: 0 }}>Call <Code>getSession()</Code> first.</p>}
    doCaption="The exact name, with its brackets."
    dontExample={<p className="plus-body-1" style={{ margin: 0 }}>Call <Code>getSession().</Code> first.</p>}
    dontCaption="A trailing period inside the chip, which the reader may type."
/>

</div>

## Accessibility

- **Announced as text.** The chip is a `code` element; screen readers read it as
  ordinary text, so write the code so it makes sense spoken.
- **Contrast.** The ink on the chip fill passes in every color mode, because both
  come from the neutral background and code ink tokens.
- **It wraps.** Long values break inside the chip, so reflow at narrow widths and
  200% zoom does not scroll the page.
