## Usage

Use `Accordion` when a page carries several long, independent sections and only
one of them matters at a time — a settings page, a FAQ, the optional detail
under a form. Each item is collapsed until asked for, so the page keeps its
shape and the headers stay a readable index of what is there.

It is uncontrolled by default: give it `defaultActiveKey` and it tracks the open
item itself. Pass `activeKey` and `onSelect` together to control it. `alwaysOpen`
lets more than one item stay open at once.

</div>

## Parts

1. **Trigger.** The full-width button: the section title on the left, the chevron on the right.
2. **Chevron.** Turns up when the section is open, so the state reads without the body.
3. **Body.** The content, shown under an open trigger.
4. **Edge.** One border round the group, with the card corner radius on the first and last item. `flush` drops it for a divider line.

## Best practices

Use an accordion for several long, independent sections where only one matters at a time.

### Open one section at a time.

A stack answers one question at a time; leaving every item open turns it into a long page.

<DoDontPair
    doExample={<Accordion items={sessionItems} defaultActiveKey="0" />}
    doCaption="One section open, the rest closed."
    dontExample={<Accordion items={sessionItems} defaultActiveKey={['0', '1', '2']} alwaysOpen />}
    dontCaption="Every section open at once."
/>

### Keep titles to a few words.

The title is the only thing visible when closed, so it has to name the content at a glance.

<DoDontPair
    doExample={<Accordion items={[{ eventKey: '0', header: 'Billing', body: sessionBody }]} />}
    doCaption="A short noun title."
    dontExample={<Accordion items={[{ eventKey: '0', header: 'Everything you need to know about billing, refunds and invoices', body: sessionBody }]} />}
    dontCaption="A title that runs on and wraps."
/>

### Stack the items in one accordion.

Items share borders so the group reads as one control. This is not the `flush` prop, which is covered below.

<DoDontPair
    doExample={<Accordion items={sessionItems} />}
    doCaption="Items touch, borders shared."
    dontExample={<div style={{ display: 'flex', flexDirection: 'column', gap: 'var(--stack-lg)' }}>{sessionItems.map((item) => <Accordion key={item.eventKey} items={[item]} />)}</div>}
    dontCaption="Items spaced apart like separate cards."
/>

### There are two ways to author items, and `children` wins.

```jsx
// Incorrect — the items array is dropped without warning. The component
// returns children whenever children exist, and never looks at items.
<Accordion items={sections}>
    <Accordion.Item eventKey="0" header="One">…</Accordion.Item>
</Accordion>

// Correct — pick one. The array for uniform, data-driven sections:
<Accordion items={sections} />

// or children when a body needs its own markup:
<Accordion>
    <Accordion.Item eventKey="0" header="One">…</Accordion.Item>
</Accordion>
```

### `alwaysOpen` needs an array key, even for one item.

```jsx
// Incorrect — the open item snaps shut on the first click elsewhere. With
// alwaysOpen set and a non-array key, opening any item replaces the whole
// selection with just that item.
<Accordion alwaysOpen defaultActiveKey="0" items={sections} />

// Correct.
<Accordion alwaysOpen defaultActiveKey={['0']} items={sections} />
```

### `flush` is for accordions inside another bordered surface.

It removes the outer border and the corner radius so the item rows sit flat
against their container. Inside a Card pattern that is what you want; on the bare page
it leaves the accordion with no edge to hold it.

## Accessibility

- **Each header is a real button.** It carries `aria-expanded` and
  `aria-controls`, wrapped in a heading. Tab reaches every header; Enter and
  Space toggle; the heading list shows the whole index.
- **The body is associated with its header.** The panel's `role="region"` is
  labelled by the header that opened it, so a screen reader can jump straight
  to it, not just land there in document order.
- **Write `header` as a heading.** It becomes the text of a heading, so it is
  read both in place and in the heading list. A short noun phrase, not a
  sentence.
- **`disabled` stops a press, not discovery.** The header stays focusable and
  announced as unavailable (`aria-disabled`) rather than removed from the tab
  order — so a keyboard or screen-reader user can tell the section exists.
  Pressing it, by mouse or keyboard, never opens it. It is still not a way to
  withhold content: the body stays in the DOM, so leave the item out if what is
  inside it is not for this reader.
- **Focus stays on the header after a toggle.** Opening an item does not move
  focus into the body and does not scroll it into view. That is the right
  behavior — the user keeps their place — but it means a tall body opened low
  in the viewport is off-screen until they scroll.

## Related

- For switching between alternative views of the same content, use `Tabs`.
  Tabs say "one of these"; an accordion says "these, some of which are open".
- When every section has to be readable at once, use none of them and lay the
  sections out. Comparing two collapsed items means opening, reading, closing,
  opening.
