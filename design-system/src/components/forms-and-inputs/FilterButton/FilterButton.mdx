## Usage

Use `FilterButton` for a control that opens a filter's options or toggles a
filter on and off, above a table or a list. For a value already chosen and
removable, show it as a `Tag` instead; `FilterButton` is the trigger, not the
applied result.

</div>

<div className="sb-ds-doc-section">

## Parts

1. **Container.** A Button, 32 at default spacing and 24 at compact.
2. **Label.** The filter's name.
3. **Metric** (optional). The count of applied values, after the name. `0` shows; leave it out to hide it.
4. **Chevron** (optional). Drawn by default; turn it off when the button toggles instead of opening a menu.

## Best practices

### Keep space between filter buttons.

Leave a gap so neighboring filter buttons read as separate targets.

<DoDontPair
    doExample={<div style={{ display: 'flex', gap: 'var(--inline-md)' }}><FilterButton text="Subject" /><FilterButton text="Grade" /><FilterButton text="Status" /></div>}
    doCaption="A clear gap between filter buttons."
    dontExample={<div style={{ display: 'flex', gap: 0 }}><FilterButton text="Subject" /><FilterButton text="Grade" /><FilterButton text="Status" /></div>}
    dontCaption="Filter buttons touching."
/>

### Show the active count.

When a filter is applied, the trailing count says how many values are
active. Pass `trailingMetric` once at least one value is selected, and leave
it out when none is: `0` renders as a visible count of zero, not an empty
state.

<DoDontPair
    doExample={<div style={{ display: 'flex', gap: 'var(--inline-md)' }}><FilterButton text="Subject" trailingMetric={3} /><FilterButton text="Grade" /></div>}
    doCaption="Subject shows its three applied values; Grade, with none, shows no count."
    dontExample={<div style={{ display: 'flex', gap: 'var(--inline-md)' }}><FilterButton text="Subject" /><FilterButton text="Grade" /></div>}
    dontCaption="Subject has three values applied but shows no count."
/>

```jsx
<FilterButton text="Status" trailingMetric={selected.length || undefined} />
```

### Let it hug its label.

Keep the natural width, so the chevron stays right after the name. Filter
button has no prop to fill its container; don't stretch it across a wide row
with your own styles.

### Use the filter's name as the label.

<DoDontPair
    doExample={<FilterButton text="Status" />}
    doCaption="The label is the filter's name."
    dontExample={<FilterButton text="Filter by status" />}
    dontCaption="A verb phrase repeats what the button already does."
/>

### Turn off the chevron only when the button doesn't open a menu.

`hasChevronDown` defaults to `true`. Set it `false` only for a filter that
toggles directly on click, with nothing to open.

</div>

## Accessibility

- **A real button, unchanged.** `FilterButton` renders a `Button`
  underneath, so focus, activation and disabled/loading states all follow
  `Button`'s own contract.
- **The chevron is decorative.** It signals that a menu opens, but the
  accessible name comes from `text` and, when present, the applied count.
