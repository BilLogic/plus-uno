## Usage

Use `Suggestion` when the system proposes a value and a person decides whether
to take it: an AI-suggested focus area beside the ones already chosen, or a
suggested question beside a chat box. Put it in the row where the accepted
value will land, after the tags already there.

### Type guidance

<DocsTable>
<thead>
<tr><th>Type</th><th>When to use</th></tr>
</thead>
<tbody>
<tr><td>Insert</td><td>The default. Adds a value to the field, in place; <code>onAccept</code> hands back the <code>value</code>. Leads with a plus. Example: "Fractions".</td></tr>
<tr><td>Prompt</td><td>Sends or fills text, starting a conversation; <code>onAccept</code> hands back the <code>text</code>. Leads with a sparkle wand. Example: "Summarize".</td></tr>
</tbody>
</DocsTable>

Use `Tag` for a value that is already in the field. Use `Button` for an action
that is not a proposed value.

## Parts

1. **Glyph.** A plus for an <code>insert</code> suggestion, a sparkles wand for a <code>prompt</code>. It says which kind of proposal this is.
2. **Label.** The proposed value or prompt, short.
3. **Edge.** Dashed, in the discovery border: the system proposed it, the person has not accepted it.

## Best practices

### Name the action.

A suggestion is a verb people can trust at a glance, not a sentence. It sits in
a tag row, so its label is a value's name; for a prompt, pass the full words as
`text` and a short `label`.

<DoDontPair
    doExample={<Suggestion label="Shorten" onAccept={() => {}} />}
    doCaption="A short verb."
    dontExample={<Suggestion label="Please rewrite this paragraph to be shorter" onAccept={() => {}} />}
    dontCaption="A sentence in the chip."
/>

### Pick insert or prompt by outcome.

Insert changes the content in place; prompt starts a conversation.

<DoDontPair
    doExample={<Suggestion label="Summary" onAccept={() => {}} />}
    doCaption="Insert for an in-place edit."
    dontExample={<Suggestion type="prompt" label="Summary" onAccept={() => {}} />}
    dontCaption="Prompt for an in-place edit."
/>

### Show an unavailable action as disabled.

A disabled suggestion stays visible so people know it exists. `isDisabled`
disables one suggestion; a disabled field or `TagGroup` disables every
suggestion in it through `TagContext`, the same value a Tag reads, so a
suggestion is disabled with the tags beside it.

<DoDontPair
    doExample={<Suggestion label="Shorten" isDisabled onAccept={() => {}} />}
    doCaption="Disabled when unavailable."
    dontExample={<div style={{ display: 'flex', flexWrap: 'wrap', alignItems: 'center', gap: 'var(--inline-md)' }}><Suggestion label="Shorten" onAccept={() => {}} /><span>Nothing to shorten</span></div>}
    dontCaption="Active with nothing to do."
/>

### Let the field decide what happens next.

`onAccept` hands back the value (insert) or the text (prompt). The suggestion
does not change itself; the field that owns the value adds a Tag, sends the
message or fills the text box, and stops offering the suggestion.

<DoDontPair
    doExample={<Suggestion label="Relationships" value="focus-relationships" onAccept={() => {}} />}
    doCaption="Insert hands back the value; the field turns it into a Tag."
    dontExample={<Tag color="purple">Relationships</Tag>}
    dontCaption="A Tag styled as a suggestion is not a button, so nobody can accept it with a keyboard."
/>

</div>

## Accessibility

- **A real button.** It takes focus, and Enter or Space accepts it.
- **Disabled is a disabled button.** It keeps its name, is announced as
  disabled, is skipped by Tab, and never calls `onAccept`.
- **Named for what pressing it does.** An insert suggestion is announced as
  `Add {label}, suggested`, so a screen-reader user knows pressing it adds a
  value. A prompt is not added to anything, so it is announced as
  `{label}, suggested`.
- **The glyph is decorative.** The plus and the sparkle wand are hidden from
  assistive technology; the name already says what the suggestion does.
- **Focus is a ring, not a fill**: a 2px Focus Ring 2px outside the edge, so
  focus never reads as pressed.
